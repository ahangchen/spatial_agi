# ESI: An Embodied Self-Improvement Flywheel for LLM–VLA Agents

**发表日期**: 2026-11-13 (arXiv: 2611.18176)
**arXiv链接**: https://arxiv.org/abs/2611.18176
**PDF链接**: https://arxiv.org/pdf/2611.18176
**HTML版本**: https://arxiv.org/html/2611.18176v1
**作者**: Yundi Cai, Zihan Wang, Chenxi Han, Yi Cheng, Houde Liu, Zilei Wang
**基座系统**: 开源 GPT-as-Policy 系统

---

## 论文一句话总结

ESI 把"LLM 教师 + VLA 学生"的模块化具身智能体当作一个整体做 system-level post-training：在部署中收集教师-学生协作轨迹，从交互中提取两类监督（LLM 子任务决策 → 语义监督；教师有效纠正 + 学生后续续写 → 动作级监督），每轮同时更新决策提示、共享技能目录和 VLA 参数再重新部署（LLM 权重固定），在 10 个 RoboDojo 任务上取得 62.03 平均 Score 与 49.41% 平均成功率，超过所有已发表的混合具身智能体（含 GO-3 Nano Preview 的 47.27 / 36.60%）与代码生成类方法。

## 核心问题

### Q1: 核心算法原理是什么？

**问题**: 这篇文章的核心算法原理是什么？请详细描述：核心思想和动机、主要技术方法、算法流程和关键步骤、输入输出。

**分析**:

#### 1. 核心思想和动机

强推理模型（LLM）与强动作模型（VLA）各自可用，但**组合起来不一定协调**。论文定位了两个精确的接口失败模式：

- **Intent gap（意图鸿沟）**：VLA 生成的动作偏离 LLM 选定的子任务。已有研究（LangForce）指出"视觉捷径"会让场景信息主导语言约束——微调过的 VLA 熟悉场景与熟悉动作，却低估教师更具体的指令；
- **Handoff gap（交接鸿沟）**：教师纠正了学生的错误（比如调整夹爪、恢复到有希望的状态），但控制权交还学生后，学生把教师刚修复的状态又毁掉了——因为学生从未学过"在这个纠正后的状态下，为当前子任务继续行动"。

一个 packing 任务的例子：教师让左臂抓红色物体，学生却去抓别的物体或在到达合适接触构型前就闭合夹爪。教师介入纠正并把控制权交回——学生重复原动作或放弃目标。解法可以是"教师多控制"，但那只是重复花推理算力，不产生持久能力提升。

**核心洞察**：**协作本身就是监督信号的来源**。

- LLM 的子任务决策提供**语义监督**（policy 应该执行什么操作）；
- 教师的有效纠正 + 纠正后学生的有效续写提供**动作级监督**（如何从协作中产生的状态继续执行）；
- 学生还从自己的有效执行中学习——即使整个 episode 失败，局部有效的经验也能贡献训练数据。

由此引出范式转变：**从 model-level post-training 转向 system-level post-training**——模块化具身智能体中，决策引导、语言接口、运动行为三者共同决定系统能力，应该把"协作"本身作为学习目标。

#### 2. 主要技术方法

**(a) 形式化：三个耦合的自适应目标**

第 r 轮的智能体表示为 A_r = (T; P_r, S_r, θ_r)：

- T：固定的预训练 LLM（权重不变）；
- P_r：系统与任务引导（决策提示）；
- S_r：共享技能目录与参数 schema（语言接口）；
- θ_r：VLA 参数。

环境交互产生经验缓冲 B_r，flywheel 用同一份证据更新 P、S、θ 三个组件并在下一轮共同部署。三个组件对应三类协调失败的修复：

- 提示演化 → 改变教师如何规划、审查动作、应对困难；
- 技能演化 → 把反复出现的操作固化成可复用的显式意图表达；
- 策略学习 → 改变机器人如何在协作中出现的状态下实现意图。

**耦合由后续交互承载**：引导与技能描述的变化改变收集到的操作分布；策略更新改变哪些操作还需要教师干预。

**(b) 接口学习的两个目标性质**

设 g 为 episode 级指令，o_t 为观测（图像 + 机器人状态），h_t 为交互历史。教师 T 用这些上下文选择局部意图与结构化子任务 z_t；学生策略 π_θ 把观测与渲染的语言条件 c_t 映射为动作块（action chunk）；教师决定执行哪个前缀或如何纠正。协调要求两个性质：

1. **Intent following**：学生应把教师选定的物体、执行臂、目标位置、关系、朝向转成恰当运动——子任务指令改变时行为必须随之改变；
2. **Continuation after intervention**：学生应保留教师做出的有效改变并朝活跃目标继续——纠正产生的物理状态应成为后续学生执行的可行起点。

两个性质耦合：同一视觉状态支持多个合理动作，所以 handoff 需要同时具备"可恢复的物理构型"与"无歧义的目标"。**学习单元因此是（观测, 意图操作, 有效执行行为）的三元组组合**。

**(c) 交互接地具身蒸馏（interaction-grounded embodied distillation）**

两个互补的迁移层次：

- **语义级迁移**：LLM 用通用知识解释场景、识别相关物体与关系、选择下一个操作；结构化子任务（如"Left arm: Grasp red block"）把推理变成显式局部目标。在该条件下对有效行为做训练，教会 VLA 实现被选定的意图；
- **动作级迁移**：LLM 通过对提议运动的判断与执行中的纠正表达具身理解——修复接近轨迹、调整物体朝向、恢复有效抓取。记录有效动作与后续续写，把这些判断转化为行为监督；策略从协作中到达的物理状态（含教师干预创建的状态）中学习，使一次成功纠正的价值超出它所在的 episode。

**一个接口同时服务控制与学习**：在线请求行为用的语言 = 离线学习该行为用的条件语言。共享技能接口连接两级迁移，并随着自定义操作被整合为可复用技能而扩展表达力。

**(d) 从在线反馈到轮级更新**

两个时间尺度：

- episode 内：教师与 VLA 用新鲜观测规划、审查、纠正、继续；
- 轮之间：系统把经验整合为更新的提示、技能、策略参数；episode 摘要还作为后续尝试的任务记忆。

三条更新路径（对应 Figure 2）：

1. **审查困难 → 精化决策引导 P**；
2. **把反复出现的自定义操作整合为可复用技能 → S**；
3. **从局部有效行为构建策略监督 → θ**（监督式 flow-matching 更新吸收合格的混合控制行为）。

#### 3. 算法流程和关键步骤

每轮（collection round）：

1. 部署当前智能体 (P_r, S_r, θ_r) 在任务集上执行；
2. 每个 episode：LLM 计划并审查；VLA 提议动作块；教师接受有效动作或施加纠正；纠正后学生从新状态继续；
3. 记录观测、指令、推理、执行动作、反馈 → 共享经验记录（链接局部意图、控制源、局部执行结果）；
4. 轮末更新：
   - 从 episode 复盘精化决策提示 P_{r+1}；
   - 把重复出现的自定义操作合并进技能目录 S_{r+1}；
   - 保留学生成功子任务、教师有效纠正及其续写（含失败 episode 中的有用片段），在对应局部意图条件下做监督式 flow-matching 训练 → θ_{r+1}；
5. 三个更新后的组件一起部署进入下一轮。

#### 4. 输入输出

- 输入：任务指令 g、多模态观测 o_t（图像 + 本体感觉）、交互历史 h_t；
- 输出：机器人动作块；系统级输出是逐轮提升的智能体 (P, S, θ)；
- 不生成任务特定的控制代码（与 code-as-policy 路线的关键区别）。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

ESI 本身不直接做空间表示，但它处理的是**空间智能的执行侧瓶颈**：

- 结构化子任务 z_t 是对空间操作的显式语义编码——"Left arm: Grasp red block"把空间智能的核心要素（哪个物体、哪只手臂、什么操作、什么空间关系）压进一条结构化指令；
- "Intent following"性质本质上要求 VLA 把语言条件正确 grounding 到空间实体（红块、左臂、目标盒子）上——这是语言-空间 grounding 的动态版本；
- Handoff 的"可恢复物理构型"概念承认：空间状态的可续行性（从哪里继续）与空间状态本身同等重要。

#### 2. 如何处理空间关系

- 教师纠正本质上是对空间关系的在线修复：调整接触几何、物体朝向、抓取构型——这些都是空间关系操作；
- 共享技能目录是空间操作的模式库：每个技能描述一种参数化的空间操作（抓、放、推、对齐），参数即空间实体引用；
- episode 摘要作为任务记忆，存储的是空间操作的时序组织（先抓什么、后放哪里）。

#### 3. 对 Spatial AGI 的启发

1. **空间智能的瓶颈常在接口而非模块**：LLM 有空间推理，VLA 有空间动作，但两者接口失败会让整体表现不如组件。这与 GeoGR 那篇的"压缩在接口"形成呼应——Spatial AGI 系统工程的第一性问题往往在组件间接口；
2. **协作数据是未被充分利用的监督富矿**：人-机/师-生协作中的纠正与续写是极高质量的空间操作监督（它们天然标记了"哪个状态是可恢复的、正确的目标是什么"）。Spatial AGI 数据引擎应该专门设计协作数据协议；
3. **局部有效 ≠ 整体成功**：失败 episode 中的成功子任务片段也有学习价值——空间操作数据的标注单位应该是"局部意图-行为对"而非 episode；
4. **系统级自改进**：Spatial AGI 不会以"一个模型"形态出现，而是"LLM + 空间记忆 + VLA + 世界模型"的组合。ESI 的 flywheel 模式（同一份交互证据更新多个组件再共同部署）是这类系统自改进的通用模板；
5. **教师-学生蒸馏的具身版本**：基础模型的进步可以通过"参与执行 + 产生训练经验"两条通道转化为具身能力——为 Spatial AGI 提供了从 web 智能到具身智能的持续转化路径。

#### 4. 可以应用的 Spatial AGI 场景

- 家庭机器人持续学习：部署中每天积累教师纠正，逐步减少干预依赖；
- 多机器人技能共享：技能目录 S 可以跨机器人迁移（语言接口通用）；
- 人机协作教学：把人类示范-纠正-放手的自然教学过程直接变成训练协议；
- 仿真到真机的适配：仿真中 LLM 教师海量收集协作数据，蒸馏到真机 VLA；
- 空间推理与操作的联合改进：LLM 的空间推理错误也可以从"纠正无效"的记录中被发现并精化提示（推理侧的自改进分支）。

### Q3: 主要创新点和局限性是什么？

**分析**:

#### 1. 主要创新点

1. **System-level post-training 的形式化**：A=(T;P,S,θ) 的分解清晰、更新路径明确，把"模块化具身智能体的协同"首次做成可优化的对象，而不是工程拼装；
2. **协作即监督的洞察与落地**：语义监督（子任务决策）+ 动作监督（纠正+续写）两类信号都从交互中自动提取，无需人工标注；"失败 episode 中的局部有效片段也可训练"的数据筛选原则务实且新颖；
3. **一个接口贯通控制与学习**：在线请求语言 = 离线训练条件的同构设计，让技能目录的演化同时改善执行与训练数据的组织；
4. **无代码路线的实证胜利**：在不生成任务特定控制代码的约束下击败所有 code-based 混合方法——证明"接口对齐 + 数据飞轮"可以替代"代码生成"这条当前主流路线；
5. **量化战绩**：10 个 RoboDojo 任务上全面超过单组件参考与所有已发表混合系统（62.03 Score / 49.41% vs GO-3 Nano Preview 47.27 / 36.60%）。

#### 2. 主要局限性

1. **教师权重固定**：自改进只覆盖 P/S/θ，LLM 自身的推理错误（如错误的任务分解）不会被修正——推理侧自改进（如 RECAP、GEPA 分支）被论文自己列为"可集成的互补分支"，即尚未做；
2. **任务集选择**："ten selected RoboDojo tasks"——任务是被选择的，泛化到完全未见任务类别的能力存疑；
3. **教师成本**：每轮部署都依赖在线多模态 LLM 做规划/审查/纠正，推理成本高；自改进的目标之一应是降低教师介入频率，论文虽提到 FastHarness 式审查调度可集成，但本体未优化这一点；
4. **监督信号的可信度依赖教师判断**：什么算"有效纠正"、什么算"有效执行"由教师评审决定，教师误判会污染数据；
5. **技能目录的扩展性**：反复操作合并进目录的机制在技能数量大增后可能面临检索与歧义问题；
6. **flow-matching 监督更新**是行为克隆性质的（吸收合格行为），没有显式的 advantage/RL 项——上限可能受限于教师质量。

#### 3. 与其他相关工作的对比

| 方法 | 自改进对象 | 监督来源 | 特点 |
|------|-----------|---------|------|
| Scaling Up & Distill Down | 策略 | LM 引导规划 + motion planner 轨迹 | 离线数据生成，无在线交互 |
| Sirius | 策略 | 自主执行 + 人工干预，加权 BC | 干预数据利用，无接口演化 |
| Yell At Your Robot | 高层策略 | 人类语言纠正 | 层级结构，无 VLA 级更新 |
| RECAP | VLA | 示范+自主+干预，advantage 条件 | 更新单一组件 |
| Reflexion / Voyager | 提示 / 技能库 | 语言反馈 / 环境反馈 | LLM 权重固定，无运动策略 |
| DSPy / GEPA | LM 程序/提示 | 执行轨迹反思 | 纯语言系统 |
| **ESI** | **(P, S, θ) 三组件联合** | **在线师-生协作** | **系统级 + 具身 + 自动化** |

ESI 的差异化在于"同时更新三个组件 + 以协作为监督来源"的组合，而不在任何单点上绝对首创。

## 核心技术发现

- 发现 1：模块化具身智能体的失败集中在接口（intent gap + handoff gap），而非组件能力不足——组合两个强模型不自动产生协调行为；
- 发现 2：师-生协作交互自动提供两类互补监督：子任务决策 → 语义监督；有效纠正 + 学生续写 → 动作级监督；
- 发现 3：以（观测, 意图, 有效行为）三元组为学习单元，失败 episode 中的局部有效片段也能稳定贡献训练价值；
- 发现 4：提示、技能目录、VLA 参数三者的耦合由后续交互自然承载——共同部署是 flywheel 闭合的必要条件；
- 发现 5：无代码的"接口对齐 + 数据飞轮"路线在选定的操作任务集上已可超过代码生成类混合方法。

## 与 Spatial AGI 的关系

### 直接贡献

- 为"多模块 Spatial AGI 系统如何变强"提供了第一个完整的自动化协议；
- 把具身蒸馏从"数据生成→蒸馏"升级为"在线协作→接口学习"。

### 技术启发

- 接口优先的调试观：Spatial AGI 系统效果不好时，先查组件接口（意图跟随、状态交接）再查组件本身；
- 协作数据协议设计：让人类/AI 教师的每一次介入都自动转化为（意图, 行为）对；
- 系统级 flywheel 是 Spatial AGI 产品化的可持续改进机制。

### 应用场景

家庭机器人持续学习、多机器人技能共享、人机协作教学、sim-to-real 数据飞轮、空间推理与操作联合改进。

## 个人思考

### 最令人兴奋的发现

"Handoff gap"是我今年看到的最有洞察力的失败模式命名之一。它点破了一个此前被含糊处理的现象：**纠正的价值不仅在于把状态改对，更在于"纠正后的状态能否被策略接得住"**。这把 imitation learning 里的 DAgger 式思想推进了一层——不只是"在学生访问的状态上训练"，而是"在教师干预制造的状态上、以教师的局部意图为条件训练"。这在概念上把"干预"从损耗项变成了资产项。

另一个深刻之处是"学习单元是三元组"的设定：观测、意图、有效行为绑在一起训练。这实际上拒绝了"行为克隆学行为、语言条件只是输入"的松散耦合观——语言条件必须因果地起作用（intent following 是可测性质），否则数据不作数。这种"性质驱动的数据筛选"比"数据多多益善"高明得多。

### 潜在局限

- 教师固定是当前最大天花板：LLM 自己的任务分解错误无法自愈，flywheel 只能放大教师正确的部分；
- "selected tasks"的选择标准未明示，存在 benchmark 过拟合风险；
- 实用化要回答"教师介入频率随轮次下降的曲线"——如果 10 轮后仍需密集纠正，边际收益存疑（论文报告了性能提升，但干预率随轮次的衰减曲线是我最想看却未见详述的图）。

### 与昨日研究的关联

- 与昨天精读的 Agentic-Teacher（失败驱动的 VLA 后训练数据引擎，同样 2026-11-12 前后）高度互补：Agentic-Teacher 关注"用什么失败数据训练"，ESI 关注"协作交互如何自动产生这种数据 + 三个组件如何一起更新"——两者合起来几乎就是一套完整的具身自改进方法论；
- 与 OnlyAct（动作表示）和 ST-VLA（时空记忆 VLA）的连接：ESI 的 intent following 性质依赖动作表示对语言条件的敏感性——Last05/STVLA 类结构的 VLA 是否天然更容易通过 ESI 的筛选，是可验证问题；
- 与 Ragu（检索引导的零样本 VLA 适配）的呼应：ESI 的技能目录 S 本质上是一种可演化的"技能记忆"，与 Ragu 的检索引导异曲同工，但 ESI 让它随部署演化。

## 总结

### 核心发现总结

ESI 证明了模块化具身智能体的"协作接口"本身可以成为后训练目标：以师-生交互为监督来源，每轮同时更新决策提示、共享技能目录与 VLA 参数再共同部署，即可把"episodic 协助"转化为"persistent 能力"。在选定任务集上，这条无代码路线已经超过所有已发表的混合具身系统。

### 对 Spatial AGI 的意义

Spatial AGI 必然是系统而非单体模型，ESI 给出了这类系统"如何随部署变强"的第一份可执行答案。其核心资产是三个可复用的设计原则：(1) 接口性质（intent following / handoff）应作为可测的学习目标；(2) 协作交互是免费的监督富矿；(3) 多组件应共享同一份交互证据并共同部署。这三条原则几乎可以原样迁移到任何"LLM + 空间记忆 + 动作模型 + 世界模型"的组合中。

## 深度拆解：flywheel 的信息流剖析

### A. 为什么三个组件必须一起更新？

考虑反例——只更新 θ（只训 VLA）会发生什么：

- 学生变强了，但教师的提示 P 还在按旧策略写（比如过度详细的抓取指导），浪费推理 token 并可能与新能力冲突；
- 技能目录 S 还是旧的，新的重复操作每次都被当作一次性自定义指令，无法沉淀；
- 更微妙的是：教师看不到学生变强，纠正频率不变，数据分布（哪些状态被纠正过）不随能力演化——训练数据分布与部署分布脱节，DAgger 式保证被破坏。

反之，只更新 P/S（不训 θ）：纯推理侧改进，能力上限锁死在学生初始策略上。

**共同部署是 flywheel 成立的动力学条件**：更新后的组件改变下一轮的交互分布，交互分布又决定下一轮的数据。论文里"coupling is carried by subsequent interaction"这句话是整个方法的动力学核心——ESI 是一个分布随策略演化的自举过程，不是静态的训练循环。

### B. 两类监督的粒度对齐问题

- 语义监督的粒度：子任务 z_t（"左臂抓红块"）——秒级、任务段级；
- 动作监督的粒度：动作块（action chunk）——亚秒级。

两者通过"共享技能接口"对齐：技能既是教师下达意图的词汇，也是训练数据条件化的标签。对齐质量决定了语义监督能否正确传播到动作级梯度。如果技能定义含糊（"grasp"没说清从哪个方向），同一技能标签下会混入不同意图的行为，条件化训练反而引入噪声。所以技能目录的质量控制（模式 schema、参数完备性）是 ESI 隐含的关键工程点。

### C. "局部有效"的判定：flywheel 的质量控制点

哪些片段进入训练集？三类：

1. 学生成功完成的子任务（含失败 episode 中的）——意图 g_t 与行为都有效；
2. 教师纠正动作本身——教师的行为是"黄金续写"；
3. 纠正后学生的有效续写——把 handoff 状态变成训练起点。

判定"有效"依赖教师审查（+ 环境结果）。这形成了一个隐含的假设：教师判断的错误率足够低。如果教师有 10% 的误判率（把无效纠正判为有效），这些片段会以高置信条件进入训练集，成为难以察觉的性能拖累。可能的强化方向：用环境结果回溯验证（纠正后任务是否更接近完成）、或引入第二个裁判模型交叉验证。

## 延伸问答（自问自答）

**Q: ESI 与 RL（如 RLHF/RLAIF、在线 RL）的关系？**

A: ESI 的策略更新是监督式 flow-matching（行为克隆性质），没有显式奖励模型与策略梯度。它的优势是稳定与简单，劣势是没有超越教师分布的机制——真正的 online RL（如用任务成功作为稀疏奖励）可以在 flywheel 之上叠加。两者关系更像"ESI 负责把交互变成合格数据，RL 负责在数据之外探索"。论文引用的 RECAP（advantage-conditioned）正是可以整合的分支。

**Q: flywheel 会不会收敛到教师的水平就停了？**

A: 会逼近"教师能力 × 接口对齐度"的上限。突破上限的通道：(1) 技能组合的涌现——学生把两个技能组合出教师没显式教过的行为；(2) 学生在密集练习的子任务上超过教师示范水平（练习效应）；(3) 换更强的教师重启 flywheel——这也是基础模型进步转化为具身能力的入口。

**Q: 这个框架如何接入空间记忆 / 世界模型组件？**

A: 自然扩展是把系统分解扩为 (T; P, S, M, W, θ)——M 是空间记忆、W 是世界模型。ESI 的"同一交互证据更新多组件"原则直接适用：纠正事件写入 M（"这个位置抓取容易滑"）、世界模型的预测误差作为其训练信号、教师的前瞻推理用 W 校验。ESI 论文没做这个扩展，但它提供了一个可扩展的骨架。

**Q: 与 Agentic-Teacher（同日另一篇）的区别？**

A: Agentic-Teacher 聚焦"数据引擎"——用 agentic 流程生成失败驱动的后训练数据，优化的是数据生产；ESI 聚焦"部署系统"——在线协作 + 三组件共同更新，优化的是系统动力学。前者是后者的上游组件候选（用更聪明的数据引擎替代 ESI 的经验缓冲构造）。

## 附：术语表

- **Intent gap**: 教师选定子任务与学生实际行为之间的偏离；
- **Handoff gap**: 教师纠正产生的状态与学生续行能力之间的断层；
- **Flywheel**: 收集-学习-再部署的循环，每轮更新 (P, S, θ) 并共同部署；
- **Shared skill catalog (S)**: 教师下达意图与学生训练条件化共用的技能描述与参数 schema；
- **Interaction-grounded embodied distillation**: 从在线师-生协作提取监督的具身蒸馏范式；
- **Semantic-level / Action-level transfer**: 子任务决策→意图实现 / 纠正与续写→状态续行的两级迁移；
- **Local effectiveness**: 片段级（而非 episode 级）的有效性判定，允许失败 episode 贡献数据。

## 三大核心问题的扩展讨论

### Q1 扩展：ESI 的学习理论视角

ESI 的动作级监督本质上是一种**非对称 DAgger**：

- 经典 DAgger：专家在学生访问的状态上提供动作标签 → 修正分布漂移；
- ESI：教师在学生（及教师自己）制造的状态上提供纠正 → 修正分布漂移 + 显式教"如何从干预状态续行"。

非对称之处：(1) 教师标签只在必要时给出（学生提议可接受时直接采纳学生行为，降低标签成本）；(2) 标签附带意图条件（c_t），使数据组织成条件化技能簇而非无结构轨迹；(3) "接受前缀 + 纠正后缀"的混合控制时序被完整保留，续写监督利用了干预后的真实后续而非截断。

从 imitation learning 理论看，ESI 的 compounding error 修正机制比标准 BC 强——因为它显式覆盖了"干预状态"这一 BC 数据中系统性缺失的状态类。这也解释了为什么 handoff gap 能被有效修复：不是学生突然变聪明，而是训练分布第一次覆盖了这些状态。

### Q2 扩展：语言接口作为系统演化的"可编程层"

ESI 的三层结构可以按可塑性排序：

```
θ (VLA 参数)      — 慢层: 监督学习, 需要数据积累
S (技能目录)      — 中层: 经验整合, 轮级更新
P (决策提示)      — 快层: 复盘反思, 轮级甚至 episode 级
T (LLM 权重)      — 冻结层: 依托外部基础模型进步
```

这个分层让系统具备"多时间尺度学习"的能力——类似生物运动学习的"快适应（小脑）+ 慢巩固（皮层）"结构。对 Spatial AGI 系统设计的启示：不要把所有学习压进一个时间尺度；提示层承担快速试错，目录层承担模式沉淀，参数层承担能力固化。

技能目录的特殊地位值得强调：它是唯一同时被三个过程读写的组件——教师写（表达意图）、学生读（条件化动作）、训练管道读（数据标签）、经验整合写（新技能）。它是整个系统的"共享内存"。它演化得好坏直接决定 flywheel 的效率上限。

### Q3 扩展：与 Spatial AGI 的执行鸿沟

Spatial AGI 领域当前最大的落地鸿沟不在"理解空间"而在"把空间理解兑现为动作"。本精读序列近期反复遇到这个问题：

- WanderBench（11-11/11-16）：世界模型探索任务中，规划质量与执行质量的落差；
- Protovis-Nav（11-16）：UAV 导航用视觉想象做规划，但执行仍依赖底层策略；
- ST-VLA（11-16）：把时空记忆注入 VLA，改善的正是"执行时的上下文"。

ESI 提供的是这个鸿沟的**训练侧答案**（协作蒸馏），而 GeoGR/压缩类工作提供的是**推理侧答案**（让 LLM 能实时参与控制环），RigidGS 类提供的是**感知侧答案**（干净的操作目标）。三条线索合起来，指向一个完整的 Spatial AGI 执行栈：干净感知 → 实时推理 → 接口对齐 → 可训练的动作模型。每日精读的价值正在于把这些碎片拼成栈。

## 补充：潜在失败模式的压力测试

1. **技能目录膨胀**：随部署时间增长，S 中的技能可能重叠、歧义（"pick" vs "grasp" vs "take"）。需要周期性的技能合并与去重——论文未涉及目录的"垃圾回收"；
2. **提示漂移**：P 的逐轮精化可能过拟合到已见困难类型，遇到新型困难时反而不如通用提示。可以借鉴 GEPA 的"评估后采纳"机制（提示修改需在新样本上验证）；
3. **教师风格锁定**：学生最终复现的是"这个教师的协作风格"而非通用能力。换教师后 handoff gap 可能复发——因为新教师的纠正风格与干预状态分布不同；
4. **安全边界**：flywheel 自动化更新部署组件，若缺乏安全回归测试，某一轮更新可能引入危险行为（尤其真实机器人场景）。部署前回归测试套件是必要的工程护栏，论文未讨论。
