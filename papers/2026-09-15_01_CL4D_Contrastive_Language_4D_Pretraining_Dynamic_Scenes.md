## 一句话总结

CL4D 是首个直接在动态 4D 点云序列上做对比语言预训练的基础视觉编码器，并据此构建了首个直接推理 4D 点云的 VLM（4DVLM），在 4D 人类动作基准上超越此前方法约 16.75%，甚至胜过使用 RGB 视频输入的 Gemini 与 GPT-5。

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

**分析**:

1. **核心思想和动机**

   物理世界本质上是四维的：三维空间 + 一维时间。具身智能（Embodied AI）要在动态物理环境中运作，就必须统一地表示几何结构和时间动态。但现有视觉编码器存在明显断层：
   - 静态 2D 图像编码器（Llama、CLIP 类）：无几何深度、无时间。
   - 视频 VLM（VideoLLM、Video-LLaVA）：有时间信号但根植于 2D 像素，缺乏显式 3D 几何推理。
   - 3D 点云方法（PointLLM、LL3DA、Ges3ViG）：有几何但只限静态场景，不建模时间演化。
   - 4D 动作编码器（Motion PointNet、Motion Patches）：要么用闭集分类目标，要么依赖结构化骨架而非原始动态点云。

   CL4D 的核心洞察是：把 CLIP 式"对比对齐"范式首次推广到 4D —— 让时间演化的点云序列（几何+运动）与自然语言共享一个嵌入空间，从而获得开放词汇的、可零样本迁移的 4D 表征。表征是下游一切 4D 视觉-语言任务的地基。

2. **主要技术方法**

   采用两阶段训练策略：

   **阶段一：CL4D 对比语言-4D 预训练**
   - **点编码器（Point Encoder, PE）**：对每个点云帧用标准 PointNet 处理局部点组（每帧分为 k 组、每组 g 个点），产出每帧 k 个 d1 维嵌入；每帧前缀一个可学习 token 聚合帧内信息。
   - **时空 Transformer 编码器（Spatio-Temporal Transformer, V_st）**：在帧间做时序建模，把 N 帧的点特征序列压缩成时空联合表征；时序编码器用预训练 ViT 权重初始化（附录 8.5），说明作者认为 4D 时序注意力的结构与 2D 图像 patch 注意力同构，可迁移。
   - **文本编码器（TE）**：标准语言编码器（CLIP 风格）。
   - **对比对齐目标**：多模态对比损失（InfoNCE 式）把 4D 序列嵌入与对应文本描述拉近、与 batch 内负样本推远，形成共享的文本-4D 嵌入空间。
   - 训练完成后，该编码器支持零样本 motion→text / text→motion 检索。

   **阶段二：4DVLM（4D 视觉语言模型）**
   - **视觉 token 投影**：把冻结/预训练好的 CL4D 时空嵌入投影为 LLM 可消费的视觉 token。
   - **语言骨干**：LLM 生成回答，条件是动态几何表征 + 指令文本。
   - **训练目标**：标准 next-token prediction（指令微调），在新建的 4D-VQA 数据上训练。

3. **算法流程和关键步骤**

   ```
   输入: 动态点云序列 {(x,y,z,t)_i}, N 帧
   Step 1: 每帧 PointNet 局部分组编码 → 每帧 k 个 token
   Step 2: 帧序列送入时空 Transformer（ViT 初始化）→ 时空嵌入 V_st
   Step 3a (阶段一): V_st 与文本嵌入 TE(text) 做 InfoNCE 对比对齐
   Step 3b (阶段二): V_st 投影为视觉 token → LLM 自回归生成 VQA 答案
   输出: 4D 表征嵌入（检索）/ 自然语言回答（VLM）
   ```

4. **输入输出**

   - 输入：时间演化的 4D 点云序列（由 SMPL 参数转 Unity 动画、加体形/纹理增广、表面采样渲染生成）；文本描述或问题。
   - 输出（CL4D）：与语言对齐的时空嵌入向量，用于零样本跨模态检索。
   - 输出（4DVLM）：对 4D-VQA 问题的自然语言回答，覆盖动作语义、身体-空间性质（肢体位置、几何关系）、时间性质（逐帧状态变化）三类。

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

1. **如何理解和表示空间**

   CL4D 给出了一种"空间=几何×时间"的原生表示主张：不用像素做代理，不用骨架做抽象，而是直接在 (x,y,z,t) 点云流上学习。空间不再是从 2D 投影"恢复"出来的东西，而是感知的第一性对象。这与 Spatial AGI 追求的"以空间为本位的智能表征"高度一致——把几何与运动作为一等公民，语言作为对齐接口。

2. **如何处理空间关系**

   - 局部几何（PointNet 分组）捕捉帧内空间结构（物体形状、肢体构型）。
   - 时空 Transformer 捕捉跨帧的空间关系演化（谁向哪移动、肢体轨迹、物体相对位置变化）。
   - 对齐到语言后，空间关系被"词汇化"：如"举起左臂""绕过桌子走向门"这样的空间谓词成为嵌入空间中的可检索语义。

3. **对Spatial AGI的启发**

   - **基础编码器范式可复制**：2D 有 CLIP、3D 有 ULIP，4D 现在有 CL4D。Spatial AGI 的技术栈可以像 2D 时代一样"编码器→对齐→VLM→Agent"逐层搭建，CL4D 提供了第 0 层的模板。
   - **几何感知优于像素代理**：4DVLM 以点云输入击败 RGB 视频输入的 Gemini/GPT-5，这是"显式 3D 表征对空间任务有本质优势"的有力证据——恰恰是 Spatial AGI 区别于通用 VLM 的价值主张。
   - **数据引擎同样重要**：DynAction4D 展示了一条 SMPL→Unity 增广→点云采样的可扩展合成数据管线，Spatial AGI 需要的 4D 预训练数据很难从真实世界大规模采集，仿真合成是现实路径。
   - **空间 QA 三分法**：Action / Body-Spatial / Temporal 的 QA 分类可以推广为空间智能的评估维度：语义、空间几何、时间动态。

4. **可以应用的Spatial AGI场景**

   - 具身机器人的动作理解与指令检索（"找到正在蹲下捡东西的人"）。
   - 4D 场景监控与异常行为检测（零样本，无需闭集标签）。
   - 人机交互：对动态人体的空间问答（护理、体育教练、康复评估）。
   - 作为 world model 的感知前端：为动态场景预测提供几何-运动基础表征。
   - 自动驾驶/无人机中的动态行人-物体 4D 理解。

### Q3: 创新点和局限性

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**分析**:

1. **主要创新点**

   - **首个 4D 基础视觉编码器**：第一次把对比语言预训练完整搬到动态点云上，形成开放词汇（而非闭集分类）的 4D 表征。
   - **首个 4D VLM**：不依赖 2D 图像/视频/静态点云，直接条件生成于动态几何表征。
   - **性能证据扎实**：文本-动作检索 Recall@1 提升约 16.75%；4DVLM 在同等场景上战胜 RGB 输入的 Gemini 与 GPT-5。
   - **DynAction4D 基准**：HumanOnly（23k 训练/4k 测试）+ ObjInteractions（510/219，72 类物体 735 种交互，来自 Humoto）+ Cluttered（23k/4k，杂物场景）+ 4D-VQA（Gemini 3.0 Flash 辅助生成）四段式结构，兼顾纯净与复杂场景。
   - **工程可复现**：数据管线、代码开源（4d-vision-uom.github.io）。

2. **主要局限性**

   - **以人为中心**：DynAction4D 几乎全部围绕人类动作（HumanML3D/Humoto），对一般物体动力学（流体、可变形物、多物体交互物理）覆盖有限，距"通用 4D 世界理解"还有距离。
   - **数据为仿真合成**：SMPL/Unity 生成的点云与真实 LiDAR/深度相机的噪声模型、遮挡模式有域差，sim-to-real 泛化未充分验证。
   - **规模有限**：ObjInteractions 仅 510 训练序列，交互多样性可能不足以支撑复杂物体关系推理。
   - **文本来源依赖**：VQA 由 Gemini 生成，可能引入标注偏差与幻觉；文本描述继承自 HumanML3D，语义粒度受限。
   - **计算成本**：动态点云 + 时空 Transformer 的开销远高于视频 token，实时具身部署存疑（论文未报告推理延迟）。

3. **与其他相关工作的对比**

   - vs CLIP/ActionCLIP/CLIP4Clip：这些在 2D 像素域，无显式几何；CL4D 直接在 3D 几何+时间上对齐。
   - vs ULIP/OpenShape/PointCLIP：这些对齐静态点云；CL4D 引入时间维度。
   - vs Motion Patches：需要骨架结构化输入；CL4D 用原始点云，更接近真实传感器。
   - vs Motion PointNet：闭集分类目标；CL4D 开放词汇对比对齐，可零样本迁移。
   - vs PointLLM/LL3DA：静态 3D 指令调优；CL4D/4DVLM 处理动态 4D。
   - 优势：表示第一性、几何显式、零样本能力强。劣势：数据域窄、生态不成熟（2D 视频数据量级远大于 4D 点云数据）。

## 核心技术发现

- 对比学习范式从 2D→视频→3D→4D 的推广是可行的，且 4D 对齐后零样本检索能力显著（R@1 +16.75%）。
- 预训练 ViT 权重可以初始化时序 Transformer，暗示时空注意力与图像 patch 注意力存在结构同构性。
- 4D 点云表征在几何-时间推理类 QA 上压倒 RGB 视频，即使对手是最强的闭源视频 VLM。
- SMPL→Unity→点云的合成数据管线是 4D 预训练数据的可扩展来源。

## 与Spatial AGI的关系

### 直接贡献

提供了 Spatial AGI 技术栈中缺失的"4D 基础编码器"这一层，使语言可以直接接地到动态三维场景，而不经过像素代理。

### 技术启发

- 编码器-对齐-VLM 的分层构建路线适用于整个空间智能体系。
- 合成数据引擎（仿真→增广→点云化）是空间智能数据规模化的一般模式。
- 空间 QA 的语义/空间/时间三分类可作为 Spatial AGI 能力评估框架。

### 应用场景

具身机器人动作理解、动态场景开放词汇检索、4D 监控、人机空间问答、world model 感知前端。

## 个人思考

### 最令人兴奋的发现

4DVLM 赢过 RGB 输入的 Gemini/GPT-5 这一结果的意义超过数字本身：它说明在空间-时间联合推理这个切片上，"正确的表示"可以击败"更多的数据+更大的模型"。这是整个 Spatial AGI 方向的合法性证明。对齐范式的第四次推广（2D→视频→3D→4D）也预示着，未来每个空间表征层级都会有自己的 CLIP 时刻。

### 潜在局限

以人为中心的数据让我们对"4D 理解"的进展产生错觉——人类动作只是 4D 世界的一小部分。真正的通用 4D 理解需要物体affordance、流体、物理交互的动态几何。另外，点云输入在实际机器人上通常来自深度传感器，噪声与丢失远比 Unity 采样严重，真实世界性能可能缩水。

### 与昨日研究的关联

昨天精读的 GraFT（training-free 3D 场景图增强空间推理）走的是"用现成 3D 结构增强 2D VLM"的路线，而 CL4D 走的是"从零构建原生 4D 表征"路线。两者是空间智能的两条互补路线：前者务实、低成本、可立即部署；后者根本、上限高、但需要数据和算力投入。长期看，原生 4D 编码器成熟后会取代 patch-work 式的 3D 增强方案，就像原生多模态模型逐步取代 caption 桥接方案一样。CST-WM（因果结构世界模型）也强调了时间动态，CL4D 可以视为其感知侧的对应物：世界模型需要能够理解"什么在动、怎么动"的感知前端。

## 关键数据

- 检索性能：文本-动作检索 Recall@1 相比此前最优 4D 编器提升约 16.75%。
- 4DVLM 在 4D-VQA 上超过 RGB 输入的 Gemini、GPT-5。
- 数据集 DynAction4D：HumanOnly 23k/4k；ObjInteractions 510/219（72 物体、735 交互）；Cluttered 23k/4k；另含 Gemini 3.0 Flash 生成的 4D-VQA 段。
- 接收：ECCV 2026。
- 代码/数据：https://4d-vision-uom.github.io/

## 总结

### 核心发现总结

CL4D 把对比语言预训练首次推广到动态 4D 点云，构建了从编码器（CL4D）到 VLM（4DVLM）再到基准（DynAction4D）的完整栈，证明原生时空几何表征在动态场景理解上系统性地优于像素代理。

### 对Spatial AGI的意义

这是 Spatial AGI "表示优先"路线的关键里程碑：空间智能的突破不在于更大的语言模型，而在于让模型感知的第一性对象就是空间-时间结构本身。合成数据管线与三分类空间 QA 体系也都是可复用的基础设施。

## 深度解析：方法细节与逐模块拆解

### 架构逐层拆解

#### 输入层：4D 点云序列

- 输入形态：N 帧点云，每帧为无序点集 {(x, y, z)}，帧索引即时间维度 t。
- 与视频的本质区别：视频的"时间"藏在帧间像素差里，
  而 4D 点云的时间与几何同等地作为一阶信息存在。
- 与静态点云的本质区别：静态点云是世界的"快照"，
  4D 点云是世界的"短片"，运动轨迹是显式的数据结构。
- 点云的挑战：无序性、不规则采样、跨帧对应关系缺失（无逐点跟踪标签），
  这使得直接把 3D 编码器堆叠上 LSTM 的朴素做法效果不佳。

#### 点编码器（PE）

- 采用 PointNet 式局部-全局聚合：
  - 每帧点云划分为 k 个局部组（grouping，如 FPS + kNN）。
  - 每组 g 个点，经共享 MLP + max pooling 得到局部嵌入。
  - 输出：每帧 k 个 d1 维 token。
- 每帧额外引入一个可学习聚合 token（类似 CLS token），
  汇总帧内全局信息，作为该帧的"摘要"。
- 设计含义：帧内几何被离散成 token 序列，
  这为后续 Transformer 在时间轴上的处理提供了统一接口。

#### 时空 Transformer（V_st）

- 输入：N 帧 × k token 的三维张量（帧数、组数、通道）。
- 建模方式：在时间轴上做 self-attention，
  使每个时空 token 都能关注其他帧的对应/非对应区域。
- 关键工程细节：时序编码器用预训练 ViT 权重初始化（附录 8.5）。
  这隐含了一个有趣的假设——图像 patch 之间的注意力结构
  与时间帧之间的注意力结构存在同构性，
  2D 预训练学到的"哪些区域值得相互关注"的先验可以迁移到时间维。
- 消融表明该初始化带来可观收益，说明时空注意力并非从零学习的难题。

#### 文本编码器与对比目标

- 文本侧为标准Transformer文本编码器（CLIP 风格双塔）。
- 对齐目标为对称 InfoNCE：
  - 正样本：匹配的（4D 序列, 文本描述）对。
  - 负样本：batch 内所有错配组合。
  - 温度系数控制分布锐度。
- 与分类目标的本质区别：
  - 分类目标把 4D 表征压到固定标签空间，开放词汇能力为零。
  - 对比目标把表征放入连续语义空间，任意文本都成为潜在"类别"，
    这就是零样本检索与零样本迁移能力的来源。

### 两阶段训练策略的深层逻辑

- 为什么不端到端联训编码器+LLM？
  - 对比预训练需要大规模、低标注成本的数据（文本对即可），
    而指令微调数据昂贵且少。
  - 先用廉价信号学表征、再用昂贵信号学行为，
    是与 CLIP→LLaVA、CLIP→Flamingo 一致的成熟范式。
- 阶段一产出可独立使用：
  - 零样本 motion→text 检索：安防、体育分析、数据检索。
  - 零样本 text→motion 检索：从监控流中搜事件。
- 阶段二复用编码器：冻结或微调后接投影层与 LLM，
  视觉 token 数量由 k（而非点数）决定，控制了 LLM 上下文开销。

### 数据引擎拆解（DynAction4D）

- 管线：SMPL 参数 → Unity 动画 → 增广 → 表面采样 → 点云序列。
- 增广手段：
  - 随机体形赋值（打破 SMPL 默认体型的捷径）。
  - 随机纹理变化（避免纹理过拟合）。
  - 物体摆放与杂物合成（Cluttered 段）。
- 三段数据的设计意图：
  - HumanOnly：干净的纯动作信号，让对比学习先学到"动作语义"。
  - ObjInteractions：引入人-物交互，学习 affordance 级动态。
  - Cluttered：引入干扰物，迫使模型学会选择性注意与鲁棒性。
- 4D-VQA 段：用 Gemini 3.0 Flash 看渲染视频 + 已有文本，生成三类问题：
  - Action：高层语义（"这个人在做什么"）。
  - Body-Spatial：3D 几何关系（"左手相对桌面的位置"）。
  - Temporal：逐帧动态（"动作是先蹲后跳还是先跳后蹲"）。
- 这三类问题的划分本身就是一个空间智能能力_taxonomy_：
  语义理解 / 空间几何 / 时间动态，缺一不可。

### 实验结果解读

- 检索任务：相对此前 4D 编码器 Recall@1 提升约 16.75%，
  且是在开放词汇设置下（无闭集动作标签）。
- 泛化性实验：CL4D 在未见过的数据段/场景上保持性能，
  说明对比表征学到了动作的一般性结构而非数据集捷径。
- 4DVLM vs 视频 VLM：
  - 对比对象包括 Gemini、GPT-5（输入为同一场景的 RGB 视频）。
  - 4DVLM 以点云输入胜出，尤其在 Body-Spatial 与 Temporal 类问题上。
  - 解释：2D 视频需要从像素"隐式重建"深度与运动，
    误差在网络内部累积；4D 点云直接给出几何+时间，
    模型只需学习"理解"而非"恢复"。
- 诚实的注意点：评测集与训练数据同源（均为合成管线产物），
  与真实传感器数据的域差未被充分检验。

## 扩展思考：对 Spatial AGI 技术路线的定位

### 位置：空间智能技术栈的第 0 层

把 Spatial AGI 的技术栈抽象为五层：

1. 感知表征层（encoders：2D/3D/4D）
2. 对齐层（contrastive grounding：文本↔空间）
3. 推理层（VLM/LLM：空间问答、规划）
4. 世界模型层（预测、反事实、物理推断）
5. 行动层（VLA、机器人策略）

- CLIP/ULIP 占据第 1-2 层的 2D/3D 位置。
- CL4D 补上了 4D 位置——这在此前是空白。
- 有了第 0-1 层，上层的世界模型与 VLA 才有稳定的"地基材料"。

### 与近期工作的谱系关系

- GraFT（昨日）：用 3D 场景图增强 VLM，training-free，属"第 2-3 层增强"。
- CST-WM（昨日）：因果结构世界模型，属第 4 层，但其输入仍需感知前端。
- CL4D（今日）：补第 1 层的 4D 空位，为第 4 层世界模型供给时空表征。
- 三者拼接起来，可以看到一个正在成形的完整空间智能栈。

### 4D 表征路线的三大开放问题

1. 数据问题：
   - 真实 4D 点云采集昂贵，合成数据域差难消。
   - 可能出路：用 3DGS/NeRF 从视频重建 4D 点云作为"半真实"数据源，
     或用 world model 生成 4D 数据（自举）。
2. 规模化问题：
   - 点云 token 化后序列长度随帧数线性增长，
     长时序（分钟级）场景的注意力开销是硬约束。
   - 可能出路：层次化时空 token 压缩、记忆机制、稀疏注意力。
3. 泛化问题：
   - 人-为中心的数据能否泛化到任意物体动力学？
   - 需要引入物理引擎增广（刚体、软体、流体），
     与可微物理仿真结合可能是下一步。

### 如果由我们来做

- 数据侧：把 DynAction4D 管线推广到物体级交互
  （用 Isaac/Genesis 的物理仿真生成物体动力学 4D 点云）。
- 表征侧：在对比目标中加入时间顺序判别（防止模型忽略时序），
  以及跨视角一致性约束（同一 4D 场景不同视角应得同嵌入）。
- 下游侧：把 CL4D 嵌入作为 world model 的观测编码器，
  检验时空嵌入是否改善预测一致性——
  这是连接"感知表征"与"世界模型"两个研究脉络的关键实验。

## 附录：背景知识梳理

### 什么是"4D 理解"

- 4D = 3D 空间 + 时间。
- 4D 点云序列：对动态场景在每个时间步采集/采样一个点云，
  按时间排列形成 (N, P, 3) 的张量（N 帧、每帧 P 点）。
- 4D 理解任务谱系：
  - 动作识别/检索（本文核心）。
  - 动态场景重建（4DGS、动态 NeRF）。
  - 运动预测（轨迹预测、世界模型 rollout）。
  - 动态场景问答（本文 4DVLM）。

### 对比学习范式演化史（与本文的对照）

- CLIP（2021）：图像↔文本，4 亿对数据。
- VideoCLIP / CLIP4Clip / ActionCLIP：视频↔文本，像素域时间建模。
- PointCLIP / ULIP / OpenShape：静态点云↔文本。
- Motion Patches：骨架序列↔文本（结构化运动）。
- CL4D（2026）：原始动态点云↔文本——第一次覆盖"几何×时间×语言"三者。

每一步推广都要解决该模态特有的难题：
视频要处理帧冗余，静态点云要处理无序性，
4D 点云则同时要处理无序性、跨帧无对应、时间对齐三重难题。

### 与检索评测相关的概念

- Recall@1：检索结果第一名即正确的比例，检索任务最严格指标。
- 零样本检索：训练与检索时文本分布不重叠，
  检验的是表征空间的语义连续性而非记忆。

### SMPL 与 Humoto

- SMPL：参数化人体网格模型（体形 β + 姿态 θ），
  是人体动作数据的标准交换格式。
- HumanML3D：SMPL 动作 + 文本描述的大规模数据集（本文 HumanOnly/Cluttered 段来源）。
- Humoto：人-物交互动作数据集（本文 ObjInteractions 段来源），
  覆盖 72 类物体、735 种交互。

## 逐问题精读笔记（Q&A 复盘）

### 关于动机

- 问：为什么不用视频作为 4D 的代理？
- 答：视频像素是几何的有损投影，
  深度、遮挡、运动都在像素中纠缠，
  模型需要先"逆渲染"再"理解"，误差链长。
  点云直接是几何采样，绕过了逆渲染环节。

- 问：为什么不用骨架（skeleton）？
- 答：骨架是人类特有且需要预设关节拓扑的表征，
  无法推广到任意物体；原始点云是传感器原生输出，通用性最强。

### 关于方法

- 问：跨帧没有点级对应，时间注意力如何"知道"哪个点变成了哪个点？
- 答：不需要显式对应。时空 Transformer 通过注意力隐式学习软对应，
  这正是用 ViT 初始化有效的另一个原因——
  图像内 patch 间学到的"匹配/关联"先验可迁移为帧间软对应。

- 问：为什么分两个阶段而不是联合训练？
- 答：数据量级差异（对比数据 ~5 万序列 vs VQA 数据较少）
  与梯度冲突风险；两阶段让表征先稳定再接语言行为。

### 关于实验

- 问：战胜 GPT-5/Gemini 的结果有多大说服力？
- 答：方向性说服力大（几何-时间类问题优势明显），
  但要注明：对手输入是被降维的 RGB 视频，
  且评测域与训练分布同源。跨域真实场景检验是必要的后续工作。

- 问：16.75% 的提升相对于什么基线？
- 答：相对于此前最优的 4D/动作编码器（闭集分类或骨架对比方法），
  在文本-动作检索基准上的 Recall@1 均值改进。

## 概念术语表

- 4D 点云序列：按时间排列的多个 3D 点云帧，
  每个点带 (x, y, z) 坐标，帧索引提供时间维度。
- 对比学习：通过拉近正样本对、推远负样本对来学习表征的自监督范式。
- InfoNCE：对比学习标准损失，本质是基于 softmax 的互信息下界估计。
- 零样本（zero-shot）：不在目标任务训练数据上训练而直接执行任务的能力。
- FPS：最远点采样，点云处理的标准下采样方法，保证覆盖均匀。
- CLS token：Transformer 中用于聚合全局信息的可学习特殊 token。
- SMPL：Skinned Multi-Person Linear model，业界标准参数化人体模型。
- Sim-to-real：仿真数据训练的模型向真实世界迁移的挑战。
- Affordance：物体提供给智能体的动作可能性（可抓、可坐、可推）。
- World model：能预测环境下一状态的概率模型，具身智能的核心组件。

## 方法的潜在失败模式（批判性审视）

- 短程动作偏置：
  HumanML3D 动作多为数秒级片段，
  模型可能只学到短时姿态语义而非长程规划级动态。
- 文本噪声：
  继承自 HumanML3D 的描述质量参差，
  对比学习对噪声正样本对有一定鲁棒性但非免疫。
- 组划分敏感性：
  k、g 的选择影响帧内 token 粒度，
  过细则序列过长、过粗则丢失局部几何，存在超参悬崖。
- 时间粒度固定：
  均匀帧采样假设运动速度恒定，
  对快慢混合的动作（先缓慢接近后突然抓取）可能欠采样关键瞬间。
- 类别不平衡：
  ObjInteractions 仅 510 训练序列，
  人-物交互的表征可能被 HumanOnly 段的大数据量淹没。

## 后续工作建议（若沿此方向深入研究）

- 引入连续时间表示（如时间正弦编码或 learned time embedding），
  支持非均匀采样与变长序列。
- 在对比目标中加入时序方向判别（正放/倒放）作为辅助任务，
  显式保护时间敏感性。
- 用 3DGS 重建的真实视频生成"伪 4D 点云"做预训练数据扩充，
  缩小 sim-to-real 域差。
- 把 CL4D 嵌入接到一个 action-conditioned world model 上，
  检验语言对齐表征是否提升 rollout 的可控性——
  这是走向 Spatial AGI 闭环的关键一步。
