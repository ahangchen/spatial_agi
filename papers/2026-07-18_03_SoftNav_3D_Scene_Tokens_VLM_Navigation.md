# SoftNav: Injecting 3D Scene Tokens into VLMs for Embodied Navigation

**arXiv**: [2607.14586](https://arxiv.org/abs/2607.14586) | **Authors**: Yi Wu, Junjie An, Xiao Liu, Yiqun Zhou, Yuechen Wu, Xiaoqing Guan, Shuyang Yu, You Wang, Guang Li | **Affiliation**: Zhejiang University, Shandong University
**Published**: 2026-07-16 | **Categories**: cs.RO | **Accepted**: IROS 2026

---

## 论文概述

SoftNav 提出了一种新的导航范式：将3D场景编码器的实体级表示直接作为"软令牌"（soft tokens）注入VLM的隐藏空间，而不是通过文本序列化传递3D信息。通过控制消融实验，首次量化了文本序列化造成的信息损失（"表示差距"），并证明直接嵌入级传递显著优于文本格式。仅需约1200个训练样本和17M可训练参数，SoftNav在HM3D-OVON上达到74.2%/68.3%/66.7% SR，并零样本迁移到GOAT-Bench、SG3D和真实机器人。

## Q1: 核心算法原理

### 1.1 核心思想和动机

当前导航系统将3D信息传递给VLM的方式存在根本缺陷——通过文本序列化（如坐标字符串、场景图描述）传递连续3D特征会造成信息损失。作者通过控制消融实验首次量化了这个"表示差距"（representation gap）：

**核心发现**：保持3D编码器和VLM不变，仅将文本接口替换为直接软令牌注入，就能获得统计显著的性能提升——特别是在路径效率(SPL)上。

这表明当前VLM导航系统的瓶颈不在模型容量，而在信息接口设计。

### 1.2 主要技术方法

#### (a) 系统架构

SoftNav包含三个主要组件：

**1. 视觉流（Visual Stream）**
- 使用冻结的DINOv3提取每帧的patch特征
- 通过CompressionHead + PatchMerger压缩为N_v=15个token
- 滑动窗口保留最近K=16帧 → 视觉记忆 M_t ∈ R^{240×2048}

**2. 3D场景流（3D Scene Stream）**
- 使用冻结的PQ3D编码器处理RGB-D观测
- PQ3D执行增量3D实例分割、维护持久目标库、检测探索前沿
- 通过跨模态注意力产生768维实体级嵌入
- 每个嵌入编码一个语义不同的物体或前沿

**3. 软令牌注入（Soft-Token Injection）**
- 可训练的MLP投影器：768维 → 2048维（VLM隐藏空间）
- 两层MLP + GELU + LayerNorm
- 中间维度1408（linspace(768, 2048, 3)的中点）
- 散射注入：在文本模板中的占位符位置替换为投影后的软令牌

**4. VLM主干**
- Qwen2.5-VL-3B（冻结）
- 联合处理视觉记忆token、软令牌和文本导航指令
- 自回归生成目标坐标 → 映射到最近前沿航点

#### (b) 训练策略

- **冻结组件**：DINOv3、PQ3D、Qwen2.5-VL-3B全部冻结
- **可训练组件**：MLP投影器（~4M）+ LoRA适配器（~13M）= 总计~17M参数
- **训练数据**：仅~1,200个监督样本（从现有导航系统蒸馏）
- **训练效率**：极致参数效率，因为大部分组件已预训练好

#### (c) PQ3D 3D场景编码器

PQ3D是一个3D视觉-语言模型，适配于embodied导航：
- 从流式RGB-D观测中进行增量3D实例分割
- 维护持久物体库（跨时间累积观测）
- 从占据图中检测探索前沿
- 通过跨模态注意力产生768维嵌入：
  - 几何信息（位置、大小、形状）
  - 语义信息（物体类别、属性）
  - 空间关系信息（物体间的拓扑关系）

### 1.3 算法流程

1. **观测采集**：RGB-D相机流 → 原始观测
2. **视觉编码**：DINOv3 → patch特征 → PatchMerger → 15个视觉token/帧
3. **3D场景编码**：PQ3D → 物体和前沿的768维查询嵌入
4. **软令牌投影**：MLP投影器 → 2048维软令牌
5. **散射注入**：在文本模板中替换占位符 → 完整输入序列
6. **VLM推理**：Qwen2.5-VL → 选择前沿航点
7. **执行导航**：移动到选定航点 → 重复

### 1.4 输入输出

- **输入**：RGB-D图像流 + 自然语言导航指令（如"Find the toilet"）
- **输出**：选定的前沿航点坐标（可执行导航动作）

## Q2: 与Spatial AGI的关系

### 2.1 如何理解和表示空间

SoftNav的空间理解体现在多个层次：

**1. 几何空间表示**：
- PQ3D编码器维护3D占据图 → 理解空间布局
- 前沿检测 → 理解已知/未知空间边界
- 体素几何 → 理解物体3D形状

**2. 语义空间表示**：
- 每个实体级嵌入包含语义类别信息
- 物体-空间关系编码在768维嵌入中
- 语言-空间对齐通过PQ3D的跨模态注意力实现

**3. 拓扑空间表示**：
- 物体和前沿作为空间图中的节点
- 空间关系通过嵌入的相对位置隐式编码
- 视觉记忆提供时序空间连续性

### 2.2 如何处理空间关系

**核心创新——绕过文本序列化**：

传统方法的空间关系处理：
```
3D特征 → 坐标/场景图 → 文本描述 → VLM理解
```
问题：浮点坐标→字符串的转换丢失精度，场景图→文本丢失结构

SoftNav的空间关系处理：
```
3D特征 → MLP投影 → 软令牌直接注入VLM隐藏空间
```
优势：保留完整的几何、语义、关系信息

### 2.3 对Spatial AGI的启发

1. **Representation Gap概念**：量化信息传递损失的思想可推广到Spatial AGI的所有模块间接口
2. **软令牌作为通用桥接**：不仅是3D→VLM，任何连续空间表示→离散语言模型的场景都可用
3. **极致参数效率**：17M参数+1200样本即可达到SOTA，证明预训练表示的力量
4. **零样本迁移**：同一策略零样本迁移到多个任务（GOAT-Bench, SG3D, 真实机器人）

### 2.4 可应用的Spatial AGI场景

- **家庭服务机器人**：开放词汇目标导航
- **仓储物流**：场景图引导的目标检索
- **多楼层导航**：3D空间理解支持垂直导航
- **协作探索**：多个agent共享3D场景token

## Q3: 创新点和局限性

### 3.1 主要创新点

1. **首次量化表示差距**：通过严格控制实验，证明文本序列化造成显著的性能损失
2. **首个3D实体级软令牌注入**：将3D场景编码器的输出直接注入VLM隐藏空间
3. **极致参数效率**：仅17M可训练参数 + 1200样本
4. **广泛零样本迁移**：单一策略迁移到多任务和真实世界
5. **IROS 2026接收**：经过严格同行评审

### 3.2 主要局限

1. **依赖RGB-D输入**：PQ3D需要深度信息，纯RGB场景不适用
2. **PQ3D依赖**：整个3D理解依赖于PQ3D编码器的质量
3. **VLM计算开销**：Qwen2.5-VL-3B推理需要一定计算资源
4. **静态场景假设**：动态环境（行人、移动物体）的影响未探讨
5. **单层建筑假设**：多楼层、复杂3D垂直空间的导航能力未验证

### 3.3 与相关工作的比较

| 方法 | 3D信息传递 | 训练参数 | 样本数 | 多任务迁移 |
|------|-----------|---------|--------|-----------|
| **SoftNav** | 软令牌（嵌入级） | ~17M | ~1,200 | ✅ (3任务+真实) |
| MTU3D | 直接嵌入(非VLM) | 全量 | 大规模 | ❌ |
| NavGPT | 文本坐标 | 0 | 0 | ❌ |
| SayNav | 场景图文本 | 全量 | 中等 | ❌ |
| NaVid | 2D视频 | 全量 | 大规模 | 部分 |

### 3.4 优势

- 信息无损传递：软令牌保留了完整的3D表示
- 训练效率极高：大部分组件冻结，仅训练桥接层
- 多任务泛化：单一策略多任务迁移
- 实证充分：严格的消融实验+多基准验证

### 3.5 劣势

- 硬件要求：需要RGB-D传感器
- 3D编码器依赖：PQ3D的局限性直接影响系统
- 实时性：PQ3D的增量处理可能有延迟
- 室外场景：PQ3D主要在室内训练

## 详细技术分析

### 消融实验核心发现

作者进行了精心设计的消融实验来量化表示差距：

1. **保持不变**：3D编码器(PQ3D) + VLM主干
2. **变量**：信息传递接口
   - 文本坐标："object at (x, y, z)"
   - 富文本："large red chair at the corner near the window"
   - 场景图文本：序列化的空间关系图
   - 软令牌：直接嵌入级传递（SoftNav方法）
3. **结果**：软令牌在SR和SPL上均显著优于所有文本格式
4. **结论**：表示差距是当前VLM导航系统的主要瓶颈

### MLP投影器设计选择

为什么选择简单MLP而非cross-attention：
1. 训练数据仅1200样本 → 高参数cross-attention易过拟合
2. PQ3D嵌入已语义丰富 → 仅需几何(维度+分布)对齐
3. LLaVA已证明轻量MLP在投影器角色中足够

### 散射注入（Scatter Injection）

1. 在文本模板中插入特殊占位符token
2. 在embedding层面用投影后的软令牌替换占位符
3. 保持VLM学习的位置编码对齐
4. 前沿token排在物体token之前（排序启发式）

### 零样本迁移机制

SoftNav为什么能零样本迁移：
1. **3D表示通用性**：PQ3D的嵌入不依赖于特定任务
2. **VLM泛化能力**：Qwen2.5-VL的预训练知识可泛化
3. **前沿导航通用性**：前沿选择是通用的导航策略
4. **桥接层通用性**：MLP投影器学到的对齐不依赖特定场景

## 个人思考

1. **Representation Gap的普遍性**：SoftNav揭示的表示差距问题在整个Spatial AGI领域普遍存在。任何需要从连续空间表示到离散语言模型的场景都可能面临这个问题。这启发了一个新的设计原则：**当连接3D感知模块和语言推理模块时，优先使用嵌入级连接而非文本接口**。

2. **与Reasmory的关系**：Reasmory（已分析过的论文）将3D重建作为VLM的显式记忆，而SoftNav将3D场景token作为隐式注入。两种方法代表了3D信息进入VLM的两种范式——显式记忆vs隐式嵌入。

3. **与SpatialForge的关系**：SpatialForge从开放世界2D图像引导3D感知空间推理，而SoftNav从RGB-D构建3D表示注入VLM。两者互补——SpatialForge适合无深度传感器场景，SoftNav在有深度传感器时更精确。

4. **工程实用价值**：SoftNav的17M参数+1200样本训练使其具有极高的工程实用价值。任何团队都可以在现有VLM基础上集成3D导航能力。

5. **未来方向**：
   - 移除深度依赖：用单目深度估计替代RGB-D
   - 动态场景：扩展PQ3D到动态环境
   - 多层建筑：增加垂直空间理解
   - 多agent协作：共享3D场景token

6. **对Spatial AGI系统设计的启示**：SoftNav的成功说明，Spatial AGI系统的关键不是让单个模型做所有事，而是**设计好模块间的高效接口**。3D编码器、视觉记忆、语言推理各自专业化，通过软令牌实现无损信息传递。
