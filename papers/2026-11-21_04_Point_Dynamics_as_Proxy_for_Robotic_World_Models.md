## 论文概述（摘要翻译）

机器人世界模型从当前观测和机器人动作序列预测未来视频帧。尽管近期模型能较好地跟随给定动作，被操纵的物体却常常坍缩（形变崩坏）或与动作不一致地运动。作者将此归因于条件化方式：动作或机器人的渲染只规定了机器人去哪里，却没有规定场景如何响应，使得单个视频模型必须在渲染外观的同时隐式推断交互动力学。为此，论文将动力学预测与视觉渲染分离，以 3D 点动力学作为两者之间的代理（proxy）。具体地：把第一帧提升为 3D 点，用学习到的点动力学模型模拟它们如何响应机器人运动，再把模拟后的点渲染回像素对齐的视频，任何视频模型都能读取。在 DROID 数据集上的受控实验中，使用两种不同架构的视频渲染器，点动力学代理将物体运动误差分别降低 8.6% 和 6.2%（图像质量不降），在真实双臂机器人上降低 8.1%。此外，视频跟随模拟：动力学越准，物体运动越准，编辑点可以引导视频。这表明动力学建模的进步可以转化为更忠实的机器人世界模型。

## 研究背景与动机

### 机器人世界模型的两个必备性质

机器人世界模型作为真实世界的 learned surrogate，用于策略评估、动作规划和训练数据合成。这要求预测的视频满足：

1. **动作跟随（action following）**：机器人必须执行给定动作；
2. **交互保真（interaction fidelity）**：与机器人接触的物体必须像现实中一样响应——被携带、推动、拖拽、形变、释放，同时保持形状与身份。

### 失败现状与归因

- **早期方案**：动作编码为数值向量（末端执行器位姿/关节角），视频模型既要从像素推断机器人外观又要推断场景响应——两头都难；
- **近期方案**：把机器人渲染成像素对齐条件（mask、URDF 渲染、表面轨迹），动作跟随大幅可靠化；
- **但交互保真改善甚微**：物体在接触时坍缩（面包片与拖它的铲子分离）、响应与动作不一致（松开的杯子跟着张开的夹爪上升）。

论文的归因非常锋利：**这是条件化的问题**。动作（无论数值还是渲染）只说"机器人去哪"，不说"场景怎么响应"，单个视频模型被迫在渲染外观的同时隐式推断交互动力学——认知负荷过载，物理必然出错。

### 解法：分离动力学与渲染

灵感来自 code world models 与物理落地视频生成：用显式机制演化世界状态 → 渲染成粗代理视频 → 让视频模型合成最终帧。

对机器人操作而言，核心设计选择是**代理（proxy）的形态**，必须满足：

1. 表示任意物体（含可形变、铰接）；
2. 可从单一真实观测获得；
3. 其动力学可在机器人动作下被预测。

- 物理仿真器：需要物理参数、物体资产、特定求解器——真实场景难以获得；
- 手写规则：表达不了推动、拖拽、形变；
- **3D 点**：无需分割或模型即可表示任意物体；可从单个 RGB-D 帧提升；机器人与场景在同一空间；动力学可直接从真实机器人交互数据学习。✓

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

**分析**:

1. **核心思想和动机**

   一句话：把"场景会怎么动"从视频模型的隐式负担中拆出来，交给一个专门学习的点动力学模拟器；视频模型只负责"动起来的世界长什么样"。模拟器决定发生什么（what happens），渲染器决定看起来怎样（how it looks），两者独立可替换。

2. **主要技术方法**

   **(a) Simulate-then-render 形式化（3.1节）**

   世界模型分解为四步：

   - Q_{0:T} = FK(a_{0:T})：前向运动学把动作转为机器人表面点；
   - P_{1:T} = S(P_0, Q_{0:T})：模拟器预测从第一帧提升的场景点如何响应机器人运动；
   - c_{0:T} = Π(o_0, P_{0:T}, Q_{0:T})：把 3D 点渲染成像素对齐代理视频；
   - o_{1:T} ~ R(o_0, c_{0:T})：渲染器（视频模型）把代理变成真实帧。

   在这个分解中动作只通过运动学进入，因此**唯一需要预测的是场景的响应**。现有接口都只用了这条链的一部分：数值动作模型只读末端位姿；机器人渲染模型只收 Q 的渲染；深度条件模型相当于把 S 固定为恒等（场景点不动）。

   **(b) 3D 状态与模拟器（3.2节）**

   - 每相机深度图反投影到机器人基坐标系（去掉 t=0 时被机器人遮挡的像素）；
   - 仿真成本随点数增长、渲染质量随密度增长 → 模拟器收稀疏体素化点 P_0（跨相机合并），代理用稠密点（每相机每像素一点+颜色）；
   - 机器人点：URDF 表面按面积比例采样一次，每帧由前向运动学摆放；
   - 模拟器接口：预测每个场景点每步的位移 Δp_{j,t}，任何此接口的模型皆可替换；
   - 实例化：PointWorld-large——场景级点动力学模型，DROID 训练，读夹爪点；真实机器人上用自己的数据微调；
   - PointWorld 细节：点按 1.5cm 体素化，DINOv3 特征描述，预测 10 步位移（每两视频帧一步），时间上线性插值；
   - 训练数据：标签点流 + 视频点轨迹估计升 3D 的伪标签。

   **(c) 点动力学代理（3.3节）**

   代理让任何视频模型通过自己的 VAE 读取模拟结果。三路 z-buffer 点溅射渲染视频：

   - **机器人渲染 c^rob**：机器人外观位置；
   - **Warp c^warp**：每个稠密点取 t=0 时 k=8 个最近模拟点的位移，逆距离加权（r=6cm 内，ε=1mm），无近邻点保持静止。移动的稠密点与机器人点共享一个 z-buffer——手臂、被移动物体、背景正确互相遮挡；无点到达的像素保持黑色，标记需要生成新内容的区域；
   - **Track c^trk**：固定子集 4000 场景点 + 1500 机器人点，不插值，按初始 3D 位置（机器人基系）着色。点的颜色随移动保持——渲染器可跨帧跨视角跟踪每个点，物体因运动方式不同而与背景分离，无需分割；
   - warp 携带外观但继承物体边界处的插值误差；tracks 直接显示模拟点但稀疏——4.2节对比两条路径；
   - 所有相机从同一模拟点渲染 → 多视角代理由构造保证一致。

   **(d) 渲染器（3.4节）**

   - 预训练视频模型：Wan2.2-TI2V-5B（DiT）或 Ctrl-World（UNet，SVD 初始化）；
   - 输入：各相机第一帧 + 三路代理视频，无文本（Ctrl-World 保留原生数值动作输入）；
   - 注入方式：每个代理视频经渲染器冻结 VAE 编码，与噪声 latent 沿通道拼接，由加宽的第一层读取（新权重零初始化——从预训练模型平滑启动）；
   - 每个 token 携带自己时空位置的代理信息，骨干注意力关联空间/时间/视角的 token；
   - 分工：干净首帧供外观，warp 指明去向，tracks 指明点运动；渲染器填充黑色区域、合成真实手臂、光照与接触；
   - 训练目标：渲染器基础去噪目标；训练代理与测试代理同源——都来自模拟器（含其误差），而非标签点流——训练/推理分布一致。

3. **算法流程和关键步骤**

   推理：

   1) 第一帧 RGB-D → 反投影提升为 3D 场景点（稀疏体素给模拟器、稠密带色给代理）；
   2) 动作序列 → FK → 每帧机器人表面点；
   3) PointWorld-large 读场景点+夹爪点 → 预测每点位移 → 线性时间插值；
   4) 三路 z-buffer 溅射渲染 per 相机：rob / warp / track 代理视频；
   5) 视频模型以首帧+三代理为条件去噪生成未来帧。

   训练：

   1) 模拟器：PointWorld 用 DROID 标签点流+伪标签预训练（本文直接复用/微调）；
   2) 渲染器：326K clips（41.5K DROID episodes），代理由模拟器生成（误差包含在内），零初始化新层微调。

4. **输入输出**

   - 输入：第一帧多相机 RGB-D、机器人关节动作序列（含夹爪）；
   - 输出：未来视频帧（多相机）；
   - 中间产物：3D 场景点轨迹（显式、可编辑、可审计）+ 三路像素对齐代理视频。

## 相关工作定位

### 机器人操作世界模型

- 大模型化趋势：基于大型视频生成模型构建；
- 条件化光谱：数值动作（推断负担最重）→ 机器人渲染（mask/mesh/骨架/point map/track/flow，解决动作跟随）→ 少数模型给场景信号（仿真深度、重建 occupancy 作为给定；next-frame scene flow、低分辨率预览作为联合预测）；
- 主流仍把场景响应留在视频模型内部：反事实/离专家动作后训练、RL 自rollout、联合生成深度/point map/flow、运动几何辅助损失（PhysisForcing 等）；
- 本文的关键对照：同一预算下，辅助损失（point forcing，3.4% 提升）远不如显式输入（8.6% 提升）。

### Simulate-then-render

- Code world models / 游戏生成器：程序演化状态+视频模型上色；
- 物理落地生成：物理仿真器/学习物理模型/演化 4D 场景状态，其渲染、流、轨迹作为视频模型的运动相机控制信号；
- 两阶段皆可学习：语言模型骨干演化 latent 世界状态 + 视频扩散解码；
- 三个并行工作：DeXplicit（手-物交互，需物体标签与规范形状）、3D World Simulator（粒子-体素动力学+高斯渲染器，每场景多相机采集拟合）、VPTwin（VLM 建数字 twin）；
- 本文差异化：显式 3D 点状态中间量，由单独训练、真实机器人数据学习的点模型从动作预测，无需物体模型、物理参数、每场景采集。

### 学习式 3D 动力学

- 粒子/图/高斯动力学模型：多拟合单物体/单任务；物体中心变体假设分割好的刚体/铰接部件；
- 场景级点模型：无这些假设，可扩展到 in-the-wild 机器人数据；
- 生成式粒子模型：大规模仿真语料训练；
- 这些模型预测演化的 3D 状态而非视频——正好可以作为本文的模拟器（代理只需要每点位移）；本文选 PointWorld（公开、真实数据训练），并在测试时变换其输出验证因果性。

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

1. **如何理解和表示空间**

   论文选择 3D 点作为世界状态的中间表示，这一选择本身是对空间表征需求的完整回答：

   - **普遍性**：点可以表示刚体、可形变物、铰接物，无需分割、无需物体模型——真实空间不可能预先建模一切；
   - **可观测性**：单帧 RGB-D 即可提升——空间状态必须可以从真实感知初始化；
   - **可预测性**：点的动力学可以从真实交互数据学习——空间状态必须支持前向推演；
   - **统一性**：机器人与场景在同一坐标系——智能体与环境的表示必须共域。

   这四条几乎是 Spatial AGI 世界状态表示的设计需求清单。点作为"最小假设的显式空间状态"，与体素（重）、mesh（需模型）、高斯（渲染优）相比，是动力学推演场景下的务实最优。

2. **如何处理空间关系**

   - warp 的逆距离加权插值把稀疏模拟点的运动传播到稠密空间——空间关系（近邻性）成为动力学传播的介质；
   - 共享 z-buffer 的多物体渲染使遮挡关系（空间的前后结构）被正确维护；
   - track 着色方案用"初始 3D 位置"作为点的身份标识，使跨帧跨视角的空间对应关系可视化——物体的空间同一性通过运动差异自然涌现，无需分割。

3. **对Spatial AGI的启发**

   - **认知分工原则**：空间智能系统应把"预测动力学"与"渲染外观"拆给专门模块——单一模型包办一切时，物理必然让位于外观。这与 Spatial AGI 的模块化架构方向一致；
   - **代理（proxy）作为模块间通用语言**：像素对齐的代理视频让任意视频模型零改动接入——定义好的中间表示接口比端到端大模型更可组合、可替换、可调试；
   - **"模拟决定什么发生，渲染决定长什么样"**：这一分工可直接推广——Spatial AGI 的想象系统中，规划器决定什么发生，渲染器决定长什么样，评估器决定好不好；
   - **训练/推理条件同源**：训练代理含模拟器误差（而非干净标签流），渲染器学到对模拟误差的鲁棒性——Spatial AGI 各模块接口都应遵循"训练即部署分布"原则；
   - **可干预性**：编辑模拟点即可引导视频——显式中间状态给了人类与上层模块干预想象过程的抓手，这是纯 latent 世界模型做不到的。

4. **可以应用的Spatial AGI场景**

   - 机器人操作的策略评估与数据合成（论文原生场景）；
   - 操作预演与规划：在模拟点上试行动作序列，错误动作在点层面就被否决；
   - 可编辑的世界想象：人类或规划器拖动点定义期望结果，渲染器补全视频（目标条件生成）；
   - 遥操作/数字孪生：真实场景单帧扫描 + 点动力学 = 可交互的轻量孪生；
   - 具身数据的反事实增广：改动模拟点的运动即可合成"如果物体在那边会怎样"的训练数据。

### Q3: 创新点和局限性

**问题**: 这个方法的主要创新点和局限性是什么？

**分析**:

1. **主要创新点**

   - **诊断性归因**：把机器人世界模型的交互失败归因到"条件化不含场景响应信息"这一精确位置，并通过四档条件递进（数值动作→机器人渲染→+深度→点动力学代理）的控制变量实验验证归因；
   - **3D 点动力学作为代理**：满足"任意物体+单帧可获取+动力学可学习"三约束的中间表示选择，兼具普遍性与务实性；
   - **三路代理设计**（rob/warp/track）：外观通道、运动插值通道、身份追踪通道各司其职，共享 z-buffer 保证多视角一致性；
   - **训练-推理分布一致**：训练代理由模拟器生成（含误差），渲染器学会容忍模拟误差——工程上反直觉但正确的选择；
   - **"视频跟随模拟"的因果验证**：从静态点到规则到学习模拟器的质量梯度 → 物体运动误差单调下降；编辑模拟点 → 视频被引导。证明了代理的信息通路真实生效；
   - **输入 vs 辅助损失的定量比较**：同预算下显式输入（8.6%）显著优于辅助损失（point forcing，3.4%）——为"显式中间表示 vs 隐式正则"的架构之争提供了关键证据。

2. **主要局限性**

   - **动力学天花板 = PointWorld 的天花板**：模拟器误差直接进入代理；点动力学对接触丰富、流体、绳缆等场景仍不准；
   - **单帧提升的盲区**：第一帧看不见的区域（遮挡背面、抽屉内部）没有点，模拟无从谈起——渲染器只能自由发挥；
   - **warp 的边界误差**：逆距离插值在物体边界混合不同刚体的运动，形变/分离场景（面包片与铲子分离正是失败案例）可能引入伪影；
   - **代理带宽开销**：三路视频条件显著增加渲染器输入通道与计算量；
   - **刚性点假设**：点本身无体积无物理属性，碰撞、摩擦、形变全部由学习到的动力学隐式承担——离真正的物理引擎还有距离；
   - **动作空间限制**：FK 只支持机器人本体动作，环境动作（人手干预、掉落的外物）无法进入条件。

3. **与其他相关工作的对比**

   - vs **PhysisForcing 等辅助损失路线**：显式输入提升约为辅助损失的 2.5 倍——架构级证据支持"显式中间表示"路线；
   - vs **DeXplicit**：需要物体标签与规范形状；本文无需任何物体模型；
   - vs **3D World Simulator**：需要每场景多相机采集拟合；本文单帧提升、跨场景泛化；
   - vs **VPTwin**：依赖 VLM 每任务建数字 twin；本文用统一训练的点动力学模型；
   - vs **纯生成式 4D 世界模型（Aether 等）**：它们联合生成外观与几何，但无"先模拟后渲染"的因果分离，交互物理仍是隐式的。

## 核心技术发现

1. **交互保真的瓶颈在条件化信息量，不在模型容量**：四档条件递进实验干净地证明了这一点；
2. **显式输入 >> 辅助损失**：同数据同预算下 8.6% vs 3.4%——显式中间表示的架构价值获得定量支持；
3. **视频忠实跟随模拟质量**：模拟器越好视频越准、编辑点即可引导视频——代理通路是因果有效的；
4. **代理设计三原则**：表示任意物体、单帧可获取、动力学可学习——3D 点同时满足；
5. **训练代理应含上游误差**：让下游学会容忍上游不完美，比用干净标签更符合部署分布。

## 与Spatial AGI的关系

### 直接贡献

提供了机器人世界模型的"模拟-渲染"分解架构与点动力学代理标准件——Spatial AGI 具身想象模块的直接候选实现。

### 技术启发

- 认知分工：动力学预测与外观渲染显式分离，各自独立进化；
- 代理即接口：像素对齐代理视频作为模块间通用语言，任意视频模型可插拔；
- 显式状态即干预点：可编辑的 3D 中间状态是规划、人类介入、目标条件生成的抓手。

### 应用场景

操作策略评估、数据合成、操作预演规划、可编辑世界想象、轻量数字孪生、反事实数据增广。

## 个人思考

### 最令人兴奋的发现

最兴奋的是那个对照数字：**显式输入 8.6% vs 辅助损失 3.4%**。这终结了一场悬而未决的架构辩论——"给模型更多监督信号"（辅助损失）和"给模型更多显式信息"（输入代理）看似都是加物理，效果却差 2.5 倍。直觉的解释是：辅助损失只调整参数的隐式倾向，输入代理则直接规定了每个时空位置的场景状态，模型只需补全外观。对 Spatial AGI 的启示：**当你想让模型懂物理，别只加 loss，把物理算出来喂给它**。

"编辑点即可引导视频"是另一个重要信号：显式中间状态让想象过程变得可编程。未来 Spatial AGI 的想象系统可能就是"规划器写点轨迹 + 渲染器拍电影"的流水线——比在 latent 空间里摸索可解释、可控得多。

### 潜在局限

整条链的质量上限被 PointWorld 钉住：它对接触动力学的预测仍是统计学习的，遇到训练分布外的交互（比如流体倾倒）会错，而渲染器会忠实地把错误画出来——"视频跟随模拟"是双刃剑。另外单帧提升是硬约束：抽屉里的东西、物体背面，从一开始就不在点云里，模拟和渲染对它们都是盲猜。

更远看，"先模拟后渲染"范式的终极形态可能是：学习动力学模型逐渐被神经物理引擎替代（可微物理+真实数据校准），渲染器逐渐被可重光照的 3D 表征（3DGS）替代——两端夹击之下，今天这个系统可能只是通往"神经物理仿真器"的中间形态。但作为当前数据条件下的最优工程解，它的价值是实的。

### 与昨日研究的关联

与今日论文02（Plan4D）形成镜像：Plan4D 把动力学（场景流）作为生成路径内部的输出通道，本文把动力学作为生成路径外部的输入代理——"动力学进生成器" vs "动力学进条件"。两篇加上论文03（证据优先）共同宣告：2026年末的世界模型共识正在成形——**动力学必须显式化，位置可以不同，但不能缺席**。此前关注的 Kinema4D、PointWorld、PhysisForcing 等工作铺垫的"显式动力学"路线，在本篇获得了目前最强的定量背书。

## 关键数据

- **训练数据**：326K clips（41.5K DROID episodes）；测试 1,515 held-out clips（900 episodes）；
- **渲染器**：Wan2.2-TI2V-5B（DiT）、Ctrl-World（UNet/SVD）两种架构；
- **条件递进对照**（DROID 上物体运动误差）：数值动作 → 机器人渲染 → 机器人渲染+深度 → 点动力学代理；
- **核心指标**：代理 vs 机器人渲染——DROID 上误差降 8.6%（Wan2.2）与 6.2%（Ctrl-World），图像质量不降；真实双臂机器人上降 8.1%；
- **模拟器**：PointWorld-large，1.5cm 体素 + DINOv3 特征，预测 10 步位移（每两视频帧一步）线性插值；
- **代理规格**：warp k=8 近邻、r=6cm；track 4000 场景点 + 1500 机器人点；
- **对照**：point forcing 辅助损失降 3.4% vs 代理输入降 8.6%；
- **因果验证**：静态点→手写规则→学习模拟器的质量梯度与视频质量单调相关；点编辑可引导视频。

## 总结

### 核心发现总结

机器人世界模型的交互失败源于条件化缺少场景响应信息；以 3D 点动力学为显式代理，"先模拟后渲染"的分解架构在两种渲染器与真实机器人上稳定降低物体运动误差，且视频忠实跟随模拟质量——显式动力学输入的架构价值获得严格的控制变量实验支持。

### 对Spatial AGI的意义

- 确立"模拟器决定发生什么、渲染器决定长什么样"的认知分工架构；
- 3D 点作为"最小假设显式空间状态"的表示选择范本；
- 定量证据支持：要物理，显式输入优于隐式损失——Spatial AGI 架构设计的决策依据。

- 机器人世界模型用途：策略评估、动作规划、训练数据合成——是真实世界的 learned surrogate；

  - 数值动作（末端位姿/关节角）：视频模型从像素同时推断机器人外观与场景响应；

- 解法谱系：code world models（程序演化显式状态→粗代理视频→视频模型合成）与物理落地生成（仿真物理）；
- 代理的三约束：表示任意物体（含形变/铰接）、单帧真实观测可得、动力学可在动作下预测；
- 否决物理仿真器（需参数/资产/求解器）与手写规则（表达不了推拖形变）；
- 3D 点全过：无分割无模型、单帧 RGB-D 可提升、机器人场景同空间、动力学可从真实交互学；
- 实验设计：DROID 受控设定 + 两种架构渲染器 + 四档条件递进 + 物体运动误差（用生成与真实视频中跟踪的物体点计算，而非被背景主导的图像指标）+ 真实双臂复现；
- 三大结果：保真提升（8.6%/6.2%/8.1%，集中于推拖形变物体）、视频跟随模拟（模拟器质量梯度→误差单调降；点编辑→视频被引导）、输入优于辅助损失（8.6% vs 3.4%）。

### A.3 Method 精读：四步分解（3.1节）

- 公式(1)：Q=FK(a) → P_{1:T}=S(P_0,Q) → c=Π(o_0,P,Q) → o_{1:T}~R(o_0,c)；

### A.4 Method 精读：3D 状态与模拟器（3.2节）

- 深度反投影到机器人基系，剔除 t=0 机器人遮挡像素；
- 稀疏体素点（给模拟器，控制仿真成本）vs 稠密每像素点（给代理，保证渲染质量）的双轨设计；
- 机器人点：URDF 表面积比例采样，FK 逐帧摆放；

### A.5 Method 精读：代理（3.3节）

- 三路 z-buffer 点溅射 per 相机：c^rob（机器人）、c^warp（运动插值）、c^trk（点追踪）；
- warp 公式(2)：Δp̄_{i,t} = Σ w_ij·Δp_{j,t} / Σ w_ij，w_ij = 1[d_ij<r]/(d_ij+ε)；k=8、r=6cm、ε=1mm；r 内无近邻→静止；
- 稠密点与机器人点共享 z-buffer：手臂/物体/背景正确互相遮挡；无点到达像素=黑色=需生成新内容区域的显式标记；
- track：4000 场景点+1500 机器人点，初始 3D 位置着色，颜色随移动保持→跨帧跨视角可追踪，物体因运动差异与背景分离（无需分割）；
- warp vs track 的互补：warp 带外观但继承边界插值误差；track 直接显示模拟点但稀疏；
- 多相机代理同源于同一模拟点→一致性由构造保证。

### A.6 Method 精读：渲染器（3.4节）

- 基座：Wan2.2-TI2V-5B（DiT）或 Ctrl-World（UNet，SVD 初始化）；输入=各相机首帧+三代理视频，无文本；Ctrl-World 保留原生数值动作；
- 注入：代理经冻结 VAE 编码、与噪声 latent 通道拼接、加宽首层读取、新权重零初始化；
- token 语义：每个 token 携带自己时空位置的代理，骨干注意力关联时空视角；
- 分工重申：首帧供外观、warp 指去向、track 指运动；渲染器填黑区、合成真实手臂/光照/接触；
- 公式(3)：f_θ([z_τ; E(c^rob); E(c^warp); E(c^trk)], τ, E(o_0))；
- 训练目标=渲染器基础去噪；训练代理来自模拟器（含误差）而非标签点流——训练即部署分布。

### A.7 Experiments 精读

- 三个受控问题：保真是否提升（4.2）、视频是否跟随模拟（4.3）、输入 vs 辅助损失（4.4）；+真实机器人复现（4.5）；

  - point forcing 辅助损失 3.4% vs 代理输入 8.6%（同数据同预算）。

## 附录B：架构要素逐项分析

### B.1 为什么点是"最小假设"的空间状态？

- 对比其他候选：
  - Mesh/CAD：需要物体模型——真实场景不预知；
  - 体素：规则网格、内存重、分辨率-内存矛盾；
  - 高斯：渲染优但动力学优化复杂、需要每场景拟合；
  - Latent 特征：不可显式编辑、不可跨模型传递；
  - 点：任意物体、单帧可提升、动力学可学习、显式可编辑——四项全过；
- 本质：点是"只假设几何、不假设结构"的最弱表示，把所有结构信息留给动力学模型学习。

### B.2 稀疏-稠密双轨的工程权衡

- 模拟器收稀疏体素点：仿真成本 ∝ 点数，1.5cm 体素在精度与速度间取衡；
- 代理用稠密每像素点：渲染质量 ∝ 密度，warp 插值把稀疏模拟传播到稠密；
- 误差引入点：插值在物体边界混合异质运动——warp 边界伪影的根源；
- track 通道作为"无插值"的补充通道，让渲染器直接看到原始模拟点。

### B.3 零初始化新层的熟悉模式

- 与 ScaleWorld（论文01）的条件注入完全同款：冻结 VAE 编码 + 通道拼接 + 加宽首层 + 零初始化新权重；
- 已成 2026 年视频模型条件注入的社区标准做法：训练从预训练行为平滑启动；
- 对 Spatial AGI 工程的意义：代理类条件接入已形成成熟 recipe，新系统可直接复用。

### B.4 "训练代理含误差"的深层合理性

- 若训练用干净标签点流、推理用含误差模拟点 → 分布迁移，渲染器对模拟误差过度敏感；
- 训练即含误差 → 渲染器学会"信任代理的整体结构、容忍局部噪声"——一种学出来的鲁棒滤波；
- 这体现了模拟器-渲染器系统的联合视角：渲染器实际是"模拟结果的美化器+误差校正器"。

## 附录C：延伸讨论

### C.1 从 proxy 到神经物理引擎的路线图

- 当前：PointWorld 式统计学习点动力学——分布内准、分布外崩；
- 中期：可微物理引擎 + 真实数据校准（参数在线估计，呼应论文03 的规则推断）——物理正确+数据适配；
- 远期：统一神经物理基础模型——跨物体类别泛化的接触/形变/流体动力学；
- 本文的贡献是证明了"无论模拟器好坏，显式代理架构都受益"——模拟器的每一分进步都会经由代理传导到视频。

### C.2 与闭环控制的结合

- 显式点状态天然支持 MPC：在点上滚动预测候选动作序列的后果，选代价最低者执行；
- 相比在视频 latent 空间做规划（不可解释、不可编辑），点空间规划可审计、可插入约束；
- 预期形态：感知（RGB-D→点）→ 模拟（点动力学）→ 规划（点空间MPC）→ 渲染（想象预览）→ 执行。

### C.3 单帧提升的根本限制与补救

- 遮挡区域无点：可用多帧融合、或让渲染器的首帧幻觉先补全再提升（自举）；
- 物体内部（抽屉内容）：只能靠先验——这是所有单帧方法的共同边界；
- 主动感知才是根治：机器人主动移动视角/打开容器，把看不见变成看见——再次呼应主动校准思想。

### C.4 点编辑作为人机交互接口

- 拖动点=指定期望结果→渲染器合成视频=目标条件世界生成；
- 这为"人类在想象回路中"提供了直觉界面：教机器人时直接拖动它想象中的物体；
- 与世界模型蒸馏、从想象数据学习等方向天然衔接。

## 附录D：关键术语表

- **Robotic World Model**：从当前观测+动作序列预测未来视频的模型；
- **Action Following / Interaction Fidelity**：动作跟随 / 交互保真——世界模型两大要求；
- **Proxy（代理）**：动力学与渲染之间的中间信号，此处为像素对齐的 3D 点派生视频；
- **Point Dynamics Model**：学习式点动力学模型（本文用 PointWorld-large）；
- **FK（Forward Kinematics）**：前向运动学，动作→机器人表面点；
- **Warp**：逆距离加权把稀疏模拟位移传播到稠密点的代理通道；
- **Track Video**：按初始 3D 位置着色的稀疏点轨迹代理通道；
- **z-buffer Point Splatting**：带深度缓冲的点溅射渲染，保证遮挡正确；
- **Point Forcing**：辅助点跟踪损失（PhysisForcing 式），本文对照的隐式方案；
- **Object Motion Error**：基于视频点跟踪的物体运动误差，交互保真的度量。

## 附录H：深度问答补遗

### H.1 为什么用"像素对齐代理视频"而不是直接给视频模型 3D 点坐标？

因为预训练视频模型的接口语言就是像素空间（VAE latent）。把点渲染回像素对齐视频，任何视频模型零改动接入——这是"代理即通用接口"设计。直接注入点坐标需要改架构、重新预训练，丧失了可插拔性。

### H.2 warp 的逆距离插值会不会把不同物体的运动混在一起？

会——这正是 warp 边界伪影的来源（面包片/铲子分离场景中边界点的运动被平均）。track 通道的存在就是为了缓解：渲染器能从 track 直接看到纯模拟点，校正 warp 的插值模糊。三通道互为冗余校验是代理设计的稳健性来源。

### H.3 该架构如何支持可形变物体？

点天然无刚性假设——形变就是点的非线性位移，PointWorld 从真实交互数据中学到的正是这些。这正是选择点而非 mesh/刚性体的重要理由：形变、铰接、切割都不需要特殊处理。

### H.4 系统延迟适合实时控制吗？

当前形态（大视频模型渲染）面向预演/评估/数据合成，非实时闭环。但架构可以退化使用：跳过渲染器，直接在点空间做 MPC——模拟器单独推理的延迟可支持低频控制。渲染器是"想象预览"，不是控制回路必需品。
