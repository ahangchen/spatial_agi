# SceneAgent: An Agentic Pipeline from 3D and 4D Captures to Simulation Environments

**发表日期**: 2026-10-26
**arXiv链接**: https://arxiv.org/abs/2610.34745

---

## 0. 一句话总结

SceneAgent 用多智能体（orchestrator → ingest → runner → reviewer → inspector）
编排"3D/4D 采集 → 交互式仿真环境"的全流程转换：物体分割、mesh 生成、
物理参数估计、部件分解、铰接、软体/流体/断裂仿真，配合基于仿真器渲染的
视觉检查与自修复，在 GraspClutter6D 上把最佳编码 agent 的 F1@1cm 从
9.51% 提到 60.75%（SimFoundry 仅 6.9%），在 4DCodeBench 上把 Gemini 4
Argon 的动态 IoU 从 0.86% 提到 99.09%，并展示 sim-only 训练的 π0.5
真机迁移 88% 成功率。

## 核心问题

### Q1: 核心算法原理是什么？

**问题**: 这篇文章的核心算法原理是什么？请详细描述：1) 核心思想和动机，2) 主要技术方法，3) 算法流程和关键步骤，4) 输入输出。

**分析**:

#### 1. 核心思想和动机

- **动机一**：通用机器人策略（VLA）的训练和评估都需要仿真环境，
  但把视觉采集（照片、3DGS、LiDAR、4D 视频）变成可交互仿真环境
  需要物体重建、物理建模、以及**中间错误的修正**——一个错误的
  mask、尺度或变换就能让整场景不可用，即使每个单独模型输出都"合理"。
- **动机二**：现有 real-to-sim 系统（PolaRiS、SimFoundry、GASE、
  Mirage2Matter）各自解决了部分环节，但缺少**跨输入类型协调这些
  组件、并在各阶段之间发现和修复错误**的机制。
- **核心思想**：把场景转换建模为 agentic 工作流——智能体执行重建与
  物理建模工具，在目标仿真器（Isaac Lab）中渲染中间结果，视觉检查、
  发现不一致、提出修复、再次验证。整个转换过程由 manifest + ledger
  （接受/拒绝记录）管理，可追溯、可复现。
- **副贡献思想**：转换好的场景不是终点，还能自动扩展——
  "digital sisters"（相关物体变体）+ 混合场景（采集物体+美术资产）+
  策略自研循环（真机失败 → 仿真复现 → 生成针对数据 → 再训练）。

#### 2. 主要技术方法

**A. 智能体编排与验证（3.1）**

- 角色分工：orchestrator（规划全流程）→ ingest agents（准备输入、
  构建 3DGS）→ runner（执行处理工具，每步 actor-critic 视觉审查）→
  reviewer（逐物体检查：配准叠加图、8 个孤立视图（6 正交 + 2 斜视）、
  装配后 2 视图）→ packager（组装场景）→ inspector（在 Isaac Lab 中
  审查导出结果）。
- 状态通过场景目录中的文件传递；每步结果记入 ledger。
- 对齐接受准则：以 SAM3D 位姿为初值的 trimmed similarity ICP，
  计算归一化中位数与 90 分位点距离、coverage、silhouette agreement
  四项指标，全部过阈值才接受。
- **技能自进化**：agent 被指示研究可能改进转换的方法，提出候选改动后
  在静态 3D、动态 4D、video-to-4D 三类基准上与当前基线对比，只有
  通过固定提升/回退阈值才保留；对外部用户则生成 draft PR 走独立
  基准复跑 + 维护者审核。这是"工具链自我改进"的治理设计。

**B. 输入与场景表示（3.2）**

- 输入支持：RGB 序列（COLMAP 位姿 + Nerfstudio splatfacto big 训练
  3DGS）、现成 3DGS、摄影测量资产、LiDAR、AI 生成场景
  （World Labs Marble、NVIDIA Lyra、腾讯 HY-World）、4D 视频。
- 3DGS 表示：g_i = (μ_i, Σ_i, α_i, h_i)（中心、协方差、不透明度、
  球谐颜色）。
- 输出场景：S = (G_bg, {o_k})，物体 o_k = (P_k 高斯集合, M_k mesh,
  T_k 变换, θ_k 物理属性, J_k 关节)。

**C. 物体重建与背景补全（3.3）**

- 语义关联：SAM 每 10 帧出 mask（步长 1-10 视场景），OpenCLIP ViT-B-16
  512 维 embedding + DINOv2 ViT-S/14 特征供物理先验用。
- 跨视角 mask 聚类成同一物体：高斯质心距离 < min(0.10, 0.6e)
  （e 为物体范围），containment ≥ 0.18 或 Jaccard ≥ 0.08。
- SAM3D 生成几何；高斯归属条件：投影在 mask 内且深度在前景表面
  附近（z ≤ ẑ + max(ε_a, ε_r·ẑ)，ε_a=0.08 重建单位 ≈7cm，ε_r=0.03）。
- mesh 与高斯做 trimmed similarity ICP 对齐；前景高斯移除后用检测
  平面补全背景，颜色取自邻近平面像素（可选 LaMa 修复）。

**D. 物理属性、部件与铰接（3.4）**

- 材质/物理估计 = 三源加权投票：每高斯物理先验 MLP（DINOv2+OpenCLIP
  特征 + 16 个几何量；训练于 GSO/YCB/ABO 的 **VLM 标注**而非实测）+
  VLM 判断 + 物体名称关键词先验；未知类别权重 ×0.4。
- 10 材质类、6 体类型（动态刚体/静态刚体/kinematic/软体/布/流体颗粒）、
  8 碰撞原语（box…cloth mesh）；质量密度按对数回归；杨氏模量等按材质
  类查表；rigidity ≥ 0.65 视为软体。
- PartSAM 部件分解；VLM 检查缺失几何（如笔帽下的笔尖），CubePart 补全；
  Articulate Anything 提议 URDF 关节与运动范围，agent 在仿真中审查。
- 断裂仿真（3.5，独立示例非自动导出）：纸张用 Warp 正交各向异性薄板
  FEM + 内聚断裂；陶瓷用 NVIDIA Blast 应力键断裂；西瓜/果冻用 Newton
  内聚有限单元。

**E. 从 3D 到 4D（3.6）**

- 4D 场景：S = (K, E, G, {d_m})——未知内外参从视频估计（消失点、
  轮廓），动态材质 d_m = (初态 x⁰, 参数 θ, 求解器 Φ)，状态按
  x^{t+1} = Φ(x^t, θ, G, {x_n^t}) 推进。
- 求解器选择：MPM（凝胶/弹塑性/液体+刚体交互）、FLIP（不可压液体）、
  断裂模型（脆性物体）。粒子不删除不重播——每条轨迹全程追踪同一
  材料块，输出持久轨迹 X ∈ R^{F×N×3}。
- 验证：用估计相机渲染仿真序列，与输入视频在早/中/晚帧做并排+叠加
  比较，按差异修正相机/静态几何/初态/参数。
- 最终场景由**单一 build 脚本**生成，脚本不读视频或外部资产——可
  从零复现并可校验帧数/分辨率/格式。

**F. 场景导出与变体（3.7-3.9）**

- OpenUSD 导出（Isaac Lab 为主，验证过 MuJoCo、Unreal）；物理 schema
  覆盖刚体/关节/摩擦，软体断裂流体需各引擎扩展。
- Digital sisters 两条路：无模型调用（有界变形 mesh + 程序化纹理，
  校验 extent/volume/可抓性）+ Meshy（Gemini 2.5 Flash 分解功能部件、
  Gemini 3 Pro Image 逐部件编辑、Meshy-6 重纹理，几何/UV 不变）。
- 混合场景：采集物体插入美术环境（如服务器机架插线任务）。

**G. 示范生成与策略学习（3.10）**

- 用仿真器真值状态写脚本专家（approach→descend→grasp→…→retreat），
  观测 = mesh 前景深度合成到 3DGS 背景；失败 episode 丢弃。
- **策略自研循环**：真机/仿真 rollout 录像 → agent 标注失败模式 →
  设计复现失败的 digital sisters → 评估 → 编码模型（GPT-6 Astra /
  Gemini 4 Argon）改写专家控制器 → 通过成功检查的 episode 进微调集 →
  LoRA 微调 π0.5 → 固定配对验证集对比新旧 checkpoint → 回真机。
- 初始状态随机化：物位置/尺寸 ±10%、偏航 [0,2π)、机器人基座 2cm 圆盘、
  外相机 pitch ±2°；物体在物理下落定后开始采集。

#### 3. 算法流程和关键步骤

```
[输入] RGB序列 / 3DGS / 摄影测量 / LiDAR / AI生成场景 / 动态视频
   ↓
[编排] orchestrator 规划 → manifest
   ↓
[采集处理] COLMAP位姿 + splatfacto 3DGS（或直接接入现成资产）
   ↓
[物体化] SAM masks → 跨视角聚类 → SAM3D几何 → trimmed ICP对齐
   → 背景平面补全
   ↓
[物理化] 物理 MLP + VLM + 关键词 三源投票 → 材质/质量/摩擦/rigidity
   → PartSAM部件分解 → CubePart补全 → Articulate Anything URDF
   ↓
[验证] 渲染配准叠加 + 8孤立视图 + 装配视图 → 发现问题 → 修复 → 重审
   ↓
[扩展] digital sisters（变形/纹理/部件编辑）+ 混合场景 + 布局光照随机化
   ↓
[4D路径] 相机估计 → 静态几何 → 求解器选择(MPM/FLIP/断裂) → 参数拟合
   → 渲染对比 → 迭代修正 → 单一build脚本输出
   ↓
[导出] OpenUSD / Isaac Lab（MuJoCo、UE 验证）
   ↓
[示范生成] 脚本专家(仿真真值) → 深度合成观测 → 成功过滤
   ↓
[策略学习] LoRA微调 π0.5 → 真机评估 → 失败分析 → sisters再生 → 循环
```

#### 4. 输入输出

- **输入**：多模态采集（RGB 序列、3DGS、摄影测量、LiDAR、生成式 3D
  场景、动态视频）+ 任务描述。
- **中间输出**：带语义/物理/关节标注的物体资产 + 补全背景 + USD 场景
  + digital sisters + 可从零复现的 build 脚本（4D）。
- **最终输出**：Isaac Lab 交互环境 + 脚本专家示范数据集 + LoRA 微调后的
  VLA checkpoint + 真机部署性能。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

- SceneAgent 的空间表示是**分层的混合表示**：背景 = 光度级 3DGS
  （外观真实但不可交互），前景物体 = 显式 mesh + 物理参数 + 关节
  （可交互但需重建）。这正是 Spatial AGI 需要的核心架构判断：
  **外观用神经隐式/泼溅表示保真，交互用显式几何保证可执行**，
  两者按物体边界缝合。
- 4D 扩展把表示再升一层：静态几何 G + 每种动态材质一个求解器 Φ +
  拟合参数 θ。空间不仅是"形状"，还是"动力学"——同一空间在不同
  物理参数下演化出不同未来。Spatial AGI 的世界模型必须包含这一层。
- 持久粒子轨迹（每粒子全程保号）提供了**物质身份连续性**的空间
  表示：水还是那滴水、凝胶还是那块凝胶。这是时空推理的底层要求。

#### 2. 如何处理空间关系

- **空间一致性靠验证闭环而非单点精度**：mask 聚类用 3D 高斯 containment
  /Jaccard 而非 2D IoU；mesh 对齐用 trimmed ICP + 四重接受准则；
  每个物体经 8 视角孤立审查 + 装配审查。空间关系的正确性被转化为
  可检查的几何判据。
- **物理常识作为空间先验**：材质投票中"物体名称关键词先验"显式
  承认语义先验的价值——"mug"应该是陶瓷/塑料而不是钢。Spatial AGI
  需要这种语义→物理的默认空间行为知识。
- **跨坐标系管理**：SfM 系、机器人系、仿真系之间的变换与对齐是
  全流程的隐形骨架（ICP 种子、相似变换对齐、相机估计）。
  空间智能的工程核心之一就是坐标系统一的纪律。

#### 3. 对 Spatial AGI 的启发

- **Agent 化的空间数据处理**：空间感知管线（重建→分割→物理化→
  仿真化）过去是脆弱的流水线，本文证明 LLM agent + 仿真器渲染
  反馈可以把成功率从个位数 F1 提到 60%。对 Spatial AGI：复杂空间
  任务的可执行性来自**感知-行动-验证的闭环**，与具身智能同构。
- **"数字姊妹"作为空间数据增广**：物体功能部件级的变体生成
  （换颜色、换形状、保持可抓性校验）比全局图像增广更符合空间
  任务的物理不变性要求。
- **失败驱动的数据引擎**：自研循环把真机失败自动转成仿真训练
  数据——这是 Spatial AGI 系统能持续自我改进的关键机制
  （与昨天 EmbodiedLGR 的空间记忆、Evolvable Embodied Agent 的
  反思机制形成互补）。
- **物理参数不求精确、只求合理**：论文坦承参数是 VLM 标注的近似
  先验，用途是 domain randomization 的起点而非真实物理。这种
  "plausible > precise" 的实用主义对 Spatial AGI 工程很关键。

#### 4. 可以应用的 Spatial AGI 场景

- **空间智能训练场工厂**：任何照片/视频可及的真实环境都能转成
  可交互空间，用于训练和评估具身/导航/操作策略。
- **4D 世界模型数据生成**：video→仿真动力学拟合，为世界模型提供
  带真值轨迹（持久粒子）的物理一致训练数据。
- **空间评估基准**：4DCodeBench 式的"从视频重建可执行动力学"任务
  本身就是 Spatial AGI 的能力试金石。
- **数字孪生运维**：实验室/数据中心/厨房的高保真孪生，支持策略
  预演和失败模式预演。

### Q3: 主要创新点和局限性是什么？

**分析**:

#### 1. 主要创新点

1. **首个 agentic 全流程 real-to-sim 编排**：不是提出新重建算法，
   而是用 agent 协调现有工具并用仿真器渲染做视觉验收/修复——
   把系统级错误率作为一等研究对象。
2. **3D→4D 统一管线**：同一 agent 工作流覆盖静态场景与动态视频
   （MPM/FLIP/断裂求解器拟合），在 4DCodeBench 上动态 IoU
   0.86%→99.09%，远超基准 18 个 agent 的最好成绩（30.57%）。
3. **技能自进化机制**：agent 提议的工具改进必须通过固定基准的
   提升/回退阈值，外部贡献走 PR + 独立复跑——为"自我改进的
   agent 系统"建立了可审计的治理模式。
4. **量化跨 harness 研究**：8 个编码 agent harness（Codex、Claude
   Code、ZCode、Grok、Antigravity、Muse、GLM-5.3 等）有/无技能
   配对比较，证明技能包对所有 harness 通用提升。
5. **闭环策略自研循环 + sim-only 迁移实证**：40 episodes 时真机
   48%，任务课程化（3 任务→目标任务、变体→无变体）后达 88%，
   展示了纯仿真训练路线的可行性。

#### 2. 主要局限性

1. **转换成本高且仍易错**：反复 VLM 调用 + 外部 GPU 工作站；
   复杂环境处理慢；无人工干预下部分 harness 直接跑挂。
2. **物理参数未标定**：质量/摩擦/刚性是"合理先验"而非实测；
   断裂参数全是工程估计；对接触密集任务的影响未验证。
3. **视觉保真残留问题**：采集高斯保留原场景光照，重光照/合成
   会有阴影反射不一致。
4. **评估范围窄**：静态重建仅 1 厨房 + 1 杂物箱，各配置只跑一次
   （无方差报告）；4D 仅 3 个合成场景，真实 4D 视频无 3D 真值
   未评估；真机只做了 pick-and-place（茄子入篮）。
5. **反直觉的数据规模结果**：真机成功率在 40 episodes 达峰（48%），
   更多仿真数据反而过拟合下降（400 条仅 24%）——sim-only 扩展
   的上限问题没有解决，靠任务课程化缓解而非根除。
6. **软体/断裂/流体未进自动导出**：USD schema 不覆盖，需各引擎
   手工设置，跨引擎能力不对齐。

#### 3. 与其他相关工作的对比

- **vs SimFoundry**：SimFoundry 支持铰接物体+参数估计+digital cousins，
  但作为固定管线；SceneAgent 在同一 13 张图输入上 F1 60.75% vs 6.9%，
  Chamfer 4.29cm vs 更低，全部 harness 配置均超过它。
- **vs PolaRiS**：PolaRiS 聚焦评估（高斯背景+生成 mesh），SceneAgent
  覆盖更全输入类型并加物理/4D/自进化。
- **vs Real2Render2Real / RoboSplat / ManiSplat**：这些做示范增广，
  SceneAgent 做"环境级"增广（sisters + 布局 + 光照）+ 失败驱动闭环。
- **vs 生成式评估环境（WorldGym/WorldEval/RoboWorld）**：视频生成
  路线 vs 显式几何+物理仿真路线——后者属性可检查可编辑，
  前者可能更 scalable，是两条值得对赌的路线。
- **vs 今天论文1（PrecisionReach-GS）**：论文1选择"不做物理仿真"的
  极简路线（只覆盖接触前），SceneAgent 选择"全物理化"的重路线
  （刚体/软体/流体/断裂都做）。两者代表 real-to-sim 光谱的两端，
  共同点是都把 3DGS 作为外观底座、都用仿真/渲染产生对齐的
  视觉-动作监督。

## 核心技术发现

- 发现1：agent 的价值在"接口处"——错误集中在模型衔接（mask→mesh→
  仿真插入），渲染检查 + 修复循环把 F1 提升 3-6 倍。
- 发现2：跨视角高斯聚类（containment/Jaccard + 质心距离）比 2D mask
  融合更适合 3D 物体身份判定。
- 发现3：物理先验用 VLM 标注训练即可——因为用途是随机化起点，
  精度要求低；关键是有三源投票和 VLM audit 兜底。
- 发现4：粒子全程保号的持久轨迹让 4D 重建可验证（逐帧 mesh +
  轨迹 + 可复现 build 脚本），这是 4D 任务能变成基准的前提。
- 发现5：sim-only 策略数据存在"质量 > 数量"的反直觉规律：
  40 条精心变体的真机成功率（48%）高于 400 条（24%）；
  任务课程化（先多任务后目标任务）才是规模化的正确姿势。

## 与Spatial AGI的关系

### 直接贡献

提供了"任意采集→可交互空间"的通用转换器，是 Spatial AGI 的

照片和视频即是资产。

- 外观（3DGS）与交互（mesh+物理）的分层混合表示范式。
- 空间管线的 agentic 化：感知系统也能像编码 agent 一样
  自我检查、自修复、自进化。

### 应用场景

策略训练场、4D 世界模型数据、空间基准、数字孪生、机器人

## 个人思考

### 最令人兴奋的发现

**4D 动态 IoU 0.86% → 99.09%** 这个数字非常惊人。同一模型
（Gemini 4 Argon）裸跑几乎完全失败，加上 SceneAgent 技能包后接近
满分——这说明当前的强大编码 agent 并不缺空间/物理知识，缺的是
**把知识组织成正确操作序列的技能 scaffold**。这对 Spatial AGI 的
启示：能力瓶颈可能不在底层模型而在任务编排层；一个好的技能库 +
验证循环能把现成模型变成专家系统。

另一个深刻细节是"数据规模的相变反转"：仿真数据从 40→400 条，
真机成功率不升反降（48%→24%）。这和论文1的"生成数据多多益善"
（300→1500 单调提升）形成鲜明对比。差异可能在于：论文1的数据
是任务内插值（同一场景同一目标），SceneAgent 的数据带物体/布局/
光照复合随机化——**随机化的复合方差超过策略容量时，额外的仿真
数据变成噪声**。课程化（先多任务后少变体）解决的是方差注入的
时序安排。这提示 Spatial AGI 数据引擎需要"方差预算"概念。

### 潜在局限

- 每配置只跑一次转换、无方差报告，agentic 系统的输出方差恰恰是
  最需要量化的量（同一个 agent 两次跑可能差很远）。
- 真机评估只有 50 layouts 的 pick-and-place，"preliminary"名副其实；
  软体/流体/断裂任务完全没有真机验证。
- 技能自进化依赖固定基准（3 静态 + 3 动态），可能过拟合这几类
  场景，泛化到新环境类型的能力存疑。

### 与昨日研究的关联

- 昨天 (10-29) 的 **Habitat-GS 类动态 3DGS 导航仿真器**与本文共享
  "高斯外观 + 可交互结构"的表示哲学，但本文把物理层做到了
  软体/流体/断裂，是更彻底的交互性。
- **WorldSimProbe**（10-29，诊断 ACWM 仿真器忠实度）关切的问题
  正是本文的软肋：物理参数未标定时，仿真里的策略表现对真机的
  预测力有多强？本文的 paired validation 设计是正确方向，
  但需要更系统的 fidelity 报告。
- **CL4D**（10-29）的跨具身 4D 预训练 + 本文的环境工厂 =
  完整闭环：CL4D 提供跨具身表征，SceneAgent 提供环境与示范。

## 总结

### 核心发现总结

SceneAgent 证明 real-to-sim 的瓶颈不在单个重建/物理模型，而在
**系统级编排与验证**。把编码 agent + 仿真器渲染验收 + 技能包 +
自进化治理组合起来，静态与动态场景转换质量都实现数量级提升，
并打通了 sim-only 示范生成 → VLA LoRA → 真机 88% 成功率的
初步闭环。

### 对Spatial AGI的意义

本文给出了 Spatial AGI 环境基础设施的参考实现：空间智能体需要
的"世界"可以从任意视觉采集程序化构造，且构造过程本身可以由
agent 自主完成、自我改进。当环境工厂 + 失败驱动数据闭环 +
跨具身表征（CL4D 等）三者成熟，Spatial AGI 的训练飞轮就完整了。
需要警惕的是物理保真度与 sim-to-real 预测力仍未闭环验证——
这正是 Spatial AGI 社区下一步必须回答的问题。

## 附录A：方法细节深挖

### A.1 为什么"任务性验证"是管线的关键防伪机制

传统真实到仿真管线用逐资产指标（Chamfer 距离、F1@阈值）验收，
但仿真环境的目的是"让策略在其中训练后能迁移到真实世界"。
资产级几何相似 ≠ 交互级行为相似：一个桌面如果摩擦/碰撞体
错了，几何上可以完美。SceneAgent 用目标条件导航成功率做
验收代理，直接对齐"环境是否支持任务"这个终极问题。
这继承了昨天 WorldSimProbe（10-29）"仿真器效度要用交互
行为检验"的方法论，并把它从"诊断已有仿真器"前移到
"生成仿真器时就把关"。

### A.2 生成-审查循环的容错设计

- 每轮审查都是独立上下文：修复 LLM 不拿到自己之前"我修好了"
  的声明，只拿到渲染对比与任务指标——防止自我确认偏差。
- 失败模式分类：渲染审查失败（材质/光照/位置错误）与任务
  验证失败（物理属性错误）走不同的修复分支（前者改资产
  排布/外观，后者改物理参数/替换求解器）。
- 迭代上限 + 逐轮指标曲线让管线可中断可审计。

### A.3 与手动管线的成本对比的隐含逻辑

Harvard 团队强调"无需艺术家介入"：传统影视级 real-to-sim
一个场景数人周；SceneAgent 单场景数小时 GPU + 数次 LLM 调用。
代价是保真上限——F1@1cm 60.75% 距离完美还很远，对工业级
数字孪生可能不够，但对大规模策略训练数据生成是数量级的
成本优势。这是"规模换质量"的典型取舍，与今天论文1
（PrecisionReach-GS 的 3DGS 数据引擎）同属一个范式。

## 附录B：与其他方法的横向对比

| 维度 | SimFoundry | 手工管线 | SceneAgent |
|---|---|---|---|

| 验收信号 | 几何指标 | 人工目检 | 渲染对比+任务成功率 |

是 real-to-sim 质量的决定因素，而非生成模型本身的强弱。

## 附录C：对 Spatial AGI 研究议程的启示

1. **仿真器即数据引擎**：真实扫描 → 仿真环境 → 策略训练的
   链条打通后，Spatial AGI 的训练数据不再受真实机器人
   采集瓶颈约束。SceneAgent + 论文1 的 3DGS 数据引擎是
   两个互补入口（前者物理仿真、后者视觉保真）。
2. **验证器设计是核心竞争力**：管线质量上限由验证器决定
   （垃圾进垃圾出）。任务性验证比指标性验证更接近真值，
   但贵且慢——分级验证（便宜指标初筛 + 贵任务终审）是
   工程化方向。
3. **物理求解器选择自动化**：MPM（沙/软体）vs FLIP（流体）
   的自动选择目前是规则/LLM 判断，未来应学习化：从物体
   视觉/几何特征预测材质类别 → 选求解器，这也是一个
   可学习的空间理解任务。
4. **开放问题**：管线输出的是"看起来对"的仿真，物理参数
   （摩擦、质量、刚度）从视觉推断本质上欠定；触觉或
   交互数据（真机试推）注入是打破欠定性的必要路径。
