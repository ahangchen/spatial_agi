## 一句话总结

World Action Agent（WAA）设计了一个多智能体 "视觉动作工作区"（visual action workspace），让通用 VLM 像飞行员一样驾驶机器人：自动选取交互中心视角（Contact views）、把每个动作变成可预演可修改的提案（Action rehearsal + Imagination Agent）、在观测视角内直接拖拽纠偏（in-view correction）——在 LIBERO-Pro 上以 75.6% 平均成功率刷新 SOTA，且同一技能库零学习迁移到 robosuite，交互轨迹还能蒸馏出 9B 的 "小飞行员"（域外成功率 1.7%→43.3%）。

## 核心问题

### Q1: 核心方法原理

**问题**: WAA 的核心设计是什么？如何让 VLM 直接驾驶机器人？

**分析**:

#### 1. 核心思想和动机

作者的出发点是对现有 VLM 参与机器人操作方式的系统性不满。现有系统让 VLM 要么 "间接参与"（预测约束、写程序：ReKep、CaP），要么 "只给视图不给世界"（Show-Harness、VIA 这类视觉接口）。后者的三大缺陷：

1. **观测不以交互为中心**：固定全局相机下，夹爪-物体-目标之间的毫米级关系被距离/遮挡/退化视角抹掉；
2. **动作不可试错**：动作一发出即生效，VLM 无法先看到后果再决定——物理世界不可撤销；
3. **感知与动作空间分离**：图像中看到的偏移要改写成坐标才能纠正——翻译损耗。

WAA 的哲学：**不改 VLM，改 VLM 看到什么、决策如何生效**。把操作变成一个发生在 "视觉动作工作区" 里的交互式视觉推理问题。

#### 2. 系统架构：多智能体 harness + 三大设计

**问题形式化**：给定任务指令 g，agent 通过工具调用序列完成任务。第 t 步，harness 呈现多视角画布 C_t 和控制上下文 m_t（有效空间引用、待定动作提案 â_t、执行反馈），策略选择工具调用 u_t ~ π(·|g, C_t, m_t)。工具分三类：

- **query 工具**：获取空间信息或技能指导（不改变物理世界）
- **proposal 工具**：构建/修改动作提案，返回可视化预览与规划反馈（不改变物理世界）
- **execution 工具**：真实驱动机器人

关键性质：query 与 proposal 不触碰物理世界 → agent 可以**无限次检查和修改动作后才提交执行**。VLM 决定 "操作什么、如何修改、何时执行"；harness 负责几何精度与运动学可行性。

**设计一：交互中心画布（Contact views）**

给定场景点云 P_t、机器人几何 R_t、高亮交互区域 H_t，优化相机参数：

c_t = argmax S_vis（交互区域与夹爪在遮挡下的可见性）+ λ1·S_frame（紧凑取景）− λ2·E_red（冗余视角惩罚）− λ3·E_stab（视角跳变抑制，保持跨帧空间关系可比）

且约束两个 Contact 视角的水平投影正交——这样对齐误差可以沿两个独立方向读取。点云来源不可知（仿真渲染、RGB-D 融合、或 VGGT 前馈重建），保持了系统的传感器无关性。全局视图给任务上下文，Contact 视图暴露精细交互关系，所有视图保留投影标定 → 图像空间标注直接映射到 3D。

**设计二：动作预演（Action rehearsal + Imagination Agent）**

VLM 最难的往往不是 "去哪里"，而是 "这个具体位姿合不合适"：会不会碰撞？够不够得着？抓完能不能进行下一步？WAA 把动作表示为**可编辑提案**：

- agent 在画布上定位目标、指定位姿
- harness 解逆运动学、用 cuRobo 规划运动
- 在每个视图中叠加半透明的 "预演机器人"，报告可行性
- agent 据此检查接近方向、预期接触点、周围间隙并修改

精细调整委托给 **Imagination Agent**：它在独立上下文中迭代编辑并重新规划提案（物理场景不变），只返回修订后的提案。**只有拥有可执行规划的提案才能变成物理运动**——预演把 VLM 的任务几何判断与规划器的可行性检查耦合起来，在物理世界出错之前暴露错误。

**设计三：视角内闭环纠偏（in-view correction）**

目标级规划运动适合大幅移动，但深度噪声、标定误差、接触扰动留下的残差往往决定放置成败。WAA 允许 agent **在观测到错误的视角中直接表达修正**：在 Contact 视图中从参考点（夹爪或所持物体上的可见点）拖拽到期望位置，harness 用视图标定把这个图像空间意图转成有界的末端位移。两个正交 Contact 视角支持互补方向的修正。每次修正后新的观测让 agent 决定继续调、松手、还是进行下一个目标级动作。

#### 3. 通过 harness 的学习与进化

驾驶技能需要 VLM 预训练中罕见的具身程序性知识，WAA 通过同一工作区以两种方式获取：

1. **技能进化**：从专家视频和人类示教中提取、编辑、评审（evidence-based review）出多模态技能库，由 Skill Agent 检索调用——非参数化的技能积累。
2. **轨迹蒸馏**：交互轨迹训练更小的 VLM 驾驶同一 harness——Qwen3.5-9B 微调后域外成功率从 1.7% 提升到 43.3%。

#### 4. 输入输出

- **输入**：任务指令 g、多视角画布（全局 + 2 个正交 Contact 视图）、控制上下文
- **输出**：工具调用序列（查询/提案/执行），最终物理世界中的任务完成
- **评测**：LIBERO-Pro 75.6% 平均成功（仅用 LIBERO-90 进化技能）；零学习迁移 robosuite；9B 蒸馏飞行员

### Q2: 与 Spatial AGI 的关系

**问题**: WAA 与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

WAA 的空间表示是一个**分层拼图**，非常清晰地展示了 "空间智能不需要单一表示"：

- **几何层**：场景点云（来源不可知）+ 机器人运动学 + 视图投影标定——确定性、精确、非学习；
- **感知层**：VLM 对 Contact 视图的语义/定性空间判断（"杯柄朝左偏了"）——模糊、模糊但语义丰富；
- **意图层**：图像空间的拖拽矢量、画布上的定位点击——把 "空间意图" 而非 "空间坐标" 作为接口。

核心洞察：**VLM 擅长定性空间判断，不擅长度量位姿**（论文设计原则原话）。WAA 不强迫 VLM 输出精确坐标，而是给它一个空间语言（视图、标注、拖拽）让它表达定性判断，度量精度由几何管线保证。这是 "语义-度量接口设计" 的教科书级示范。

#### 2. 如何处理空间关系

三个设计各自处理一类空间关系难题：

- **视角选择**（Contact views 优化）：解决 "从哪里看才能看清空间关系"——主动视角规划，与 GPT-6-Astra 的 observe() 行为、Planning with the Views 的视角推理形成呼应，但这里是用几何优化显式求解的。
- **预演**：处理 "动作-空间后果" 的关系——把反事实推理（"如果我这样抓会怎样"）外包给物理规划器，用半透明渲染把结果可视化给 VLM。这实际是世界模型的**确定性替代品**：与其学习预测未来，不如直接用运动学/动力学求解器算未来。
- **视角内修正**：处理 "感知-行动的空间一致性"——把感知空间（图像）与行动空间（末端位移）通过标定直接缝合，消除坐标翻译损耗。

正交双视角的设计尤其精妙：对齐误差天然是 3D 的，两个正交视角恰好提供两个独立观测方向，让误差可分解、可读出、可分别修正——这是把人类 "绕到另一边看看" 的纠错直觉工程化了。

#### 3. 对 Spatial AGI 的启发

1. **"给世界而不只是视图"** 是 Spatial AGI 界面设计的第一原则：空间智能体需要的不是摄像头画面，而是一个可查询、可预演、可标注的校准空间工作区。
2. **反事实推理的确定性实现**：Imagination Agent 用求解器而非学习式世界模型做 "想象"。在结构化环境（机器人、已知几何）中，解析求解器完胜学习式预测——这对 "世界模型热" 是一个重要的清醒剂（呼应今日论文 2）。
3. **技能库 + 蒸馏的双通道知识积累**：非参数技能（视频进化）与参数蒸馏（轨迹→9B）都通过同一工作区进行——空间智能的 "学习接口" 与 "执行接口" 可以是同一个。
4. **空间误差的分层处理**：目标级（规划器保证）+ 残差级（视角内修正）分离处理，避免了 "一个模块包打天下" 的设计。

#### 4. 可以应用的 Spatial AGI 场景

- 家庭机器人操作（WAA 的直接目标）
- 遥操作/人机协作：人类教学通过同一工作区进入技能库
- 仿真数据管线：交互轨迹天然是 VLA 微调数据
- 其他空间任务的工作区化：把 WAA 模式搬到导航（视角选择=观察点规划、预演=路径预演、修正=局部重规划）

### Q3: 创新点和局限性

**问题**: WAA 的主要创新与局限是什么？

**分析**:

#### 1. 主要创新点

1. **"动作即提案" 范式**：把不可逆的物理动作变成可编辑、可预演、带规划反馈的提案——这是对 "LLM agent 的 tool use" 范式在物理世界的关键改造。软件 agent 错了可以重跑，机器人错了会打碎东西；预演机制补上了这个不对称。
2. **Contact views 自动视角优化**：首个把 "交互中心视角选择" 形式化为带约束的优化问题的系统（可见性+取景+冗余+稳定四项，正交约束）。正交双视角读出对齐误差的设计简洁而有效。
3. **工作区统一执行与学习**：同一画布既是决策界面也是教学界面（人类示教）也是数据采集界面（轨迹蒸馏）——接口复用最大化。
4. **实证结果强**：LIBERO-Pro 75.6%（超过 ASPIRE 72.0%）、跨模拟器零学习迁移、9B 蒸馏有效——三个维度的证据链完整。

#### 2. 主要局限性

1. **点云依赖**：虽然来源不可知，但 Contact 视角优化和标定校正都以场景点云为前提。无深度/无重建的纯 RGB 部署（GPT-6-Astra 的场景）下 WAA 的几何管线失效——两篇论文恰好是互补的极端。
2. **推理成本与延迟**：每步多视图渲染 + IK + cuRobo 规划 + 多 agent（主 agent + Imagination Agent + Skill Agent）调用，单动作决策链路长。实时任务（抓取运动物体）不适合。
3. **评测环境的局限**：LIBERO-Pro/robosuite 都是桌面操作仿真，物体刚性、场景静态、无流体/可变形物。预演机制的可行性检查（碰撞/可达）在柔性物体上会系统性失效。
4. **对比基线的公平性**：与端到端 VLA、CaP 对比，但 VLA 基线是否有同等的测试时计算预算？WAA 每步多次 VLM 调用 + 规划器，VLA 是单次前向——算力不对等。
5. **技能进化的评估缺口**：专家视频→技能库的 "evidence-based review" 细节和失败率未在摘要层面披露，技能质量对专家视频覆盖度的依赖未知。

#### 3. 与相关工作的对比

| 系统 | VLM 角色 | 动作产生方式 | 试错能力 |
|---|---|---|---|
| RT-2/OpenVLA/π0.5 | 被微调为策略 | 端到端动作 token | 无 |
| ReKep/HAMSTER | 出约束/路径 | 下游优化器执行 | 部分 |
| CaP/CaP-X | 写程序 | 代码调 API | 代码级反馈 |
| Show-Harness/VIA | 直接选动作 | 视觉接口 | 无预演 |
| **WAA** | **直接驾驶+多 agent** | **提案+预演+修正** | **物理执行前完整预演** |

WAA 的定位：在 "VLM 直接控制" 的路线上做到了最完整的物理世界安全机制，同时保留了 VLM 的通用推理不被微调损伤。

## 核心技术发现

1. **75.6% LIBERO-Pro SOTA**，仅用 LIBERO-90 技能进化，超过 ASPIRE（72.0%）与同 backbone 视觉 harness 基线。
2. **零学习跨模拟器迁移**：技能库在 robosuite 上直接有效——非参数技能的形态无关性。
3. **蒸馏有效**：Qwen3.5-9B 学习驾驶同一 harness，域外 1.7%→43.3%（+41.6 点）——harness 轨迹是高质量的具身训练数据。
4. **正交双 Contact 视角**：让对齐误差沿两个独立方向可读，视角内拖拽即可修正。
5. **预演-执行解耦**：query/proposal 工具不触碰物理世界的设计，使 VLM 的决策试错从物理世界移到信息空间。

## 与 Spatial AGI 的关系

### 直接贡献
给出 "VLM 空间智能 → 物理动作" 的完整接口栈：语义层（VLM 判断）↔ 意图层（画布标注/拖拽）↔ 几何层（点云/规划器）。

### 技术启发
- 空间智能的接口设计优先于模型设计：给对工作区，现有 VLM 立即变成可用的空间智能体。
- 反事实推理可以确定性实现：结构化环境中求解器 > 学习式世界模型。

### 应用场景
家庭操作机器人、遥操作教学、具身数据管线、空间任务工作区化。

## 个人思考

### 最令人兴奋的发现

**"动作即提案" 这个抽象**。它抓住了一个此前被普遍忽视的本质不对称：软件 agent 的试错免费，机器人 agent 的试错昂贵且不可逆。过去的方案要么靠训练把 "正确性" 烧进权重（VLA），要么靠 VLM 小心决策（纯 agentic）。WAA 的答案是在接口层创造一个 "沙箱"——所有试错在信息空间完成后才提交物理世界一步。这不仅是机器人技术，更是一种通用的 "高危决策 agent" 架构模式，可以直接推广到任何不可逆操作场景。

### 潜在局限

最深的隐患是**几何管线的隐性成本**。论文反复强调 VLM "不擅长精确度量位姿"，于是把度量全部推给点云+IK+规划器。但真实家庭环境恰恰是几何管线最脆弱的地方：反光/透明物体、动态遮挡、非结构化杂物。WAA 在仿真桌面上的 75.6% 有多少能活过真实客厅，是个大问号。此外，多 agent 架构（主 agent、Imagination Agent、Skill Agent）的决策延迟和成本在摘要中未量化——如果每个放置动作要 10+ 次 VLM 调用，商业化前景受限。

### 与昨日/今日研究的关联

- **与论文 1（GPT-6-Astra）的对偶**：导航任务中 "最小接口 + 最强模型" 直接赢；操作任务中 WAA 表明 "结构化工作区 + 通用模型" 才能赢。合起来看：**任务的空间自由度越连续、错误代价越高，越需要工作区结构**。导航的错误是 "走错路"（可恢复），操作的错误是 "打碎杯子"（不可逆）——预演机制的价值与错误代价成正比。两篇论文合起来给出了 "接口复杂度 vs 任务性质" 的设计定律雏形。
- **与论文 2（评测综述）的呼应**：WAA 与 VLA 的对比恰恰是综述抱怨的 "partial contrast"——同 backbone 的视觉 harness 基线是好设计，但整体算力预算未对齐。
- **与 09-25 世界模型蒸馏线的呼应**：Imagination Agent 用求解器做想象，是 "Think Like a World Model" 的非学习版本；9B 蒸馏则是 "Act Like a VLA" 的 harness 版。

## 总结

### 核心发现总结

WAA 证明：不改 VLM 本身，仅通过 "交互中心视角 + 动作预演 + 视角内修正" 的视觉动作工作区，通用 VLM 就能以 SOTA 水平驾驶机器人操作，且技能可进化、轨迹可蒸馏。空间智能的瓶颈可以出现在接口层，也可以在接口层被解决。

### 对 Spatial AGI 的意义

1. 空间智能系统 = 空间模型（VLM）× 空间工作区（校准接口）。工作区设计是被低估的第一性问题。
2. 反事实空间推理在结构化环境有确定性实现（求解器预演），不必依赖学习式世界模型。
3. "语义判断-度量执行" 分层接口是可复用的架构模式。
4. 同一工作区统一执行、教学、蒸馏三个环节，为空间智能的持续学习提供工程模板。

## 背景与相关工作深度梳理

### VLM 参与机器人操作的五种范式

把 2023-2026 年的工作排成谱系，可以看清 WAA 的位置：

1. **VLA 端到端**（RT-2、OpenVLA、π0.5）：VLM 被微调成动作 token 生成器。优点是推理快；代价是微调损伤通用推理（Hancock et al. 2026 的发现），且动作数据需求巨大。
2. **约束/路径中介**（ReKep、HAMSTER、OmniManip、FSD）：VLM 输出关键点约束、2D 路径、可供性区域，下游优化器/策略执行。VLM 保留通用性，但只是 "副驾驶"。
3. **代码生成**（CaP、CaP-X、RATs、ASPIRE、GaP）：VLM 写程序调感知/控制 API。灵活但受制于 API 抽象质量——CaP-X 自己报告 "移除手工抽象后性能下降"。
4. **层次编排**（Hi Robot、AtomBridge、Harness VLA）：高层推理 + VLA 执行的分层系统。任务组合好，但每次 VLA 调用的能力上限还是学到的策略。
5. **直接视觉接口**（Show-Harness、VIA → WAA）：VLM 通过视觉界面直接选择/修改动作。WAA 属于这一支，但把 "视图" 升级为 "世界"。

WAA 的自我定位是第 5 支的完成形态：**VLM 作为飞行员（pilot）而非副驾驶或程序员**。

### "VLA 微调损伤通用推理" 的含义

论文引用的 Hancock et al. 2026 发现值得单独强调：对 VLM 做动作预测微调会削弱其通用理解与推理。如果这个结论稳固，它对整个 VLA 路线是个警告：**把通用模型变专用，可能同时破坏它的通用性**——而这正是它比专用模型值钱的原因。WAA 的 "冻结 VLM + 外挂工作区" 架构是对这个问题的架构级回避。它与今天论文 1（GPT-6-Astra 零样本不微调）一起，构成了 "非微调具身智能" 的两条证据线。

### LIBERO-Pro 为什么是好的战场

LIBERO-Pro 是 LIBERO 系列的对抗性扩展：刻意打破 LIBERO-90 中的捷径（物体位置、干扰物、指令措辞变化），专测 "真理解 vs 背轨迹"。端到端 VLA 在其上大幅退化（它们学的是环境统计规律），而依赖 VLM 通用推理的系统退化较缓。WAA 选这里作主战场，本身就体现了 "通用推理优先" 的立场。75.6% 对 ASPIRE 72.0% 的领先幅度不大，但在一个刻意反捷径的基准上，方法多样性（非参数技能 vs 程序修复+进化搜索）比分数更重要。

## 附录 A：WAA 工具分类学的完整解读

WAA 的三类工具划分（query / proposal / execution）表面简单，实则是物理 agent 安全架构的核心：

| 工具类 | 物理副作用 | 可逆性 | 频率 | 作用 |
|---|---|---|---|---|
| Query | 无 | 完全可逆（重复调用） | 高 | 感知与知识获取 |
| Proposal | 无（仿真预演） | 完全可逆 | 中 | 决策试错 |
| Execution | **有** | **不可逆** | 低（每动作一次） | 物理提交 |

这个设计把 "决策计算" 与 "物理提交" 彻底分离，让 VLM 的 token 消耗集中在无副作用区间。对比之下，VLA 模型的每个前向都直接产生物理动作——没有 "想一想再说" 的缓冲区。可以预言：**未来所有安全关键的具身 agent 都会采用类似的三层工具架构**，正如软件 agent 演化出 "plan-then-act" 与 dry-run 机制。

## 附录 B：Contact 视角优化目标的技术细节再展开

公式（2）的四项各司其职，值得逐项评注：

1. **S_vis（可见性）**：遮挡下的交互区域与夹爪可见性——这是第一优先级，看不见一切白搭。
2. **S_frame（紧凑取景）**：交互区域应在画面中足够大——512² 像素下的毫米级关系需要足够的角分辨率。
3. **E_red（冗余惩罚）**：避免两个视角给出同一信息——正交硬约束之外 ещё一层软保障。
4. **E_stab（稳定性）**：与上一帧视角的跳变惩罚——空间关系的跨帧可比性依赖视角连续，频繁换视角会让 VLM 丢失 "心理地图"。

特别值得注意的是 λ3·E_stab 的存在暗示：**VLM 的空间记忆是脆弱的**——视角一变，它对场景的空间理解就要重建。这个工程细节是对 VLM 空间认知局限的诚实承认与务实补偿。

## 附录 C：与人类技能习得的类比

WAA 的技能双通道（视频进化 + 人类示教）与蒸馏（轨迹→9B）恰好对应人类技能传承的三种方式：

1. **观察学习**（看专家视频提取技能）↔ 社会学习理论
2. **手把手教学**（人类示教经 evidence-based review 进入技能库）↔ 学徒制
3. **内化**（轨迹蒸馏成 9B 小模型的直觉能力）↔ 技能自动化（从陈述性记忆到程序性记忆）

特别是第三种的类比：大模型驾驶时需要显式的工作区操作（每步推理），蒸馏后的 9B 驾驶员则可能发展出 "跳过中间步骤" 的模式——正如新手司机变老司机。如果蒸馏后的 9B 在 harness 内发展出更短的决策链（调用更少的 query 工具），那将是 "技能内化" 的可测量证据，值得后续论文追踪。

## 附录 C2：Imagination Agent 的设计剖析

Imagination Agent 是整个系统里命名最传神的组件，值得单独剖析：

### 工作机制

1. 主 agent 在画布上定位目标、给出初始位姿提案
2. harness 做 IK + cuRobo 规划，叠加半透明预演机器人，报告不可行
3. 主 agent 把 "空间意图 + 不可行反馈" 交给 Imagination Agent
4. Imagination Agent 在**独立上下文**中迭代：编辑位姿 → 重新规划 → 检查 → 再编辑
5. 物理场景全程不变，只返回修订后的提案

### 为什么要独立上下文？

预演的迭代修改会产生大量中间状态（多次渲染、多次规划反馈）。如果留在主 agent 的上下文里：一是上下文爆炸；二是大量失败的中间尝试会污染主 agent 的决策判断（心理学的 "锚定效应" 的 agent 版）。独立上下文 = 把 "试错的脏活" 与 "决策的判断" 隔离，主 agent 只看干净的结果。这是多 agent 架构中 "上下文卫生学" 的漂亮应用。

### 与学习式世界模型的本质对比

| 维度 | Imagination Agent | 学习式世界模型（GR-2 类） |
|---|---|---|
| 预测机制 | IK + 运动学规划（解析） | 神经网络外推 |
| 可靠性 | 结构化环境内近乎精确 | 分布外退化 |
| 覆盖面 | 只限可解析的物理（刚性、运动学） | 原则上可学任意动态 |
| 成本 | 每次规划毫秒级 | 每次视频生成秒级+GPU |

结论重申：在 "已知几何 + 刚性物体 + 准静态" 的操作场景，解析式想象完胜；学习式世界模型的领地在解析不可达处（柔性物体、流体、与其他 agent 交互）。这为今日论文 2 的 "对比缺口" 提供了一个具体的假设：**世界模型的闭环优势应该集中在解析求解器失效的场景**。

## 附录 A2：问题形式化的教学式解读

WAA 的形式化（式 1）值得逐符号解读，因为它精确刻画了 "VLM 驾驶" 的本质：

- **u_t ~ π(·|g, C_t, m_t)**：策略是纯函数——同样的指令、画布、上下文决定工具调用。没有隐藏状态、没有 RNN 记忆——所有 "记忆" 都外化在画布与上下文文本中。这是 Transformer 时代 "stateless agent + externalized state" 哲学的延续。
- **C_t（画布）**：多视图渲染 + 标定。它是 agent 的 "视网膜"，但被工程化地优化过（视角选择），不是被动传感器。
- **m_t（控制上下文）**：有效空间引用、待定提案、执行反馈——这是 agent 的 "工作记忆"，由 harness 维护而非模型自己管理。
- **工具三分类的效果**：query/proposal 不改变物理世界，使 π 可以在提交前被任意次采样——这就是把 RL 里的 "模拟采样" 搬进了推理时。

公式虽只有一行，但它是 "把 POMDP 的观察函数交给优化器、把策略留给 VLM、把状态外化给 harness" 的完整宣言。

## 附录 B2：正交双视角与人类双目/移动观察的对照

为什么是两个正交视角而不是三个或全景？

- **误差几何**：3D 对齐误差是 3 自由度。两个正交的水平投影恰好提供两个独立观测方向，覆盖平面误差（x、y）；深度方向的误差（z）由接近运动的视角变化补足——拖拽接近时自然获得第三方向。
- **认知负荷**：全景给 VLM 的是 "数据过载 + 分辨率稀释"；两个 512² 的正交特写是 "刚好够读出关系" 的信息熵配置。
- **与人类的对照**：人类对齐物体时的本能动作正是 "绕到侧面再看一眼"——WAA 的正交双视角把这个策略固化成了几何约束。E_stab 项则对应人类的 "别转太快，会晕"。

这个设计的普遍教训：**给空间智能体的视觉输入应该按 "误差可读性" 而非 "覆盖完整性" 配置**。全景提供上下文（WAA 也保留一个全局视图），特写提供精度——两者的分工与人类中央凹/周边视觉的分工同构。

## 附录 B2b：视角内修正的操作语义分析

in-view correction 看似简单（"在图上拖一下"），但语义上有三层精妙：

1. **指代结构**：拖拽 = (参考点, 位移矢量, 视角)。参考点可以是夹爪或所持物体上的可见点——后者意味着 agent 可以说 "把这个碗的边缘往右挪" 而不必知道夹爪该去哪。这是 **对象中心（object-centric）而非姿态中心（pose-centric）** 的动作语义，与 OmniManip 等物体中心工作呼应但更直接。
2. **有界性**：harness 把拖拽转换为 "有界" 末端位移——图像空间的拖拽距离到物理位移的映射有一个上限，防止 VLM 的一次幻觉拖拽变成 20cm 的物理运动。安全约束在接口层而非提示层实现。
3. **修正后的再观察回路**：每次修正后 fresh observation 让 agent 决定 "继续调 / 松手 / 下一步"——修正不是开环指令而是闭环对话。类似人类精细放置时的 "放-看-再调" 微动循环。

这三层共同把 "图像空间" 变成了一个真正可编程的动作语言，而不仅是可视化。

## 附录 D2：实验结果的批判性精读

### 75.6% 的含金量分析

- 对 ASPIRE（72.0%）领先 3.6 点：幅度中等，在 100+ episode 的评测上是否显著取决于方差（论文若未报多种子/置信区间则存疑）。
- "同 backbone 视觉 harness 基线" 是最关键对照：它隔离了 "工作区设计" 的贡献（相对于 Show-Harness 式简单接口）。WAA 超过它多少？摘要说 "outperforming ... a visual-harness baseline with the same backbone" 但未给数字——这个数字其实是全文最重要的消融，应追问。
- LIBERO-90 → LIBERO-Pro：技能从训练域进化、在对抗域评测，这个设置对 "泛化" 的测量是诚实的。但注意技能进化用的 LIBERO-90 与 LIBERO-Pro 共享物体/场景族，严格 OOD 程度有限。

### 1.7% → 43.3% 蒸馏结果的两面性

亮点：9B 模型能学会操作 harness，说明工作区接口是 "可学习的"——这对降低部署成本意义重大。
另一面：43.3% 仍远低于大模型驾驶的 75.6%，且差距（32 点）就是 "通用推理能力" 的价格。这给 "蒸馏路线" 划定了现实预期：**蒸馏买到成本，买不回能力**——与 LLM 蒸馏的一般规律一致。

### 缺失的消融

读者最想要但摘要层面未见：
1. 去掉 Imagination Agent（主 agent 自己迭代修改）的损失
2. 去掉 in-view correction（只做目标级动作）的损失
3. 随机视角 vs Contact views 优化的损失
4. 技能库为空（纯工作区、无技能）的表现

这四个消融分别对应三大设计的贡献分解与技能库的贡献——是判断 "哪个组件最值钱" 的关键。期待 v2 或开源后社区补齐。

## 附录 E：WAA 作为 "空间智能操作系统" 的架构解读

把 WAA 的组件映射到操作系统概念，会发现一个惊人的同构：

| OS 概念 | WAA 对应物 | 功能 |
|---|---|---|
| 硬件抽象层 | Contact views + 投影标定 | 把 3D 物理世界渲染成 VLM 可读的 "标准视图" |
| 系统调用 | 三类工具（query/proposal/execution） | 受控的能力暴露面 |
| 沙箱 | Action rehearsal | 不可逆操作前的预演执行 |
| 守护进程 | Imagination Agent | 后台迭代求解，主线程只收结果 |
| 动态链接库 | Skill Agent + 技能库 | 可复用程序性知识的检索与加载 |
| 编译器 | 蒸馏管线（轨迹→9B） | 高级操作编译成高效二进制（小模型直觉） |

这个同构提示 WAA 的真正贡献可能不是某个算法，而是 **"具身操作系统" 的架构草案**：VLM 是 CPU（通用推理），harness 是 OS（安全管理物理资源），技能库是软件生态。如果这个类比成立，那么未来的竞争焦点是 "哪家的具身 OS 生态更繁荣"——技能库的格式标准、共享协议、质量评审机制，正如移动时代的 App Store 之争。

## 附录 F：与今日论文矩阵的互补性分析

### 导航 vs 操作：接口复杂度定律（草案）

综合论文 1（GPT-6-Astra 导航）与本文（WAA 操作），可以提出一个初步的设计定律假设：

> **任务所需的接口结构化程度 ∝ 空间自由度连续性 × 错误不可逆性 ÷ 语义复杂度**

- 导航：语义复杂（指令理解）但自由度相对粗（走到哪都行，错误可恢复）→ 最小接口够用
- 操作：自由度连续（毫米级位姿）且错误不可逆（打碎）→ 需要完整工作区（视角优化+预演+修正）

这个定律若成立，可以预测其他任务的接口需求：
- 折衣/柔性操作：比 WAA 现状更需要学习式预演（解析不可达）→ 世界模型的真正战场
- 手术：不可逆性极高 → 预演+人类审批的双重保险
- 无人机穿越：错误不可逆+实时性 → 预演不可行（太慢），需要训练内化的策略——恰好解释为什么竞速无人机用端到端 RL 而不是 agentic 框架

## 附录 G：可复用工程模式的提炼

WAA 中至少四个模式可移植到任何 "LLM 驾驶物理系统" 的场景：

1. **提案-预演-提交**：任何不可逆操作（数据库变更、代码部署、金融交易）都可套用：agent 产出提案 → 干跑/仿真/影响分析 → 人工或自动审批 → 提交。
2. **视角优化目标函数**：信息呈现的自动化设计——给 VLM 看什么视角、什么分辨率、是否稳定，都可以形式化为优化问题。
3. **上下文卫生学**：把试错的中间噪声隔离在子 agent，主上下文保持决策干净。
4. **证据化评审**（evidence-based review）：技能入库前经过审查，对应人类组织的 "code review"——知识积累的质量关口。

## 附录 G2：失败场景推演

为了让分析更立体，构造几个 WAA 可能失败的具体场景：

1. **透明玻璃杯抓取**：点云在透明物体上残缺 → Contact 视角优化基于错误几何 → 预演的可行性判断全错。VLM 语义上 "知道" 这是玻璃杯，但工作区不给它表达怀疑的通道。
2. **抽屉里的袜子（柔性物体）**：IK/规划器假设刚性 → 预演显示可行，实际拉抽屉时袜子滑动导致抓空。预演与现实的 gap 无反馈机制修正（除非 in-view correction 补救，但抓空发生在接触瞬间，修正回路太慢）。
3. **动态干扰**：宠物撞桌 → 场景点云失效 → 画布与现实脱节。需要重感知机制，但 E_stab 项反而在抑制视角更新。
4. **技能检索错误**：任务 "把杯子放到架子上" 检索到 "把杯子放到碟子上" 的技能 → 执行到一半才发现目标高度不同。evidence-based review 管入库质量，不管检索匹配度。

这些场景的共同点：**工作区对 "感知-几何失配" 无自检机制**。一个可能的补丁是给画布加 "新鲜度指标"（点云与当前 RGB 的一致性分数），失配时强制重感知。这些建议可作为后续论文/开源版的改进方向。

## 附录 H：对 Spatial AGI 产品化的路线启示

假设一家公司要在 12 个月内做出 "通用家庭操作机器人" 原型，WAA 提供的路线图：

### 阶段 1（0-3 月）：工作区 MVP

- 固定 RGB-D 相机 + 点云融合 → Contact views 管线
- cuRobo 类规划器 + 预演渲染
- 调用最强可用 VLM API 作为主 agent
- 目标：在 10 个家庭常见任务上打通 "提案-预演-执行-修正" 闭环

### 阶段 2（3-8 月）：技能生态

- 人类遥操作示教 → evidence-based review → 技能库
- Skill Agent 检索上线
- 覆盖 50+ 技能，开始测量 "新任务由已有技能组合解决的比例"

### 阶段 3（8-12 月）：成本工程

- 交互轨迹蒸馏到 9B-30B 端侧模型
- 简单步骤路由小模型、复杂决策路由大模型
- 单任务 VLM 成本目标：从数千次调用降到数百次

### 关键风险对冲

- 柔性/透明物体：预演失效 → 预留学习式预测分支（这正是学习式世界模型的入场券）
- 延迟敏感步骤：纯 agentic 无法胜任 → 保留 VLA 快速通路的混合架构

## 附录 H2：多 agent 分工与通信协议的再思考

WAA 的 agent 角色表：

| Agent | 上下文 | 职责 | 输入 | 输出 |
|---|---|---|---|---|
| 主 agent | 任务+画布+上下文 | 感知判断、提案、执行决策 | Canvas, m_t | 工具调用 |
| Imagination Agent | 独立 | 迭代修改提案至可行 | 意图+不可行反馈 | 修订提案 |
| Skill Agent | 独立 | 技能检索与适配 | 任务描述 | 技能指导 |
| （人类） | 遥操作 | 示教 | 工作区界面 | 示教轨迹 |

通信都通过结构化工件（提案、技能指导）而非自然语言自由对话——这保证了可解析性与可复现性。**结构化工件 > 自然语言** 作为 agent 间协议，是一个值得在任何多 agent 系统中优先考虑的设计选择。
