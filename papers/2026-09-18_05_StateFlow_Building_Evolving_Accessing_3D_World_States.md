## 一句话总结

StateFlow 把"生成式预可视化"（影视/游戏/建筑设计的中间层创作）从一次性图像/视频合成重新形式化为**持久 3D 世界状态建模**：世界 W^t = {物体实体}，每个实体 = (几何 g, 空间位姿 p, 语义属性 s) 三元组；三阶段流水线——状态构建（前视图语义接地 + BEV 空间接地的先验引导冲突感知双视图初始化）、状态演化（意图引导的结构化状态转移表更新，支持场景扩展/风格改变/物体运动/离散事件替换且保留世界记忆）、状态访问（VLM 提案 + 渲染反馈反射的相机规划）——同一持久 3D 世界同时服务分镜/运镜/视频生产与 3D 游戏原型两类下游；视频模型只被当作世界状态的"观测器"而非世界本身。

## 核心问题

### Q1: 这篇文章的核心算法原理是什么？

**问题**：这篇文章的核心算法原理是什么？请详细描述：1) 核心思想和动机，2) 主要技术方法，3) 算法流程和关键步骤，4) 输入输出。

**分析**：

#### 1. 核心思想和动机

预可视化（previsualization）是影视、游戏、建筑与城市设计中"想法 → 成品"之间的中间层：创作者规划场景、编排动作、测试相机、探索时空动态。现有生成式方法（图像/视频模型）不适配这个迭代过程：

- **一次性合成范式**：简单 prompt 必须同时指定场景内容、布局、运动与相机；生成的观测不暴露持久状态，无法局部编辑与验证；
- **结果病灶**：时空不一致、身份漂移、修改/扩展/换机位时细节不稳定。

**核心洞察**：一个世界由多个带几何、外观、属性的元素 + 相机构成；不同帧/镜头大部分是**复用共享状态**，只对子集做局部修改或重组。因此预可视化的正确建模对象不是孤立的视觉输出序列，而是**显式且持久的工作状态**。

形式化为三函数过程：

```
W^0 = F_build(C)      # 从输入条件构建初始世界状态
W^t+1 = F_evolve(W^t) # 随时间演化
y^t = F_access(W^t)   # 可控访问（渲染/交互）产生观测
```

这一分解把生成式模型里纠缠在一起的三种角色分开：世界状态 W^t、其演化 F_evolve、观测 y^t。**视频不是世界，视频只是世界的观测**——需要更高保真时才调用现成视频模型增强几何接地观测，不改动底层世界。

#### 2. 主要技术方法

**状态表示**：W^t = {o_i^t}，o_i^t = (g_i^t, p_i^t, s_i^t)：
- g：几何（渲染与物理推理的基础）；
- p：3D 位置与位姿（空间布局一致性）；
- s：语义/外观/状态描述符（可控语义演化）。
三者缺一不可：去 g 失视觉实现，去 p 失空间一致性，去 s 失可控演化。

**(a) 状态构建：Prior-Guided Conflict-Aware Dual-View Initialization**

单视图无法同时可靠捕捉物体细节与全局布局。StateFlow 生成两张互补参考图并显式处理冲突：
- **前视图** = 外观/资产源：物体身份、局部视觉细节、几何参考；
- **BEV 俯视图** = 空间源：地面布局、场景拓扑、粗空间支撑。

两图独立生成必然冲突（物体数量、位置、外观不一致），按非对称角色分派 + 因子化消解：
- **匹配物体**：前视图资产实例化，按 BEV 框放置；
- **BEV-only 物体**：用 VLM 结合 prompt、邻域物体与布局上下文判断——与 prompt 不符或物理上无支撑的作为幻觉移除/降权，合理的上下文元素保留；
- **前视图-only 物体**：作为语义锚保留，VLM 从 prompt、类别、邻近匹配物体推断暂定布局假设，后续联合优化精化。

**BEV → 3D 提升**：VLM 为每个保留物体预测接地先验 γ ∈ {grounded, floating}；结合 BEV 框与类别尺寸先验 s̄，通过接地感知提升算子得到初始 3D 框：b_i^(0) = Lift_γ(r_i^BEV, s̄_i)——grounded 物体按物体高度定垂直中心，floating 物体由 VLM/类别先验推断高度。不训练 3D 检测器就把语义接地线索转成物理合理的 3D 摆放。最后联合优化精化所有框。

**(b) 状态演化：Intent-Guided Structured State Transition**

不做连续动力学仿真、不重新生成视频，而是把用户意图翻译成**结构化状态表上的紧凑更新**：
- 场景扩展（长出新物体/区域）；
- 局部风格改变；
- 物体位姿与运动编辑；
- 离散资产替换（如破坏事件——物体换成破损版本）。

关键性质：**世界记忆保留**——每次编辑只动状态表的一个子集，避免全场景重生成，保持实体身份与空间关系的连续性，状态可复用于后续访问。

**(c) 状态访问：World-State Camera Planning with Render-Feedback Reflection**

双系统设计：
- **VLM 提案系统**：从导演意图与镜头风格提出相机轨迹；
- **渲染反馈验证系统**：几何忠实地渲染轨迹，暴露可见性、遮挡、取景、运动问题，反馈引导局部修复。

避免仅依赖 VLM 语义的相机规划（VLM 对"这个机位能不能看到目标"没有几何概念），也不训练相机策略——渲染即验证。

#### 3. 算法流程和关键步骤

```
输入: 自然语言创作意图 C（+ 可选参考图）
阶段1 状态构建:
  1.1 图像模型生成前视图（资产源）+ BEV（布局源）
  1.2 分别检测物体实例 / 2D 布局框
  1.3 跨视图冲突消解（匹配/BEV-only 幻觉过滤/前视图-only 布局假设）
  1.4 接地感知提升 BEV 框 → 3D 框 → 联合优化 → W^0
阶段2 状态演化（迭代）:
  2.1 解析用户意图 → 状态表紧凑更新（扩展/风格/运动/事件替换）
  2.2 保留世界记忆，局部修改 → W^t+1
阶段3 状态访问:
  3.1 VLM 从导演意图提出相机轨迹
  3.2 渲染轨迹 → 暴露可见性/遮挡/取景问题 → 反射修复
  3.3 输出几何接地观测；需要高保真时调用视频模型增强 → y^t
下游: 分镜/运镜/视频生产 或 3D 游戏交互原型
```

#### 4. 输入输出

- **输入**：自然语言创作意图；可选参考图；迭代中的编辑指令与镜头意图。
- **输出**：持久可编辑的结构化 3D 世界（物体几何/位姿/语义状态表）；相机轨迹；视频成品或可交互原型。
- **应用**：电影级分镜与视频生产、可控镜头规划、3D 游戏式交互原型设计。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**问题**：这篇文章与通用空间智能（Spatial AGI）有什么关系？请分析：1) 如何理解和表示空间，2) 如何处理空间关系，3) 对Spatial AGI有什么启发，4) 可以应用到哪些Spatial AGI场景。

**分析**：

#### 1. 如何理解和表示空间

StateFlow 的核心主张对 Spatial AGI 极其相关：**智能系统与世界的正确交互模型是"持久状态 + 局部演化 + 可控访问"，而不是"观测序列的生成"**。它把世界表示为对象级结构化状态表（几何/位姿/语义三元组），这几乎就是一个最小空间世界模型的形式化定义：

- **空间 = 物体在共享坐标系中的布置**：实体级、显式、可查询（与 SoftNav 的实体 token、与场景图方法同宗）；
- **时间 = 状态表的离散转移**：不是连续视频流，而是"什么变了"的结构化记录——世界记忆天然持久；
- **观测 ≠ 状态**：视频/图像是从任意相机对状态的投影。这个区分修正了"视频生成 = 世界模型"叙事中的一个概念混淆：能生成观测不等于维护状态。

#### 2. 如何处理空间关系

- **跨视图空间接地**：前视图（外观）与 BEV（布局）的非对称因子化，加上冲突感知消解，是"多源空间信息融合"的干净模板——每个源只负责自己擅长的空间信息类型；
- **接地先验（grounded/floating）**：显式建模"物体与地面的物理关系"，用 VLM 的语义常识补全 3D 布局的垂直维——语义先验兑换几何约束；
- **相机-空间关系**：渲染反馈反射把"相机与场景的几何关系"（可见性/遮挡/取景）纳入决策闭环，VLM 只提假设、几何做裁判。

#### 3. 对 Spatial AGI 的启发

1. **世界状态持久性是一等需求**：Spatial AGI 的世界模型讨论多聚焦"预测下一帧"（观测预测），StateFlow 提醒我们真正的世界模型要回答"状态如何演化"——可编辑、可记忆、可复用。具身 agent 的世界模型同样应该是状态表驱动（物体放了哪、什么变了）而非帧驱动。
2. **意图 → 结构化状态转移**：把语言指令翻译成状态表操作的范式可直接迁移到具身任务规划（"把杯子放到桌上" = 更新杯子的位姿状态 + 约束传播），比端到端视频预测更可审计。
3. **渲染反馈反射**："提案系统 + 几何验证系统"的双系统模式是空间智能的通用安全架构：学习模型提案、物理/几何系统验证。适用于相机规划、路径规划、操作规划。
4. **多视图角色因子化**：不同感知源有不同空间信息专长，融合时应显式分派角色并处理冲突，而非无差别拼接——对多传感器融合、多 agent 协同感知都有借鉴。

#### 4. 可以应用的 Spatial AGI 场景

- **创作与仿真内容生产**：影视/游戏/建筑预可视化（原生场景）；
- **具身仿真环境构建**：从意图快速生成可交互 3D 训练环境（合成数据引擎）；
- **机器人任务规划的世界模型**：结构化状态转移 + 渲染验证 = 可审计的任务规划器；
- **数字孪生的交互接口**：城市/工厂的意图级查询与演化推演；
- **空间智能评测环境**：自动生成带 GT 状态的评测场景（状态表即真值）。

### Q3: 基于前面的分析，这个方法的主要创新点和局限性是什么？与其他相关工作相比有什么优势和劣势？

**分析**：

#### 1. 主要创新点

1. **问题重形式化**：把生成式预可视化从"一次性视觉合成"重构为"持久 3D 世界状态建模"（build/evolve/access 三分解）——概念贡献清晰且具普适性；
2. **状态/观测分离**：明确"视频是世界状态的观测而非世界本身"，修正视频世界模型叙事的概念基础；
3. **冲突感知双视图初始化**：前视图/BEV 的非对称角色分派 + 三类冲突的显式消解协议，不训练 3D 检测器实现语义-物理接地；
4. **意图引导结构化状态转移**：编辑 = 状态表局部更新，保世界记忆，避免全场景重生成；
5. **渲染反馈反射相机规划**：VLM 提案 + 几何验证的双系统，无需训练相机策略。

#### 2. 主要局限性

1. **状态表示的粒度限制**：物体级三元组（g, p, s）不含物理属性（质量/摩擦）、关节结构、材质细节——真实物理仿真与精细操作场景需要更丰富状态；
2. **演化依赖 VLM 语义推断**：状态转移靠 VLM 解析意图，复杂动力学（流体、布料、碰撞后果）无真值，"演化后的世界"物理正确性无保证；
3. **双视图生成的固有上限**：物体几何来自图像模型的先验/资产库，多物体精细交互、复杂拓扑场景的几何质量受限；
4. **冲突消解的启发式性**：BEV-only 幻觉过滤、front-only 布局假设都依赖 VLM 判断，误差会进入状态表并传播；
5. **评测主观性**：预可视化质量天然主观，自动指标与人类创作需求的差距比常规视觉任务更大。

#### 3. 与其他相关工作的对比

| 维度 | StateFlow | 程序化场景生成 | LLM/VLM 资产布局 | 3D 生成模型 | Agentic 视频生成（MovieAgent 等） |
|---|---|---|---|---|---|
| 核心产物 | 持久 3D 世界状态 | 规则化大环境 | 检索资产布局 | 资产/场景网格 | 视频/分镜 |
| 可编辑性 | 结构化局部编辑 | 规则内 | 布局级 | 重新生成 | 候选选择 |
| 世界记忆 | ✓（状态表） | 部分 | 静态 | ✗ | 弱（依赖管理） |
| 相机控制 | 渲染反馈验证 | 脚本 | 有限 | 无 | 规划式 |
| 视频/观测角色 | 状态的观测（可调用增强） | — | — | — | 视频即产物 |
| 物理接地 | 接地先验 + 联合优化 | 规则保证 | 有限 | 隐式 | 无 |

**优势**：唯一以"持久可编辑世界状态"为中心、同时打通构建-演化-访问全链路的框架；概念上对"视频世界模型"给出更准确的定位。
**劣势**：视觉细节与物理真实性不如端到端 3D/视频生成（后者直接优化渲染质量）；资产多样性受生成先验限制；系统级 pipeline 的端到端误差传播比单一模型复杂。

## 核心技术发现

1. **预可视化 = 持久世界状态建模**：build/evolve/access 三函数分解，把纠缠在生成模型里的三种角色分离；
2. **状态/观测二分**：视频是世界状态的投影，不是世界本身——高保真需求由现成视频模型按需增强，不动底层世界；
3. **双视图非对称因子化**：前视图管资产、BEV 管布局、冲突显式消解、接地先验提升 3D——无训练的语义-物理接地；
4. **编辑即状态表局部更新**：世界记忆保留，身份与空间关系跨编辑持久；
5. **渲染反馈反射**：VLM 提案 + 几何验证的相机规划，学习系统提假设、几何当裁判。

## 与Spatial AGI的关系

### 直接贡献
提供了一个"最小可行世界模型"的完整实例：状态表示（实体三元组）、演化机制（意图→状态转移）、访问机制（可控渲染）——正是 Spatial AGI 所需的世界模型三要素的工程化蓝本。

### 技术启发
- 持久状态优于观测序列；
- 提案-验证双系统架构；
- 多感知源的角色因子化融合；
- 语义常识兑换几何约束（接地先验）。

### 应用场景
影视/游戏/建筑预可视化、具身仿真环境生成、机器人规划世界模型、数字孪生交互、空间评测环境自动构建。

## 个人思考

### 最令人兴奋的发现

最值得圈点的是那句"video is an observation of the world state, not the world itself"。当前"视频生成 = 世界模型"的叙事把观测预测和状态建模混为一谈——Sora 类模型可以生成一致的观测序列，但问它"桌子底下现在有什么"它没有答案，因为它没有状态。StateFlow 的三函数分解（build/evolve/access）给 Spatial AGI 的世界模型讨论提供了一个干净的概念坐标系：**World Model = 状态表示 + 转移机制 + 观测映射**，三个组件可以独立演进、独立评测。

另一个实用洞察是"提案-验证"双系统：VLM 相机规划单独用会产出几何上不可能的镜头（穿墙、遮挡主体），StateFlow 让渲染当裁判、VLM 只当编剧。这个分工对具身规划同样成立——LLM 提议、物理引擎裁决。

### 潜在局限

物体级状态表的表示力是天花板：真实世界的空间智能需要处理材质、关节、流体、部分整体关系、物体内部状态（杯子里的水）。StateFlow 的三元组对创作预可视化够用，对物理严密的世界模型不够。另外 VLM 在冲突消解中的幻觉判断本身就是误差源——"BEV 里多出来的椅子是不是幻觉"这类问题 VLM 的判断并不可靠，错误进入状态表后会随演化传播。

### 与今日其他论文的关联

- **PanoGS-SLAM**（今日 02）：StateFlow 的世界是"生成"出来的，PanoGS 的世界是"重建"出来的——两者代表世界状态的两个来源（生成式世界模型 vs 重建式世界模型）。合流点：SLAM 重建的世界状态同样应该结构化（实体表），StateFlow 的演化/访问机制可以接在 SLAM 状态之上；
- **SoftNav**（今日 04）：StateFlow 的实体状态表（几何/位姿/语义）与 SoftNav 的实体 token（几何/语义/空间关系）几乎是同一抽象的两面——前者服务创作，后者服务导航。统一两者（实体化空间状态 + 语言接口）就是 Spatial AGI 世界模型的雏形；
- **NormLift**（今日 01）：StateFlow 状态表中的语义属性 s 目前靠 VLM 推断，NormLift 式的语义化 3D 表示可以为重建来的世界提供更可靠的语义状态源。

StateFlow 把生成式预可视化重构为持久 3D 世界状态建模：状态/观测分离、意图驱动结构化演化、渲染反馈验证访问，同一持久世界支撑视频创作与游戏原型两类下游。它对 Spatial AGI 的最大价值在于给出了世界模型的形式化骨架与"提案-验证"安全架构的完整工程实例。

## 扩展分析：方法细节深挖

### A. 状态/观测分离的概念力量

把 y^t = F_access(W^t) 与 W^t+1 = F_evolve(W^t) 分开后，许多此前纠缠的问题变清晰：

- **一致性**：观测间的不一致（身份漂移、时空矛盾）根源是每次生成都是独立采样；状态固定后，任何相机的观测天然一致；
- **编辑**：对观测做编辑（视频改帧）是 ill-posed 的；对状态做编辑（改位姿表）是 well-defined 的；
- **多视角**：同一状态的任意相机渲染自动多视角一致；
- **视频模型的角色**：从"世界模拟器"降级为"神经渲染增强器"——接受几何接地观测、输出高保真视频，世界观仍是确定性的状态表。

这个概念框架与 model-based RL 中"state vs observation"的经典区分同源，StateFlow 把它引入生成式创作领域并给出工程实例。

### B. 双视图冲突消解的协议设计

三类冲突的处理各自对应一种认知原则：

- **匹配物体**：外观锚定（前视图）+ 空间锚定（BEV），直接合并——信息互补时的标准融合；
- **BEV-only**：布局图里多出的物体。用 prompt 与邻域做幻觉判别（"prompt 没提 + 物理无支撑 → 删"）。这里隐含了一个先验：布局生成模型比语义先验更容易幻觉出多余物体；
- **前视图-only**：语义上存在但布局图漏掉的物体。作为"语义锚"保留并用 VLM 推断位置——语义源比布局源更可信的物体存在性。

非对称信任结构（外观信前视图、布局信 BEV、存在性信语义+物理常识）是整篇方法最精致的设计。

### C. 接地先验与提升算子

Grounded/floating 二分类是对垂直维接地关系最简的离散化：桌上的杯子 floating（由桌子表面支撑高度）、树 grounded。配合类别尺寸先验 s̄，把 2D BEV 框升为 3D 框只需要一次查表式计算。训练 3D 检测器 vs 用 VLM 常识 + 尺寸先验，后者零样本、可扩展到任意类别——典型的"语义常识兑换几何监督"策略。

### D. 渲染反馈反射的循环

相机规划循环：VLM 提案 → 几何渲染 → 检测四类问题（可见性/遮挡/取景/运动）→ 定位问题根因 → 局部修复提案 → 再渲染。与 ReAct/ Reflexion 类 agent 范式同构，但验证器是确定性的几何渲染器而非 LLM 自评——这避免了 LLM 自我验证的确认偏差。确定性验证器 + 生成式提案者的组合是 agentic 系统的稳健模式。

### E. 演化机制的层次

四类演化操作对应四种状态表变更：

1. **场景扩展**：增实体（新 o_i）+ 布局约束传播；
2. **风格改变**：只动 s（外观描述符），g/p 不变——身份保持；
3. **位姿/运动编辑**：动 p（含轨迹段），几何语义不变；
4. **事件替换**：g 整体替换（完好杯子 → 碎杯子），但 s 中的身份与 p 中的位置延续——世界记忆的体现。

每类操作都最小化状态变更范围，这是"编辑连续性"的算法保障。

## 扩展分析：对 Spatial AGI 研究路线的启示

### F. 生成式与重建式世界状态的合流

世界状态的两个来源：StateFlow 的生成式（意图 → 状态）与 SLAM 的重建式（观测 → 状态，如 PanoGS-SLAM）。两者的状态表示正在趋同——实体级结构化状态。可以预见一个统一栈：

```
真实观测 → SLAM/重建 → 结构化世界状态 → （StateFlow 式）演化与访问
                                          ↑
                                   创作意图 / agent 意图
```

Spatial AGI 的世界模型本质上是这个栈：真实与生成的边界在状态层面消失。

### G. 可评测性红利

状态表即真值：StateFlow 式世界天然提供空间推理评测的 GT（物体 A 在相机 2 是否可见、编辑后物体 B 的位置）。这解决了空间智能评测的一个痛点——真实场景的 GT 采集昂贵。自动生成带 GT 的评测世界是 Spatial AGI benchmarking 的一条务实路线。

### H. 意图接口的泛化

"自然语言意图 → 结构化状态转移"这个接口对具身 agent 的任务规划同样成立。机器人收到指令后做的本质上是同一件事：解析意图 → 规划状态转移序列 → 执行并验证。StateFlow 的渲染反馈验证对应机器人执行中的感知闭环。两者的方法论可以互馈。

## 常见问题（FAQ）

**Q1: StateFlow 与视频世界模型（如 Genie 类）的关系？**
互补而非替代：视频世界模型学习观测分布，适合快速交互预测；StateFlow 维护显式状态，适合需要可编辑性、一致性、可查询性的创作与规划。长期看显式状态 + 神经渲染增强是更可审计的形态。

**Q2: 物体几何从哪来？**
前视图资产（图像生成模型产出）+ 几何参考。不依赖固定资产库（区别于 LLM 布局方法），但几何精细度受图像-to-3D 先验限制。

**Q3: 相机轨迹的平滑性如何保证？**
渲染反馈检测运动问题（抖动/穿模），修复在轨迹参数层面局部进行；风格约束（导演意图）由 VLM 提案端保证。

**Q4: 能用于真实场景编辑（如数字孪生）吗？**
概念上可以：重建的结构化状态 + StateFlow 演化。但重建状态的实体化（从网格/高斯中提取物体三元组）仍是研究问题。

**Q5: 多物体物理交互（碰撞、堆叠）如何处理？**
主要通过接地先验与联合优化保证静态合理性；动态物理后果不仿真，靠离散资产替换表达事件结果——这是状态表范式的当前边界。

## 对后续研究的具体建议

1. **状态表示增维**：物理属性、关节、材质、容器关系（杯中的水）——向物理严密世界模型靠拢；
2. **重建式状态注入**：把 SLAM/3DGS 重建场景实体化为状态表（连接 PanoGS/SoftNav/NormLift 栈）；
3. **演化物理验证**：状态转移后用物理引擎验证合理性，替代纯 VLM 判断；
4. **评测集构建**：用 StateFlow 自动生成带状态 GT 的空间推理评测任务族；
5. **与 VLA 规划对接**：把意图→状态转移接口接到机器人任务规划，渲染反馈换成真机感知闭环。

## 风险与反思

- **表示粒度**：物体级三元组对创作够用、对物理智能不够；
- **VLM 幻觉传播**：冲突消解与布局假设的错误进入状态表后随演化累积；
- **生成几何上限**：资产几何质量受图像-to-3D 先验限制；
- **评测主观性**：预可视化质量的人工评估难自动化；
- **管线复杂度**：多阶段多模型的误差传播与调试成本高于端到端模型。

## 深度问答与批判性检验

### Q: "视频是观测不是世界"这个论断对视频世界模型公平吗？
对 Genie/Sora 类纯观测模型公平——它们确实没有可查询的状态。但对带隐状态的世界模型（RSSM 类）不完全公平：它们维护隐状态，只是不可编辑、不可查询。StateFlow 的真正论点是**显式可编辑状态**优于**隐式状态**与**无状态**，而非否认状态建模的价值。

### Q: 双视图生成的冲突率实际有多高？消解的可靠性？
论文未给出冲突率的统计。直观上图像模型对"俯视图里该有几把椅子"的控制很弱，冲突应常见。消解依赖 VLM 判断，其错误率直接进入状态表。这个模块的可靠性是整个系统精度的天花板——也是最值得后续工作量化的部分。

### Q: 结构化状态转移 vs 神经动力学预测，哪个是世界模型的终局？
短期各有领地：创作/规划需要可审计性（状态表赢），物理预测需要连续动力学（神经预测赢）。长期收敛形态可能是**结构化状态 + 神经转移函数**：状态表提供可查询骨架，转移由学习的动力学模型驱动并在实体粒度上落地。StateFlow 的 VLM 转移是这条路上语义驱动的第一步。

### Q: 渲染反馈能发现所有相机问题吗？
不能。几何渲染能查可见性/遮挡/取景/穿模，但查不了美学（构图情绪、节奏感）与叙事逻辑（镜头语言是否表达意图）。这些仍依赖 VLM 提案端的人类先验。双系统的分工边界：物理可行性归渲染，叙事合理性归 VLM 与人类。

### Q: 状态表方案如何扩展到开放世界规模（城市级）？
物体级状态表在城市尺度会爆炸（百万实体）。需要层次化状态（区域-建筑-物体三层）+ 稀疏激活（只物化当前视野的状态细节）+ LOD 式状态精度管理。这与空间智能的通用问题一致：状态表示必须随规模层次化。

## 给工程师的实施要点

1. 状态表建议用 schema 化存储（实体 ID、几何引用、位姿、语义 JSON），编辑操作全部走状态 diff；  
2. 双视图生成时在 prompt 中显式约束两图的一致性要素（物体类别清单）可降低冲突率；  
3. 冲突消解的 VLM 调用应带邻域上下文，孤立判断幻觉不可靠；  
4. 相机规划循环设置最大反射轮数（如 3 轮）防死循环；  
5. 视频增强模型按需调用：预览用直渲染（实时），成片才调视频模型（昂贵）；  
6. 状态表即 GT：可直接导出为下游评测或仿真环境的真值标注。

| 构建 | 双视图生成 + 冲突消解 + 接地提升 | 图像生成模型、VLM | BEV 幻觉物体、前视图布局错误 | VLM 语义+物理常识过滤、联合优化 |
| 演化 | 意图→状态表转移 | VLM | 转移语义误读、物理不合理 | 最小变更原则、（可加）物理引擎验证 |
| 访问 | 相机提案+渲染反馈 | VLM + 渲染器 | 美学/叙事问题几何查不出 | VLM 提案端风格约束、人工终审 |

## 附录B：与"视频世界模型"叙事的三点辨析

1. **可生成 ≠ 可查询**：视频模型能生成"合理的下一帧"，但不能回答"桌子底下有什么"——查询需要状态；  
2. **一致性来源不同**：视频一致性靠生成先验（软约束），状态一致性靠共享表示（硬保证）；  
3. **编辑能力不同**：对观测编辑是 ill-posed 的图像修复问题，对状态编辑是 well-defined 的局部更新问题。  

StateFlow 的贡献是把这三点辨析落成了可运行的系统。对 Spatial AGI 的迁移价值：任何声称"世界模型"的系统都应回答这三个问题——状态在哪、一致性从哪来、怎么编辑。

## 附录C：常见误读澄清

**误读1**："StateFlow 是又一个视频生成系统"——不。视频模型只是它按需调用的观测增强器；系统的核心产物是结构化 3D 状态表，视频是状态的投影。

**误读2**："预可视化是个小众应用"——预可视化只是切入点。build/evolve/access 的世界状态范式对具身仿真、机器人规划、数字孪生是通用的。

**误读3**："结构化状态 = 简单场景图"——场景图通常只有静态关系；StateFlow 的状态含几何、位姿、语义三元组且支持时间演化与事件替换，是带动力学语义的可变状态。

**误读4**："不用视频模型就不行"——直渲染已可用于预览与交互；视频模型是保真增强选项而非依赖项。
