# FloMo: 3D Scene Flow as a World Action Model Intermediate for Learning from Human Video

**发表日期**: 2026-11-03

## 论文概览

FloMo 的核心论点极其锋利：**视频是一个对动作预测来说高度冗余的信号；稠密 3D 运动才是视频预训练迁移到机器人动作的真正媒介**。预训练视频生成模型蒸馏了互联网尺度的运动先验，但如果世界动作模型（WAM）以"预测未来像素"为目标，模型容量会浪费在与控制无关的纹理、光照、材质、背景上。

FloMo 的做法：把 3D scene flow（每个场景点在规范坐标系下随时间的 3D 位移）渲染成 RGB 视频，用**冻结的预训练视频 VAE** 编码——让"运动"与"视频"共享同一个 latent 空间，从而用同一个 5B 视频生成骨干（Wan 2.2 DiT）flow-match 预测 scene flow token 和 action token。仅在人类视频（无动作标注）+ 机器人遥操作数据（有动作标注）上共训，就能泛化到未见过的物体、运动基元和任务。

关键实验结论（全文最有杀伤力的部分）：
- 用视频预测目标**替换**运动预测 → OOD 泛化**变差**；
- 在运动之外**加**视频目标 → 策略成功率**下降**而非提升；
- 运动+视频+动作联合预测时，注意力分析显示 **action token 对 motion token 的注意力远大于对 video token**——预测视频是在浪费模型容量。

## 核心问题

### Q1: 这篇文章的核心算法原理是什么？

**1) 核心思想和动机**

- 视频到动作的迁移通常被归因于"RGB 与产生它的动作之间的信息重叠"。但视频是比动作高得多的熵信号：纹理、光照、材质、背景不同的视频可以描述**同一个运动**、蕴含**同一个动作**。像素级 WAM 把容量花在外观上，而这些外观对动作预测毫无用处。
- 核心问题重述：**哪个预测目标能让视频预训练最直接地迁移到动作？** 作者的回答是 3D 运动：
  - 给定当前观测，产生未来状态的动作取决于**场景如何变换**而非它看起来什么样；
  - 运动是低熵、纹理不变的目标，模型无需自己学习不变性，不变性被直接内置在目标里；
  - 动作头面对的是一个更紧的信息瓶颈，可以直接解码。
- 2D 光流不够：它混淆相机自运动与任务相关运动。3D scene flow 在规范坐标系（窗口首帧相机坐标系）中表达，隔离几何状态转移，丢弃外观与相机运动。
- 巧妙之处：预训练视频 VAE 本身就是一个现成的运动 latent 空间。把 scene flow 渲染为 RGB 就能直接用冻结 VAE 编码，无需训练新 tokenizer。

**2) 主要技术方法**

**(a) 问题形式化**

两类数据：
- 自我中心人类视频 V = {(o_{0:T-1}, ℓ)}：16 帧 RGB 序列 + 语言指令，无动作；
- 机器人交互数据 R = {(o_{0:T-1}, ℓ, a)}：额外有 T×da 动作块。
两类数据都离线提取 3D scene flow 序列 F_{0:T-1}。模型学习 p(F_{0:T-1}, a | o_0, ℓ)。

**(b) Scene flow 提取与规范坐标系**

- 用现成的 SpatialTrackerV2 3D 点跟踪器离线提取；
- 每个片段滑窗 T=16 帧，首帧 64×64 网格放 Q=4096 查询点，反投影到 3D 并跨窗传播，得到轨迹 {p_i(u,v)}；
- 所有轨迹表达在**窗口首帧相机坐标系**（原点为当前相机焦点），对相机自运动不变，运动场主要反映物体与手的运动；
- 提取成本 ≈2.4 s / 16 帧窗口（单张 L40S）。
- **累积 scene flow**：F_i(u,v) = p_i(u,v) − p_0(u,v)（首帧到第 i 帧的总 3D 位移，F_0=0）。比逐帧瞬时速度更平滑，抑制逐帧跟踪噪声，使指尖/物体级细粒度运动可被精确预测。

**(c) Scene flow 的 token 化（复用视频 VAE）**

- 累积 scene flow 的每个位移通道按数据集全局 1st/99th 百分位裁剪并缩放到 [0,1]，渲染为 RGB 视频 F_rgb；
- 用**冻结的 Wan 2.2-TI2V VAE 编码器** E 编码：z^f = E(F_rgb) ∈ R^{Tz×48×Hz×Wz}（时间步长 4，首帧单独编码；空间步长 16）；
- 效果：scene flow token 与视频 token 分布相近，骨干不偏离视频预训练太远，无需新 tokenizer。

**(d) 架构**

- 骨干：预训练 Wan 2.2 5B Text-Image-to-Video DiT；
- 观测：冻结 VAE 编码 o_0 成 conditioning prefix；umT5-XXL 冻结文本编码经 cross-attention 注入；
- 预测目标：scene flow latent z^f + action token（20 维双臂末端动作空间：每臂 3D 位置+6D 旋转+1D 夹爪，2nd/98th 百分位归一化）；视频 latent z^v 仅在消融中启用；
- 动作 token：噪声动作线性投影成 DiT token；
- 所有目标 token 沿序列维拼接，由共享 DiT 联合去噪；双向全注意力；
- **LoRA 微调**（r=64, α=128, dropout 0）：注入全部 30 个 block 的自/交叉注意力 QKVO 与两个 FFN；VAE 与文本编码器冻结；可训参数仅 ≈161M（在 5B 冻结骨干之上）；
- 损失掩码机制使同一骨干支持任意输出模态子集。

**(e) 训练目标与流程**

Flow-matching 损失：单一噪声水平 t~U[0,1] 共享于所有模态，x_t=(1−t)x_0+tε，速度目标 v=ε−x_0。
L = λ_f‖v̂^f−v^f‖² + λ_a‖v̂^a−v^a‖² + λ_v‖v̂^v−v^v‖²
默认 λ_f=1, λ_a=0.1, λ_v=0（人类视频样本 λ_a=0）。

- **Stage 1 中训练**：≈14,000 步，全局 batch 512，lr 2.8e-4；完整混合数据（人类视频只监督 scene flow；机器人数据监督 scene flow+action）；建立大规模自我中心运动先验。
- **Stage 2 微调**：≈1,500 步，batch 256，lr 5.6e-5；只用机器人数据，λ_a=1；锐化动作预测。

**(f) 推理**

给定 o_0 与指令，UniPC ODE 求解器 + 移位噪声调度积分速度场，联合去噪 motion 与 action 头。

**3) 算法流程和关键步骤**

```
离线：所有视频 → SpatialTrackerV2 提取3D点轨迹 → 首帧坐标系累积scene flow → 渲染成RGB
训练：
  Stage1: 人类视频(scene flow loss) + 机器人数据(scene flow+action loss)
          Wan2.2 5B DiT + LoRA，冻结VAE/文本编码器
  Stage2: 仅机器人数据，action loss 权重↑
推理: o_0 + 指令 → 联合去噪 → scene flow + 动作块
```

**4) 输入输出**

- **输入**：初始观测图像 o_0 + 语言指令 ℓ
- **输出**：未来累积 3D scene flow（latent 形式，可解码为逐点 3D 位移场）+ 20 维双臂动作块
- **中间表示**：scene flow 与视频共享同一 VAE latent 空间

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**1) 如何理解和表示空间**

FloMo 对空间的理解浓缩在一个表示选择里：**空间 = 点集在规范坐标系下的位移场**。3D scene flow 剥离了外观（纹理/光照/材质）与相机自运动，只保留"什么在哪里、往哪里动"——这正是空间智能需要的最小充分信息。把位移场渲染成 RGB 并塞进视频 VAE，则是对"空间结构可以用感知模态的原生格式编码"的漂亮证明：空间信息不必有专属 tokenizer，它可以寄生在为外观设计的表示系统里。

**2) 如何处理空间关系**

- **相机-场景关系**：规范坐标系（首帧相机焦点为原点）显式解耦相机自运动与场景运动，是"观察者无关"的空间描述；
- **点-点关系**：4096 个查询点的 3D 轨迹保持物体/手内部与相互之间的空间拓扑随时间演化；
- **运动-动作关系**：累积位移场是动作的充分统计量的近似——动作头直接从运动场解码动作，中间不需要恢复外观；
- **人类-机器人关系**：共训使人类视频中的运动先验（怎么抓、怎么倒）通过共享的运动表示迁移到机器人动作空间，绕过了具身 retargeting 的困难。

**3) 对 Spatial AGI 的启发**

- **低熵目标是样本效率之源**：预测目标的信息熵直接决定训练效率。对 Spatial AGI 的任何预测任务（未来状态、轨迹、可供性），都应问"这个目标的运动学充分统计量是什么"。
- **预训练资产的最大复用**：冻结 VAE + LoRA 的组合表明，空间智能模型不必从头构建空间 tokenizer——可以在已有感知系统的 latent 空间里表达新模态（运动、深度、占据）。
- **注意力归因作为容量审计工具**：action token 对 motion vs video 的注意力对比，是一种直接测量"模型容量花在哪"的方法，可推广为 Spatial AGI 架构诊断的标准手段。
- **人类视频的价值通过运动中介实现**：Spatial AGI 利用互联网视频的正确方式可能不是学像素预测，而是学运动预测。

**4) 可以应用的 Spatial AGI 场景**

- 从人类演示视频学习机器人操作（无动作标注的大规模数据利用）；
- 空间运动预测作为通用中间任务（导航、抓取、人机协作中的意图预测）；
- 视频世界模型的输出接口改造：世界模型 rollout 出 scene flow 而非像素，供下游规划直接消费；
- 跨具身技能迁移：运动基元作为具身无关的技能表示。

### Q3: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**1) 主要创新点**

1. **预测目标层面的范式挑战**：不改动架构、不改训练数据，只换预测目标（像素→3D scene flow），就得到 ID 成功率与 OOD 泛化的双重提升——这是对 WAM 设计空间的正交探索，结论干净有力。
2. **Scene flow 寄生于视频 VAE**：零新 tokenizer 成本把运动变成视频模型的"母语"，最大化预训练资产复用，这是工程与科学的双重优雅。
3. **累积位移代替瞬时速度**：平滑监督信号、抑制跟踪噪声的细节设计，让细粒度运动（指尖）可预测。
4. **负面结果的清晰呈现**：加视频目标反而掉点、联合预测时注意力天然涌向 motion——两个反直觉的实证结论对领域有矫正作用。
5. **人类视频→机器人动作的实证迁移**：泛化到仅在人类数据中见过的物体、运动基元、任务。

**2) 主要局限性**

1. **依赖 3D 点跟踪器质量**：SpatialTrackerV2 的跟踪误差直接成为监督噪声；对遮挡、快速运动、透明物体，离线提取的 scene flow 可能有系统性错误，且这些错误被渲染成 RGB 后无法被模型区分。
2. **4096 点的分辨率限制**：64×64 查询网格对细小物体、精细接触（穿针引线级任务）的空间分辨率不足。
3. **首帧坐标系对长程任务的非遍历性**：16 帧窗口与首帧锚定适合短时操作，长时程导航中相机大幅移动后，首帧坐标系可能不再是最优规范系。
4. **推理成本**：5B DiT + ODE 求解器联合去噪 motion+action，实时控制场景下的延迟论文报告有限（推断部分被截断，但从架构看不便宜）。
5. **评测域限制**：以桌面双臂操作为主，对导航、全身移动、多物体长程任务未验证；scene flow 对静态场景（"什么都不动"）的表达退化为零场，可能弱化"不动也是决策"的建模。

**3) 与其他相关工作的对比**

| 维度 | FloMo | 像素预测 WAM（Genie/GR-2类） | Latent action 类（LAPA等） | 2D 点轨迹接口类 |
|------|-------|------------------------------|---------------------------|-----------------|
| 预测目标 | 3D scene flow + action | 未来像素 | latent action | 未来图像点轨迹 |
| 熵 | 低（纹理不变） | 高 | 中 | 中（混淆自运动） |
| tokenizer | 复用冻结视频VAE | 自有 | 需对齐 | 2D |
| 相机自运动 | 显式剥离 | 混杂 | 混杂 | 混杂 |
| 3D 感知 | 有（3D位移） | 隐式 | 隐式 | 无 |
| 部署成本 | 中（DiT去噪） | 高（视频 rollout） | 低-中 | 低 |

**优势**：唯一以 3D 运动为 WAM 预测目标并用严格消融证明其优越性的工作。
**劣势**：依赖离线点跟踪器；分辨率与长程性受限；推理仍需 5B 骨干去噪。

## 核心技术发现

- **发现1**：预测 3D 运动优于预测视频——替换视频目标提升 OOD 泛化，附加视频目标反而降低成功率。
- **发现2**：action token 的注意力显著偏向 motion token 而非 video token，证明视频预测消耗模型容量而不服务控制。
- **发现3**：预训练视频 VAE 可以无损复用为运动 tokenizer（scene flow 渲染为 RGB 即可）。
- **发现4**：累积 scene flow（首帧锚定）比瞬时速度更平滑、更可学。
- **发现5**：动作无关的人类视频通过运动目标有效注入操作先验，泛化到未见物体/基元/任务。

## 与Spatial AGI的关系

### 直接贡献
确立了"稠密 3D 运动是视频→动作迁移媒介"的实证结论，为 Spatial AGI 的训练目标设计提供了低熵原则。

### 技术启发
- 预测目标的信息熵工程：为每个空间任务寻找纹理不变的运动学充分统计量；
- 预训练表示的最大复用模式（冻结 VAE + LoRA）；
- 注意力归因作为架构容量审计工具。

### 应用场景
从人类视频学操作、空间运动预测、世界模型输出接口、跨具身技能迁移。

## 个人思考

### 最令人兴奋的发现
"加视频目标反而掉点"这条负面结果。它推翻了"多任务监督总是有益"的直觉，说明在 WAM 里视频不是运动的有益补充而是有害干扰。结合注意力归因（action 更关注 motion），这几乎是在说：**像素是运动的低效载体**。如果这个结论在导航、全身控制等更多域上成立，那么整个"视频生成即世界模型"的叙事都需要加一个限定语——视频生成是训练载体，但世界模型的**输出接口**应该是运动而非像素。

### 潜在局限
整条管线建立在"离线 3D 点跟踪完美"的假设上。真实演示视频中的跟踪失败（遮挡、模糊）会被不加区分地渲染成监督信号。我预期后续工作会做跟踪置信度加权损失，或者把 scene flow 提取做成可学习/在线的部分以闭环纠错。另外 4096 点的离散化对接触密集型精细操作的分辨率可能是硬瓶颈。

### 与昨日研究的关联
昨天精读的 Trace4D（4D 状态序列做接地时空推理）与 FloMo 高度互补：两者都主张用"点级 3D 运动结构"替代原始视频作为空间推理的中间表示。Trace4D 从推理/评测角度切入，FloMo 从策略学习/预测目标角度切入，结论同向——**4D 点轨迹/运动场是空间智能的通用货币**。结合今天 PrimeSim 的世界模型模拟器，一个候选架构浮现：世界模型 rollout scene flow（FloMo 式目标）→ 4D 状态序列做推理与规划（Trace4D 式）→ 策略执行。

## 总结

### 核心发现总结
FloMo 用最干净的消融证明了 WAM 的预测目标应该是 3D scene flow 而非视频：运动是纹理不变的低熵信号，通过渲染成 RGB 复用冻结视频 VAE 即可让 5B 视频骨干直接 flow-match 运动与动作，人类视频的运动先验经此通道有效迁移到机器人动作。

### 对Spatial AGI的意义
为空间智能的训练目标设计确立了"低熵、纹理不变、观察者无关"三原则，并示范了预训练感知资产的最大化复用路径。它与 4D 状态序列推理（Trace4D）、世界模型模拟器（PrimeSim）共同指向"以 3D 运动为中心"的空间智能架构。
