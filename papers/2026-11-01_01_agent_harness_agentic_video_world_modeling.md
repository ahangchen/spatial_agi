## 论文概览

这篇报告研究了一个正在发生的范式转变：视频生成正从"端到端合成"走向"Agentic 生成"——即由具备规划、工具使用、反馈回路的 agent harness（智能体执行框架）来编排视频生成过程。同时，视频世界模型（video world models）提供了动作条件化的观察和未来预测，可以充当 agent 的交互环境。作者用"agent harness"（围绕模型的可执行运行时：构建上下文、暴露工具、维护状态、路由反馈、执行预算约束）作为统一的分析单元，覆盖三个方向：

1. **Agentic Video Generation**（智能体化视频生成）：harness 协调剧本与分镜规划、资产管理、分镜生产、剪辑。
2. **Agentic World Modeling**（智能体化世界建模）：harness 介入观察、控制、执行与状态维护，包括"游戏引擎/代码持有世界状态、视频模型负责渲染"的设计，以及 agent 与世界模型互相测试改进。
3. **Recursive Self-Improvement（RSI，递归自我改进）**：区分"对当前输出的修订"、"对 harness 状态/生成器参数/评估器的更新"、以及"对产生后续更新的流程本身的修改"，并识别改进回流到开发过程的通道。

## 核心问题

### Q1: 这篇文章的核心思想与框架原理是什么？

**问题**: 这篇文章的核心框架是什么？它如何组织视频生成与智能体的结合？

**分析**:

1. **核心思想和动机**

   - 视频生成器本身只能产出"一段越来越逼真的片段"，但完成一个视频任务需要一系列决策：创意简报如何变成连贯的分镜、参考素材如何跨场景持久化、生成的 take 如何被检查、剪辑如何保留正确内容。
   - 交互式视频还需要"基于观察的持续动作"，而不只是产出一段成品。
   - 因此作者提出从 video generation 到 **agentic video generation** 的转变：一个目标导向的过程，生成结果会反过来影响后续决策（修改计划、检索参考、选择工具、定位失败）。
   - 关键洞察：视频在时间维度上耦合了这些决策——参考影响后续镜头、动作改变后续观察、局部修复可能破坏其他地方的时间一致性。"看起来合理"的片段仍可能违反叙事要求或未能实现预期动作，所以单一质量分数无法指明下一步该做什么。
   - 有效的控制需要：把观察连接到局部化决策，同时维护项目/交互状态，并考虑生成成本。

2. **主要技术方法（Agent Harness 作为分析单元）**

   - **Agent Harness 定义**：围绕模型的可执行运行时（executable runtime），职责包括：
     - 构造 agent 的上下文（context construction）
     - 暴露工具（tool exposure）
     - 维护状态（state maintenance）
     - 路由反馈（feedback routing）
     - 强制权限与预算约束（permissions and budgets enforcement）
   - 对视频生成而言，harness 是"创意简报或交互目标变成对生成器、编辑器、世界模型的可执行操作"的地方。
   - 核心问题从"生成一个好片段"转变为"通过反馈可靠地完成一个视频任务"。

3. **反馈在不同时间尺度上改变不同对象（关键分类学）**

   - **当前工件层面**：prompt 修订、take 替换——修复当前这条视频。
   - **后续任务层面**：保留一个技能（skill reuse）——影响未来任务。
   - **后续模型版本层面**：更新数据集、critic、生成器——影响下一代模型。
   - 作者强调：这三者不应被混淆。修复了当前视频不代表未来能力得到改进——这是全文最重要的概念区分。

4. **Context Engineering 与 ACE**

   - Agentic Context Engineering (ACE)：从执行反馈中积累并修订结构化上下文，而不更新模型权重。这把注意力从"当前响应"转向"可复用知识"，但留下了"构建和更新知识的机制本身能否改进"这个开放问题。

5. **RSI 的严格定义**

   - RSI 问的是：系统能否改进"产生后续改进的程序"（the procedures that produce further improvements）。
   - 视频领域 RSI 的具体对象：失败诊断、数据收集、监督构造、更新选择、候选验证。
   - **重要区分**：重复固定的"收集-训练"流水线只是迭代改进（iterative improvement）；只有当证据能够修订该流水线本身（改变下一轮发现和解决弱点的方式）才是递归方向。
   - 参考 AI Scientist、autoresearch（Karpathy）、Darwin Gödel Machine、RRSI 等工作：自动化一个固定的实验循环 ≠ 改进循环本身。

6. **输入输出（框架层面）**

   - 输入：创意简报 / 交互目标 / 开发目标。
   - 中间：harness 编排的可执行操作序列（规划、生成、检查、修订、学习）。
   - 输出：成品视频 / 可持续的交互环境 / 改进后的模型与 harness。
   - 伴随物：被结构化记录的执行经验（可复用技能、可修订的流水线）。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

1. **如何理解和表示空间**

   - 视频世界模型是 Spatial AGI 的核心候选载体之一：它以潜空间/像素空间的形式隐式表示了三维世界的几何、动力学与因果结构。
   - 本文的关键贡献是把"世界状态"从生成器中**显式分离**出来：一种设计是让游戏引擎或 coding agent 写出的程序持有世界状态，视频模型只负责"渲染"这个状态。这相当于把空间表示从神经隐式（视频潜空间）部分地拉回到符号显式（程序化状态），形成 hybrid 世界表示。
   - 这对 Spatial AGI 有直接的架构启发：**空间状态的可执行性（executable world state）**——空间不是被一次性生成，而是被一个可查询、可修改、可验证的状态机持有。

2. **如何处理空间关系**

   - 交互式视频世界模型要求动作条件化（action-conditioned）：agent 的动作改变后续观察，这正是空间智能中"感知-行动循环"的体现。
   - Harness 维护的"项目/交互状态"本质上是空间-时间状态的持久化：跨镜头的对象一致性、跨回合的世界演化，都是空间关系管理问题。
   - 多镜头生成中的参考持久化（references persist across scenes）= 空间实体在场景切换下的恒等性保持。

3. **对 Spatial AGI 的启发**

   - **Harness 思维**：Spatial AGI 不应只是一个更强的生成/感知模型，而应是"模型 + harness"的系统。感知模型提供能力原语，harness 负责状态、反馈、预算——这与我们此前对 world model 架构的判断一致：单一模型难以同时做好"逼真渲染"和"精确状态管理"。
   - **反馈的三个时间尺度**分类学可以直接迁移到空间智能系统：
     - 修复当前场景重建 → 修当前工件
     - 保存导航技能/操作技能 → 供未来任务复用
     - 用失败案例更新空间感知模型 → 迭代模型
     - 修订数据收集与评估流程本身 → 递归方向
   - **Agent 与世界模型互测互改**（reciprocal evaluation）：agent 在世界模型中测试，世界模型暴露 agent 策略的漏洞——这是 Spatial AGI 安全与能力评估的天然框架。
   - **RSI 视角**：目前没有任何 surveyed 系统完成了完整的 RSI 回路（修订训练/验证生成器的流程本身）。Spatial AGI 的长期路径很可能也要经过：执行经验 → 技能库 → 数据/critic 更新 → 流程自我修订。

4. **可以应用的 Spatial AGI 场景**

   - 具身 agent 的训练环境：用 video world model + harness 生成无限、可控、带状态的训练场景（接续昨天 L3G-World 的"无限世界生成"思路，但加上 agent 编排层）。
   - 自主内容生产（autonomous video production）：影视级空间叙事的自动化。
   - 机器人 sim-to-real 数据工厂：harness 控制世界状态的程序化生成器，视频模型渲染，产出的数据经反馈通道回流训练。
   - 空间智能评估：用 agent 在生成世界中执行任务，把"视频质量"与"任务表现"联动评估——这解决了一个长期痛点：生成得好看 ≠ 世界可用。

### Q3: 这个框架的主要创新点和局限性是什么？

**分析**:

1. **主要创新点**

   - **以 harness 为分析单元**：现有综述分别覆盖时空一致性、后训练对齐、评估、agentic visual generation、世界模型、harness 工程、self-evolving agents，但没有一篇以"视频生成器周围的 harness"为统一单元，横跨生产、交互、开发三个场景。本文填补了这个空白。
   - **改进的三层区分**：当前输出修订 / 状态与参数更新 / 流程修订。这个分类学澄清了文献中大量被混用的"self-improvement"概念。
   - **四条改进回流通道**的识别（改进如何重新进入开发流程），并明确指出：目前没有系统完成了完整 RSI 回路——这是一个诚实且重要的研究现状判断。
   - **Agent 能力清单**：系统梳理了视频任务对 agent 提出的能力要求——视听感知（audiovisual perception）、长程规划、记忆、通过代码和 computer use 的交互、反馈引导控制、技能复用、多 agent 组织。
   - **Hybrid 世界状态设计**：游戏引擎/程序持有状态 + 视频模型渲染，这是对"纯生成式世界模型"的重要架构修正。

2. **主要局限性**

   - **Survey 性质**：本身不提出新方法或实验，三个方向都停留在框架和文献综合层面，许多判断（如 RSI 通道）缺乏实证支撑。
   - **RSI 部分较为推测性**：识别的"通道"更多是概念上的可能性，距离可运行的系统还很远。
   - **视频质量与任务表现的联动评估**被列为开放挑战而非解决方案。
   - **成本会计与溯源（provenance and cost accounting）**也只是被提出，没有给出机制。
   - 对 3D 显式表示（3DGS 等）与视频世界模型的结合着墨很少——而这恰是 Spatial AGI 近期最活跃的方向（参考昨天的 L3G-World、WorldFlow）。

3. **与其他相关工作的对比**

   - vs Wu et al. 的"visual generation capability ladder"（把 agentic 生成和世界建模当作生成器的连续阶段）：本文改为以 harness 为中心，能同时覆盖生产、交互、开发。
   - vs agentic world model 综述（chu2026, liu2026, yang2026）：那些关注世界模型本身的预测/仿真能力；本文关注 harness 如何介入观察/控制/执行/状态接口。
   - vs AI Scientist / DGM：那些自动化固定实验循环；本文强调"改进循环本身"的递归定义。
   - 优势：框架统一、概念区分严格。劣势：无实验验证，深度不及各专项综述。

## 核心技术发现

- 发现1：视频生成正在系统性地"agent 化"，harness（而非模型）正成为系统的组织中心。
- 发现2：反馈必须按时间尺度分层（当前工件 / 未来任务技能 / 下一代模型），混淆这三层是当前 self-improvement 文献的普遍问题。
- 发现3：Hybrid 架构（程序化世界状态 + 神经渲染）在可控性和一致性上优于纯生成式世界模型。
- 发现4：没有任何现有系统完成了视频领域的完整 RSI 回路——递归自我改进仍是开放问题。
- 发现5：Agent 与世界模型可以互为测试环境（reciprocal evaluation），形成双向质量压力。

## 与Spatial AGI的关系

### 直接贡献

给出了 Spatial AGI 系统架构的一个顶层框架：感知/生成模型 + harness（状态、工具、反馈、预算）+ 递归改进通道。这可以直接作为 Spatial AGI 路线图的骨架。

### 技术启发

- "世界状态外置到可执行程序"的设计可以解决视频世界模型长期一致性崩坏的问题（与昨天 L3G-World 的 latent 3D memory 形成两条互补路线：显式程序状态 vs 隐式高斯记忆）。
- 反馈三层分类学应成为我们评估任何"自我改进型空间智能系统"的检查表。

### 应用场景

- 无限世界生成 + agent 编排 → 具身训练数据工厂
- 互测互评 → 空间智能 agent 的自动化基准
- RSI 通道 → Spatial AGI 长期演进路径

## 个人思考

### 最令人兴奋的发现

"harness 作为分析单元"这个视角转换非常有力。过去我们习惯把世界模型的演进看作模型架构的竞赛（扩散 vs 自回归 vs 高斯记忆），但本文提示真正的系统性进展发生在模型外围的运行时层——上下文构造、状态维护、反馈路由。这和软件工程中"框架比算法更长寿"的规律呼应。对 Spatial AGI 而言，可能最终胜出的不是最强的单一世界模型，而是最强的"世界模型 + harness"组合。

### 潜在局限

作为 position report，它描绘的 RSI 蓝图可能在几年内都停留在纸面。四条回流通道里，最现实的其实是"数据与 critic 更新"这一条；"修订训练流程本身"需要极高风险控制，学术界短期不会碰。另外，综述对 3D 显式表示的忽视是一个盲区：如果世界状态外置到程序，那 3DGS 类显式表示正好是"程序状态"与"神经渲染"之间的天然接口。

### 与昨日研究的关联

昨天精读的 L3G-World 用 latent 3D Gaussian memory 解决无限世界生成的空间一致性，Wizard 用 agentic 控制实现实时世界操纵，CoAWM 研究连续动作世界模型。本文恰好是这三者的"上一层抽象"：它回答的不是"如何生成一致的世界"，而是"如何组织生成世界的系统"。L3G-World 的显式记忆可以视为本文 harness 中 state maintenance 的一种实现；Wizard 的 agentic control 是 control interface 的实例；CoAWM 的连续动作先验是 execution 层的基础。今天这篇把三个点连成了面。

## 总结

### 核心发现总结

本文以 agent harness 为分析单元，统一了视频生成的三个前沿场景：智能体化生产、智能体化世界交互、递归自我改进。核心贡献是严格的反馈分层分类学（当前输出/未来技能/下一代模型/改进流程本身）和诚实的现状判断（RSI 回路尚未闭合）。架构上，"程序持有世界状态、视频模型负责渲染"的 hybrid 设计是值得高度关注的方向。

### 对Spatial AGI的意义

Spatial AGI 的路线图应从"训练一个更强的世界模型"升级为"构建一个世界模型 + harness + 递归改进通道的系统"。空间状态的持久化、可查询、可修订是空间智能超越感知能力、走向持续智能的关键。反馈分层分类学为评估任何空间智能系统的"自我改进"声明提供了严格检查表。

## 附录A：三大方向逐项展开分析

### A1. Agentic Video Generation（智能体化视频生产）

#### A1.1 Harness 在生产流水线中的功能分解

生产环节可以被分解为若干由 harness 编排的功能模块，每个模块对应一类 agent 决策：

- **剧本与分镜规划（Script & Shot Planning）**：
  - 把创意简报（creative brief）转化为结构化的分镜序列。
  - Harness 负责把分镜约束（时长、镜头语言、角色出场）编码为可执行的生成指令。
  - 关键点：规划必须考虑"参考影响后续镜头"——前镜中的角色外观、场景布局会成为后镜的生成条件，因此规划器需要持有项目级状态。

- **资产管理（Asset Management）**：
  - 角色、场景、道具的参考图像/视频/描述需要跨镜头持久化。
  - 空间智能视角：资产本质上是"空间实体的恒等性记录"，其一致性管理是一个实体锚定（entity grounding）问题。

- **分镜生产（Shot Production）**：
  - 调用视频生成器产出候选 take。
  - Harness 施加预算约束（生成次数、算力、时间），决定何时"够好了"。

- **检查与剪辑（Inspection & Editing）**：
  - Take 检查：评估叙事合规性而非仅画面质量——"看起来合理"不等于"实现了预期动作"。
  - 剪辑的局部修复风险：修复一个镜头可能破坏其他镜头的时间一致性，harness 需要管理修复的传播范围。

#### A1.2 评估必须区分什么

- 生成质量（画面好不好）≠ 任务完成（叙事要求是否满足）≠ 交互可用（动作是否被正确执行）。
- 单一质量分数无法定位失败：有效的控制需要"观察→局部化决策"的映射，即失败必须被归因到具体镜头/具体属性。
- 这要求评估器输出结构化的失败诊断，而非标量分数。

#### A1.3 代表性能力需求

| 能力 | 在生产中的体现 | 空间智能关联 |
|------|---------------|-------------|
| 视听感知 | 检查生成片段的语义与音画一致性 | 场景理解 |
| 长程规划 | 多镜头叙事编排 | 任务分解 |
| 记忆 | 角色外观、场景布局跨镜头持久化 | 空间状态维护 |
| 代码交互 | 调用生成器/编辑器 API | 工具使用 |
| 反馈控制 | 根据 take 检查结果修订指令 | 感知-行动循环 |
| 技能复用 | 保存有效的提示/流程模板 | 经验积累 |
| 多 agent 组织 | 编剧/导演/剪辑分工协作 | 系统设计 |

### A2. Agentic World Modeling（智能体化世界建模）

#### A2.1 Harness 的五个介入接口

1. **观察（Observation）**：决定 agent 看到什么——视角、分辨率、模态（音/视/文）。主动感知（active perception）的编排者。
2. **控制（Control）**：把 agent 意图翻译为世界模型可接受的动作条件（action conditioning）。
3. **执行（Execution）**：管理 rollout 的调用、缓存、回滚。
4. **事件组织（Event Organization）**：把连续的观察流切割成离散事件，供记忆和规划使用。
5. **状态管理（State Management）**：维护世界状态的持久表示——这是空间一致性架构的核心。

#### A2.2 世界状态持有者的三种设计谱系

- **纯生成式**：世界状态完全隐式于视频生成器的潜空间中。优点是视觉自由度高；缺点是长期一致性随 rollout 长度衰减（yesterday's CoAWM 试图用连续动作先验缓解）。
- **引擎持有状态 + 视频模型渲染**：游戏引擎（或 coding agent 写的程序）持有可查询的世界状态，视频模型只做条件化渲染。优点：状态精确、可回滚、可验证；缺点：渲染受状态描述的保真度限制。
- **混合渐进式**：显式空间记忆（如 latent 3D Gaussian memory，L3G-World）作为状态锚，生成器在其上做条件外推。介于两者之间。

作者没有明确给出这个谱系，但文中"game engine or a program written by a coding agent holds the world state while the video model renders it"的描述指向第二种设计，这是报告中最具架构意义的论点之一。

#### A2.3 Agent 与世界模型的互测互评（Reciprocal Evaluation）

- Agent 在世界模型中执行任务 → 暴露世界模型的不合理之处（物理错误、状态跳变）。
- 世界模型的 rollout 作为 agent 策略的测试床 → 暴露 agent 的策略漏洞。
- 形成双向质量压力：任一侧改进都会提高对另一侧的要求。
- 这实质上是把"仿真器与策略共同进化"的老想法（cf. POET、Co-Evolution）搬到了视频世界模型时代。

#### A2.4 空间一致性挑战

- 动作改变观察：每次交互后世界必须"记住"变化——空间状态的持久化是硬需求。
- 回滚与分支：交互式应用需要从任意历史状态重开（branching rollouts），这要求状态表示可快照。
- 跨视角一致性：agent 移动后重访旧区域，渲染必须与记忆一致——这正是 3D 显式记忆（L3G-World、Wizard）要解决的问题。

### A3. Toward RSI（递归自我改进）

#### A3.1 改进对象的四层分类

| 层级 | 对象 | 时间尺度 | 例子 |
|------|------|---------|------|
| L1 | 当前输出（视频工件） | 即时 | prompt 修订、take 重生成 |
| L2 | Harness 状态（上下文/技能库） | 跨任务 | ACE 结构化上下文、技能保存 |
| L3 | 模型与评估器（数据集/生成器参数/critic） | 跨版本 | 数据回流训练、DualIPO critic 更新 |
| L4 | 改进流程本身（数据收集/验证/更新选择的程序） | 跨轮次 | 修订开发流水线 |

- L1-L3 是文献中已存在的构建块（building blocks）：VideoWeaver 的技能保留（L2）、AutoExplore 的不确定性引导数据获取（L3）、DualIPO 的验证制 critic 更新（L3）。
- L4 是递归方向的定义性要求：证据必须能改变"下一轮如何发现和解决弱点"。
- 诚实结论：**没有任何被综述的系统完成了 L4**。重复固定流水线 = 迭代；修订流水线 = 递归。

#### A3.2 四条改进回流通道（Channels）

1. 失败诊断经验的通道：生产/交互中暴露的失败如何进入下一轮训练数据的构造。
2. 数据收集策略的通道：世界模型作为数据工厂时，采集策略本身能否被经验优化。
3. 监督构造的通道：critic、奖励模型的更新机制。
4. 候选验证的通道：模型版本的验收流程能否被改进。

#### A3.3 为什么 L4 困难

- 风险：修订开发流程可能引入系统性偏差，且评估一次流程修订需要多个完整训练轮次的证据——成本极高。
- 安全：流程自我修订接近"目标自修改"，需要严格的外部验证约束（RRSI 的正则化思路）。
- 可信度：流程修订的贡献难以与数据/算力增长的贡献解耦。

### A4. Agent 能力需求全景

视频任务对 agent 提出的七项能力：

1. **Audiovisual Perception**：不能只看画面，声音是事件与动力学的重要载体（呼应 SonoWorld4D 等音视联合建模）。
2. **Long-horizon Planning**：多镜头叙事/多步交互的编排。
3. **Memory**：项目状态与交互历史的持久化，且需要分级（工作记忆 vs 长期记忆 vs 终身记忆——lifelong memory 被列为开放挑战）。
4. **Interaction through Code & Computer Use**：harness 的操作界面是代码与 GUI。
5. **Feedback-guided Control**：从检查结果到修订指令的闭环。
6. **Skill Reuse**：把成功的操作流程固化为可复用技能。
7. **Multi-agent Organization**：编剧-导演-剪辑式分工，或 agent 与世界模型的互评组织。

## 附录D：关键概念术语表

- **Agent Harness**: 围绕模型的可执行运行时，负责上下文构造、工具暴露、状态维护、反馈路由、权限与预算约束。全文的分析单元。

- **Agentic World Modeling**: harness 介入观察、控制、执行、事件、状态五接口的世界模型交互范式。
- **Recursive Self-Improvement (RSI)**: 系统改进"产生后续改进的程序"本身；区别于重复固定流水线的迭代改进。
- **Context Engineering / ACE**: 从执行反馈中积累并修订结构化上下文而非更新权重的方法；属于 L2 层改进。
- **Reciprocal Evaluation**: agent 与世界模型互为测试环境、双向暴露缺陷的评估组织方式。
- **L1-L4 改进分层**: 当前输出 → harness 状态 → 模型/评估器 → 改进流程本身。
- **Hybrid World State**: 程序化状态持有（引擎/代码）+ 神经渲染（视频模型）的架构设计。

## 附录H：常见问题（FAQ）

### H1. 这篇是方法论文还是综述？
是综述/立场报告（survey/position report），不提出新模型，但提出了新的分析框架（harness 中心框架 + L1-L4 改进分层）。

### H2. 为什么"修复当前视频"不算自我改进？
因为能力改进必须在未来任务上被独立验证。修复当前工件只消耗经验而不积累经验；只有改进被保留（技能、数据、critic、流程）并在后续任务上验证有效，才构成改进。

### H3. 递归和迭代的区分是否过于学究？
不是。它直接决定研究评价标准：一个"self-improving video system"如果只是重复固定的 collect-train-evaluate 流水线，其贡献应按迭代系统评价；声称递归必须有流程被修改的证据。这影响资源分配和方向判断。

### H4. 游戏引擎持有状态是否与"视频世界模型"的理念冲突？
不冲突，反而互补。视频世界模型的价值在于视觉真实性和泛化渲染；引擎的价值在于状态精确性。混合架构让两者各司其职——渲染层开放（神经），状态层收敛（符号）。

### H5. 对 Spatial AGI 最近期可落地的启示是什么？
互评式评估：用可控世界生成针对 agent 弱点的测试场景，比静态基准更有效率且不会饱和。

### H6. 报告中哪一段最值得精读？
反馈的三时间尺度分类（当前工件/未来技能/下一代模型）和世界状态持有者的设计讨论——前者是评估任何自我改进声明的检查表，后者是最直接的架构启示。
