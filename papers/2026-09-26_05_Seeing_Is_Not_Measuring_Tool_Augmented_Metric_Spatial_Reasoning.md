# Seeing Is Not Measuring: Tool-Augmented Metric Spatial Reasoning for Vision-Language Models

**发表日期**: 2026-09（arXiv:2609.29073）
**arXiv链接**: https://arxiv.org/abs/2609.29073
**PDF链接**: https://arxiv.org/pdf/2609.29073
**HTML版本**: https://arxiv.org/html/2609.29073

**基准**: ReVSI-Bench（ARKitScenes 子集）

---

## 一句话总结

本文用一个极简但锋利的实验设计回答了一个 Spatial AGI 的核心问题：给一个 4B 小 VLM（Qwen3.5-4B）配上 3D 检测、度量深度、确定性几何求解器等工具后，它在 ReVSI-Bench 的度量空间推理上大幅跃升（绝对距离 MRA 0.46→0.74，相对方向 25.9%→73.4%——后者原本低于瞎猜）；再通过 "GT oracle vs 真实检测器 vs 无 VLM 几何天花板" 的三方对照，把剩余误差精确分解为 **感知误差 vs 编排误差**——结论：度量几何应该藏在工具后面而不是塞进上下文，且单目 3D 检测器（而非 VLM）才是当前瓶颈。

## 核心问题

### Q1: 核心方法与实验设计

**问题**: 这篇文章的核心框架和实验逻辑是什么？

**分析**:

#### 1. 核心思想和动机

VLM 会描述场景，但度量 3D 推理（绝对距离、物理尺寸、自我中心方向）极差。ReVSI-Bench 上的证据触目惊心：

- Qwen3.5-4B 绝对距离 MRA 仅 0.46（2B: 0.21；0.8B: 0.00）
- **把相机内参以文本形式附到提示里，MRA 反而从 0.46 掉到 0.17**——信息越给越差！

这引出全文最重要的设计原则：

> **度量几何更适合封装在模型可以调用的东西（工具）背后，而不是被语言化塞进上下文窗口。**

这与人类认知形成有趣的平行：人也不会从内参矩阵心算距离，而是使用尺子、激光测距仪——"测量" 是工具行为不是内省行为。标题 "Seeing Is Not Measuring" 一语双关：看见（qualitative perception）≠ 测量（metric computation），VLM 擅长前者，两者不应混为一谈。

#### 2. 系统框架：预测器无关的工具增强

**工具链**（每任务一个 toolset）：

1. **detect_object_3d**：在每物体 "最佳视图" 的相机系中检出有向 3D 框（OBB）
2. **project_box_to_world**：用帧的相机位姿把各物体的框统一抬升到一个共享的世界坐标系——多视图度量的关键
3. **确定性求解器**：
   - calculate_object_distance：表面到表面最小距离（而非中心距！）
   - calculate_object_size：3D 范围的最长边（旋转不变，无需世界系投影）
   - 相对方向：把观察者、朝向、目标统一到世界系，分类自我中心方位角

**编排**：Qwen3.5-4B 作为 orchestrator，CoT 循环中逐次 JSON 调用工具；坐标与矩阵缓存在宿主环境中——**上下文永远不填满数字，模型从不自己做算术**。

**细节中的魔鬼**：表面距离 vs 中心距的选择贡献了大部分可达精度——GT 框上中心距 MAE 0.644m vs 表面距 0.077m。几何接口的语义选择（benchmark 答案是表面距）比模型能力更决定性。

#### 3. 实验设计的精髓：三方误差分解

这是全文最有价值的部分——一个干净的三方对照体系：

| 配置 | 测量什么 |
|---|---|
| 无工具 VLM 基线 | 模型从像素直接推理的上限 |
| 工具链 + 真实检测器（Cube R-CNN / OVMono3D / WildDet3D / DINO+DepthPro） | 感知 + 编排的联合效果 |
| 工具链 + GT oracle | 纯编排效果（感知完美时） |
| 无 VLM 几何天花板（脚本直接跑工具于 GT 框） | 感知后端允许的上限 |

由此可以分解：
- **编排误差** = GT oracle − 几何天花板
- **感知误差** = 真实检测器 − GT oracle

#### 4. 关键结果

**绝对距离**（MRA）：
- 无工具 0.46；+WildDet3D 0.74；+GT 0.94（天花板 0.97）→ **编排仅花 0.03**
- 但其他检测器全部低于无工具基线：OVMono3D 0.26、Cube R-CNN 0.32、2D+depth 0.32（深度离群值高达 10187m！）
- **"坏框比没有框更糟"**：检测器漏检时模型回退瞎猜，MRA 甚至能超过其自身天花板

**物体尺寸**：
- GT 框上工具近乎完美（0.97 vs 天花板 1.00），但最佳真实检测器仅 0.61 vs 无工具 0.58
- 原因：尺寸直接读自框的最长边，WildDet3D 最长边中位误差 14.3%——单目检测器恰恰在尺寸上最不准
- 距离容忍框噪声（中心距主导），尺寸不容忍——**不同任务对感知噪声的敏感度结构性不同**

**相对距离**：39.1% → 67.4%（WildDet3D）→ 92.1%（GT，天花板 94.9%）

**相对方向**（最戏剧性）：
- 无工具 25.9%——**低于 29.3% 的瞎猜概率**，甚至不比 "从不看帧" 的盲模型（28.3%）好——帧里根本没有 VLM 能用的方向信号！
- +工具：73.4%（WildDet3D）/ 80.0%（GT，天花板 100%）
- 这里误差首次由模型主导：23% 的问题模型跳过工具直接回答

**无菜谱自主探针**（No-Recipe Autonomous Probe）：
- 一次性暴露所有工具、不给调用顺序菜谱
- 关键发现：**修好工具的错误信息（把 "No 3D box found" 改写为点名缺失步骤）比调提示更有效**——工具错误从 138 降到 36，距离 MRA 0.58→0.88
- 修好后，无菜谱编排追平脚本管线（0.94/0.97/92.5%）——**路由能力天生就有，缺的是调用工具的纪律**
- few-shot 顺序示例反而有害（距离 -0.05，相对距离 -12.5 点）

#### 5. 输入输出

- **输入**：视频问题（每题 16 候选帧，预选出 1-2 个最佳帧）、任务问题
- **输出**：度量答案（距离/尺寸数值或方位分类）
- **中间**：相机系 OBB → 世界系 OBB → 确定性几何量

### Q2: 与 Spatial AGI 的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

本文隐含一个空间表示的分层假设，与 WAA（今日论文 3）高度互补：

- **感知层**：相机系 3D OBB——空间的最小语义单元（"一个物体在某处，有朝向和尺寸"）
- **配准层**：共享世界坐标系——多个视角的空间统一（本文靠相机位姿；WAA 靠点云标定）
- **度量层**：确定性求解器——空间关系的精确计算（距离/尺寸/方位）
- **语义层**：VLM 只负责 "哪个物体、什么问题、怎么编排"

核心主张：**空间表示不必装进模型权重，可以外置为一套可调用的确定性服务**。这与 "把空间智能训练进权重" 的主流路线（MM-Spatial、SpatialLadder、SpatialThinker 等）形成方法论对垒：本文证明不改权重、纯 in-context 编排就能让 4B 模型大幅超过原生 8B+ 的表现。

#### 2. 如何处理空间关系

本文揭示了空间关系处理的两个深层规律：

1. **关系的度量语义必须与计算接口对齐**：benchmark 问表面距，求解器就算表面距（中心距 MAE 0.644→0.077m 的 8 倍差距）。空间关系的 "关系类型"（表面/中心/边界）是接口设计问题，不是模型能力问题。
2. **不同空间关系对感知噪声的鲁棒性结构不同**：
   - 距离：由中心分离主导，容忍框噪声（鲁棒量）
   - 尺寸：直接读框边长，噪声直通（脆弱量）
   - 方向：读中心、不读范围（介于两者，感知误差 11 点）
   
   这意味着空间智能系统需要 **任务-感知器的误差敏感性匹配表**——哪些空间问题可以直接用单目感知，哪些必须多视图/深度/主动测量。

3. **方向是 VLM 完全缺失的空间维度**：无工具时不比瞎猜好——不是 "弱" 而是 "无"。自我中心方位角需要自我运动参照系，这与 GPT-6-Astra 论文里 "模型缺位姿积分" 的发现互为印证：**自我中心空间参照系是当前基础模型的结构性盲区**。

#### 3. 对 Spatial AGI 的启发

1. **"Seeing ≠ Measuring" 应成为 Spatial AGI 架构的第一性原则**：不要期望大模型从像素内省出度量——给它工具。这与 GPT-6-Astra 的教训合并：最小接口能释放导航智能，但度量接口是导航智能的必要补充（到达验证=度量问题！）
2. **误差分解方法论是评测的黄金标准**：本文的 GT oracle / 真实检测器 / 几何天花板三方对照，正是评测综述（今日论文 2）呼吁的 "对比归因" 的教科书实现。任何 "工具增强空间智能" 工作都应复用此设计。
3. **工具错误消息的信息设计**：把错误从 "失败宣告" 改写为 "缺失步骤点名"，编排错误降 75%——这是 LLM agent 工程中易被忽视的杠杆点：**工具的 API 错误消息是 agent 的教师**。
4. **"调用纪律" 是微调的明确目标**：模型在 "看起来可以目测" 的问题上跳过工具（23%）——这为后续 fine-tuning 给出了精确靶点：不是学空间推理，而是学 "何时该测量"。
5. **坏工具比没工具危险**：深度离群 10187m、坏框导致低于基线——空间工具集成必须有置信度门槛（直接连接今日论文 4 的不确定性！）

#### 4. 可以应用的 Spatial AGI 场景

- 机器人问答/任务规划中的度量接地（"桌子离门多远"）
- 家庭助手的空间指令验证（"把杯子放到冰箱左边" 的可行性检查）
- AR 空间注释的度量校准
- 具身 Agent 的 "测量子代理"：任何需要度量的决策前强制走工具链
- VLM 空间基准的改良设计（分出 "测量型" 与 "感知型" 题目）

### Q3: 创新点和局限性

**问题**: 主要创新与局限是什么？

**分析**:

#### 1. 主要创新点

1. **预测器无关的工具接口**：GT oracle / 三种单目检测器 / 2D+深度管线在同一接口后自由切换——既实用（可升级）又科学（可归因）。
2. **编排-感知误差分解**：三方对照（oracle/真实/天花板）把 "工具增强为什么有效" 拆到可归因的程度——这比 "我们提升了 X%" 的普通报告科学价值高一个量级。
3. **无菜谱自主性验证**：证明 4B 模型天生具备正确的工具排序能力，缺失的是调用纪律——为后续微调给出精确靶点，也修正了 "小模型不会编排" 的流行偏见。
4. **工具错误消息的实验**：错误信息重写（138→36 错误，0.58→0.88 MRA）是对 agent 基础设施的一个被低估杠杆的量化证明。
5. **诚实的局限性披露**：框架选帧用 GT 框、不做多视图三角化、无工具基线看 16 帧而工具组只看 1-2 帧（部分增益可能来自取景而非工具！）——这种自我批判在论文中罕见。

#### 2. 主要局限性

1. **帧选择是第一个 oracle**：用 GT 3D 框投影选最佳帧——真实部署没有 GT。作者已把它列为下一个要移除的 oracle，但在那之前所有数字都带 * 号。
2. **取景混淆**：工具组看精选 1-2 帧、无工具基线看 16 帧——部分增益可能来自 "看对帧" 而非工具。一个 "无工具+精选帧" 的缺失基线让对照不完全干净。
3. **不做多视图三角化**：只用单帧检测+位姿抬升，浪费了多视图几何的冗余优势。真实单目检测在多帧上的三角化融合可能显著改善尺寸误差（尺寸恰是当前最大短板）。
4. **感知在域内**：检测器都训练于 Omni3D（含 ARKitScenes 训练集，虽然 161 测试场景在验证折），跨域真实世界的检测误差会更大——"WildDet3D 是可用后端" 的结论在域外未必成立。
5. **相对距离的名字-实例映射**：每个名字映射到单个预测框，天花板因此只有 94.9%——接口语义的粗糙处。
6. **规模局限**：Qwen3.5-4B、ARKitScenes 室内、161 场景。"小模型+工具" 是否随模型变大而失效（大模型直接推理更强）值得探究——但注意 +intrinsics 掉分的证据暗示 "更大 ≠ 更会算"。

#### 3. 与相关工作的对比

- **vs 权重内训练路线**（MM-Spatial、SpatialLadder、SpatialThinker、VLM-3R）：本文不动权重；优势是即插即用、误差可归因、检测器可升级；劣势是推理成本、帧选择 oracle、无能力内化。
- **vs SpaceTools**（两阶段 RL 教工具组合，单图）：本文免训练、多视图视频；结果上两者互补——SpaceTools 教 "怎么组合"，本文发现 "组合其实天生会"。
- **vs ViperGPT/Visual Programming**：那些把查询编译成程序（代码即计划）；本文是交互式 CoT 编排——保留了模型中途调整的灵活性。
- **vs ViSRA**：配点云建显式 3D 场景——比本文重，但可能解决本文的尺寸短板（多视图冗余）。

## 核心技术发现

1. **度量几何应封装为工具而非语言化**：+intrinsics 文本使 MRA 0.46→0.17——上下文里的数字是毒药。
2. **相对方向是 VLM 的结构性盲区**：无工具时不比瞎猜/盲模型好——自我中心方位角在帧中无可用信号。
3. **编排极便宜（0.03 MRA）**：4B 模型的工具编排能力接近无损；误差在感知端。
4. **坏工具比没工具更糟**：3/4 检测器低于无工具基线；深度离群可达 10187m——空间工具集成需要置信度门槛。
5. **任务-噪声敏感度结构**：距离鲁棒（中心主导）/尺寸脆弱（直读框边）/方向中等。
6. **路由能力天生，调用纪律需训练**：无菜谱编排可追平脚本管线（修好错误消息后）；23% 的跳过工具是微调靶点。
7. **工具错误消息是教师**：点名缺失步骤的错误信息使错误降 75%。

## 背景与相关工作深度梳理

### 空间基准的演化线：GQA → VSI-Bench → ReVSI-Bench → 本文

- **GQA 时代**：空间=2D 关系（"left of"、"inside"），与具身需求脱节。
- **VSI-Bench**（2025 前后）：把空间智能评测推进到室内扫描视频上的度量问题（距离/尺寸/方向）。影响巨大，但后来被发现有问题：查询物体可能根本不在帧中可见——题目不可答，评测失真。
- **ReVSI-Bench**（修正版）：验证查询物体在帧中确实可见，并提供每题的相机位姿、内参和 GT 3D 框。后两者恰是本文工具链的输入——**本文的方法学选择直接由基准的数据结构使能**。这是一个值得注意的 "基准驱动方法" 案例：评测基础设施的设计决定了能做什么实验。
- **MMSI-Video-Bench / MV-RoboBench**：扩展任务面/多相机设定；后者发现单视角空间能力不能可靠迁移到多相机——与本文的多视图统一世界系动机呼应。

### "训练进权重" vs "外挂工具" 的路线对垒

本文 related work 梳理的 "训练派" 阵容豪华：
- SFT：MM-Spatial、Visual Spatial Tuning、SpatialLadder、Spatial-MLLM
- RL：SpatialThinker（空间奖励）
- 架构：VLM-3R（3D 重建内化）
- 缩放：Cambrian-S、Scaling Spatial Intelligence

训练派的隐含赌注：空间能力是可学习权重。本文的赌注：**至少度量部分不必学习，学习它不如调用它**。目前的证据似乎支持一个分工：定性/拓扑空间关系（上下、左右、包含）训练有效且必要；度量关系（距离、尺寸、方位角）工具完胜。这个分工如果稳固，Spatial AGI 的训练目标应该收窄为 "定性空间 + 编排纪律"，度量外包。

### ReAct / Toolformer / ViperGPT 谱系中的位置

- Toolformer：把工具调用烤进权重（训练时决定何时调用）；
- ReAct：推理与工具调用交错（in-context，训练自由）；
- ViperGPT / Visual Programming：查询编译成整段程序再执行；
- 本文：ReAct 式交互编排 + 任务级 toolset 限定 + 宿主侧状态缓存（数字不进上下文）。

最后一项（状态缓存）是被低估的工程决策：它同时解决了 "上下文爆炸" 和 "模型算术不可靠" 两个问题——模型只见物体名与结论，永不见坐标。这实际上重新定义了 "agent 记忆" 的边界：**记忆属于宿主环境，模型只持有意图**。

## 实验的批判性精读

### 三方对照的严谨性检查

设计本身是教科书级，但有三处需要较真：

1. **取景混淆（作者自己承认）**：工具组看精选 1-2 帧，无工具组看全部 16 帧。表面上工具组 "信息更少" 却表现更好，凸显工具价值；但缺 "无工具 + 精选帧" 基线意味着无法完全排除 "取景效应"。一个便宜的补测就能堵上这个洞。
2. **GT 帧选择 oracle**：最佳帧用 GT 3D 框投影可见性选出。真实场景的开放词汇 2D 检测能否替代投影打分？作者计划中（把可见性评分做成工具），但当前所有结论条件于这个 oracle。
3. **检测器域内训练**：三个检测器都见过 ARKitScenes 训练折。域外（真实家庭、异国建筑风格）的单目 3D 检测误差大概率更糟——"WildDet3D 可用" 的结论的域外有效性存疑。

### "坏工具比没工具糟" 的机制再分析

三个失败后端的失败模式各不相同：
- OVMono3D（0.26）：检出率低？框质量差？
- Cube R-CNN（0.32）：同为 Omni3D 训练但架构差异；
- DINO+DepthPro（0.32）：深度离群 10187m——度量深度模型的 "自信的荒谬值" 问题。10187m 的深度估计竟然能通过 sanity check 进入距离计算，说明管线缺少物理常识守卫（室内距离>50m 即应报警）。

这引出一个工程原则：**几何工具链需要 "物理合理性守卫层"**——范围检查（室内距离、尺寸的先验界）、跨视图一致性检查、以及直接连接论文 4 的不确定性门槛。守卫层缺失时，工具链不是中性的：它把感知错误转换成自信的荒谬答案，比模型的 "模糊的模糊答案" 更危险。

### 23% 跳过率的深层含义

模型在相对方向任务上 23% 跳过工具直接回答。为什么偏偏是这个任务？合理推测：方向问题（"冰箱在电视的左边还是右边"）看起来像 "看一眼就知道" 的感知题——触发了模型的 "目测捷径" 偏好。这揭示工具调用纪律的敌人不是能力不足而是 **元认知误判**：模型把度量问题误分类为感知问题。对症的微调数据应该专门包含 "看似可目测实则需测量" 的对抗样本。这个诊断比 "多训练工具调用" 更精确。

## 个人思考

### 最令人兴奋的发现

**"相对方向低于瞎猜、不比盲模型好"** 这个结果。它以最干净的方式证明：VLM 从多帧视频中提取自我中心方位信息的能力为零——不是弱，是无。这比 "距离不准" 之类的程度性缺陷深刻得多：方位感需要一个稳定的自我参照系（我在哪、朝哪边），而这恰是语言/互联网语料中缺失的经验（文本没有 "朝向"）。结合 GPT-6-Astra 的位姿积分缺失，两条独立证据指向同一结论：**自我中心空间参照系是基础模型的结构性空洞，工具或具身经验必须外挂补足**。

## 总结

### 核心发现总结

"看见" 与 "测量" 是两种能力：VLM 拥有前者、完全缺乏后者。把度量几何封装为确定性工具，让小 VLM 只做编排，就能在度量空间任务上大幅超越其原生能力；误差归因显示编排近乎免费、感知才是瓶颈；而自我中心方向感是 VLM 的结构性空洞。

### 对 Spatial AGI 的意义

1. 架构原则：语义在模型、度量在工具、配准在世界系——三层各司其职。
2. 评测方法：oracle/真实/天花板三方对照，任何工具增强系统都应报告。
3. 风险管理：空间工具必须带置信度门槛，坏工具比无工具危险。
4. 训练靶点：教的不是空间推理，而是 "何时该测量" 的调用纪律。

## 附录 A0：一次完整工具调用的走查示例

以一个绝对距离问题为例，走查工具链的全过程：

**问题**："沙发离电视有多远？"（候选：3m / 4.5m / 6m / 8m）

1. **帧选择**（预处理）：GT/检测框投影到 16 帧，选沙发与电视各自可见性最高的帧（各 1 帧）
2. **VLM 第 1 轮**：CoT "我需要先检测沙发和电视的 3D 位置" → 调用 `detect_object_3d("sofa", frame_7)` → 返回相机系 OBB（缓存在宿主）
3. **VLM 第 2 轮**：`detect_object_3d("tv", frame_3)` → OBB 缓存
4. **VLM 第 3 轮**：`project_box_to_world(["sofa","tv"])` → 两个世界系 OBB（缓存）
5. **VLM 第 4 轮**：`calculate_object_distance("sofa","tv")` → "表面最小距离 4.3m"
6. **VLM 终轮**：比对选项 → 回答 "4.5m"

注意全程模型上下文里只有物体名、工具签名和最后的距离值——没有任何坐标数字。若第 2 轮误先调用距离求解，宿主返回 "No 3D box projected for [sofa, tv]; call detect_object_3d and project_box_to_world first"——错误消息直接指出缺失步骤（重写后版本），模型自我纠正。

这个走查揭示 "编排" 的真实认知负荷：每轮只是 "下一步该调哪个工具" 的路由决策——这正是 4B 模型能近乎完美完成的原因，也解释了为什么 "路由天生会、纪律需要教"。

## 附录 A2：ReVSI-Bench 的 MRA 指标解读

MRA（Mean Relative Accuracy）= 多个置信阈值下 "相对误差达标" 的平均：

MRA = (1/|C|) Σ 1[ |x̂−x|/x < 1−θ ]，θ ∈ {0.5, 0.55, …, 0.95}

直觉：θ=0.5 要求答案误差 <50%，θ=0.95 要求 <5%。MRA 是 "在最严阈值下的通过率" 的温和版本——比 MAE 更抗离群、比二值成功率更细腻。注意它对 "答案数量级" 敏感：问 0.3m 的距离答 0.5m 与问 8m 答 13.3m 同样扣分——相对误差对近距物体更苛刻。这解释了为什么表面距离的 0.077m MAE 在近距物体上仍会损失 MRA，以及为什么中心距的 0.644m MAE 是灾难。

## 附录 B：工具接口的语义设计清单

从本文提炼的几何工具 API 设计规范：

1. **对齐答案语义**：表面距 vs 中心距（8 倍 MAE 差距）——接口的度量定义必须匹配下游任务的语义。
2. **状态外置**：坐标/矩阵存宿主，模型只见 ID 与结论。
3. **错误消息即教学**：错误必须点名缺失的前置步骤，不能只宣告失败。
4. **物理守卫**：范围检查（室内距离界）、离群拦截（10187m 深度）、一致性校验。
5. **不确定性门槛**（借论文 4）：低置信检测拒绝入链，宁可回退基线也不要坏框。
6. **任务-工具集匹配**：每任务只暴露所需工具 + 顺序提示（但保留模型自主排序空间——本文证明排序天生会）。

## 附录 B2：相对方向为什么是 "结构性空洞"——认知科学视角

人类的方向判断依赖三个参照源的融合：
1. **视网膜信号**：物体在视野中的位置——VLM 有（粗略）；
2. **头/眼朝向的本体感受**：我正朝哪看——VLM 无（帧不携带相机姿态的感知通道）；
3. **环境参照系的记忆**：房间布局中 "北在哪"——VLM 无跨帧积分机制。

本文的无工具失败（低于瞎猜）说明问题不在 1 而在 2、3：即使物体 "看得见"，"相对我的方向" 需要把视野位置 + 相机姿态 + 布局记忆融合，而 VLM 的预训练中几乎没有这种融合的监督信号（互联网文本与图像天然解耦了观察者姿态）。bearing 工具之所以有效，正是因为它把 2、3 显式化了：用位姿把观察者、朝向、目标投到统一世界系，方位角变成一次几何分类——恰好外包了模型缺失的两个参照源。

跨论文印证：GPT-6-Astra 的到达失败 = 缺 3（布局积分）；MetricBench 的度量失败 = 缺度量校准；本文的方向失败 = 缺 2+3。三者共同指向：**自我中心参照系的维护**是 VLM 作为空间智能体的根本缺口，也是 "具身化"（身体与姿态的持续在场）不可被替代的认知功能。这对 Spatial AGI 的哲学含义：空间智能可能本质上需要 "有一个身体"，而不仅是 "看过很多视频"。

## 附录 C2：few-shot 有害现象的分析

一个反直觉消融：few-shot 工具排序示例让距离 MRA -0.05、相对距离准确率 -12.5 点，仅在尺寸与方向小赚。

可能的机制：
1. **示例锚定**：示例固定了某种调用序列，实际问题需要微调顺序（如尺寸不需要世界投影），模型被示例锁死走弯路；
2. **上下文预算**：示例占用 token，挤压 CoT 空间；
3. **过度模仿**：模型模仿示例的字面调用而非理解目标，遇到示例未覆盖的情况时行为退化。

这与 "in-context learning 有益" 的默认直觉相反，但在工具编排场景下合理：**当任务结构已由工具签名与错误反馈定义时，示例是冗余且误导的信息源**。更广泛教训：agent 系统中，环境的反馈（可解析的错误消息）比示例（静态先验）更可靠——前者无条件适应实际状态，后者是作者对任务的猜测。
