## arXiv 摘要原文

> Real-world spatial intelligence requires reasoning over a continuous and evolving 3D world, yet existing VLMs and tool-augmented agents largely remain tied to static, stateless inference from isolated visual observations. We introduce **S-Agent**, a spatial tool-use agentic paradigm for understanding and reasoning over continuous multi-view images and videos. By formulating spatial reasoning as spatio-temporal evidence accumulation rather than isolated frame-level prediction, S-Agent reshapes spatial perception into scene-centric understanding beyond frame-centric recognition. Specifically, S-Agent casts the VLM as a semantic planner that decides what evidence is needed, while a hierarchy of spatial tools and experts grounds objects in 2D, lifts them into 3D geometric evidence, and aggregates this evidence into high-level spatial knowledge (e.g., counting, measurement, orientation, and relative position). Additionally, a temporal memory mechanism, including Scene Memory for maintaining the evolving scene state and Agent Memory for accumulating reasoning context, enables evidence integration across frames and reasoning steps. Comprehensive experiments on multi-view and video spatial reasoning benchmarks show that S-Agent consistently improves both open-source and closed-source VLMs in a training-free manner. Beyond inference-time augmentation, supervised fine-tuning (SFT) on S-Agent-generated spatial trajectories S-300K yields S-Agent-8B, a compact spatial agent that significantly surpasses similar-scale baselines (e.g., Qwen3-VL-8B) and performs comparably to advanced closed-source models (e.g., GPT-5.4 and Gemini 3).

# Q1: 核心算法原理

## 1.1 核心思想和动机

### 1.1.1 问题诊断：帧中心范式的根本缺陷

S-Agent 的核心动机来自一个关键观察：当前 VLMs 和工具增强 agents 都被"锁定"在**帧中心（frame-centric）**的推理模式上。论文从三个层面分析了这一缺陷：

**（1）语义-几何鸿沟（Semantic-to-Geometric Gap）**

VLMs 在被动 2D 视觉-文本语料上训练，缺乏显式 3D 监督或具身体验。这导致：
- VLMs 擅长概率性和定性的语义推理
- 但其推理被"有损语义表示"中介，无法忠实捕捉高保真几何信息
- 容易依赖文本模式和语义先验，而非 3D 几何证据

**（2）孤立观察问题**

现有方法（如 VADAR、SpaceTools）虽然通过工具增强了 VLMs，但仍聚焦于静态图像或孤立的视觉观察。这远离真实世界空间智能的需求：
- 真实 3D 世界是**隐藏的**——无法从单一视角完全观测
- 真实 3D 世界是**演化的**——场景随时间变化
- 3D 世界被连续投影为 2D 观测流——需要从多帧整合信息

**（3）无状态推理的局限**

从孤立的 2D 视角推理导致根本性挑战：
- 无法维护**持久的目标状态**——物体在不同帧间的身份追踪困难
- 无法跨视点和时间**整合证据**——信息碎片化
- 无法构建对底层 3D 场景的**连贯理解**——缺乏全局空间表征

### 1.1.2 核心洞察：从帧级识别到场景中心理解

S-Agent 的核心思想是**将空间推理形式化为时空证据累积（spatio-temporal evidence accumulation）**，而非孤立的帧级预测。

这一范式转换包含两个关键维度：

**空间维度（Spatial Dimension）——分层证据获取：**
- 不是要求 VLMs 隐式内化整个 3D 理解过程
- 而是将 VLM 定位为**语义规划器**：决定"需要什么证据"
- 然后由分层工具和专家提供**连续且显式的 3D 感知**
- 从低层 2D/3D 证据（物体定位、深度信息）到高层空间知识（方向、关系）

**时间维度（Temporal Dimension）——持续记忆维护：**
- **Scene Memory**：跨帧追踪已定位的实体，保持物体身份一致性，抑制重复证据
- **Agent Memory**：存储已积累的工具观察和中间推理轨迹，用于迭代精化

### 1.1.3 时空证据累积的本质

证据累积范式的本质可以用论文的形式化来表达：

在推理步骤 t，S-Agent 维护两个记忆状态：
- 场景记忆状态 $\mathcal{S}_t$：存储已定位的实体及其累积的空间属性
- Agent 记忆状态 $\mathcal{H}_t$：记录之前的工具调用、观察和推理决策

VLM 规划器 $\pi_\theta$ 将问题 $q$、输入观察 $\mathcal{F}$ 和当前记忆状态映射为证据请求 $r_t$：

$$r_t = \pi_\theta(q, \mathcal{F}, \mathcal{S}_t, \mathcal{H}_t)$$

工具执行请求并返回观察 $o_t$，更新两个记忆状态：

$$(\mathcal{S}_{t+1}, \mathcal{H}_{t+1}) = \text{Update}(\mathcal{S}_t, \mathcal{H}_t, r_t, o_t)$$

Agent 在累积的证据足以回答 $q$ 时终止。**这一框架的关键创新在于：每个证据请求都以问题**和**演化的记忆状态为条件——不是将每次工具调用视为孤立动作，而是将感知和几何计算按需调用，其输出可在后续推理步骤中重复使用。**

## 1.2 主要技术方法

### 1.2.1 VLM as Semantic Planner —— 具体机制

S-Agent 中的 VLM 被赋予了一个特定角色：**语义规划器（Semantic Planner）**。这与传统 VLM 的"全做"模式根本不同：

**传统 VLM 模式：**
```
图像 + 问题 → VLM 直接输出答案
（VLM 需要同时完成语义理解、空间感知、几何推理、关系判断）
```

**S-Agent 模式：**
```
图像 + 问题 + Scene Memory + Agent Memory → VLM 决定"需要什么证据"
→ 工具/专家执行并返回观察 → 更新记忆
→ 循环直到证据充分 → VLM 基于累积证据给出最终答案
```

VLM 规划器的核心职责：
1. **问题分解**：将空间问题分解为需要的证据类型（计数？测量？方向？位置？）
2. **工具选择**：根据问题类型和当前记忆状态选择合适的工具/专家
3. **证据评估**：判断已获取的证据是否足以回答问题
4. **策略调整**：基于工具反馈调整下一步证据获取策略
5. **答案综合**：将累积的空间证据综合为最终答案

**关键设计理念：将语义理解与空间感知分离。** VLM 专注于它擅长的语义推理和规划，而将场景特定的感知和空间计算（视觉定位、几何恢复、度量/关系计算）委托给专用工具。

### 1.2.2 分层工具架构 —— 三层细节

S-Agent 的工具架构分为三个层级，反映了空间任务所需的证据层次：

#### Level 1: 2D 视觉证据获取（$\mathcal{T}^{(1)}$）

**目标：** 从原始 2D 观察中提取有用的视觉线索。

**核心工具：**
- **关键帧选择（Keyframe Selection）**：视频/多视图图像包含大量冗余、部分或无关的视角。关键帧选择工具从 $\mathcal{F}$ 中选择与问题最相关的信息帧。
- **VLM Grounding**：使用 VLM 在选定的帧中定位问题中引用的实体（如"耳机"、"门"），建立以物体为中心的视觉事实。
- **开放词汇检测（Open-Vocabulary Detection）**：使用 GDINO 等检测器定位候选区域，当 VLM grounding 失败时提供备选方案。

**具体场景示例（来自项目主页）：**
```
Step 01 · 2D Evidence
Ground the entities before reasoning.
headphones + door + camera · 3 / 3 located ✓
```

**设计哲学：** 这些图像级线索可以直接支持简单查询（如"图中有什么"），同时为后续 3D 提升和空间推理提供基础观察。

#### Level 2: 2D 到 3D 几何提升（$\mathcal{T}^{(2)}$）

**目标：** 将图像级证据提升为场景的 3D 感知表征。

**核心工具：**
- **度量级 3D 重建（Metric 3D）**：使用 Depth Anything 3 (DA3) 从 2D 图像恢复度量级深度结构。
- **相机位姿估计（Camera Pose Estimation）**：恢复多视图间的相机位姿关系，使不同视角的证据可以在共享空间中对齐。
- **鸟瞰图/新视图生成（BEV / Novel View）**：从恢复的 3D 信息构建鸟瞰图或新视图，提供超越原始图像平面的推理视角。

**具体能力：**
- 碎片化的 2D 观察可以在**共享空间上下文**中进行比较
- 表观 2D 大小可以从**物理尺度**中消歧
- 空间关系可以相对于**相机运动或替代视角**进行评估

**消融实验的重要发现：** 论文发现直接添加 Level 2 的 3D 证据效果有限（仅从 49.0% 到 49.8%）。原因是原始 3D 证据包含密集的数值信息（相机位姿、深度值、噪声重建点），对 VLM 规划器来说难以解释，甚至可能分散注意力。**3D 证据需要经过 Level 3 专家的过滤和解释才能发挥最大价值。**

#### Level 3: 空间知识聚合（$\mathcal{T}^{(3)}$）

**目标：** 将 2D 和 3D 线索抽象为高层、场景特定的空间知识。

**核心专家（Spatial Experts）：**

| 专家名称 | 功能 | 输入 | 输出 |
|---------|------|------|------|
| **Counting Expert** | 物体计数 | 多帧检测结果 | 去重后的物体数量 |
| **Measurement Expert** | 物理测量 | 3D 度量信息 | 距离、尺寸的数值估计 |
| **Relative Position Expert** | 相对位置 | 3D 坐标 + 鸟瞰图 | 物体间的方位关系 |
| **Visual Orientation Expert** | 视觉朝向 | 物体 3D 模型 | 物体面朝的方向 |
| **Object View Expert** | 物体视角 | 多视图信息 | 从特定视角观察物体的状态 |

**关键设计理念：** 专家将碎片化的感知和几何线索转化为**显式的场景级空间知识**，减少 VLM 在自由文本中进行不可靠度量或关系推理的需求。

**实际工作流示例（来自论文 Figure 4）：**
```
问题："货架相对于电话机的位置是什么？"

Step 1: VLM grounding 尝试定位 shelf 和 telephone → 部分失败
Step 2: Agent 发布检测调用，使用语义相关查询 "desk phone" → 成功获取两个物体的框
Step 3: 相对位置专家将选定框通过深度工具提升为度量 3D 表征
Step 4: 构建鸟瞰图布局：
   - shelf 位于 (-0.52, 1.21)
   - telephone 位于 (-0.34, 1.46)
Step 5: 几何恢复显示 shelf 在 telephone 的左侧和后方 → 正确答案
```

### 1.2.3 Scene Memory 和 Agent Memory —— 数据结构和更新机制

S-Agent 的双记忆系统是其核心创新之一，支持跨视图、跨帧和跨推理步骤的状态维护。

#### Scene Memory

**设计理念：** Scene Memory 将 2D/3D 线索转化为持久的、场景级的理解。它不是对完整环境的密集重建，而是**问题条件化的空间记忆**——只保留当前查询所需的证据。

**存储内容：**

```
Scene Memory
├── Grounded Entities（已定位实体）
│   ├── 实体 1
│   │   ├── textual_alias: ["shelf", "bookshelf"]
│   │   ├── supporting_frames: [frame_3, frame_7, frame_12]
│   │   ├── localized_visual_evidence: bounding_boxes
│   │   └── accumulated_geometric_attributes:
│   │       ├── 3D_position: (-0.52, 1.21)
│   │       ├── depth_profile: [...]
│   │       └── BEV_projection: [...]
│   ├── 实体 2
│   │   └── ...
│   └── ...
│
└── Derived Spatial Facts（导出空间事实）
    ├── 事实 1
    │   ├── type: "relative_position"
    │   ├── content: "shelf is left-of and behind telephone"
    │   ├── evidence_source: ["depth_tool", "BEV_layout"]
    │   └── confidence: 0.92
    ├── 事实 2
    │   └── ...
    └── ...
```

**更新机制：** Merge 操作
- 当新观察到达时，S-Agent 要么将其链接到现有的 Scene Memory 条目（更新实体的别名、帧、属性），要么创建新条目
- 这允许后续推理步骤**重用之前定位的证据或事实**，而非从头重新处理每一帧

**关键特性：**
- **实体持久性**：同一物体在不同帧、视点、尺度下的重复观察被绑定到同一场景实体
- **证据累积**：几何属性随更多观察而累积，提高精度
- **问题条件化**：不是重建完整场景，而是保留与当前问题相关的最小必要证据

#### Agent Memory

**设计理念：** Agent Memory 保持导致场景理解演化的**推理过程**。它记录的不是可重用的场景证据，而是**程序性上下文**——那些证据是如何获得和使用的。

**存储内容：**

```
Agent Memory
├── Step 1
│   ├── planner_thought: "需要先定位问题中的物体"
│   ├── tool_call: vlm_ground(["shelf", "telephone"], frame_5)
│   ├── observation: "shelf found at [x1,y1,x2,y2]; telephone not found"
│   ├── failure_message: "telephone not detected in frame 5"
│   └── intermediate_conclusion: "需要尝试其他检测方式"
│
├── Step 2
│   ├── planner_thought: "尝试使用开放词汇检测器"
│   ├── tool_call: detect("desk phone", frames[1-20])
│   ├── observation: "telephone found in frame 8, 11, 15"
│   └── intermediate_conclusion: "所有物体已定位，可以进行3D提升"
│
├── Step 3
│   ├── planner_thought: "需要获取相对位置"
│   ├── tool_call: relative_position_expert(shelf, telephone)
│   ├── observation: "shelf at (-0.52,1.21); telephone at (-0.34,1.46)"
│   └── intermediate_conclusion: "shelf is left-behind telephone"
│
└── ...
```

**更新机制：** Append 操作
- 每个推理步骤的请求、观察、推理上下文被追加到记忆轨迹中
- 不做合并或压缩——保留完整的推理历史

**关键特性：**
- **避免冗余调用**：知道什么已经被尝试过
- **识别未解决的不确定性**：知道什么仍然不确定
- **保持推理一致性**：不会与之前的观察矛盾
- **支持策略调整**：基于工具反馈细化下一步策略

#### 两种记忆的协作关系

每次工具执行后，观察 $o_t$ 被分解为两部分：
- **场景相关内容 $e_t$**：合并到 Scene Memory（Merge 操作）
- **过程上下文 $c_t$**：追加到 Agent Memory（Append 操作）

这种分离使 VLM 规划器能够：
1. 基于 Scene Memory 中累积的空间知识进行推理
2. 同时参考 Agent Memory 中的推理历史来决定下一步

## 1.3 算法流程和关键步骤

### 完整推理流程

```
输入：问题 q，视觉观察集合 F（多视图图像或视频帧序列）

初始化：
  S_0 = ∅ （空的 Scene Memory）
  H_0 = ∅ （空的 Agent Memory）
  t = 0

循环：
  Step 1: VLM 规划器决策
   r_t = π_θ(q, F, S_t, H_t)
   - 规划器综合考虑：问题需求、可用观察、已累积的场景证据、推理历史
   - 输出：证据请求 r_t（选择哪个层级、哪个工具/专家、针对哪些实体/帧）

  Step 2: 工具执行
   选择 T^(k) ∈ 𝒯^(k), k ∈ {1,2,3}
   o_t = T^(k)(r_t, F, S_t)
   - 工具在当前场景记忆的辅助下执行（例如，利用已有实体定位信息）

  Step 3: 观察分解
   将 o_t 分解为：
   - e_t：场景相关证据（新发现的实体、更新的几何属性、计算的空间关系）
   - c_t：过程上下文（请求内容、返回观察、成功/失败信息、推理思路）

  Step 4: 双记忆更新
   S_{t+1} = Merge(S_t, e_t)   // 合并到场景记忆
   H_{t+1} = Append(H_t, c_t)  // 追加到推理记忆
   t = t + 1

  Step 5: 终止判断
   如果累积证据足以回答 q → 跳出循环
   否则 → 返回 Step 1

输出：基于 (q, S_t, H_t) 的最终答案 a
```

### 典型推理轨迹示例

以项目主页上的空间定向问题为例：

```
问题：站在耳机旁，背对入口门——相机在哪里？
选项：左前、右前、左后、右后

Step 00 · 问题理解
  VLM 规划器分析问题维度：
  - 需要定位三个实体：headphones, door, camera
  - 需要建立以 headphones 为中心、背对 door 的自我中心坐标系
  - 需要在该坐标系中确定 camera 的象限

Step 01 · Level 1 - 2D 证据获取
  工具调用：vlm_ground(headphones, door, camera)
  结果：3/3 实体定位成功 ✓
  → Scene Memory 更新：三个实体的 2D bounding box 和所在帧
  → Agent Memory 追加：grounding 步骤的请求和结果

Step 02 · Level 2 - 3D 提升
  工具调用：metric_3d(headphones, door, camera centers)
  结果：三个实体的 3D 锚点坐标
  → Scene Memory 更新：实体的 3D 位置属性
  → Agent Memory 追加：3D 提升步骤

Step 03 · Level 3 - 朝向专家
  工具调用：orientation_expert(headphones → face_away_from door)
  结果：建立以 headphones 为原点、Z 轴背离 door 的自我中心坐标系
  → Scene Memory 更新：添加坐标系定义作为导出空间事实
  → Agent Memory 追加：朝向推理步骤

Step 04 · Level 3 - 方向专家
  工具调用：direction_expert(camera position in egocentric frame)
  结果：camera 落在 person's back-right
  → Scene Memory 更新：camera 的相对方向事实
  → Agent Memory 追加：方向解析步骤

Step 05 · 终止 + 答案
  证据充分，输出答案：D (back-right)
  ✓ 正确 · GT: D · 3 turns · 6 tool calls
```

## 1.4 输入输出格式

### 输入格式

**视觉输入 $\mathcal{F}$：**
- 多视图图像集：同一场景的多个视角图像 $\{I_1, I_2, ..., I_n\}$
- 视频帧序列：视频按时间采样得到的帧 $\{f_1, f_2, ..., f_t\}$
- 支持可变数量的输入帧

**问题 $q$：**
- 多选题：如 "A. front-left  B. front-right  C. back-left  D. back-right"
- 数值问题：如 "What is the distance between A and B (in meters)?"
- 文本问题：如 "Describe the spatial relationship between A and B"

**问题类型覆盖：**
- 位置关系（Positional Relationship）：C-C, O-O, R-R, C-O, O-R, C-R
- 几何属性（Geometric Attribute）：测量、表观大小
- 运动感知（Motion Perception）：相机运动、物体运动
- 多步推理（Multi-step Reasoning）

### 输出格式

- **最终答案 $a$**：基于累积证据的答案
- **完整推理轨迹**：包括规划器的思考、工具调用、观察、中间结论
- **记忆状态快照**：Scene Memory 和 Agent Memory 的最终状态

# Q2: 与 Spatial AGI 的关系

## 2.1 如何理解和表示空间 —— Scene Memory 的空间表示方式

### 2.1.1 空间表示的层次结构

S-Agent 的 Scene Memory 采用了一种独特的**层次化空间表示**，这与传统的空间表征方法（如点云、体素、神经辐射场）有本质不同：

**传统空间表征 vs S-Agent 的方法：**

| 方法 | 空间表示 | 特点 |
|------|---------|------|
| 点云（Point Cloud） | 3D 点集 | 密集、精确，但计算开销大 |
| 体素（Voxel Grid） | 3D 网格 | 结构化，但分辨率受限 |
| NeRF | 神经网络权重 | 隐式表示，难以推理 |
| SLAM 地图 | 特征点 + 位姿图 | 适合导航但不包含语义 |
| **S-Agent Scene Memory** | **实体中心 + 几何属性 + 导出事实** | **问题条件化、语义化、可推理** |

### 2.1.2 Scene Memory 的空间表示方式

Scene Memory 的空间表示可以理解为一种**语义化的空间认知地图**：

**（1）实体中心的坐标系统**
- 每个物体作为独立实体被追踪
- 实体绑定多个层次的几何属性：
  - 2D 层：bounding box、关键帧位置
  - 3D 层：度量坐标 $(x, y, z)$
  - 关系层：与其他实体的相对位置

**（2）多坐标系共存**
- 绝对坐标系：基于场景的 3D 度量坐标
- 相机坐标系：相对于观察者的视角
- 自我中心坐标系：基于问题情境（如"站在耳机旁，背对门"）

**（3）导出空间事实的语义编码**
- 不是存储原始数值，而是存储**语义化的空间关系**
- 例如："shelf is left-of and behind telephone" 而非仅存储坐标差
- 这使得空间知识可以直接被 VLM 规划器消费

### 2.1.3 对 Spatial AGI 的启发：问题条件化的空间记忆

Scene Memory 最重要的设计决策是**不做全场景重建**，而是维护问题条件化的空间记忆。这对 Spatial AGI 有深远启发：

- **认知效率**：人类也不会对环境进行全细节重建，而是根据当前目标选择性注意
- **可扩展性**：问题条件化意味着记忆需求与问题复杂度成正比，而非场景复杂度
- **推理导向**：存储的内容直接服务于推理需求，而非追求几何保真度

这种表示方式暗示了一条**非传统**的 Spatial AGI 路径：不是构建越来越精细的 3D 重建，而是构建越来越智能的、选择性空间记忆。

---

## 2.2 如何处理空间关系 —— 证据累积范式如何处理空间关系推理

### 2.2.1 空间关系推理的挑战

空间关系推理是 Spatial AGI 的核心能力之一，包括：
- **拓扑关系**：相邻、包含、重叠
- **方向关系**：左/右、前/后、上/下
- **度量关系**：距离、大小
- **视角依赖关系**：从不同观察者的视角看，空间关系会变化

传统 VLMs 处理空间关系的主要问题：
1. **2D 投影歧义**：3D 空间关系投影到 2D 后产生歧义（如"近大远小"问题）
2. **视角依赖性**：同一空间关系从不同视角看不同（如"左"vs"右"取决于面朝方向）
3. **多步推理需求**：复杂空间问题需要多步推理（如"A在B的左边，B在C的前面，则A相对于C在哪？"）

### 2.2.2 证据累积范式处理空间关系的机制

S-Agent 通过以下方式系统性地处理空间关系推理：

**（1）2D 到 3D 的消歧**
- Level 2 的几何提升将 2D 观察提升为 3D 表示
- 深度信息消解 2D 投影中的位置歧义
- 鸟瞰图提供无歧义的俯视布局

**（2）专家系统的精确计算**
- 相对位置专家使用 3D 坐标计算精确的方位关系
- 朝向专家建立自我中心坐标系来处理视角依赖
- 测量专家使用度量 3D 信息计算精确距离

**（3）记忆支持的迭代推理**
- Agent Memory 保持多步推理的上下文连贯性
- Scene Memory 累积中间空间事实供后续步骤使用
- 支持条件化的空间推理链（如先确定 A→B 关系，再确定 B→C 关系，最后推导 A→C）

**（4）容错和恢复**
- 当初始 grounding 失败时，Agent 可以尝试语义相关查询
- 失败信息被记录在 Agent Memory 中，指导后续尝试
- 多帧证据的累积可以提升定位置信度

### 2.2.3 实验验证

论文的实验结果强有力地支持了这一范式的有效性：

- **MMSI-Bench 运动感知子任务**：相机运动 +31.1pp，物体运动 +14.5pp —— 这些任务需要跨帧整合运动证据
- **ViewSpatial-Bench P-RD（相对方向）**：81.1%（+32.6pp）—— 视角依赖的方向推理大幅提升
- **ReVSI 相对方向和路线规划**：均为最佳结果 —— 需要多步空间关系推理的任务

## 2.3 对 Spatial AGI 的启发 —— 小模型+工具匹配大模型的意义

### 2.3.1 打破规模垄断

S-Agent 最具启发性的结果是：**S-Agent-8B 在多个基准上与 GPT-5.4 和 Gemini 3 Pro 表现相当**。

| 模型 | MMSI-Bench | ViewSpatial-Bench | ReVSI |
|------|-----------|-------------------|-------|
| Gemini 3 Pro | 45.2 | 50.4 | 60.9 |
| GPT-5.4 | 41.9 | 45.6 | - |
| Qwen3-VL-8B (base) | 31.1 | 42.2 | 49.1 |
| **S-Agent-8B** | **41.6** | **46.8** | **52.8** |

这意味着一个 8B 参数的模型，通过学习工具使用和证据整合的模式，可以在空间推理能力上匹配**参数量大一到两个数量级**的模型。

### 2.3.2 对 Spatial AGI 架构设计的启示

**（1）分解优于端到端**

S-Agent 证明了将空间推理分解为"语义规划 + 工具执行"的 agent 范式优于让单一模型端到端处理一切。这对 Spatial AGI 的架构设计指向：
- 核心模型不需要"什么都会"，而是要会"知道什么时候需要什么工具"
- 专用工具（深度估计、3D 重建、空间计算）可以独立优化和替换
- 系统可以按需扩展——添加新的空间专家不需要重新训练整个模型

**（2）记忆是空间智能的关键**

双记忆系统的成功表明，Spatial AGI 不能只有感知，还需要：
- **场景记忆**对应人类的"空间工作记忆"——维护当前任务相关的空间信息
- **Agent 记忆**对应人类的"推理工作记忆"——追踪思考过程

这暗示 Spatial AGI 的架构需要内置记忆组件，而非依赖单一的前馈推理。

**（3）证据累积范式优于单次预测**

空间推理本质上不是一次性预测，而是逐步收集和整合证据的过程。这一范式转换意味着：
- Spatial AGI 的评估标准应该包括推理过程的质量，而非仅看最终答案
- 训练方法应该关注如何生成高质量的证据获取轨迹
- 推理效率不应仅看模型大小，而应看整个证据获取流程的效率

**（4）自我改进的数据飞轮**

S-300K 的成功展示了一种可扩展的自我改进范式：
```
强大的 Agent (GPT-5.4 + tools) → 生成轨迹 → 过滤+分解 → 训练数据
→ 训练紧凑 Agent (8B) → S-Agent-8B ≈ GPT-5.4
```
这种范式可以迭代：
```
S-Agent-8B → 更好的轨迹 → 更好的训练数据 → S-Agent-8B v2 → ...
```

### 2.3.3 对空间认知科学的呼应

S-Agent 的设计与人类空间认知理论高度一致：

**（1）双系统理论**
- Scene Memory ≈ 空间认知系统（"where" pathway）
- Agent Memory ≈ 推理控制系统（前额叶工作记忆）

**（2）空间更新的认知机制**
- Scene Memory 的 Merge 操作 ≈ 人类跨视点整合空间信息的认知过程
- 类似于人类在导航时不断更新"认知地图"的方式

**（3）选择性空间注意**
- 问题条件化的记忆 ≈ 人类的目标导向空间注意
- 只处理与当前任务相关的空间信息，忽略无关细节

# Q3: 创新点和局限性

## 3.1 主要创新点

### 3.1.1 与现有 Agent 框架的系统对比

| 特性 | Visual ChatGPT | ViperGPT | VADAR | SpaceTools | **S-Agent** |
|------|---------------|----------|-------|------------|-------------|
| 空间推理专门化 | ✗ | ✗ | ✓ | ✓ | **✓** |
| 多视图/视频支持 | ✗ | ✗ | 部分 | 部分 | **✓ (核心)** |
| 状态化推理 | ✗ | ✗ | ✗ | 部分 | **✓ (双记忆)** |
| 分层工具架构 | ✗ | ✗ | 部分 | ✓ | **✓ (三层级)** |
| 证据累积范式 | ✗ | ✗ | ✗ | ✗ | **✓ (核心创新)** |
| 训练数据生成 | ✗ | ✗ | ✗ | RL | **✓ (S-300K)** |
| 训练紧凑 Agent | ✗ | ✗ | ✗ | ✓ | **✓ (S-Agent-8B)** |

### 3.1.2 六大核心创新

**创新 1：时空证据累积范式（Spatio-Temporal Evidence Accumulation）**

这是 S-Agent 最根本的创新。之前的空间推理方法（无论是端到端 VLM 还是工具增强 agent）都将推理视为一次性过程：输入图像 → 输出答案。S-Agent 首次将空间推理形式化为一个**逐步累积证据的迭代过程**，每一步都基于问题需求和当前证据状态来决定下一步获取什么证据。

**关键区别：**
- ReAct 框架：通用的推理-行动交替，无空间专门化
- ViperGPT：生成代码执行视觉推理，但无状态维护
- S-Agent：**空间专门化的证据累积**，每一步的条件包含演化的场景状态

**创新 2：VLM 语义规划器与空间工具的分离**

S-Agent 不是让 VLM "做所有事"，也不是让工具"自动运行"。它的创新在于明确定义了 VLM 的角色——**语义规划器**：
- VLM 决定"需要什么证据"（语义层）
- 工具/专家"提供证据"（感知和计算层）
- 记忆"连接两者"（状态层）

这种三角分离使每个组件可以独立优化，且组合效果远大于任何单一组件。

**创新 3：分层工具架构（2D → 3D → 知识）**

三层架构不是随意的堆叠，而是反映了空间理解的**内在层次性**：
- Level 1（2D）：视觉事实层——"什么在哪里"
- Level 2（3D）：几何恢复层——"在 3D 空间中的位置"
- Level 3（知识）：空间推理层——"这意味着什么"

消融实验证明这一分层是关键的：跳过任何层或打乱顺序都会降低性能。特别是 Level 3 的专家层（将噪声几何输出转化为可消费的空间知识）贡献了最大的性能提升（从 49.8% 到 56.7%）。

**创新 4：双记忆系统（Scene Memory + Agent Memory）**

虽然记忆机制在 NLP agent 中已有应用（如 ReAct 的推理轨迹），但 S-Agent 的创新在于：
- **功能分离**：Scene Memory 存储可重用的场景证据（Merge 操作），Agent Memory 存储推理过程（Append 操作）
- **空间专门化**：Scene Memory 是实体中心的，支持跨帧的物体身份持久性
- **问题条件化**：不是全场景重建，而是选择性记忆当前问题所需的证据

消融实验显示两种记忆各自独立贡献约 1-2% 的提升，组合使用达到最优效果。

**创新 5：轨迹蒸馏训练范式（S-300K）**

S-Agent 不仅是一个推理框架，还是一个**数据生成引擎**。核心创新在于：
- 用强大的 teacher agent（GPT-5.4 + tools）生成完整的推理轨迹
- 将轨迹分解为多种粒度的训练信号：
  - **最终答案轨迹**：教端到端空间推理
  - **轮次级轨迹**：教迭代工具使用决策
  - **专家/工具轨迹**：提升空间工具使用策略
- 多粒度监督使学生模型不仅学到答案分布，还学到如何请求证据、解释观察

**创新 6：Training-free 与 Training-based 统一框架**

S-Agent 在两种模式下都有效：
- **Training-free**：直接将框架应用于现有 VLMs，获得即时提升
- **Training-based**：通过轨迹蒸馏训练出专门的紧凑 agent

这种统一性意味着 S-Agent 可以同时服务于：
- 需要即时部署的场景（使用 training-free 模式）
- 需要高效推理的场景（使用蒸馏的紧凑 agent）

### 3.1.3 技术贡献的量化验证

消融实验（Table 5, ViewSpatial-Bench with GPT-5.4 planner）精确量化了每个组件的贡献：

| 配置 | 准确率 | 增量 |
|------|--------|------|
| VLM-only (no tools) | 45.6% | baseline |
| + Level 1 (2D evidence) | 49.0% | +3.4 |
| + Level 2 (3D lifting) | 49.8% | +0.8 |
| + Level 3 (3D experts) | 56.7% | +6.9 |
| + Scene Memory | 58.2% | +1.5 |
| + Agent Memory | 57.6% | +0.9 (vs L1-L3 only) |
| Full S-Agent | 60.0% | +14.4 total |

关键发现：
- Level 3 专家层贡献最大（+6.9pp），证明"解释 3D 证据"比"获取 3D 证据"更重要
- Level 2 直接使用反而效果有限（+0.8pp），因为原始 3D 数据对 VLM 来说噪声太大
- 两种记忆各自贡献相当，组合使用有协同效应

## 3.2 主要局限性

### 3.2.1 计算开销

**工具调用链的成本**

S-Agent 的每次推理涉及多次工具调用，这带来显著的计算开销：

| 推理模式 | 模型调用次数 | 工具执行次数 | 总延迟（估计） |
|---------|-------------|-------------|---------------|
| 直接 VLM | 1 | 0 | 1-3 秒 |
| S-Agent (典型) | 3-5 | 6-10 | 10-30 秒 |
| S-Agent (复杂) | 5-8 | 10-15 | 20-60 秒 |

- 多次 VLM 规划调用累积大量 token 消耗
- 3D 工具（DA3、VGGT 等）本身需要 GPU 资源
- 工具间的数据传递（特别是 3D 数据）增加 I/O 开销

**延迟问题**
- 项目主页显示典型推理需要 3 turns / 6 tool calls
- 对于实时应用（自动驾驶、机器人控制）可能太慢
- 对比：人类空间感知几乎是即时的

**API 成本**
- Zero-shot S-Agent 使用 GPT-5.4 作为 planner，每次推理消耗大量 API 调用
- 大规模部署的成本可能成为瓶颈
- S-Agent-8B 虽然更经济，但需要 GPU 部署

### 3.2.2 工具依赖

**工具可用性**
- S-Agent 依赖多个外部工具：Depth Anything 3、GDINO、VGGT 等
- 每个工具可能有不同的依赖、版本和部署需求
- 工具的更新可能影响 S-Agent 的行为一致性

**工具质量瓶颈**
- Level 1 的 grounding 精度直接影响后续推理
- Level 2 的深度估计误差会传播到 Level 3
- 工具在特定场景下可能失效（如遮挡严重、光照极端）

**工具选择策略**
- 论文发现 base Qwen3-VL-8B 直接使用 S-Agent 工具"并不一致改善性能"
- 弱模型在工具选择和观察解释上存在困难
- 这意味着 S-Agent 框架的効果高度依赖 planner 模型的能力

### 3.2.3 时空一致性的局限

**动态场景处理**
- Scene Memory 的 Merge 操作假设实体在不同帧间是静止的
- 对于快速移动的物体或严重形变的场景可能不适用
- 物体的非刚性形变（如人体姿态变化）没有被显式建模

**长期时序推理**
- Scene Memory 是问题条件化的短期记忆，推理结束后即清空
- 不支持跨问题、跨场景的长期空间记忆积累
- 无法回答"昨天办公室里的桌子和今天的有什么不同"这类问题

### 3.2.4 空间表示的局限

**2.5D 而非真正的 3D**
- Depth Anything 3 从单视图恢复深度，本质上是 2.5D
- VGGT 的多视图 3D 重建精度受视图重叠度限制
- 闭塞区域的 3D 信息需要推测，可能不准确

**语义空间关系不完备**
- 当前专家集覆盖：计数、测量、方向、相对位置
- 缺少：拓扑关系（包含、相邻）、运动轨迹、物理属性（重量、材质）
- 无法处理需要物理常识的空间推理（如"这个架子能承受那个花瓶吗"）

### 3.2.5 评估局限

**基准覆盖**
- 四个基准主要评估室内/城市场景的空间推理
- 缺少：自然环境、大规模室外场景、复杂工业场景
- 缺少：实时视频流（vs 采样的帧序列）

**对比公平性**
- Zero-shot S-Agent 使用 GPT-5.4 作为 planner，这在对比中可能不公平
- S-Agent 的多次工具调用本质上获得了比单次推理更多的信息
- 一个更公平的对比可能是：给所有方法相同的推理预算（总 token 数或总时间）

## 3.3 S-300K 数据集的意义和可扩展性

### 3.3.1 数据集概况

**来源：** SenseNova-SI-800K 训练集（与所有评估基准完全不相交）
**采样：** 随机采样 100K 问题
**生成：** 使用 GPT-5.4 planner 的 zero-shot S-Agent 生成轨迹
**过滤后：** 292,391 个 SFT 样本（S-300K）

**过滤标准：**
- 执行有效性：轨迹中的所有工具调用必须成功执行
- 答案正确性：
  - 多选题：预测选项必须匹配 ground truth
  - 数值题：mean relative accuracy 达标
  - 文本题：normalized answer matching
- 工具使用不是硬性过滤标准——允许 planner 自主决定是否需要工具

**数据分解为三种监督形式：**
1. **Final-answer trajectories**：完整的端到端推理轨迹
2. **Turn-level trajectories**：单轮工具使用决策（在部分推理上下文下）
3. **Expert/tool trajectories**：特定工具或专家的使用模式

### 3.3.2 数据集的意义

**（1）填补空间推理数据的空白**

现有的视觉指令调优数据集（如 LLaVA、VisualChat）主要关注 2D 图像理解和描述，缺少高质量的空间推理轨迹。S-300K 是首批：
- 包含完整工具调用链的空间推理轨迹数据集
- 覆盖多视图和视频场景的空间指令数据
- 通过高质量 teacher agent 生成的多粒度监督数据

**（2）验证 Agent 数据飞轮范式**

S-300K 证明了一种可扩展的数据生成范式：
```
强 Teacher Agent (GPT-5.4 + tools)
    → 生成完整推理轨迹
    → 质量过滤（执行有效性 + 答案正确性）
    → 多粒度分解
    → S-300K
    → 训练紧凑 Student Agent (8B)
    → S-Agent-8B ≈ GPT-5.4
```

这种范式的核心价值在于**可迭代性**：
- 随着工具质量提升，teacher 轨迹质量也会提升
- 随着 student 模型能力增强，可以更好地利用 teacher 数据
- 可以持续扩展到更多场景和问题类型

**（3）多粒度监督的创新**

传统的 SFT 数据只包含"输入-输出"对。S-300K 的创新在于多粒度分解：
- 最终答案：教模型"推理到什么结论"
- 轮次级：教模型"在给定上下文下应该做什么决策"
- 工具级：教模型"如何使用特定工具和解释其输出"

这种多粒度策略使 8B 模型能够学到比简单模仿更深层的能力——它学到了工具使用的**策略**和**语法**。

### 3.3.3 可扩展性分析

**优势：**

1. **数据源可扩展**：SenseNova-SI-800K 提供了 800K 的种子问题，当前仅采样了 100K（12.5%）。理论上可以从剩余数据生成更多轨迹。

2. **Teacher 可升级**：随着更强大的 VLMs 出现（如 GPT-6、Gemini 4），可以使用更强的 teacher 生成更高质量的轨迹。

3. **工具可扩展**：新的空间专家（如物理推理专家、拓扑关系专家）可以被添加到框架中，生成相应类型的训练数据。

4. **学生模型可替换**：S-300K 不局限于 Qwen3-VL-8B，可以用于训练任何兼容的 VLM。

**限制：**

1. **数据质量上限受 Teacher 限制**：如果 teacher agent（GPT-5.4 + tools）在特定类型问题上表现不佳，生成的轨迹也会反映这些错误。

2. **工具依赖**：轨迹中包含的工具调用与特定工具版本绑定。如果工具升级（如 DA3 → DA4），旧轨迹可能需要重新生成。

3. **领域覆盖**：训练数据来自 SenseNova-SI-800K，其领域覆盖范围可能限制 S-Agent-8B 在完全不同场景（如医疗影像、卫星图像）下的表现。

4. **分布偏差**：通过难度采样和工具使用倾向采样选择的问题可能引入分布偏差，使 S-Agent-8B 在特定问题类型上过度优化。

### 3.3.4 对 Spatial AGI 数据策略的启示

S-300K 的成功为 Spatial AGI 的数据策略提供了重要启示：

**（1）过程数据 > 结果数据**

传统的空间推理数据集只包含"问题-答案"对。S-300K 证明了包含完整推理过程（工具调用、中间观察、推理决策）的数据更有价值。这暗示 Spatial AGI 的训练需要：
- 捕获空间推理的中间步骤
- 记录成功的和失败的推理路径
- 包含工具使用和证据评估的决策点

**（2）合成数据的潜力**

S-300K 本质上是合成数据——由 AI agent 生成的推理轨迹。它的成功挑战了"合成数据不如真实数据"的传统观念。对于 Spatial AGI：
- 高质量的 agent 轨迹可能比人工标注的"问题-答案"对更有训练价值
- 合成数据可以覆盖更广泛的场景和问题类型
- 合成数据可以随模型进步而持续改进

**（3）数据质量 > 数据数量**

S-300K 从 100K 问题出发，经过过滤得到约 292K 训练样本。过滤率（约 3x 扩展）说明：
- 不是所有 agent 轨迹都值得学习
- 正确性和有效性的过滤至关重要
- 即使是"成功"的轨迹也可能包含次优的推理路径

# 总结与展望

## 核心贡献回顾

S-Agent 通过三个关键创新推动了空间智能的发展：

1. **概念创新**：将空间推理从"单次帧级预测"重新定义为"时空证据累积过程"
2. **架构创新**：VLM 规划器 + 三层工具 + 双记忆系统的完整框架
3. **实践创新**：Training-free 增强 + 轨迹蒸馏训练的统一范式

## 对 Spatial AGI 路线图的启示

S-Agent 的成功和局限共同指向 Spatial AGI 的下一步发展方向：

**短期（可立即推进）：**
- 扩展专家集：添加拓扑关系、物理属性、时间变化等空间专家
- 优化工具效率：减少工具调用次数，实现增量式 3D 更新
- 扩展到更多场景：室外、大规模、动态场景

**中期（1-2 年）：**
- 实现长期空间记忆：跨场景、跨时间的空间知识积累
- 集成物理推理：理解物体稳定性、碰撞、支撑等物理关系
- 支持主动感知：agent 自主决定在哪里看、看什么

**长期（3-5 年）：**
- 统一空间-语义推理：将空间推理与因果推理、社会推理结合
- 实现空间创造力：不仅理解已有空间，还能设计和创造新空间
- 走向具身 Spatial AGI：在真实机器人上实现完整的空间智能

## 最终评价

S-Agent 代表了 2026 年中空间智能领域的重要突破。它不是通过更大的模型或更多的数据来"暴力"解决问题，而是通过**精心设计的架构**——将空间推理分解为可管理的子任务，用专用工具处理几何计算，用记忆维护状态连续性。这种工程哲学对整个 Spatial AGI 领域都有深远启发。
