## 一句话总结

一个面向真实无人机的实时 ObjectNav 框架：用 YOLO 检测 + OctoMap 三维占据图做感知与接地，用 LLM（o3-mini）做贝叶斯化的语义相关性推理来挑选"最可能藏着目标物体的对象"，再用 A* + 七阶多项式样条生成平滑的环绕检查轨迹——在真实 Crazyflie 纳米无人机上实现 100% 搜索成功率，比割草机式全扫描基线缩短约 25-36% 任务时间、减少约 44-52% 路径长度。

## 核心问题

### Q1: 这篇文章的核心算法原理是什么？

#### 1. 核心思想和动机

**(a) 现有 ObjectNav 的三个实践痛点**

1. **VLM 计算负担**：OpenFMNav、LM-Nav、ESC、PixNav 等用 VLM 桥接视觉感知与语义推理效果好，但推理太慢，无法机载实时运行，不适合时间敏感任务；
2. **模拟器动作空间失真**：主流方法在 Matterport3D/Gibson/Habitat 中用离散动作（前进/定角转向/停止），不考虑真实物理机动，难以迁移到真实系统——尤其无人机需要连续三维轨迹；
3. **指标偏科**：现有工作偏重 SR/SPL 等空间效率指标，忽视实时响应、搜索时长、动态机动性等实践因素。

**(b) 核心设计决策**

- **只用 LLM、不用 VLM**：感知交给轻量 YOLO 检测器，LLM 只处理"符号化的语义+空间关系推理"（检测结果列表+空间上下文+用户指令），把计算从"理解像素"降为"理解符号"，换取实时性；
- **真实连续轨迹**：完整考虑无人机的三维连续飞行轨迹（A* 全局 + 七阶多项式样条平滑），而非离散动作空间；
- **时间效率优先**：目标函数是搜索时间与路径长度，而非单纯的 SR/SPL。

#### 2. 主要技术方法：四模块流水线

**(a) 模块一：体积空间表示（VSRM）**

- 用 OctoMap 层次化八叉树占据栅格表示环境，每个体素 v 分类为 free / occupied / unknown；
- S = S_free ∪ S_occ ∪ S_unk；
- 关键假设（可放宽）：环境预先建图（论文用外部 LiDAR + Cartographer SLAM 预建 OctoMap），无人机可精确定位。对更大平台可换成机载 LiDAR + 增量建图在线扩展。

**(b) 模块二：视觉感知（VPM）**

- 实时 2D 检测：VP(I_k) = o_k，YOLO 系检测器（实际用 YOLO11，offboard 处理）；
- 每个检测 o_i = {box_i, class_i, prob_i}，box_i = (u,v,w,h)。

**(c) 模块三：三维位置估计（PEM）**

这是"检测→地图接地"的关键：

1. 用相机内参（分辨率、畸变、FOV）从检测框中心像素 (u,v) 计算 3D 视线方向向量 d = (x_d, y_d, z_d)，校正镜头畸变；
2. 从无人机当前世界位姿 C 沿 d 做 **ray-casting**，在 OctoMap 中取射线上第一个 occupied 体素，即该物体的 3D 位置 pos_i ∈ S_occ；
3. 多视角检测累积：同一物体从不同角度被多次检测产生空间散布的位置估计，用 **DBSCAN 按空间邻近+语义标签聚类**合并：

   O = Cluster(∪_{k=1}^{K} O_k)

   得到 n ≪ Σm_k 的一致物体集合 O = {O_i = {pos_i, class_i}}。

**(d) 模块四：LLM 引导的决策逻辑（PRM，概率相关性模块）**

理论形式是贝叶斯后验：

```
PR(O, T, D) → O*          （挑选最相关物体）
P(O_i | D, T) ∝ P(D | O_i, T) · P(O_i | T)
```

- P(O_i|T)：先验——基于语义关联与共现模式，目标 T 出现在 O_i 附近的可能性；
- P(D|O_i,T)：似然——假设 T 与 O_i 空间关联时，观察到当前数据 D 的概率；
- D 随搜索推进持续扩充：用户指令 U + 已访问区域 V_isited + 当前检测集 O 及其空间关系；
- 另设 **B_none 假设**：目标不在探索空间内的备择假设——穷尽搜索后 B_none 占优则判定失败。

LLM 的实际职责：对每个检测物体估计 P(O_i|D,T)（生成相关性分数与解释）、决定下一步动作：

- 若 O* 相关性超过阈值 → 围绕 O* 做 thorough search（彻底环绕检查）；
- 若找到与 T 匹配的物体 → 终止并报告成功；
- 若都不达标 → 回退策略（fallback，如沿墙飞行继续探索）。

**(e) 轨迹规划与彻底搜索（II-E）**

两阶段规划：

1. **离散路径**：A* 在三维空间搜索到目标区域的无碰撞路径（查询 OctoMap 保证在自由空间内）；
2. **连续轨迹**：对 3D 航点做**七阶多项式样条**插值，满足位置/速度/加速度约束，生成平滑动力学可行轨迹。

Thorough search 设计：围绕选中物体 O* 在固定半径、固定高度生成**圆形检查轨迹**，多角度观察以应对部分/完全遮挡；靠近墙壁或自由空间外的航点被剔除（如物体贴墙时圆退化为半圆）。搜索中持续采集新观测、更新 PRM，迭代决定下一步。

#### 3. 算法流程和关键步骤

```
用户自然语言指令 U
  ↓
[起飞] 360° 扫描获取初始场景概览
  ↓
循环 {
  VPM: YOLO 检测当前帧物体
  PEM: 内参+畸变校正 → ray-casting OctoMap → 3D位置 → DBSCAN聚类合并
  PRM: LLM 输入 (U, O, V_isited, 空间关系) → 各物体相关性 P(O_i|D,T)
    ├─ O* 相关性 > 阈值 → A* 全局路径 → 七阶样条平滑 → 环绕彻底搜索
    │    ├─ 找到 T → 成功终止
    │    └─ 未找到 → 更新 D，继续循环
    ├─ 有进展但无高相关 → LLM 决定下一步探索（与飞行并行推理）
    └─ 穷尽空间未找到 → B_none 占优 → 判定失败
}
```

#### 4. 输入输出

- **输入**：自然语言指令 U（如 "I can't find my computer mouse"）、预建 OctoMap、机载相机实时图像流、无人机位姿；
- **输出**：目标物体的 3D 位置（成功时）、完整搜索轨迹、相关性解释（LLM 生成的推理说明）。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

本文的空间表示策略是**经典的分层符号化**：

- **几何层**：OctoMap 占据栅格——可导航性、碰撞、射线投射；
- **语义层**：YOLO 类别标签 + 3D 位置——"什么在哪"；
- **关系层**：物体间的空间关系与共现先验——"什么通常在哪附近"；
- **指令层**：自然语言——任务的语义指定。

与 NavArena 的三层（渲染/约束/语义）对照，本文多了**关系层与指令层**，少了渲染层。这恰好构成空间智能表示光谱的两极：NavArena 是"像素保真、符号稀疏"，本文是"符号丰富、像素极简（只有检测框）"。Spatial AGI 需要在两极之间找到可伸缩的中间表示。

更深的观察：本文的空间推理核心是**共现先验的空间化**——"鼠标通常在显示器/桌子附近"本质是从语言模型的 world knowledge 中读取的统计空间规律。LLM 在这里不是空间推理引擎，而是**空间常识知识的查询接口**。真正的空间计算（射线投射、路径搜索、样条插值）全部由经典算法完成。这种"LLM 出语义先验、经典几何出空间计算"的分工，是当前空间智能工程最务实也最有效的架构之一。

#### 2. 如何处理空间关系

- **跨模态接地**：检测框（像素）→ 视线向量（相机系）→ ray-casting（世界系占据图）→ 3D 位置。这条接地链虽简单，却暴露了语义-几何对齐的本质难题：YOLO 框中心未必对准物体可见表面的深度——ray-casting 命中的第一个占据体素可能只是物体前方的噪声，或对大物体只命中边缘。DBSCAN 多视角聚类是对此误差的部分补偿。
- **空间关系作为概率证据**：物体的空间关系（邻近、共现）被 LLM 转换为相关性概率，即"把空间关系当作贝叶斯证据来处理"。D（已访问区域）的纳入让负证据也参与推理——搜过桌子附近没找到鼠标会降低该区域后验。
- **物理可行空间处理**：七阶多项式样条（满足 pos/vel/acc 约束）+ A* 避障 + 贴墙圆轨迹退化半圆——空间关系处理延伸到"无人机动力学与环境的耦合"，这是地面机器人 ObjectNav 文献普遍忽略的维度。

#### 3. 对 Spatial AGI 有什么启发

1. **语义先验与空间计算解耦**是可复用的架构模式：LLM/VLM 负责"世界常识"（什么和什么常在一起），几何系统负责"空间计算"（可达性、轨迹、可见性）。比起端到端 VLA，这种分工在可解释性（LLM 输出相关性解释）、实时性、可调试性上都有优势。
2. **时间维度进指标体系**：SR/SPL 之外，搜索时长、推理延迟、与飞行并行推理的能力应成为 Spatial AGI 评估的一等指标。真实世界的时间是硬约束——尤其搜救场景。
3. **负证据与 B_none 假设**：显式建模"目标不存在"的备择假设并支持失败判定，是空间搜索任务中被普遍忽略的完备性设计。空间智能体需要知道"何时放弃"。
4. **真实平台验证的示范价值**：在 27g 的 Crazyflie 纳米无人机（AI Deck 单色相机、无法载 LiDAR）上跑通整个框架，证明"LLM 语义推理 + 轻量感知"路线的机载可行性（推理 offboard 但延迟可控 ~10s 首次，后续并行）。

#### 4. 可以应用的 Spatial AGI 场景

- **室内搜救/搜物**：地震废墟、火灾现场的定向搜索（时间关键）；
- **仓储巡检**：按语言指令定位特定货物/异常；
- **家庭服务机器人**："帮我找到我的钥匙"类任务的空中版本；
- **多机协同搜索**：相关性地图可分区给多架 UAV（框架天然模块化）；
- **Spatial AGI 系统的语义前端**：PRM 模块可作为任何空间智能系统的"去哪里看"决策器。

### Q3: 基于前面的分析，这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

1. **纯 LLM（无 VLM）的实时语义导航**：感知用 YOLO、推理用 LLM，绕开 VLM 的算力墙，首次在真实纳米无人机上实现 LLM 语义引导的 ObjectNav（首次决策 ~9.97s，后续决策与飞行并行、零额外耗时）。
2. **真实连续轨迹的 UAV ObjectNav**：跳出 Habitat 离散动作空间，A* + 七阶多项式样条的完整规划链考虑了无人机动力学约束，并在真实平台上验证。
3. **贝叶斯化的 LLM 推理接口**：把 LLM 的语义判断形式化为后验 P(O_i|D,T)（先验×似然），纳入已访问区域的负证据与 B_none 失败假设——比常见的"LLM 直接给答案"更规范、可扩展。
4. **Thorough search 例程**：围绕高相关物体的多视角环绕检查（含贴墙自适应半圆），针对性解决小目标/部分遮挡目标的检测可靠性。
5. **指标体系的实践校正**：以搜索时间缩短（STI）与路径缩短（PLR）为主指标，直接对齐真实任务价值。

#### 2. 主要局限性

1. **预建图假设**：环境需先用外部 LiDAR + Cartographer SLAM 预建 OctoMap——在真正未知/灾后环境中不可用（作者自己指出可用机载 LiDAR 在线建图扩展，但未实验）。
2. **感知-接地链路粗糙**：YOLO 闭集类别（无法检测训练集外物体）；框中心射线可能错过物体实际占据体素；深度由 OctoMap 而非深度传感器直接提供，误差经多级传播。
3. **LLM 依赖与延迟**：依赖 OpenAI o3-mini 云端 API——机载/离网场景不可用；首决策延迟 ~10s；LLM 概率估计的校准性（是否真的接近贝叶斯后验）完全未评估。
4. **实验规模小**：仿真仅 3 个场景 × 20 起点（120 架次），真实世界仅 1 个 8×10m 场景的单一成功案例；基线只有割草机一种（未对比其他语义导航方法如 ESC/LM-Nav 的适配版）。
5. **相关性阈值与回退策略**：阈值如何设定、wall-following fallback 的性能贡献，均缺乏消融。
6. **单机、单目标、静态场景**：无动态障碍、无多目标、无多机协同。

#### 3. 与其他相关工作的对比

| 方法 | 推理模型 | 感知 | 动作空间 | 真机验证 | 实时性 |
|---|---|---|---|---|---|
| ZSON / L-ZSON | RL + 语言条件 | RGB | 离散 | ✗ | 快（无推理） |
| OpenFMNav / ESC / LM-Nav | VLM+LLM | RGB | 离散 | ✗ | 慢（VLM 瓶颈） |
| PixNav | VLM | RGB-D | 连续（地面） | 部分 | 中 |
| **本文** | **纯 LLM（o3-mini）** | **YOLO+OctoMap** | **连续 3D 轨迹** | **✓（Crazyflie）** | **首决策10s，后续并行** |

**优势**：实时性-语义丰富度权衡的最佳点，且是少数真机闭环的 LLM ObjectNav。
**劣势**：语义感知能力（闭集检测）与场景规模显著弱于 VLM 方案；"搜索效率"的对比基线过弱。

## 核心技术发现

1. **符号化 LLM 推理足以驱动真实搜索任务**：不需要 VLM 理解原始像素——"检测标签+3D位置+空间关系"的符号摘要已能让 LLM 做出有效搜索决策，计算量降 1-2 个量级。
2. **首次决策 9.97s、后续决策零耗时的调度设计**：推理与轨迹执行并行化是 LLM 进入实时控制回路的关键工程手段。
3. **语义先验的价值量化**：三场景中 LLM 引导相对割草机基线，成功率 +5~35%（65%→100% / 75%→100% / 95%→100%），时间 -24.8~-36.0%，路径 -43.5~-52.3%。
4. **用户上下文的决定性作用**：玩具斑马场景证明——没有"陪我睡觉的玩具"这一上下文，LLM 无法把 zebra 与室内环境建立语义关联；语义接地质量直接由指令信息量决定。
5. **Thorough search 对遮挡的鲁棒性**：香蕉被花瓶部分遮挡的场景中，环绕多视角检查可靠定位目标——单视角检测无法解决遮挡，多视角主动观察可以。

## 关键数据

- **平台**: Crazyflie 2.1 纳米四旋翼 + AI Deck（单色相机）；OptiTrack 动捕定位；CrazyRadio 控制 + WiFi 图传；检测/推理 offboard。
- **感知**: YOLO11 检测；Cartographer SLAM + 外部 LiDAR 预建 OctoMap；LLM 为 OpenAI o3-mini。
- **仿真**: Gazebo Garden，10×10 m，3 场景（香蕉/鼠标/玩具斑马），每场景 20 随机起点，共 120 架次。
- **结果（LLM-guided vs Lawn Mower）**:

| 场景 | SR（LLM / 基线） | 时间缩短 | 路径缩短 |
|---|---|---|---|
| 香蕉（花瓶遮挡） | 100% / 65% | 36.02% ± 30.52 | 52.26% ± 38.16 |
| 电脑鼠标 | 100% / 75% | 24.83% ± 25.13 | 43.50% ± 33.79 |
| 玩具斑马 | 100% / 95% | 29.24% ± 28.71 | 51.93% ± 27.86 |

- **延迟**: 首次 LLM 决策 ~9.97 s（含在搜索时间内）；后续决策与飞行并行。
- **真机**: 8×10 m 场地，指令 "Where is my computer mouse?"，检测到桌子/椅子/显示器后聚焦显示器周围，成功定位鼠标。

## 与 Spatial AGI 的关系

### 直接贡献
证明了"LLM 语义常识 + 经典空间计算"的分工架构在真实三维飞行平台上的端到端可行性，为 Spatial AGI 提供了一个轻量、实时、可解释的空间搜索参考系统。

### 技术启发
- 语义先验空间化：把语言模型的世界知识转成搜索空间上的概率分布，是"知识驱动的空间推理"的最小可行实现；
- 负证据（已访问区域）与失败假设（B_none）应成为空间搜索类任务的标配；
- 时间效率指标（STI/推理延迟/并行推理）应纳入 Spatial AGI 评估体系。

### 应用场景
搜救、仓储巡检、家庭服务、多机协同搜索、通用空间智能系统的"下一步看哪里"决策模块。

## 个人思考

### 最令人兴奋的发现

这篇论文最值得记住的可能不是数字，而是它验证的**分工假说**：空间智能的"语义"与"几何"可以干净地解耦，中间只交换两类信息——检测符号（什么在哪）与相关性分数（去哪找）。在 VLA 端到端浪潮的背景下，这是一个逆流但务实的立场。真机上那个细节尤其打动我：27 克的无人机、单色相机、检测和 LLM 全部 offboard，但闭环成功了——真实世界的空间智能不一定需要所有智能都在机上，**延迟工程（并行推理）本身就是智能系统设计的一部分**。

### 潜在局限

贝叶斯外衣下的 LLM 推理其实没有概率语义的保证：o3-mini 输出的"相关性分数"不经过校准，先验/似然的分解在 prompt 里如何实现也未披露——这套框架的"概率"更多是组织信息的结构，而非真正的贝叶斯推断。另外实验对比的公平性存疑：割草机基线不使用任何语义信息，赢得它并不意外；真正要回答的问题是"这个轻量方案比 VLM 方案差多少时间精度、省多少计算"，而论文没有提供这个交叉点。

### 与近期研究的关联

- 与 NavArena（今日论文1）构成镜像：NavArena 是"重表示、轻语义"（3DGS 像素保真 + 三类任务），本文是"轻表示、重语义"（OctoMap + 检测符号 + LLM）。两者可以互补：NavArena 的语义层（实例中心）恰好可以作为本文 PRM 的输入，从而在照片级场景里做语义搜索。
- 与 S-Agent、Spatial Memory Agent 等空间工具使用工作同属"LLM 作为空间决策器"流派，但本文的真实平台闭环是稀缺的差异化。
- 混响式的呼应：与论文2（BinauralVAE）对照，本文的感知完全无声学模态——搜救场景里声学恰恰重要（废墟下的敲击声），多模态扩展是显见的下一步。

### 批判性思考

Ray-casting 接地的误差模型没有分析：YOLO 框中心射线命中的第一个占据体素与物体真实中心之间，在透视投影下存在系统性偏差（框中心对应物体可见面，而非质心；近大远小加剧偏差）。DBSCAN 聚类能吸收部分散布，但对"第一次就把无人机引向错误区域"的早期误差没有纠错机制。另外，10 秒级的首决策延迟对时间关键任务（搜救黄金72小时里单次搜索的分钟级预算）是否可接受，需要任务级的分析而非仅报告相对缩短。

## 总结

### 核心发现总结

本文用"YOLO 检测 + OctoMap 射线接地 + LLM 贝叶斯化语义相关性推理 + A*/七阶样条轨迹"的四模块架构，在真实 Crazyflie 纳米无人机上实现了实时语言引导的 3D ObjectNav：3 个仿真场景全部 100% 成功（基线 65-95%），搜索时间缩短 24.8-36.0%、路径缩短 43.5-52.3%，并在真实 8×10m 场景闭环成功。核心洞见是符号化的语义常识足以驱动高效空间搜索，无需昂贵的 VLM 像素理解。

### 对 Spatial AGI 的意义

Spatial AGI 不等于"更大的端到端模型"。本文展示的"语言模型提供空间常识先验、经典算法执行空间计算、轻量感知维持实时性"的分工架构，是通向可部署空间智能的一条被低估的路径。它同时提醒我们：空间智能的评估必须走出模拟器离散动作空间，走向真实平台的连续轨迹、真实延迟与真实失败模式。

## 深度扩展分析

### 扩展一：贝叶斯相关性模块的真正含义

论文把 LLM 的判断写成 P(O_i|D,T) ∝ P(D|O_i,T)·P(O_i|T)，但需要辨析这个形式化的实际地位：

1. **先验 P(O_i|T)**：LLM 从预训练语料中"知道"鼠标常与显示器/桌子共现——这实际是世界知识的频率编码，LLM 输出一个相关性分数近似它。误差来源：语料偏差（文学中"斑马在草原"压倒"玩具斑马在卧室"，除非指令提供上下文）。
2. **似然 P(D|O_i,T)**：观测证据的权重——已访问区域 V_isited 提供负证据，检测到的物体提供正/负证据。LLM 如何在 prompt 中实现似然计算（把 V_isited 作为文本上下文让模型综合考虑）与真正的似然评估相差甚远。
3. **B_none 假设**：理论上应作为备择假设参与归一化 P(O_i|D,T,¬∃T)——但论文未说明 B_none 的分数如何产生与比较。

**方法论评价**：这个形式化的价值不在统计正确性，而在**信息组织**——它规定了 LLM 每次决策需要哪些输入（指令、检测、空间关系、访问史）、输出什么（分数+解释），让系统行为可审计。一个改进方向是让 LLM 输出分布参数而非点估计，或用多次采样估计 LLM 分数的方差，作为决策置信度。

### 扩展二：ray-casting 接地的误差几何

检测→3D 位置链路的系统性误差源：

1. **框中心 ≠ 视线锚点**：检测框中心对应物体可见区域的投影中心，而非物体质心。对非凸/侧视物体（椅子侧面），框中心射线可能落在物体包围盒之外的自由空间或背景上；
2. **遮挡偏置**：ray-casting 命中"第一个"占据体素——若目标部分被前景遮挡，命中的是遮挡物，产生类别-位置错配（把花瓶的位置标成香蕉）；
3. **OctoMap 分辨率与动态更新**：预建地图的分辨率上限与建图时的视角盲区（OctoMap 的 unknown 空间）都会引入定位误差；
4. **DBSCAN 的参数敏感性**：eps/minPts 未披露；大物体（桌子）的多视角检测散布可能被拆成多簇，或相邻物体被合并。

工程改进方向： 用检测框四角+中心多条射线投票； 深度相机直接读取深度替代 OctoMap 间接推断； 多视角一致性检验（triangulation）替代首命中。

### 扩展三：与割草机基线对比的公平性分析

割草机基线是"零语义、全覆盖"策略，其成功率上限由覆盖完整性决定（65-95% 的失败主要来自遮挡物后目标永不可见或超时）。LLM 方法的提升来源可分解为：

| 提升来源 | 机制 | 证据 |
|---|---|---|
| 语义先验聚焦 | 直奔高概率区域 | 时间/路径缩短 ~50% |
| 多视角主动观察 | 环绕检查破解遮挡 | 遮挡场景 SR 65%→100% |
| 上下文消歧 | 用户描述引导搜索区域 | 斑马场景（无上下文时会失效） |
| 早停能力 | 找到即停 vs 覆盖全图 | 时间指标整体下降 |

缺失的对照： 相同环绕检查例程+随机物体选择（剥离语义贡献，隔离 thorough search 的贡献）； 弱语义基线（物体共现统计表替代 LLM）——量化 LLM 相对经典共现知识的增量。作者自己的证据（斑马场景依赖用户上下文）其实暗示：在指令信息量低时，LLM 的优势会显著缩水。

### 扩展四：实时 LLM 控制回路的调度模式

本文的推理调度值得作为"LLM 进入实时系统"的工程模板：

```
t0: 起飞 → 360°扫描（~10s窗口） → LLM首次决策（9.97s，隐藏在扫描后）
t1: 执行轨迹A（~30-60s） ‖ 并行: LLM基于新观测预计算下一步
t2: 到达决策点 → 零等待切换
...
```

关键设计：**决策与执行解耦**——LLM 延迟被飞行时间掩盖。适用于延迟预算 > 10s 的任务（搜索、巡检），不适用于秒级反应任务（避障、跟踪——那是经典控制/学习策略的领域）。这个分层暗示了一个通用的空间智能体时效架构：

- 毫秒级：控制/避障（板上策略网络）
- 秒级：局部规划（经典算法）
- 10秒级：语义决策（云端 LLM）
- 分钟级：任务级反思（更慢的推理）

### 扩展五：UAV ObjectNav 与地面 ObjectNav 的本质差异

| 维度 | 地面（Habitat 系） | 空中（本文） |
|---|---|---|
| 自由度 | 2.5D（平面+转向） | 6DoF 连续 |
| 动力学约束 | 弱（速度/转角离散） | 强（pos/vel/acc 连续可行） |
| 观察优势 | 近距交互 | 俯视全景、越障视角 |
| 感知负载 | 可载重型传感器 | 克服重量限制（27g 级） |
| 电池/时间预算 | 宽松 | 严苛（时间效率是真需求） |
| 安全风险 | 低 | 坠机风险，轨迹平滑是硬要求 |

这解释了为什么本文把"时间效率与动力学可行"作为一等公民：空中搜索的时间预算直接由电池决定，轨迹不平滑直接消耗电量与稳定性。Spatial AGI 评估向空中平台扩展时，需要新增能量效率、动力学可行率、坠机风险等指标。

### 扩展六：可复用工程要点备忘

- OctoMap ray-casting 是"2D检测→3D位置"最低成本的接地方案（无需深度传感器），但要知道其误差模式；
- DBSCAN（空间邻近+标签一致）是多视角检测合并的简单有效手段；
- LLM 决策与轨迹执行并行化：把 10s 延迟藏进 30-60s 的飞行段；
- 七阶多项式样条满足 pos/vel/acc 三重约束，是无人机轨迹平滑的标准选择；
- 圆形检查轨迹遇墙自动退化半圆：多视角观察例程必须做自由空间裁剪；
- 回退策略（wall-following）保证语义推理失效时系统仍有兜底行为——任何语义驱动系统都应有非语义 fallback。

```
VP(I_k) = o_k = {o_i = {box_i=(u,v,w,h), class_i, prob_i}}     (1) 检测

  step1: 像素(u,v) + 内参/畸变 → 视线方向 d=(x_d,y_d,z_d)
  step2: 从位姿C沿d ray-casting → 首个occupied体素 = pos_i
O = Cluster(∪_{k=1}^{K} O_k)                                    (3) DBSCAN合并
```
