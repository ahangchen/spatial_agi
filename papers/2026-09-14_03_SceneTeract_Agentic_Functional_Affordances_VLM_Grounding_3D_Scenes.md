## 0. 论文速览

SceneTeract（Guibas 组与 Dassault Systèmes、École Polytechnique 合作）是一个**3D 场景功能性可供性（functional affordance）验证引擎**。核心问题：一个 3D 场景"看起来对"不等于"用得了"——一个视觉逼真的房间，可能对轮椅使用者是彻底不可用的（门太窄、把手太高、家具间无通行空间）。

给定三元组 **⟨任务 T，智能体档案 A，场景 S⟩**，SceneTeract：
1. 用 VLM 把开放式活动（"泡杯茶然后看电视"）分解为**原子动作序列**（封闭词表：导航/接触/操作/感知四族）
2. 用**显式 3D 几何检查**（可达性/间隙/可导航性/可见性/可交互性）逐一验证每个原子动作，全部以智能体身体档案（身高、臂长、通行宽度、步行/轮式）为条件
3. 输出**细粒度可行性诊断报告**（哪一步、因哪个物理约束、差多少厘米而失败）

三大应用：
- **场景审计**：3D-FRONT 3396 个场景-任务-智能体配置，暴露合成场景大量功能缺陷（成人任务成功率仅 59%，轮椅用户 42.5%）
- **VLM 基准**：前沿 VLM 在功能可行性判断上存在"语义自信 vs 物理失败"的系统性错位
- **GRPO 后训练**：把验证器当奖励引擎，用确定性几何奖励做 RL，显著提升 Qwen3-VL-4B 的功能推理（Decomposed 任务准确率 61.4→69.2，MCC 0.172→0.364）

**一句话总结**：可供性不是场景的属性，是场景与身体的**关系**——SceneTeract 把这个关系变成了可计算的几何验证，再用它同时审计场景、评测模型、训练模型。

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

**分析**:

#### 1. 核心思想和动机

**问题背景的两条断层线**：

- **3D 场景生成的评估断层**：合成场景质量由 FID/KID/CLIP 语义对齐等感知代理指标主导——全是 2D 渲染上的打分，完全不测量"场景是否支持交互"。门被堵死、物体够不着、导航路径不通，这些功能性失败在指标上不可见
- **VLM 的接地断层**：VLM 语义和常识推理很强（知道泡茶需要杯子、桌子可以放东西），但物理/结构诊断能力弱——会自信地宣称"孩子能够到柜子把手"，哪怕几何上差 12 厘米

**理论出发点：可供性的关系性（relational nature）**。可供性不是场景的内禀属性，而是**以智能体身体能力为条件的关系属性**。对站立的成人功能完好的环境，对轮椅使用者可能根本不可用。因此严谨的功能验证必须显式参数化身体：高度、触及半径、移动方式。

这直接引出 SceneTeract 的设计哲学：**语义规划与几何验证解耦**——VLM 负责"做什么"（开放式语义分解），几何引擎负责"能不能"（确定性物理检查）。两者各干自己擅长的。

#### 2. 主要技术方法

**输入三元组 I = ⟨T, A, S⟩**

- T：自然语言的高层次具身意图（"从上层书架取书"）
- A：**参数化身体档案**（关键创新）：

```
A = ⟨w_clear, h_eye, h_arm, r_arm, m_loco⟩
    通行净宽  眼高    肩高   臂展半径  移动方式{walk, wheel}
```

- S = ⟨O, G⟩：场景几何 G（含可导航面）+ 物体集 O（语义类、3D 包围盒、mesh）

**步骤一：VLM 任务分解**

VLM 规划器 Φ 用**封闭词表**的原子动作库分解任务，每个原子动作与目标物体组成交互元组 (a, o)，如 (Open, cabinet_01)。四个功能族：

| 符号 | 族 | 包含动作 |
|------|----|---------|
| A_m | Mobility | NavigateTo, SitOn, LieOn |
| A_c | Contact | Toggle, PickUpFrom, ReleaseOn |
| A_h | Handling | Open, Close, PutIn, TakeOutOf |
| A_p | Perception | LookAt |

**步骤二：布尔属性字典 + 动作-属性映射**

属性 P 是布尔分类器：P: y → {0,1}，y = (S, A, a, o)。五个核心属性及实现：

- **P_nav（可导航）isNavigableTo**：3D 几何投影为 2D 占据栅格 → 按 w_clear 做形态学腐蚀（身体越宽可通过区域越小！）→ VLM 解析目标物体的语义交互区（如"沙发前面"）→ 验证智能体到该区的 2D 路径连通性
- **P_reach（可触及）isReachable**：计算智能体连通可导航地面区到目标 mesh 的最小欧氏距离，按肩高 h_arm 垂直平移后对照臂展 r_arm 验证
- **P_inter（可交互）isInteractable**：VLM（Molmo）在正交视图上定位功能部件（把手等）交互点 → SAM 提取 2D 掩码 → 深度图反投影到世界系，跨视图融合成功能部件 3D 点云 → 验证该体积是否在臂展内
- **P_clear（有间隙）hasClearance**：在目标前方（如门/抽屉的开启方向）生成 3D 交互体积 V_clear，与场景几何做碰撞检测（门后有没有柜子挡着门打不开）
- **P_vis（可见）isVisible**：从姿势调整后的眼高位置向目标包围盒关键点投多射线，计算可见率（含遮挡）

**动作→检查序列的映射（编码层级依赖）**：

| 动作族 | 检查序列 |
|--------|---------|
| Mobility | nav |
| Contact | nav → reach |
| Handling | nav → reach → inter → clear |
| Perception | vis |

注意 Handling 的检查是有序的：先能走过去（nav），再够得到物体（reach），再够得到把手（inter），再门前有空间开门（clear）——**检查顺序本身就是具身交互的依赖结构**。

**步骤三：诊断报告聚合**

所有检查聚合为细粒度、可执行的诊断报告。例如："计划失败，因为 Child 智能体无法打开 cabinet_1。柜体本身可达，但功能把手距离 0.52m，超出 Child 的 0.40m 臂展上限"——**不是一句"不可行"，而是指出哪一步、哪个物理量、差多少**。

#### 3. 算法流程和关键步骤

```
输入: ⟨活动T, 身体档案A, 场景S⟩
 1. VLM规划器: T → 原子动作序列 [(a1,o1), (a2,o2), ...]
 2. 对每个 (a_i, o_i):
    a. 查动作族 → 得到检查序列 Req(a_i)
    b. 逐项执行几何检查（每项都是确定性算法 + 局部VLM辅助如交互点定位）
    c. 记录通过/失败 + 具体物理量（需要0.52m，只有0.40m）
 3. 聚合为诊断报告 R（整体可行性 + 逐步归因）
 4. 下游三用:
    - 场景审计: 统计场景/智能体维度的失败模式
    - VLM基准: 让VLM预测可行性, 与验证器标签对照
    - GRPO训练: 对比验证器标签 v 与模型预测 v̂ 生成奖励
```

**GRPO 后训练细节**（第三应用）：

- 对每个原子动作步骤，VLM 采样 G 条独立 CoT 推理路径，各以可行性判断 v̂_i 结尾
- 稀疏奖励：r_i = 𝟙[v̂_i = v]（v 是验证器标签）
- 组相对优势：A_i = (r_i − μ_r)/(σ_r + ε)
- 通过对比同一查询下成功与失败的推理路径，模型内化真实的 3D 功能意识而非记忆布局。作者选择 RL 而非 SFT，理由是 SFT 易 superficial alignment 和灾难性遗忘

#### 4. 输入输出

- **输入**：3D 场景（几何+物体）、身体档案参数、自然语言活动描述
- **输出**：细粒度可行性诊断报告（整体判定 + 每步通过/失败 + 物理归因 + 具体数值差距）
- **间接输出**：场景审计统计、VLM 基准分数、RL 奖励信号

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

SceneTeract 的空间观有三个鲜明特征：

- **空间是身体化的（embodied）**：同一场景在不同 w_clear/h_arm/m_loco 下是**不同的功能空间**。2D 导航图按通行宽度腐蚀后连通区域都不同——空间结构本身依赖观察者的身体参数
- **空间是活动化的**：不是抽象的几何体集合，而是"支持什么活动"的功能空间。检查序列（nav→reach→inter→clear）编码了空间能力的层级依赖
- **空间是可判定的**：功能可行性被分解为有限个布尔几何谓词的组合——空间理解被还原为**可计算验证的命题集合**，而非端到端的黑盒评分

#### 2. 如何处理空间关系

五种属性恰好覆盖了具身交互的五类基本空间关系：
- **通行关系**（nav）：身体宽度和路径连通性
- **接近关系**（reach）：臂展球与物体的距离
- **功能关系**（inter）：交互部件的功能几何（把手在哪、朝向）
- **运动学关系**（clear）：机构运动扫掠体积与环境的冲突
- **视线关系**（vis）：眼高射线与遮挡

深度设计在于 P_inter：把"可交互"从"物体可达"细化到"**功能部件**可达"——用 Molmo 定位 + SAM 分割 + 深度反投影构建交互部件 3D 体积。这是语义（哪个部分是把手）与几何（该部分的空间位置）的精妙接合点。

#### 3. 对Spatial AGI的启发

1. **"可供性的关系性"应该成为 Spatial AGI 的公理**：空间记忆和空间推理系统如果只存"世界是什么样"，而不参数化"对谁、用什么身体"，就无法回答具身问题。空间记忆的查询接口应该接受身体档案作为一等参数

2. **验证器作为空间智能的"单位测试框架"**：SceneTeract 证明可以用确定性几何引擎为开放式空间推理生成可靠标签。这解决了空间推理训练的核心瓶颈——**真值从哪来**。几何模拟器生成的标签可以无限扩展，且零标注噪声

3. **诊断报告的归因价值**：不像端到端评分只给一个数，细粒度失败归因（哪步、哪个约束、差多少）既是场景修复的指南，也是模型失败分析的显微镜。Spatial AGI 系统应该输出这种"可执行的诊断"而非笼统置信度

4. **揭示 VLM 系统性盲区**：基准发现前沿 VLM（Gemini/Claude 级）任务级准确率仅 ~62%，物理幻觉（FP）率 20-36%——语义自信与物理可行性的鸿沟是当前空间智能的最大短板之一。Inclusivity Gap 指标还揭示模型对儿童/轮椅档案的忽视：VLM 默认以"标准成人"看世界

5. **Decomposed > Direct 的方法论**：逐步分解式评测普遍优于直接整体判断（Gemini-3-Flash: 62.1→69.9 任务准确率），且模型自洽性（Cons.）远非 100%——模型"直觉"与"细查"经常互相矛盾

#### 4. 可以应用的Spatial AGI场景

- **无障碍环境设计与审计**：建筑/室内设计中为不同身体条件用户自动验证可达性（Dassault Systèmes 的直接工业动机）
- **机器人任务预验证**：执行前在数字孪生中验证计划的功能可行性，失败则获得精确归因
- **具身仿真环境的自动质检**：仿真/合成数据管线中的功能过滤器，保证训练环境可交互
- **VLA 模型的 RL 奖励引擎**：为操作/导航策略提供几何正确的稀疏奖励
- **家庭服务机器人的计划自检**："我（臂长 0.8m 的机器人）能完成这个任务吗"的先验检查
- **游戏/VR 关卡自动测试**：NPC/玩家可达性回归测试

### Q3: 创新点和局限性

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**分析**:

#### 1. 主要创新点

1. **可供性的形式化：身体参数化 + 布尔属性字典 + 动作-属性映射**。把哲学上含糊的"affordance"翻译成有限个可计算谓词的组合，且谓词全部以智能体档案为条件——这是对 Gibson 式可供性概念的第一次完整工程化（在该活动层级上）

2. **任务-智能体-场景三元组输入设计**：以往场景评估假设"通用观察者"，SceneTeract 强制显式建模身体。Inclusivity Gap 成为可测量的指标（成人 66% vs 轮椅 42.5% 任务成功率——差距惊人）

3. **一个验证引擎，三重部署**：场景审计、模型基准、RL 奖励共用同一验证器。"验证即奖励"把评测基础设施转化为训练基础设施，一鱼三吃

4. **功能部件级交互检查（P_inter）**：Molmo 定位 + SAM 分割 + 深度反投影构建 3D 交互体积，把"够不到把手"与"够不到柜子"区分开——这是很多可达性检查粗糙处理的细节

5. **GRPO + 确定性奖励的功能推理训练**：用零噪声几何奖励做组相对策略优化，Qwen3-VL-4B 的 Decomposed 任务准确率 +7.8、MCC 翻倍（0.172→0.364）、FP 下降——证明几何验证器可以有效蒸馏进语言推理

#### 2. 主要局限性

1. **原子动作词表的封闭性**：固定四族 12 个动作覆盖常见室内交互，但开放式活动（"帮我把画挂正"）超出词表即失效。分解质量完全依赖 VLM 规划器，分解错误则验证无意义（垃圾进垃圾出）

2. **交互几何的静态化**：P_clear 用固定交互体积近似关节运动学，真实人体/机械臂的冗余自由度、姿势调整、双手协调未建模；动力学（惯性、平衡）完全缺失——"几何上可行"仍是"物理上可行"的近似

3. **P_inter 依赖视觉管线的级联脆弱性**：Molmo 定位错误 → SAM 分割错误 → 3D 体积错误 → 判定错误。功能部件被遮挡/非正面视角时管线可靠性存疑

4. **单一物体交互假设**：原子动作独立验证，跨步骤的状态变化（拿走椅子后能开门了）未建模——验证是"快照式"而非"状态演化式"

5. **基准的验证器偏差**：用几何验证器当 VLM 基准真值，VLM 被惩罚的"错误"中可能有些是验证器自身近似造成的（如严格臂展模型 vs 人类弯腰侧身的能力）——真值上界被验证器保真度锁死

6. **GRPO 提升的边界**：4B 模型提升明显，但对话中 Direct 模式几乎无提升（61.5→61.5）——几何奖励改善的是分解推理，未触及模型的直接空间直觉

#### 3. 与其他相关工作的对比

| 维度 | SceneEval | FirePlace | MoVer | 通用空间基准 (VSI-Bench等) | **SceneTeract** |
|------|-----------|-----------|-------|------|------|
| 评估对象 | 文本→场景合成 | 物体放置 | 生成动画 | 通用空间感知 | **活动级功能可行性** |
| 身体参数化 | 通用观察者 | 无 | 无 | 无 | **显式档案(5参数)** |
| 检查粒度 | 全局指标 | 场景级 | 时空约束 | 题目级 | **原子动作级+归因** |
| 开放式活动 | 部分 | 否 | 否 | 否 | **是(VLM分解)** |
| 用作RL奖励 | 否 | 否 | 否 | 否 | **是(GRPO)** |

定位：SceneTeract 把"混合范式"（VLM 语义 + 几何一致性模块）从单点任务（放置/动画）推进到**活动级、智能体感知**的功能验证，并首次闭环到模型训练。

## 核心技术发现

1. **合成 3D 场景的功能可行性普遍不达标**：3D-FRONT 3396 配置中任务成功率 Adult 59.0% / Child 66.0% / Wheelchair 42.5%；最弱环节是 clearance（~67%）和 interactability（64-76%）——"看起来好"的场景大量无法支持基本交互
2. **前沿 VLM 语义自信 ≠ 物理可行**：最强模型任务级准确率 ~62%，物理幻觉（FP）率 20%+，Inclusivity Gap 表明模型默认"标准成人"视角
3. **分解式评测显著优于直接判断**（Gemini-3-Flash 62.1→69.9），且 Decomposed 模式下 HSI 接近/超过 100% 表明分解能对冲长程任务的复杂度衰减
4. **GRPO + 几何奖励有效**：Qwen3-VL-4B Decomposed 任务准确率 61.4→69.2，MCC 0.172→0.364，FP 22.8→14.1，InGap 20.3→9.7（ inclusivity 也改善了！）
5. 检查序列的层级结构（nav→reach→inter→clear）本身是有价值的具身知识编码

## 与Spatial AGI的关系

### 直接贡献
提供了 Spatial AGI 缺失的"功能层"：在感知（是什么）与规划（怎么做）之间，验证"能不能"。空间智能不仅要知道世界什么样，还要知道**世界对特定身体允许什么**。

### 技术启发
- 可供性 = f(场景几何, 身体参数)，必须参数化身体
- 确定性几何验证器可作为空间推理的无限、零噪声训练信号源
- 诊断报告应输出物理归因与量化差距，而非笼统判定

### 应用场景
无障碍审计、机器人计划预验证、仿真环境质检、VLA 奖励引擎、游戏/VR 关卡测试。

## 个人思考

### 最令人兴奋的发现

**42.5% 这个数字**。轮椅用户在合成场景中只有 42.5% 的任务成功率——意味着超过一半的"看起来正常"的现代室内场景对轮椅使用者是不可用的。这不仅是 AI 论文的数据，简直是对合成场景生成领域的控诉。它宣告了 FID 类指标时代的终结：**一个场景的价值在于它支持谁做什么事，而不是它看起来多逼真**。

第二件兴奋的事是**"验证即奖励"闭环**的完成度：同一个引擎，早上审计场景、中午评测 GPT 级模型、晚上给开源模型当 RL 教练。GRPO 结果里最动人的是 Inclusivity Gap 从 20.3 降到 9.7——用几何奖励训练后，模型对非标准身体（儿童、轮椅）的判断公平性真的改善了。**几何验证器把"具身包容性"从道德呼吁变成了可优化的损失项**。

### 潜在局限

1. **验证器保真度是整个体系的地基**：布尔判定把连续的物理世界二值化，边界 case（勉强够到/差 1cm）的判定可靠性决定一切。而真实人类有大量"几何上不可行但实际能做到"的策略（爬、跳、用工具）——严格的几何验证会把人类的适应性当成失败
2. **状态演化缺失是根本性的**：现实活动会改变场景（推椅子、开门），快照式验证无法处理计划中的场景变更。真正的功能验证需要"动作-状态转移"的模拟，那就是完整物理仿真了
3. **VLM 分解的单点依赖**：整个系统的开放式能力由 VLM 规划器承载，而 VLM 恰恰是物理推理弱的——用弱物理直觉的模型分解任务，再用强几何验证器验证，分工合理但接口处（分解的正确性）没有验证机制

### 与今日研究的关联

- 与 **GraFT** 共享"符号工具 + 确定性验证"的哲学，但对象不同：GraFT 验证"空间事实"（距离多少），SceneTeract 验证"空间可能性"（能不能做到）。两者可以共享同一个 3DSG 基础设施——SceneTeract 的五属性检查几乎可以原样实现为 GraFT 式的符号工具（事实上 P_reach 与 GraFT 的 distance 工具同源）
- 与 **CST-WM** 的因果主题呼应：SceneTeract 的检查序列（nav→reach→inter→clear）本质是功能可行性的**因果依赖链**——前置条件不满足则后续全为假。三个研究共同指向：空间智能需要显式的结构（几何/因果/功能），而非纯学习
- 与 **AffordanceVLA**（今日第4篇）形成"验证侧 vs 生成侧"的对偶：SceneTeract 验证可供性，AffordanceVLA 生成可供性感知的动作
- Guibas 组持续的 3D 理解路线（从函数映射到场景图到功能验证）在本篇展现其系统性：几何准确性 → 语义结构 → 具身功能的逐层抽象

## 总结

### 核心发现总结
SceneTeract 把"可供性"从哲学概念工程化为可计算的验证问题：以身体档案为条件，将开放式活动分解为原子动作，用五个布尔几何属性逐一验证，输出带物理归因的诊断。三重应用揭示了合成场景普遍的功能缺陷（轮椅用户任务成功率仅 42.5%）与 VLM 的物理幻觉问题，并通过 GRPO 几何奖励训练有效缩小了后者的差距。

### 对Spatial AGI的意义
Spatial AGI 需要"功能层"：空间理解最终要回答"谁能在这里做什么"。SceneTeract 提供了该层的参考架构（属性字典 + 检查序列 + 身份条件化），更重要的是提供了训练范式——确定性几何验证器作为无限奖励源。开放缺口：动态状态演化、软性人类策略（攀爬/工具使用）、分解正确性的元验证。

## 附录: 结构速查与设计模式

### A1. 五属性实现要点

| 属性 | 实现 | 身体参数 | 辅助模型 |
|------|------|---------|---------|
| P_nav | 2D 栅格 + w_clear 腐蚀 + 连通性 | w_clear | VLM 解析交互区 |
| P_reach | 地面区到 mesh 最小距离 vs r_arm | h_arm, r_arm | — |
| P_inter | Molmo 定位→SAM 分割→深度反投影→3D 体积可达性 | r_arm | Molmo + SAM |
| P_clear | 交互体积 vs 场景碰撞检测 | — | — |
| P_vis | 眼高多射线可见率 | h_eye | — |

### A2. 基准指标体系（VLM 评测的七维）

1. **Action Acc**：单步可行性判断
2. **Task Acc**：全序列判断（分解模式下要求全对）
3. **FP Rate**：物理幻觉率（把不可能判为可能）
4. **MCC**：不平衡数据下的综合分类质量
5. **Inclusivity Gap**：三个身体档案间任务准确率最大差（公平性）
6. **Horizon Stability Index**：长程(3+步)/短程(1-2步)任务准确率比（抗复杂度衰减）
7. **Consistency**：直接判断与分解判断逻辑一致的任务比例

这套指标本身就是空间推理评测的方法论贡献——特别是 InGap（具身公平性）和 Consistency（自我一致性）是新颖维度。

### A3. GRPO 训练循环

```
for 每个原子动作步骤:
    采样 G 条 CoT 推理路径 → 各得判断 v̂_i
    验证器标签 v（确定性几何检查）
    奖励 r_i = 1[v̂_i = v]
    组优势 A_i = (r_i - μ_r)/(σ_r + ε)
    GRPO 策略更新（同组内成功路径 vs 失败路径对比）
```

设计亮点：奖励是稀疏但**零噪声**的（几何判定确定），组内相对化消除了价值网络的需求。

### A4. 可复用模式

- **验证器三用模式**：审计 / 基准 / 奖励，一套基础设施三种杠杆
- **条件化谓词模式**：所有谓词带上下文参数（身体档案），谓词库可组合
- **层级检查序列模式**：检查顺序编码依赖结构，失败早停且归因到层
- **关系性可供性原则**：永远不要问"这个场景可及吗"，要问"对谁可及"

## 附录B: 深度延伸分析

### B1. 可供性哲学的工程化谱系

Gibson (1979) 提出可供性（affordance）：环境为动物提供行动可能性。此后 AI 领域的工程化路径：

```
Gibson 可供性 (关系性, 动物-环境耦合)
  │
  ├─ 视觉可供性学习: 图像→交互热力图 (跨像素级, 无身体参数)
  │
  ├─ 物体级可供性: "杯子可抓握" (物体类别级, 场景无关)
  │
  ├─ FirePlace: 放置可行性 (场景级几何, 但无身体/活动)
  │
  └─ SceneTeract: 活动级 + 身体级 + 场景级 三者同时条件化 (本文)
```

SceneTeract 的位置在于把三个条件维度补齐：活动（分解为原子动作）、身体（五参数档案）、场景（显式几何）。这才是 Gibson 原意的完整形式化——可供性从来不是单变量函数。

### B2. 检查序列作为具身常识的形式化

Handling 族检查序列 nav→reach→inter→clear 背后是一阶逻辑蕴含链：

```
可开门 ⟹ 前置: 能走到门前 ∧ 手够得到把手 ∧ 把手实际可操作 ∧ 门有开启空间
```

这条链是人类幼儿都在内化的具身常识，但 VLM 会在这条链的任意一环产生幻觉。SceneTeract 的贡献是把常识链条**从神经网络的隐式知识提升为显式验证协议**。推广到更复杂活动，需要的只是更长的谓词链——框架是开放的。

### B3. VLM 失败模式的定性画像

从基准结果可以拼出前沿 VLM 在功能推理上的画像：

- **直接判断是"语义直觉"主导**：62% 左右的准确率且各模型趋同，说明都在用语义先验（"从书架取书应该是可行的"）而非几何分析
- **FP > FN 的普遍倾向**（Gemma3 FP 高达 36-39%）：模型倾向于说"可行"——语义上合理的活动默认判可行，物理障碍被系统性低估
- **分解显著提升但-self-consistency 不满分**：模型细查时能发现障碍，但直觉与细查矛盾率可观（Cons. 58-98%），说明几何分析能力存在但未被可靠调用
- **GRPO 后 Decomposed 提升而 Direct 不动**：强化的是"细查时的几何验证技能"，不是"直觉本身"——提示未来工作应研究如何把验证技能蒸馏进直觉（System 2 → System 1）

### B4. Inclusivity Gap 的双重含义

InGap 既是模型指标也是世界指标：

- **模型侧**：VLM 对非标准身体的忽视（InGap 20+）——训练数据里的"人类"默认是标准成人
- **世界侧**：场景的 InGap（成人 66% vs 轮椅 42.5%，差 23.5 个百分点）——合成场景生成从未考虑轮椅使用者

GRPO 训练把模型 InGap 从 20.3 压到 9.7，证明了**模型公平性可以被几何监督直接优化**。这个发现对具身 AI 的社会维度有超出技术的意义：机器人进入人类空间时，其空间智能的"默认用户假设"将决定它服务谁、排除谁。

### B5. 与物理仿真引擎的关系辨析

一个自然的问题：为什么不用 Isaac Sim 等完整物理引擎做验证？

| 维度 | 完整物理仿真 | SceneTeract 几何验证 |
|------|------------|--------------------|
| 保真度 | 动力学/接触/摩擦全模拟 | 运动学近似 + 布尔化 |
| 成本 | 高（资产、调参、算力） | 低（轻量几何计算） |
| 可解释性 | 低（ emergent 结果） | 高（逐步归因） |
| 标签可靠性 | 参数敏感 | 确定性、可复现 |
| 开放活动扩展 | 需技能/控制器 | 需谓词扩展 |

SceneTeract 的选择是**刻意的低保真**：要的是"确定性、可解释、可大规模生成标签"，运动学近似在这个精度需求下够用。这体现了一个成熟的工程判断：验证器的价值不在物理保真，而在**标签的一致性**——训练用的奖励/评测用的真值最怕的就是随机性。

### B6. 失败案例空间（未来工作地图）

1. 活动需要状态变化的场景：拿走挡路的椅子 → 原本 fail 的 open 变 pass（快照验证无法处理）
2. 非标准策略：够不到 → 踩凳子（词表外动作，被误判不可行）
3. 双手/双臂协调、工具中介操作（用钩杆够高处）
4. 软体/可变形物体（拉开窗帘、铺床）
5. 多智能体协作活动（两人抬桌子）
6. 时间维度（趁门开着穿过）

每个失败点对应谓词库与状态模型的一次扩展——这张地图本身就是后续研究的路线图。

## 附录D: 诊断报告实例解析

以项目主页给出的失败案例（Child 开 cabinet_1）为例，看诊断报告的信息结构：

```
整体可行性: FAILED

[P_nav]   ✓ 通向交互区的无碰撞路径存在
[P_nav]   ✓ 通向交互区的无碰撞路径存在
[P_reach] ✓ 物体可触及。需求距离: 0.35m, 智能体臂展: 0.40m
[P_inter] ✗ 交互体积不可达。需求距离: 0.52m, 智能体臂展: 0.40m
[P_clear] ✓ 找到 1 个无碰撞交互区

归因: 计划失败，因为 Child 无法打开 cabinet_1。
      柜体本身物理可达，但功能把手距离 0.52m，
      超出 Child 的 0.40m 臂展上限。
```

三个信息层次：
1. **布尔层**：每步通过/失败（供自动化管线消费）
2. **数值层**：需要 vs 拥有的物理量对比（供人类/LLM 消费）
3. **归因层**：自然语言的失败解释（区分"够不到柜子"与"够不到把手"）

这个三层结构值得所有 Spatial AGI 系统的诊断输出借鉴：同一份报告同时服务机器（布尔）、工程（数值）、人（归因）。

## 附录E: 场景审计的分属性洞察

从 3D-FRONT 审计数据可以读出合成场景生成的系统性缺陷排序：

```
has_Clearance (66-67%)  ← 最差: 家具布置不考虑开启动作的扫掠空间
is_Interactable (64-76%) ← 次差: 功能部件(把手等)位置随意
任务成功率 (42-66%)      ← 综合结果
is_Visible (97-99%)      ← 最好: 视线几乎总是通的
```

洞察：**生成式场景布局优化的是"视觉构图"，而交互的瓶颈集中在动态扫掠空间（clearance）与精细功能几何（interactable）——恰是视觉指标完全不看的地方**。修复方向：把 clearance/interactable 检查作为布局生成的后处理约束或损失项（类似 FirePlace 的思路但推广到活动级）。

## 附录F: GRPO 实验的完整对照

Qwen3-VL-4B-Instruct 训练前后（Decomposed 配置）：

| 指标 | 训练前 | GRPO后 | 变化 |
|------|--------|--------|------|
| Action Acc | 70.4 | 75.3 | +4.9 |
| Task Acc | 61.4 | 69.2 | +7.8 |
| FP Rate | 22.8 | 14.1 | -8.7 |
| MCC | 0.172 | 0.364 | +0.192 |
| InGap | 13.2 | 9.7 | -3.5 |
| HSI | 97.6 | 98.2 | +0.6 |
