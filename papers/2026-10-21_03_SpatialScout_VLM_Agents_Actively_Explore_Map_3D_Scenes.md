**发表日期**: 2026-10-19

## 一句话总结

SpatialScout 是首个把"主动探索 + 物体级 3D 建图"作为直接评测目标的 VLM Agent 空间智能基准：80 个室内场景、3,140 个目标物体，Agent 拿着物体清单和相机工具自主探索、跨视角关联、三角化估计物体中心并维护共享坐标系下的地图；前沿 VLM 表现揭示巨大短板——最强的 Claude Opus 5.5 全目标平均 IoU 仅 41.71%，IoU>0.9 的精确匹配只有 3.25%，暴露"粗略布局识别"与"完整精确度量建图"之间的鸿沟。

## 核心问题

### Q1: 这篇文章的核心算法原理是什么？

#### 1. 核心思想和动机

- **对现有空间智能基准的根本质疑**：
  - VSR、BLINK、VSI-Bench、OpenEQA 等采用图像/视频 QA 评测计数、方向、距离、空间关系；
  - **选择题可以靠猜和排除**；语言先验与答案分布偏差可以让模型靠非空间线索答对；
  - 最关键的：真实世界要求 Agent **自主获取证据、更新空间表示、用表示指导后续动作**——QA 无法端到端覆盖这个多步闭环。
- **评测哲学转变**：从"回答正确性"转向"空间表示构建质量"。把"通过主动交互在连续 3D 空间中构建物体地图"变成直接评测目标，形成观测-推理-决策的闭环。
- **任务的本质耦合**：当前空间估计决定下一个观察什么，所选视角又塑造之后的可用证据——这种感知与建模的双向耦合只有在主动探索中才能被测出来。

#### 2. 主要技术方法（基准设计）

**(a) 任务定义**

- 输入：物体清单 ℰ = {(i, c_i, g_i)}——实例 ID、类别、等价组（同类多实例）；初始 RGB 观测；相机内参与位姿；目标区域半径 r。
- 目标：Agent 自主探索，在**共享任务坐标系**（原点在初始相机，+x 沿初始光轴向前，+y 向左，+z 向上）下估计所有目标物体的 AABB 中心，维护地图 P̂。
- 几何目标定义：物体中心 = 渲染几何紧致世界轴对齐包围盒（AABB）的中点（铰接物体取链接几何并集），公式 p_i = R₀ᵀ((b⁻+b⁺)/2 − o₀)——可复现，且不依赖资产内部原点。
- 等价组机制：同组多实例按**多重集**比较（避免"哪把椅子是 3 号"的语义任意性）。

**(b) 统一 Agent 工具接口（10 个工具）**

| 工具 | 功能 |
|------|------|
| list_entities | 列出目标与元数据 |
| get_camera_pose | 返回相机位姿 |
| get_camera_intrinsics | 返回相机标定 |
| set_camera_position / move_camera / rotate_camera | 相机控制（设置/平移/旋转） |
| capture_image | 拍摄 RGB 帧 |
| triangulate_observations | 多视角三角化估计点 |
| submit_positions | 提交/更新中心地图 |
| finish_mapping | 结束建图回合 |

- **无任何工具泄露 GT 位置或评测分数**——评测的公正性保证。

**(c) 场景构建**

- 80 个室内场景，SAPIEN/ManiSkill3 渲染：32 iTHOR + 12 RoboTHOR + 10 ArchitecTHOR + 6 ReplicaCAD + 30 ProcTHOR。
- 每景 30-40 个目标（12 景 35 个、68 景 40 个），共 3,410 实例（正文评测集 3,140）。
- 目标区域半径 1.95-9.23 m；43.3% 目标（1,489 个）属于等价组——多实例重复类别刻意考察跨视角实例关联。
- 涵盖单房间到整套公寓，保留源布局与目标摆放，每个源场景只出现一次。

**(d) 评测协议**

- 交互预算：每轨迹上限 100 个工具调用轮次。
- 评测指标族：
  1. **平均中心误差**（米）：等价组内最小距离一对一匹配后统计；
  2. **清单覆盖率**（coverage）：提交目标占比——**漏报计零分**；
  3. **3D IoU**：把参考框平移到预测中心计算重叠；
  4. **命中率**：τ ∈ {0, 0.5, 0.9} 三档严格阈值，组内 hit-maximizing 分配。
- 过程记录：地图更新轨迹（map traces）可回放——研究空间表示如何随探索涌现。

**(e) 被评模型**

GPT-6 Astra、Claude Opus 5.5、DeepSeek V4.1 Flash、Qwen3.8-Max、Kimi-K3、GPT-6 Sol 等前沿 VLM（xhigh 推理档）。

#### 3. 算法流程（一个评测回合）

```
初始化：初始观测 + 物体清单 + 相机标定 + 目标半径
  loop (≤100 轮):
    Agent 决策：移动/旋转相机 → capture_image
    识别物体 → 跨视角关联（对应到清单 ID）
    必要时 triangulate_observations 三角化
    submit_positions 增量提交/修订地图
    （当前地图指导下一步去哪看 → 反馈闭环）
  finish_mapping
评测：覆盖率 + 组内匹配中心误差 + IoU 命中率
```

成功案例的行为模式（六条成功轨迹的共同点）：
1. 充分的**多视角几何接地**（triangulation 支撑）；
2. **增量提交**并持续扩大覆盖；
3. 提交后**持续精修**已提交位置。

#### 4. 输入输出

- **输入**：物体清单、初始 RGB、相机内参/位姿、目标区域半径、10 个工具。
- **输出**：共享坐标系下目标物体中心的 3D 地图（含增量更新过程）。
- **评测输出**：全目标/已提交目标平均 IoU、覆盖率、各阈值命中率、中心误差。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

- **空间理解 = 空间构建**：论文的立场是——能回答空间问题 ≠ 能构建空间表示。真正的空间智能体现在**把局部观测整合成一致、精确、完整的度量地图**的能力。
- **表示选择**：物体中心地图（object-center map）——介于拓扑图（离散节点）与稠密重建（voxel/mesh）之间，是机器人任务规划最常用的中层表示。
- **度量与坐标系**：强制共享公制坐标系，拒绝"差不多相对位置"的糊弄——Spatial AGI 最终要落到物理动作上，米级精度不可回避。

#### 2. 如何处理空间关系

- **跨视角实例关联**是核心空间关系操作：43.3% 目标有同景多实例，模型必须回答"我看到的两把椅子哪个是清单里的 #17"——这是视角不变的身份追踪问题。
- **观测-估计耦合**：模型要根据当前地图的不确定性选择下一个视角（主动感知），空间关系的处理从静态判断变成动态信息采集策略。
- **几何工具协作**：triangulate 工具要求模型在不同视角图像中**指出同一物理点的像素坐标**——细粒度跨视角对应是空间关系的原子操作。

#### 3. 对 Spatial AGI 的启发

1. **"识别 ≠ 建图"的分水岭发现**：Claude Opus 5.5 能答对多数空间 QA，但建图 IoU>0.9 仅 3.25%——VLM 的空间"理解"主要是语义与关系层面，度量几何层面严重缺失。Spatial AGI 需要专门的几何接地机制，不能指望 VLM 底座自然涌现。
2. **主动感知应成为空间智能的训练目标**：六条成功轨迹全部依赖多视角三角化 + 增量提交 + 持续精修——这些行为当前靠 prompting 涌现，未来应显式训练（如 RL 奖励地图质量）。
3. **行为差异即能力差异**：弱模型"移动多、观察少"，观察随进度衰减——无法维护和更新可靠空间表示是行为层面的可诊断症状。空间智能评测应报告**过程行为**而不仅是最终分数。
4. **工具使用的质量重于数量**：GPT-6 Astra 拍照更少但三角化支撑率 99.33%（DS-V4.1 仅 63.48%）、警告率 2.69% vs 38.65%、中位中心误差 7.08cm vs 68.17cm——近 10 倍差距全部来自几何工具的使用质量。
5. **成本维度不可忽视**：Claude Opus 5.5 每任务 28.85 美元的推理成本——空间智能若要落地机器人，感知闭环的计算经济学必须纳入设计。

#### 4. 可以应用的 Spatial AGI 场景

- **空间智能训练数据生成**：80 场景 + 回放轨迹可作为 SFT/RL 训练素材（成功轨迹做示范、失败做负例）。
- **机器人探索策略评测**：next-best-view 规划器的 VLM 版对照实验台。
- **Agent 过程诊断**：map-update replay 提供了分析空间表示演化的仪器。
- **模型选型**：IoU-成本 Pareto 前沿为部署提供量化依据。

### Q3: 基于前面的分析，这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

1. **评测目标的结构性升级**：从"答案正确性"到"空间表示构建质量"（定位精度 + 覆盖率联合），是空间基准谱系中第一个**主动 + 多轮 + 显式空间构建 + 直接 3D 坐标打分**四项全占的工作。
2. **物体级 3D 建图作为任务**：连续 3D 空间、公制坐标、物体中心 AABB 定义可复现——比 Theory of Space 的离散认知地图更接近机器人真实需求。
3. **统一工具接口 + 无泄露设计**：10 个标准化工具，无任何 GT 泄露，可比、可复现、可信。
4. **过程级评测**：地图更新轨迹回放 + 工具调用行为分析——首个把"如何建图"与"建得如何"一起评测的空间基准。
5. **等价组多重集匹配**：优雅解决同景多实例的语义歧义。
6. **前沿模型的系统性诊断**：6+ 模型 × 80 场景 + 40 轨迹失败模式分析 + 成本分析，给出了当前 VLM 空间智能的精确"体检报告"。

#### 2. 主要局限性

1. **仿真渲染域**：SAPIEN/ManiSkill3 渲染的 iTHOR/ProcTHOR 类场景视觉真实感有限，结论向真实室内环境的迁移待验证。
2. **相机-only 具身**：只有相机自由度（set/move/rotate），无碰撞约束、无机器人运动学——"探索"的物理现实性打了折扣。
3. **物体中心单点目标**：只评 AABB 中心，不评朝向、尺寸、形状——地图的丰富度被压缩；铰接物体的"中心"定义也略任意。
4. **无地图修订惩罚机制**：submit_positions 可反复覆盖，策略性反复提交可能钻评分空子（论文未讨论防作弊细节）。
5. **场景规模与多样性**：80 场景全部来自 THOR 系/ReplicaCAD 家族，布局风格同质；无室外、无杂物极端场景。
6. **成本结论的时效性**：28.85 美元/任务的数字随 API 定价快速变化，成本分析半衰期短。

#### 3. 与其他相关工作的对比

| 基准 | 主动 | 多轮 | 显式空间构建 | 3D 坐标打分 | 环境反馈 |
|------|------|------|--------------|-------------|----------|
| VSI-Bench | ✗ | ✗ | ✗ | ✗ | ✗ |
| OpenEQA | ✗ | ✗ | ✗ | ✗ | ✗ |
| E3VS-Bench | ✓ | ✓ | ✗ | ✗ | ✗ |
| ESI-Bench | ✓ | ✓ | ✗ | ✗ | ✗ |
| S3-Bench | ✗ | ✗ | ✗ | ✗ | ✗ |
| Theory of Space | ✓ | ✓ | ✓ | ✗ | ✗ |
| IR3D-Bench | ✗ | ✗ | ✓ | ✓ | ✗ |
| **SpatialScout** | **✓** | **✓** | **✓** | **✓** | **✓** |

- **vs Theory of Space**：后者评测离散认知地图构建，SpatialScout 要求连续度量 3D 坐标 + 直接几何打分。
- **vs IR3D-Bench**：后者被动评测场景参数恢复，SpatialScout 要求自主探索采集证据。
- **vs ESI-Bench/S3-Bench**：它们在空间 QA 里加交互，最终仍评答案；SpatialScout 直接评地图。

## 核心技术发现

- **发现 1**：最强模型 Claude Opus 5.5 全目标平均 IoU 仅 41.71%（GPT-6 Astra 33.16%）；正重叠召回 77.36% vs IoU>0.5 47.23% vs IoU>0.9 仅 3.25%——**粗放 vs 精确的断崖**。
- **发现 2**：成功六要素高度一致——多视角三角化接地、增量提交扩覆盖、持续精修；失败首因是不完整覆盖（26/34），其次是"三角化残差低但对应错误"（21/34）——**几何自洽不能保证语义正确**。
- **发现 3**：几何工具使用质量决定精度：GPT-6 Astra 三角化支撑率 99.33%、警告率 2.69%、中位误差 7.08cm；DeepSeek V4.1 Flash 为 63.48%、38.65%、68.17cm——差距近 10 倍。
- **发现 4**：行为模式可诊断：弱模型（DS-V4.1-Flash、Qwen3.8-Max）随进度减少观察、移动多观察少——空间表示维护失败的 behave 信号。
- **发现 5**：成本-精度 Pareto：Claude Opus 5.5 精度最高但 28.85 USD/任务；开源模型在精度-成本权衡上几乎无优势（仅 DS-V4.1-Flash 便宜于 GPT-6 Sol）。
- **发现 6**：模范案例：Claude Opus 5.5 单任务提交全部 35 目标、中心误差 0.073m、全目标 IoU 0.530——说明上限远未触及，是策略而非能力天花板。

## 与Spatial AGI的关系

### 直接贡献
- 提供了空间智能的"度量建图"试金石：把 VLM 从"会说空间话"到"会建空间图"的距离第一次量化（41.71% vs 100%）。
- 开源 80 场景、10 工具接口、轨迹回放仪器，可直接用于训练数据生产与过程诊断。

### 技术启发
- Spatial AGI Agent 的能力栈分解：视角选择 → 跨视角关联 → 几何估计 → 地图修订——四项都需显式训练与评测。
- 几何工具（三角化）的质量是当前最大杠杆：7cm vs 68cm 的差距提示"工具使用微调"是性价比最高的改进方向。

### 应用场景
- 空间 Agent 训练（成功轨迹 SFT / 失败分析 RL）、探索策略研究、模型诊断与选型。

## 个人思考

### 最令人兴奋的发现
- **3.25% 这个数字**。当所有人都被 VLM 的空间 QA 分数麻痹时，SpatialScout 用一个无法靠语言先验糊弄的任务揭示：前沿模型对"东西到底在哪一米"几乎无精确概念。这类似 Vision 模型当年在 Counting 上的翻车——暴露的是表征层面的缺失，而非提示词工程能解决的。
- **行为即诊断**：观察频率随进度衰减 = 空间表示维护失败。这种把 Agent 评测从"分数"扩展到"行为画像"的思路，值得所有 agentic 基准借鉴。

### 潜在局限
- 仿真渲染 + 相机-only 具身让"主动探索"的困难被低估：真实机器人还要处理碰撞、能耗、运动学约束与传感器噪声，真实场景的数字会更难看。
- 只评中心点不评朝向/尺寸，可能让模型钻"把点放在物体堆中央"的空子（部分被 IoU 阈值缓解但未根除）。

### 与昨日研究的关联
- **与 Holi-World（今日 02）互为镜像**：Holi-World 用感知流水线自动建图（Foundry 达到 ScanNet AP25 0.68），SpatialScout 测 VLM Agent 裸建图（IoU 0.42）——**专用几何流水线 vs 通用 Agent** 的差距清晰可见。但 SpatialScout 评测的"主动选择视角"能力是 Foundry 被动流水线不具备的。Spatial AGI 的正解可能是"VLM Agent 指挥几何流水线"的分层架构。
- **与 Ropedia W0（今日 01）**：W0 的 loco-manipulation 假设机器人已有空间地图能力，SpatialScout 恰好测出这个前提在当前 VLM 中多么不牢靠——世界模型与空间建图能力的共同进化缺一不可。
- **与昨日 DynThinker**：DynThinker 统一静态 3D 与动态 4D 空间推理，但仍在 QA 框架内；SpatialScout 证明了推理之外还有"构建"这块更硬的骨头。

## 关键数据

- **基准规模**：80 场景（32 iTHOR / 12 RoboTHOR / 10 ArchitecTHOR / 6 ReplicaCAD / 30 ProcTHOR）、3,410 目标实例（评测 3,140）、每景 30-40 目标、43.3% 等价组多实例、目标半径 1.95-9.23m。
- **交互预算**：100 工具轮次/轨迹。
- **主结果（80 景共同比较，xhigh）**：
  - Claude Opus 5.5：全目标 IoU 41.71% / 已提交 46.69%；正重叠召回 77.36%；IoU>0.5 47.23%；IoU>0.9 3.25%；成本 28.85 USD/任务。
  - GPT-6 Astra：全目标 IoU 33.16% / 已提交 41.76%；召回 67.79%；IoU>0.5 35.15%；IoU>0.9 1.62%。
- **几何接地对比（Astra vs DS-V4.1-Flash）**：三角化支撑率 99.33% vs 63.48%；警告率 2.69% vs 38.65%；每任务拍照 32.41 vs 39.63；中位中心误差 7.08cm vs 68.17cm。
- **失败模式分布（40 轨迹）**：覆盖不足 26；低残差对应错误 21；几何不一致未解决 13；过早终止 13；无三角化支撑提交 6；观察多进展少 5；只修旧不补缺 3。
- **成功定义**：≥90% 覆盖 + 匹配目标中心误差 ≤0.2m；40 轨迹中仅 6 条达标。

## 总结

### 核心发现总结
SpatialScout 把空间智能评测从"答题"推进到"主动建图"，用物体级 3D IoU + 覆盖率联合打分量化了前沿 VLM 的空间构建能力——最强模型也只达到 41.71% 平均 IoU、3.25% 高精度匹配，并从行为与工具使用层面定位了失败根源：跨视角语义关联与几何工具使用质量，而非探索努力不足。

### 对Spatial AGI的意义
- 它为 Spatial AGI 划出了一条新的能力底线：**能被提问 ≠ 能自主构建度量地图**。未来的空间智能模型必须在闭环感知-构建-修正中训练与评测。
- 行为级诊断与成本 Pareto 为空间 Agent 的工程化提供了仪器与经济学视角。
- 通用 VLM 与专用几何流水线之间的巨大差距，指明了"Agent 编排几何工具"这一最有前景的中间架构。

## 附录 A：任务设计的工程细节精读

### A.1 坐标系的"刁钻"设计

任务坐标系：原点在初始相机，+x = 初始光轴方向，+y = 初始左方，+z = 初始上方。

**关键刁钻点**：初始相机允许有俯仰角（pitched），此时任务坐标系的"上"轴**相对世界竖直方向是倾斜的**。

- 为什么这样设计？逼模型真正读取并使用位姿数据做坐标变换，而不是默认"z 轴竖直向上"的先验。
- 这类设计细节是区分"背空间常识"与"会做几何"的探针。

### A.2 目标定义的可复现性考量

- 中心 = **渲染几何**的紧致 AABB 中点，而非资产模型原点——很多资产的内部原点偏离可见几何（如模型原点在脚底或世界原点），用原点会让目标不可预测。
- 铰接物体（如带门微波炉）取所有链接渲染几何的并集 box——状态无关的静态定义，避免评测目标随物体状态漂移。
- 公式 p_i = R₀ᵀ((b⁻+b⁺)/2 − o₀)：把世界系中点变换到初始相机任务系——**所有目标以初始观测为锚**，强调第一帧信息的基础地位。

### A.3 等价组的评测语义

- 同组多实例 → 组内**多重集**最小距离一对一匹配。
- 解决的问题：清单说"椅子 ×4"，模型无法（也不需要）知道哪把是"#12"——按位置多重集匹配才公平。
- 副作用：模型可以把 4 个估计放进任意 4 个提交槽位，匹配算法会找最优对应——评测聚焦"是否找齐且放准"。

### A.4 防泄露清单

- 10 个工具中没有任何一个返回 GT 位置、物体 box 或当前分数；
- 参考中心、box、资产几何全部留在 evaluator 侧；
- 目标区域半径 r 是唯一的位置信息泄露（场景级搜索边界），设计上刻意提供以支持公制估计。

## 附录 B：结果深读

### B.1 三分数据集的真实含义

| 指标（Claude Opus 5.5） | 数值 | 解读 |
|------|------|------|
| 正重叠召回 | 77.36% | 3/4 目标能"放对大概区域" |
| IoU>0.5 | 47.23% | 一半目标能"放进物体占据一半体积的范围" |
| IoU>0.9 | 3.25% | 只有 3% 达到"精确中心对准" |

**断崖结构**说明错误不是均匀分布的噪声，而是系统性能力缺失：从"区域级"到"精确级"之间存在能力真空。对比：人类拿相机做同样任务（给足时间）IoU>0.9 应可达到 80%+（三角化是摄影测量百年成熟技术）。

### B.2 三类定性案例

- **案例 A（成功）**：Claude Opus 5.5 提交全部 35 目标，中心误差 0.073m，全目标 IoU 0.530——重建视图与参考排布几乎对齐。证明任务可解。
- **案例 B（漏报）**：GPT-6 Astra 两景 65/80 提交，已提交误差 0.141m 不差，但 15 个漏报把全目标分数拖垮——**覆盖率与精度同等重要**的设计意图达成。
- **案例 C（错位）**：DeepSeek V4.1 Flash 提交全部 40 目标（覆盖率 100%！），但中心误差 1.000m、全目标 IoU 0.034——**全提交 + 全错位**，说明有些模型"为交而交"，估计完全没有几何支撑。

### B.3 工具调用行为画像（四模型）

1. **Claude Opus 5.5**：工具调用最多（贴近 100 轮上限）——"勤奋型"，多看多算换取最高 IoU 与最高成本。
2. **GPT-6 Astra**：调用更少但表现次优——"高效型"，观测/移动/建图三类动作比例均衡。
3. **DS-V4.1-Flash / Qwen3.8-Max**：随交互进度**观察频次下降**——后期靠早期旧视图"凭记忆"定位，空间表示维护失败；且移动多、观察少，视角选择低效，白白消耗上下文（图像很贵）。
4. 推论：**观察-移动-建图的均衡性是空间表示维护能力的外在表现**，可作为轻量诊断指标。

### B.4 轨迹深挖（Astra vs DS-V4.1-Flash 对照实验）

选择两个工具调用量相近的模型对照，隔离"努力"变量：

| 指标 | GPT-6 Astra | DS-V4.1 Flash |
|------|-------------|----------------|
| 已提交目标有成功三角化支撑 | 99.33% | 63.48% |
| 三角化带几何警告率 | 2.69% | 38.65% |
| 每任务平均拍照 | 32.41 | 39.63（更多！） |
| 提交目标中位中心误差 | **7.08 cm** | 68.17 cm |

**结论**：拍的更多 ≠ 建的更准。triangulate 要求跨视角指出**同一物理点**的像素坐标——细粒度视觉对应是瓶颈。DS 拍照多但对应质量差，警告率 38.65% 说明它明知几何不自洽仍然提交。

### B.5 40 轨迹失败模式 taxonomy

| 失败模式 | 频次 | 本质 |
|----------|------|------|
| 覆盖不完整 | 26 | 探索规划/终止策略问题 |
| 低残差但对应错误 | 21 | **几何自洽≠语义正确**：三角化收敛到一个错误点 |
| 几何不一致未解决 | 13 | 忽视警告继续提交 |
| 过早终止 | 13 | 预算感知/自我评估失败 |
| 无三角化支撑提交 | 6 | "拍脑袋"定位 |
| 观察多进展少 | 5 | 信息→地图转化失败 |
| 只修旧不补缺 | 3 | 修订策略短视 |

最深刻的是第 2 项：两条视线交会于一点只保证几何一致性，不保证你选的点是"物体中心"——可能选在物体表面、边缘甚至背景。**视觉对应选择是一个语义决策，不是几何运算**。

## 附录 C：方法论评析

### C.1 评测设计的三个聪明之处

1. **漏报计零**：把"少交不罚"的传统漏洞堵死——覆盖率与精度强制联合。
2. **过程留痕**：submit_positions 的每次更新都记录，map trace 可回放——评测数据集同时是一台"显微镜"。
3. **预算公开且紧**（100 轮）：逼出真实策略，而非无限预算下的暴力扫场。

### C.2 潜在争议点

1. **IoU 用参考框平移到预测中心**：等于假设模型已知物体尺寸——未评尺寸估计，可能高估"精确"程度（一个尺寸大误差敏感度低的物体会更宽容）。
2. **命中阈值组内 hit-maximizing 分配**：对多实例组 somewhat 宽松（挑最好的配对）。
3. **模型可能通过反复 submit 探测**（无分数反馈，所以探测收益有限）——设计上基本闭环。
4. **场景授权链**：iTHOR/ProcTHOR 等许可各异，开源完整性待查。

### C.3 与 agentic 基准一般趋势的呼应

- 长时程 + 工具 + 过程评测是 2026 年 agentic 基准的共同演化方向（论文自引 [25, 63]）。
- 成本进报告（28.85 USD）与 GAIA 类基准一致——能力必须与经济学一起呈现。
- 用另一个 LLM（Codex + GPT-6 Astra）做轨迹归因分析——"AI 评测 AI 行为"的方法论正在成形，需警惕评测器的自我偏好。

## 附录 D：Spatial AGI 能力栈视角

SpatialScout 实际上把空间智能 Agent 分解为可分别训练/评测的五段流水线：

```
S1 视角规划   "下一步去哪看"        → 失败模式: 观察多进展少 / 过早终止
S2 物体识别   "看到的是什么"        → VLM 强项（相对不 bottleneck）
S3 跨视角关联 "这是清单里哪个"      → 失败模式: 低残差对应错误（最隐蔽）
S4 几何估计   "它中心在哪一米"      → 失败模式: 无三角化支撑 / 忽视警告
S5 地图修订   "新证据如何更新旧地图" → 失败模式: 只修旧不补缺 / 覆盖不足
```

**各段训练处方**：
- S1：RL，奖励 = 单位预算覆盖增量。
- S3：跨视角实例关联的对比学习（类似视频目标关联，但跨离散视角）。
- S4：几何工具调用微调（选点质量 = S3 与 S4 的交界）+ 警告响应训练。
- S5：地图一致性维护（新证据 vs 旧估计的贝叶斯更新）。

**对齐 SpatialScout 数据**：当前 S3/S4 是最大瓶颈（21+6+13 ≈ 半数失败与几何估计链相关），S1 是第二瓶颈（26 覆盖不足）。

## 附录 K：精读问答补充

**Q: 为什么不用 SLAM/重建把任务"作弊"掉？**
A: 工具集里没有重建工具，只有单点三角化——接口设计刻意限制为"VLM 可驱动"的原子操作。这也是对"未来 VLM 原生空间能力"的测量承诺：不借专业重建栈。

**Q: 为什么任务中心地图而不是物体 box（含尺寸朝向）？**
A: 论文未明说，但可推断：(1) 中心 + IoU 已构成可微调难度的连续指标；(2) box 全参数估计会让失败归因混杂（尺寸错 vs 位置错）；(3) 中心是下游任务（抓取、导航目标）的最小充分信息。代价是丢掉朝向信息——对铰接物体尤其可惜。

**Q: 28.85 USD/任务意味着什么？**
A: 80 任务全套评测约 2,300 美元——这也是"前沿模型过程评测"的门槛现实。随着上下文成本下降与工具调用优化，预计一年内同协议成本降一个数量级，届时开源模型可能进入 Pareto 前沿。

**Q: 这个基准会被"过拟合"吗？**
A: 场景公开 + 布局保留，过拟合风险真实存在。缓解：ProcTHOR 可程序化生成无限新布局（基准框架本身可扩展），类似 ARC-AGI 的"训练集/评测集分离"策略可后续引入。

| 开放问题 | 2D 接口局限 | 跨会话记忆 | 精确级能力真空 |

三篇合读的一句话结论：**预测、记录、构建是空间智能的三根支柱**——W0 证明预测可以规模化，Holi-World 证明记录可以自动化，SpatialScout 证明构建（Agent 版）还是短板。下一代的题眼是把三者接进一个系统：Foundry 建初始地图 → SpatialScout 式 Agent 主动补盲区 → W0 式世界模型在地图上想象未来。
