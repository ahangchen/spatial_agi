**发表日期**: 2026-10-17

## 一句话总结

DialogMem 是首个把"**人类对话**"作为具身记忆一等信息源的基准：Agent 在 27 个真实 3D 场景中沿时间对齐的 RGB-D 观测流 + 对话流构建记忆，之后用记忆做物体级导航与问答——142 个 episode、14,193 个 QA 对、11,890 条导航指令，统一评测 9 种记忆表示。核心发现扎心：**把对话附到视觉记忆上，QA 大涨但导航几乎不动**——对话信息"在记忆里"却"没接到物体上"，由此识别出对话接地具身记忆的三大瓶颈：构建期对象级组织、检索期正确条目命中、定位期空间恢复。

## 核心问题

### Q1: 这篇文章的核心算法原理是什么？

#### 1. 核心思想和动机

- **问题根源**：现有具身记忆（embodied memory）几乎全部由视觉经验构建——RGB-D 流、3D 重建、场景图。但人类中心的真实环境里，大量关键信息是**人告诉你的**："我把药收进床头柜第二层了""别动沙发上那个盒子，是给妈妈的礼物"。
- **科学问题**：对话信息如何才能**接地（ground）**到 Agent 在物理环境中遇到的物体上？不是"听过"就算记住，而是"下次能走到那个物体跟前/答对关于它的问题"。
- **为什么难**：对话是稀疏的、时序的、无空间坐标的；观测是稠密的、空间的、无语义意图的。把"床头柜第二层"这句话接到"t=347s 视野左下角那个家具"的实体条目上，需要时间对齐、视觉定位、语义消歧三重对齐。

#### 2. 主要技术方法：两阶段基准设计

**(a) 阶段一：记忆构建（memory formation）**

- 输入：时间对齐的**带位姿 RGB-D 观测流** + **对话流**（人与环境/与 Agent 的自然对话）；
- Agent（被评的记忆系统）在此流上自由构建记忆表示——不限定格式；
- 记忆系统需要决定：对话内容是否/如何与观测中的物体关联。

**(b) 阶段二：记忆使用（memory utilization）**

- 两类下游任务：
  1. **实例级物体导航**（instance-level object navigation）：走到对话中提到的特定物体实例（"那把被修过的椅子"）——11,890 条导航指令；
  2. **问答（QA）**：关于物体位置、状态、历史的问题——14,193 个 QA 对；
- 记忆系统经历"证据检索 → 推理输出"的统一流程。

**(c) 评测框架：三段统一管线**

```
记忆形成（formation） → 证据检索（evidence retrieval） → 任务推理（reasoning → QA / navigation output）
```

- 9 种记忆表示在同一下游评测器上比较——**控制变量，隔离记忆表示本身的贡献**；
- 27 个真实世界 3D 场景（非仿真渲染）、142 个 episode。

**(d) 诊断实验设计（本文最精彩的部分）**

- **对照 1**：评测时才把对话追加到视觉记忆（append-at-eval）vs 构建时就融合；
- **对照 2**：改变对话-物体**链接质量**（oracle 完美链接 vs 系统自动链接）；
- **对照 3**：oracle 物体级记忆 vs 系统记忆——量化"距完美记忆还有多远"。
这些受控诊断把"记忆系统哪里断了"拆解到具体环节。

#### 3. 核心发现（摘要报告）

1. **追加对话显著提升 QA，但对导航收益可忽略**——对话信息"存在于记忆中"却未被**组织到具体物体条目**上，QA 可以靠全文检索凑合，导航却要求"知道去哪个坐标找"；
2. **导航随链接质量提升而改善，但即便完美链接也达不到 oracle 物体级记忆水平**——说明检索与定位环节还有独立损失；
3. **三大瓶颈定位**：
   - **形成期**：把对话按对象级条目接地与组织（dialogue grounding at object-level entries）；
   - **检索期**：正确命中相关条目（retrieving the correct entry）；
   - **定位期**：从条目恢复精确空间位置（localizing it accurately）。

#### 4. 输入输出

- **输入**：时间对齐 RGB-D + 位姿流 + 对话流；下游查询（QA 问题 / 导航目标描述）；
- **输出**：记忆系统内部表示 + QA 答案 / 导航轨迹；
- **评测输出**：QA 准确率、导航成功率（实例级），以及瓶颈归因诊断。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

- DialogMem 揭示了一个被忽视的表示断层：**人类语言里的空间信息与 Agent 度量空间之间的翻译缺口**。"第二层抽屉"→ (x,y,z) 的映射不是词汇对齐问题，而是**对象级接地**问题——先要知道"抽屉"对应场景中哪个实例、哪个几何部位。
- 真正的具身空间记忆必须是**多模态溯源的**：同一物体条目下挂接视觉观测证据 + 语言证据，且各自带时间戳与可信度。纯视觉记忆是对人类中心环境的"半盲"建模。
- 空间信息的**提供渠道决定其使用方式**：对话提供的信息（不可见历史、意图、约束）是视觉永远无法补的——空间智能若只学视觉，将系统性缺失"人告诉你的空间"。

#### 2. 如何处理空间关系

- "对话-物体-位置"三角关系是本文的核心空间关系结构：
  - 对话给出**语义-空间约束**（"在X旁边""第二层"）；
  - 观测给出**度量-空间证据**（坐标、几何）；
  - 导航要求两者**融合成可执行的位姿目标**。
- QA 与导航的收益分离精确刻画了空间关系的两个使用层级：**关系级使用**（答"在哪"：语言空间关系足够）vs **度量级使用**（走到那：必须落地为坐标）——这正好对应 Spatial AGI 里 System 2 语义推理与 System 1 度量行动的分工。

#### 3. 对 Spatial AGI 的启发

1. **"知道"与"能用"的表示标准不同**。QA 涨导航不涨证明：以语言为载体的空间知识若不落到对象级条目（含位姿），就只是"可检索的文本"而非"可行动的空间记忆"。Spatial AGI 的记忆设计必须以**最苛刻的下游（导航/操作）**为表示标准，而非最宽容的下游（问答）。
2. **对话是空间智能的免费监督**。人类随手一句"药在床头柜"是比任何标注都廉价的物体-位置监督信号。把对话流变成空间记忆的接地产线（语义解析 → 实例关联 → 空间锚定），是空间智能数据引擎尚未开采的富矿——Holi-World（10-21/02）的 Foundry 只做感知侧，对话侧是它的天然补全。
3. **三段管线的诊断方法论**。形成/检索/推理三段拆解 + oracle 对照是记忆系统研发的标准仪器——空间记忆系统（3DGS 记忆、场景图记忆）都应跑一遍这套诊断，定位自己的断点。
4. **瓶颈的优先级排序直接指导投入**：当前自动链接质量下导航就受限，说明**接地质量是第一杠杆**——比换更强的检索器或推理器收益大。

#### 4. 可以应用的 Spatial AGI 场景

- **家庭助理机器人**：主人语言指示直接成为空间记忆的一部分（"放好了"类状态更新）；
- **多用户空间知识库**：不同家庭成员提供的物体位置信息带署名与可信度融合；
- **空间问答 + 主动确认**：检测到对话信息未接地时主动发问（"您说的蓝色盒子是桌上这个吗？"）——闭环接地面向交互的扩展；
- **记忆系统研发诊断**：三段 oracle 对照协议可直接用于任何空间记忆 stack 的调试。

### Q3: 基于前面的分析，这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

1. **对话作为具身记忆一等信息源的首次系统评测**——此前的具身记忆基准（ScanQA、OpenEQA、VSI-Bench）全部以视觉为唯一记忆来源；
2. **真实场景大规模数据**：27 个真实 3D 场景、142 episodes、14K QA、12K 导航指令——规模与真实性兼备；
3. **统一三段评测框架 + 9 种记忆表示横向对比**——把"记忆表示"作为受控变量隔离评测，方法论干净；
4. **受控 oracle 诊断设计**：追加时机对照、链接质量对照、oracle 记忆对照——三个诊断实验分别隔离"融合时机""接地质量""表示上限"三个因素；
5. **QA/导航收益分离的发现本身**——这是对"记忆里有什么"与"记忆能干什么"之间鸿沟的首次清晰量化；
6. **三大瓶颈的可操作定位**——为后续工作给出了明确攻关顺序。

#### 2. 主要局限性

1. **不提供解决方案**。作为诊断型基准，它定位了瓶颈但没有给出接地机制——"对话如何自动接到物体条目"仍是开放问题；
2. **对话来源与质量依赖数据收集协议**。真实家庭对话噪声大、指代模糊（"那个""那边"），基准里的对话若过于脚本化，接地的真实难度会被低估；
3. **实例级导航的歧义处理**。多实例同类物体（"那把椅子"）的 GT 实例判定依赖标注约定，边界 case 的公平性存疑；
4. **9 种记忆表示的选择偏差**。评测的记忆系统若都以视觉为主、对话为辅设计，结论"对话未接地"可能部分是**被评系统都缺乏接地模块**的循环论证——需要一个原生多模态记忆的强基线；
5. **静态场景假设**。27 个真实场景的对话-物体关系若基本静态，"对话驱动的状态更新"（"我把X移走了"）这一最具价值的动态维度可能覆盖不足；
6. **单机器人视角**。未涉及多用户对话的信息冲突与信任融合（妈妈说在客厅、爸爸说在卧室）。

#### 3. 与其他相关工作的对比

| 工作 | 记忆来源 | 对话接地 | 导航评测 | 诊断设计 |
|------|----------|----------|----------|----------|
| OpenEQA | 视觉 | ✗ | ✗ | ✗ |
| VSI-Bench | 视频 | ✗ | ✗ | ✗ |
| ScanQA | 扫描+语言查询 | 部分（查询侧） | ✗ | ✗ |
| EmbodiedLGR | 视觉图记忆 | ✗ | ✓ | ✗ |
| BetaMem（今日01） | 视觉+交互（方法侧） | 架构隐含 | — | 错误复发率 |
| **DialogMem** | **视觉+对话（评测侧）** | **✓ 核心评测对象** | **✓ 实例级** | **✓ oracle 三对照** |

- **vs BetaMem**：完美互补——DialogMem 从评测侧证明"对话必须接到对象级条目"，BetaMem 从方法侧给出"契约强制链接实体条目"的架构答案。两者合读：问题与药方齐备，下一波工作是把药方放进基准里验证。
- **vs SpatialScout**：SpatialScout 评"视觉主动建图"，DialogMem 评"语言-视觉融合记忆"——分别攻空间记忆的两个信息输入端。

## 核心技术发现

- **发现 1**：对话追加 → QA 显著提升 / 导航几乎不变。语言空间知识若停留在"文本层"就只服务语言型任务。
- **发现 2**：导航增益与链接质量单调正相关，但完美链接仍不及 oracle 物体级记忆——检索与定位是独立于形成的第二个、第三个损失源。
- **发现 3**：三大瓶颈排序：形成期对象级接地 > 检索期条目命中 > 定位期空间恢复——第一瓶颈决定其余瓶颈的可解性。
- **发现 4**：27 真实场景的可行性与诊断方法论验证——受控 oracle 对照应成为记忆基准的标配。

## 与Spatial AGI的关系

### 直接贡献
- 定义了"对话接地具身记忆"这一新评测维度，补上空间记忆信息源拼图的语言端；
- 提供三段式诊断协议与 oracle 对照仪器。

### 技术启发
- 空间记忆的表示标准应由导航/操作等度量级下游决定；
- 对话流是空间接地数据引擎的低成本富矿。

### 应用场景
- 家庭机器人（语言指示→空间记忆）、多用户空间知识融合、记忆系统诊断。

## 个人思考

### 最令人兴奋的发现
- **"QA 涨、导航不涨"这个不对称**。它用一个对照实验戳破了"把文本塞进记忆库就算多模态记忆"的幻觉。这和 SpatialScout 的"QA 能答、建图不会"是同构的：**语言层掌握的空间知识 ≠ 度量层可行动的空间知识**。两条独立证据链指向同一个结论：空间 AGI 的评测和训练都必须锚定在几何可验证的下游任务上。
- **oracle 对照的杠杆作用**。完美链接仍打不过 oracle 记忆，说明这个领域每一环都有 20-30% 的提升空间——好消息是每一环都值得做，坏消息是没有单点银弹。

### 潜在局限
- 诊断完备但无疗法；被评系统普遍缺接地模块的循环论证风险值得警惕——期待下一代工作直接带"对话接地模块"来打这个基准。
- 真实家庭对话的混乱度（指代、口音、打断）若未充分体现，接地难度的下限被低估。

### 与前日研究的关联
- **与 BetaMem（今日01）**：问题-药方配对（见上表）。值得做的后续实验：把 BetaMem 的 entity 链接契约作为第 10 种记忆表示放进 DialogMem，验证"契约化接地"能否把导航收益拉起来。
- **与 Holi-World（10-21/02）**：Holi-World Foundry 把感知流自动建成世界记录；DialogMem 指出语言流必须进入这个记录才有完整语义。下一代"世界记录"应是感知+对话双流自动接地——Foundry 的对话版。
- **与 SpatialScout（10-21/03）**：两者都是"构建侧"评测的推进——一个评视觉构建，一个评语言融合；共同宣告空间智能评测从 QA 时代进入构建/接地时代。
- **与 Friday 的 EgoJEPA/LTM（10-19）**：LTM 做 VLA 的潜空间记忆，DialogMem 做符号层记忆诊断——潜空间记忆天然避开了"接地"问题但也失去了审计性，两种范式的地盘划分开始清晰。

## 关键数据

- 规模：142 episodes / 27 真实 3D 场景 / 14,193 QA 对 / 11,890 导航指令
- 评测记忆表示：9 种，统一"形成→检索→推理"框架
- 核心对照：评测时追加对话 = QA↑↑ 导航≈0；链接质量单调改善导航；完美链接 < oracle 记忆
- 三大瓶颈：形成期对象级接地 / 检索期条目命中 / 定位期空间恢复

## 总结

### 核心发现总结
DialogMem 首次将人类对话引入具身记忆评测，用三段式框架与 oracle 对照定位出对话接地记忆的三重瓶颈，并以"QA 提升而导航不动"的不对称现象确立了核心判据：空间知识的记忆价值取决于它是否被组织到可定位的对象级条目，而非仅仅可检索。

### 对Spatial AGI的意义
- 为空间记忆立下"可行动性"标准：语言、视觉、几何三源证据必须在对象级条目上融合；
- 指明语言流是空间智能数据与监督的未开采富矿；
- 与 BetaMem（方法）、Holi-World（感知接地产线）共同构成"对话接地空间记忆"的完整问题空间。

## 附录 A：三段管线的逐段故障模式分析

```
阶段 1 形成期（formation）
  断点: 对话未被解析 / 解析了但没关联到实例 / 关联了但条目结构扁平
  症状: QA 好（全文检索兜底）导航差（无位姿可依）
  对应 BetaMem 药方: 契约强制 entity 链接

阶段 2 检索期（retrieval）
  断点: 查询嵌入与证据表示失配 / 检索粒度错（场景级 vs 条目级）
  症状: 记忆库里有正确条目但没被取出来
  诊断: oracle 链接仍不达 oracle 记忆 → 本段贡献独立损失

阶段 3 定位/推理期（reasoning & localization）
  断点: 条目内的空间描述（"第二层抽屉"）未换算为坐标 / 导航策略不消费记忆
  症状: 走到大致区域但到不了实例跟前
  诊断: "recovering its spatial location remains a bottleneck"
```

**关键洞察**：三段损失是**乘性**的——每段 70% 的保真度，端到端只有 34%。
这也解释了为什么单点改进（只强化检索器）在整链评测中收益被稀释。

## 附录 B：9 种记忆表示的推测分类（基于领域主流方法）

虽摘要未列名，但按该领域标准做法，被评表示大概率覆盖：

| 类型 | 代表形态 | 对话融合方式 | 预期短板 |
|------|----------|--------------|----------|
| 原始观测索引 | 关键帧库 | 附加文本 | 无对象级结构 |
| 场景图 | 3D scene graph | 挂节点属性 | 对话-节点对齐难 |
| 语义地图 | 2D/3D semantic map | 文本标签 | 实例歧义 |
| 向量库 RAG | chunk embeddings | 混合检索 | 无空间结构 |
| 知识三元组 | (物体,关系,物体) | 谓词抽取 | 空间精度丢失 |
| 混合层级 | 图+向量+文本 | 多路 | 接地仍靠启发式 |

如果被评集合确实没有"对话原生接地"的表示，附录 A.4 的循环论证担忧成立——
这本身就是本文的隐含结论：**市面上还不存在合格的对话接地空间记忆**。

## 附录 C：与 SpatialScout 对照的"空间知识四象限"

按（信息来源 × 使用方式）划分空间知识：

```
              语义级使用            度量级使用
视觉来源   │ 看图答"哪边"        │ 主动建图/三角化
           │ (VSI-Bench 模式)    │ (SpatialScout 模式)
语言来源   │ 听话答"在哪"        │ 听指示走到物体
           │ (DialogMem-QA 模式) │ (DialogMem-Nav 模式, 最难)
```

**右下角（语言→度量行动）是当前全领域最弱象限**——
DialogMem 用导航不动证明了它，SpatialScout 用 3.25% 精确匹配从另一侧逼近它。
Spatial AGI 的下一代评测应直接攻这个象限：**对话驱动的主动验证**（听人说X在Y → 主动走过去看 → 更新记忆）。

## 附录 D：数据收集协议的工程推演

27 真实场景 × 对话流 = 最难的部分是 GT 构建：
1. **时间对齐 GT**：每句对话提到物体时，需要知道当时该物体真实位置（可能用后期扫描+人工核对）；

4. **11,890 条导航指令**意味着约每 episode 84 条——模板化生成 + 人工校验的混合产线。

**对国内团队的启示**：这类"真实环境+多模态流+密集 GT"数据集的产线能力（扫描、对齐、标注、质控）
本身就是护城河——比模型创新更难复制。

## 附录 H：实例级导航与普通物体导航的差距精析

普通物体导航（ObjectNav）："找一个椅子"——找到任意实例即成功。
实例级导航（Instance-level Nav，DialogMem 口径）："找那把修过的椅子"——必须是对话指涉的**那一个**。

难度跃迁的三重来源：
1. **身份消歧**：同类多实例场景下需维护实例身份（哪把是哪把）——与 SpatialScout 的跨视角实例关联是同一难题的"时序版"；
2. **证据链推理**：目标属性可能只存在于对话中（"修过"），需要 episodic 记忆而非外观匹配；
3. **到达精度**：实例级 GT 通常要求更近的到达半径——度量精度压力更大。

**与 ObjectNav 文献的关系**：ObjectNav 社区 2024-2026 年在"找类"上已接近饱和（HM3D 上 SR>60%），
DialogMem 把指针从"类"移到"实例"，实为开辟 ObjectNav-Next 赛道——
预计 2027 年会出现"对话实例导航"成为标准评测组件。

## 附录 I：QA 与导航评分机制的差异推演

为什么对话文本能"骗过"QA 而骗不过导航？

- **QA 的容错路径**：问题"药在哪？"→ 记忆全文检索命中"药收进床头柜第二层"→ 语言模型直接复述 → 得分。全程**无需坐标**，语言自洽即可。
- **导航的强制路径**：指令"去拿药"→ 系统必须输出可执行目标位姿 → 位姿必须来自与场景几何绑定的条目 → 纯文本条目在"转坐标"环节断裂 → 原地打转或走到错误区域。
- **结论**：QA 的答案空间（语言）与对话的证据形态（语言）同构；导航的答案空间（坐标）与对话证据异构——**异构转换正是接地（grounding）的定义**。

这个分析给出了接地的一个操作性定义：
**当且仅当系统能把语言证据转换为目标模态的可执行形式时，该证据才算被接地。**

## 附录 J：对话类型学与其接地难度分级

| 对话类型 | 示例 | 接地难度 | 所需能力 |
|----------|------|----------|----------|
| 显式位置陈述 | "药在床头柜第二层" | ★ | 实例识别 + 空间关系解析 |
| 指示性指涉 | "把它放那儿" | ★★ | 共指消解 + 消歧"那儿" |
| 状态更新 | "我把剪刀移走了" | ★★★ | 实体追踪 + 旧条目失效 |
| 隐式约束 | "别动那个盒子" | ★★★ | 意图理解 + 条目标记保护 |
| 条件性指示 | "客人来了就把杂物收柜子里" | ★★★★ | 事件触发 + 规划级记忆 |

低难度类型（★-★★）可由当前 VLM 直接处理；★★★ 以上需要 BetaMem 式契约架构
（状态更新需失效旧断言、保护标记需链接到规划模块）。
DialogMem 的对话流若以 ★-★★ 为主，则真实难度仍被低估——
"对话类型学分布"应成为此类基准的必报统计量。

## 附录 K：与三段式诊断对应的改进路线图

```
Phase 1: 形成期接地（最高杠杆）
  ├─ 话语→实例对齐模块（小模型专用，输入对齐流输出链接）
  ├─ 契约化写入（BetaMem 方案）：无实例链接的对话记忆标记为"待接地"
  └─ 目标: 链接准确率 90%+（对照 oracle）

Phase 2: 检索期校准
  ├─ 条目级（非 chunk 级）检索索引
  ├─ 多路检索: 语义向量 × 空间邻近 × 时间邻近
  └─ 目标: oracle 链接下检索命中 ≥95%

Phase 3: 定位期融合
  ├─ 空间关系短语→坐标约束编译器（"第二层"→ z 区间）
  ├─ 记忆-导航策略接口（goal memory → planner）
  └─ 目标: oracle 记忆下导航成功率逼近 oracle 记忆本身
```

三阶段的验收都应使用 DialogMem 的 oracle 对照协议——
先在 oracle 链接/记忆下验证单段上限，再放开前段观察端到端衰减。

## 附录 L：真实场景 vs 仿真的选择代价

DialogMem 选真实场景（27 个）而非 ProcTHOR 式仿真，得失账：

**得**：
- 对话的生态效度（真实住户的说话方式无法仿真）；
- 视觉-语言分布的真实性（VLM 无域差）；
- 结论的部署外推可信度。

**失**：
- 规模天花板（27 场景 vs 仿真无限生成）——过拟合风险；
- GT 成本（每个物体位置需实测标注）；
- 失败重跑成本（导航评测无法 reset，需多遍采集或回放协议）。

**结论**：诊断型结论（三瓶颈）在 27 场景已可信； leaderboard 型排名需谨慎——
样本量不足时模型间差异可能落入噪声区间。后继工作可采用"真实小规模诊断 + 仿真大规模排名"的双轨制。

## 附录 M：精读问答补充

**Q1: 为什么"评测时追加对话"是合理的对照设计？**
A: 它模拟了当前最常见的工程捷径——视觉记忆系统照常构建，对话作为侧信道文本在推理时拼接。这个对照的意义在于证明：捷径能提 QA（因为 QA 本质是文本任务）但不能提导航（因为导航需要结构化接地）。它把"对话无效"精确定位为"对话接入方式无效"而非"对话信息无用"。

**Q2: 9 种记忆表示里最接近成功的是哪类？**
A: 摘要未明说，但从"navigation improves with link quality"可推断：具备某种对象级结构（场景图类/实体条目类）的表示对链接质量最敏感——收益曲线斜率最大。纯向量 RAG 类对链接质量应该不敏感（对话全文都在库里，加不加链接都能检索到）。

**Q3: 这个基准与 LLM 时代的 RAG 有什么本质区别？**
A: RAG 的评测终点是答案文本；DialogMem 的终点包含物理到达。RAG 的"相关性"是语义相似度；这里的"相关性"最终由几何可达性裁决。一句话：RAG 服务语言智能，DialogMem 服务空间智能——检索正确只是及格线，走到才算数。

**Q4: 对空间智能创业者最可执行的一条建议是什么？**
A: 在你的家庭/仓储机器人架构里，把"用户语音→空间记忆"作为独立模块立项（话语-实例对齐器 + 契约化写入），而不是把语音转文本扔进 RAG 库。DialogMem 的数据说明这条管线是导航级能力的缺失环节，而竞品几乎都还没做。

## 附录 O：从 DialogMem 看空间智能评测的"下游优先"原则

DialogMem 的方法论核心可以提炼为一条设计公理：

> **评测的下游决定表示的合格标准。**

推演到空间智能评测体系：

```
下游 = QA            → 合格标准: 证据可检索（语义层）
下游 = 导航          → 合格标准: 证据可定位（度量层）
下游 = 操作          → 合格标准: 证据可交互（几何+物理层）
下游 = 长期服务      → 合格标准: 证据可维护（新鲜度+一致性+可遗忘）
```

当前多数空间评测停留在第一层（QA），DialogMem 推到第二层，
操作层与长期服务层的标准评测仍缺席——
结合 SpatialScout（构建层）与 BetaMem 的错误复发率（维护层），
2026 年末的空间智能评测版图正在四个层次同时铺开：

| 层次 | 代表评测 | 缺口 |
|------|----------|------|
| 语义（QA） | VSI-Bench / OpenEQA | 饱和，区分度下降 |
| 构建（地图） | SpatialScout | 精确级天花板待破 |
| 度量行动（导航/操作） | DialogMem-Nav / LIBERO-Dynamic | 实例级+语言驱动刚起步 |
| 长期维护 | EMem-Bench（复发率） | 无空间版 |

**预测**：第一个"空间记忆维护"基准（跨会话状态跟踪 + 错误复发 + 遗忘质量）
将在 12 个月内出现，且大概率由本季这批工作（BetaMem/DialogMem/Holi-World）的作者群体推出。

## 附录 P：对话接地的技术方案浅勘（给工程师）

如果明天要在产品里做"对话→空间记忆接地"，最小可行架构：

```
输入流: ASR 文本 + 时间戳 ──┐
观测流: RGB-D + 位姿      ──┼──► 实时对齐器
场景图: 实时构建的实例库   ──┘         │
                                     ▼
                          话语解析（VLM 小模型）
                          输出: {指涉物体描述, 空间关系, 动作类型, 置信度}
                                     │
                                     ▼
                          实例链接器: 描述 × 候选实例（时间窗内可见+空间约束）
                          输出: 话语 → instance_id 链接（带置信度）
                                     │
                          ┌──────────┴──────────┐
                          ▼                     ▼
                    高置信: 直接写入      低置信: 待确认队列
                    spatial+entity 条目   （下次该物体可见时视觉验证，
                    （附证据类型=证言）     或向用户主动确认）
```

三个工程要点：
1. **时间窗约束**是免费强先验：话语提到的物体 90% 在前后 30s 的视野内；
2. **置信度分层写入**（证言 < 观测）避免对话噪声污染度量记忆；
3. **待确认队列 + 主动验证**把 DialogMem 的"低链接质量"瓶颈转化为主动感知机会——
   顺路看一眼就能确认，边际成本近零。
