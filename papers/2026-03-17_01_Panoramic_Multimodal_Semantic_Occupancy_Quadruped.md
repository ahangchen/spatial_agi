## 1. 摘要 (Abstract)

全景图像为四足机器人的感知提供了完整的360°视觉覆盖。然而，现有的占据预测方法主要针对轮式自动驾驶设计，严重依赖RGB线索，限制了它们在复杂环境中的鲁棒性。为弥补这一差距：

1. **PanoMMOcc数据集**：首个面向四足机器人的真实世界全景多模态占据数据集，包含四种传感模态和多样化场景。

2. **VoxelHound框架**：一个针对腿部移动和球形成像定制的全景多模态占据感知框架，包含：
   - **垂直抖动补偿(VJC)模块**：缓解移动过程中身体俯仰和翻滚引起的严重视点扰动
   - **多模态信息提示融合(MIPF)模块**：联合利用全景视觉线索和辅助模态增强体积占据预测

3. **基准评估**：基于PanoMMOcc建立基准并提供详细数据分析，VoxelHound在mIoU上达到23.34%，相比基线提升+4.16%。

## 2. 核心算法原理

### 2.1 问题定义

给定四种模态的输入：
- 全景RGB图像 $\mathcal{I}^{pal}$
- 热成像图像 $\mathcal{I}^{th}$
- 偏振图像 $\mathcal{I}^{pol}$
- LiDAR点云 $\mathcal{P}$

目标是生成密集的3D语义占据体素网格：

$$\mathbf{O} = \Phi(\mathcal{I}^{pal}, \mathcal{I}^{th}, \mathcal{I}^{pol}, \mathcal{P})$$

其中 $\Phi$ 表示多模态融合网络，$\mathbf{O} \in \mathbb{R}^{X \times Y \times Z}$ 是最终预测结果。

### 2.2 整体架构

VoxelHound采用双分支架构：

#### 2.2.1 相机分支
处理三种图像模态（全景RGB、热成像、偏振）：

1. **特征提取**：每个模态通过独立的2D主干网络提取多尺度特征
   $$\mathbf{F}_{c\_backbone}^{m} = \{\mathbf{F}_{1/8}^{m}, \mathbf{F}_{1/16}^{m}, \mathbf{F}_{1/32}^{m}\}, \quad m \in \{pal, th, pol\}$$

2. **特征金字塔**：FPN聚合多尺度特征
   $$\mathbf{F}_{c\_neck}^{m} \in \mathbb{R}^{C_{neck} \times \frac{H'}{8} \times \frac{W'}{8}}$$

3. **2D到BEV转换**：将2D特征投影到鸟瞰图空间
   $$\mathbf{F}_{c}^{m} \in \mathbb{R}^{C_m \times H \times W}, \quad m \in \{pal, th, pol\}$$

#### 2.2.2 LiDAR分支
处理点云数据：

1. **体素化**：将3D空间划分为体素网格，每个体素最多保留10个点
2. **3D稀疏卷积**：提取分层几何特征，总步幅为8
3. **BEV投影**：将稀疏3D特征投影到BEV空间
   $$\mathbf{F}_{l} \in \mathbb{R}^{C_l \times H \times W}$$

#### 2.2.3 融合分支
融合多模态BEV特征：

$$\mathbf{F}_{f} = \mathcal{F}_{\text{fusion}}(\mathbf{F}_{l}, \mathbf{F}_{c}^{pal}, \mathbf{F}_{c}^{th}, \mathbf{F}_{c}^{pol})$$

使用SECOND-FPN架构进行多尺度空间表示增强，最终通过占据头预测3D语义占据。

### 2.3 关键创新模块

#### 2.3.1 垂直抖动补偿 (VJC) 模块

**问题**：四足机器人的步态引起身体垂直振荡，导致图像特征错位和BEV转换不稳定。

**解决方案**：
1. **垂直特征提取**：沿宽度维度折叠特征图
   $$\mathbf{F}_{v}(c,h) = \frac{1}{W}\sum_{w=1}^{W}\mathbf{F}(c,h,w)$$

2. **垂直编码**：通过1D卷积编码器处理
   $$\hat{\mathbf{F}}_{v} = \mathcal{E}_{v}(\mathbf{F}_{v})$$

3. **偏移估计**：估计全局垂直偏移
   $$\Delta h_{\text{raw}} = \mathcal{R}(\hat{\mathbf{F}}_{v})$$

4. **归一化**：
   $$\Delta h = \frac{2}{H}\Delta h_{\text{raw}}$$

5. **网格采样**：应用垂直位移补偿
   $$\mathcal{G}(h,w) = \mathcal{G}_{0}(h,w) + (0, \Delta h)$$
   $$\mathbf{F}_{\text{comp}} = \text{GridSample}(\mathbf{F}, \mathcal{G})$$

**设计理念**：轻量级设计，在图像编码器和2D到BEV转换之间插入，估计并补偿垂直特征位移。

#### 2.3.2 多模态信息提示融合 (MIPF) 模块

**问题**：传统对称融合策略（拼接、逐元素相加）对所有模态一视同仁，缺乏明确的角色区分。

**解决方案**：采用非对称融合原则——**几何主导，语义补充**。

**实现步骤**：

1. **特征投影**：将各模态投影到共享嵌入空间
   $$\tilde{\mathbf{F}}_{l} = \phi_{l}(\mathbf{F}_{l}), \quad \tilde{\mathbf{F}}_{c}^{m} = \phi_{m}(\mathbf{F}_{c}^{m})$$

2. **语义提示生成**：为每个图像模态生成紧凑的语义提示
   $$\mathbf{p}_{m} = \mathcal{M}_{m}(\text{GAP}(\tilde{\mathbf{F}}_{c}^{m}))$$
   $$\mathbf{P} = [\mathbf{p}_{\text{rgb}}, \mathbf{p}_{\text{th}}, \mathbf{p}_{\text{polar}}]$$

3. **几何引导的提示注意力**：以LiDAR BEV特征为查询，模态提示为键和值
   $$\mathbf{F}_{\text{attn}} = \text{Softmax}\left(\frac{\tilde{\mathbf{F}}_{l}(\mathbf{W}_{K}\mathbf{P})^{\top}}{\sqrt{D/h}}\right)\mathbf{W}_{V}\mathbf{P}$$

4. **残差调制**：保留几何主导性
   $$\mathbf{M} = \sigma(\gamma(\mathbf{F}_{\text{attn}}))$$
   $$\mathbf{F}_{f} = \tilde{\mathbf{F}}_{l} + \mathbf{M} \odot \tilde{\mathbf{F}}_{l}$$

**优势**：
- 提示自适应地重新加权LiDAR BEV特征，而不是直接覆盖
- 确保几何结构保持主要表示基础
- 避免密集空间交叉注意力的高计算成本

## 3. PanoMMOcc数据集

### 3.1 数据集特色

**首个**面向四足机器人的全景多模态占据数据集，具有以下特点：

1. **多模态传感器**：
   - 全景环形镜头(PAL)相机：360°×70° FoV，40 FPS，2048×2048分辨率
   - MiD-360 LiDAR：10 Hz扫描频率
   - 热成像相机：Guide Infrared N-Driver P302B，25 FPS，640×512分辨率
   - 偏振相机：LUCID TRI050S-QC，1224×1024分辨率，四个偏振角度（0°、45°、90°、135°）

2. **多样化场景**：
   - 校园、城市街道、居民区、绿地、乡村、森林
   - 包含白天和夜间序列
   - 涵盖结构化和非结构化环境

3. **数据规模**：
   - 54个序列，10 Hz采集，每序列40秒
   - 总计21,600帧
   - 42个序列用于语义标注（30训练+12测试）
   - 16.8k关键帧

4. **占据标注**：
   - 3D体积：64×64×16体素
   - 空间范围：x-y平面[-12.8, 12.8]m，z轴[-2.4, 4.0]m
   - 体素分辨率：0.4m×0.4m×0.4m
   - 12个语义类别

### 3.2 采集平台

- **四足机器人**：Unitree Go2
  - 尺寸：70cm×31cm×40cm
  - 载重：7kg
  - 垂直障碍：15cm
  - 坡度：30°

### 3.3 标注流程

1. 专业标注员提供语义、对象级和实例级标签
2. 帧级校准补偿LiDAR信号丢失
3. 按12个语义类别组织
4. 遵循SurroundOcc协议确保兼容性

### 3.4 时间同步

基于主机PC和千兆以太网交换机的集中式时间同步方案：
- 主机PC作为中央数据采集和控制单元
- 以太网传感器（LiDAR、偏振相机）通过交换机连接
- 全景和热成像相机直接连接
- 所有传感器时钟与主机时间参考同步

### 3.5 校准

**内参校准**：
- 使用棋盘格进行相机内参标定
- 估计焦距、主点和畸变系数
- 最小化重投影误差

**外参校准**：
- LiDAR与相机之间的外参标准
- 所有传感器统一到LiDAR中心坐标系

**偏振信息处理**：
Stokes向量计算：
$$\mathbf{S} = [S_0, S_1, S_2, S_3]^T$$

其中：
$$S_0 = I_0 + I_{90}$$
$$S_1 = I_0 - I_{90}$$
$$S_2 = I_{45} - I_{135}$$

线性偏振度(DoLP)和偏振角(AoLP)：
$$\text{DoLP} = \frac{\sqrt{S_1^2 + S_2^2}}{S_0}$$
$$\text{AoLP} = \frac{1}{2}\arctan\left(\frac{S_2}{S_1}\right)$$

## 4. 实验结果与分析

### 4.1 主要结果

在PanoMMOcc测试集上的性能对比：

| 方法 | 模态 | mIoU (%) |
|------|------|----------|
| MonoScene | C | 8.94 |
| TPVFormer | C | 10.25 |
| SurroundOcc | C | 11.37 |
| VoxFormer | C | 12.49 |
| FlashOcc | C | 13.62 |
| OccDepth | C | 14.78 |
| EFFOcc-T | C+L | 19.18 |
| **VoxelHound (C+L+T+P)** | **全模态** | **23.34** |

**关键发现**：
- 相比MonoScene（纯相机）提升+14.40% mIoU
- 相比EFFOcc-T（相机+LiDAR）提升+4.16% mIoU
- 多模态融合显著优于单模态方法

### 4.2 不同光照条件下的性能

| 模态 | 白天 mIoU (%) | 夜间 mIoU (%) |
|------|---------------|---------------|
| C | 6.93 | 3.52 |
| C+T+P | 6.85 | 4.07 |
| C+L | 22.56 | 19.17 |
| C+L+T+P | 23.34 | 18.68 |

**观察**：
- 纯相机方法在夜间性能急剧下降（-3.41%）
- 加入热成像和偏振改善夜间性能（+0.55%）
- LiDAR几何信息是性能提升的关键（+15.63%白天，+15.65%夜间）
- 全模态融合在白天达到最佳性能

### 4.3 不同场景类别的性能

| 场景 | C mIoU (%) | C+L+T+P mIoU (%) | 提升 |
|------|------------|------------------|------|
| 居民区 | 较高 | 最高 | 最大 |
| 校园 | 较高 | 高 | 大 |
| 城市街道 | 中等 | 中高 | 中等 |
| 绿地 | 较低 | 中等 | 中等 |
| 乡村 | 低 | 中等 | 中等 |
| 森林 | 最低 | 中低 | 较小 |

**发现**：
- 结构化环境（居民区、校园）性能更好
- 非结构化自然环境（森林、乡村）更具挑战
- 不规则地形、密集植被和模糊对象边界增加预测难度

### 4.4 消融实验

- **训练轮数**：48 epochs
- **图像编码器**：ResNet-18（所有模态）

### 4.6 损失函数

$$\mathcal{L}_{\text{occ}} = \mathcal{L}_{\text{ce}} + \mathcal{L}_{\text{ls}} + \mathcal{L}_{\text{scal}}^{\text{geo}} + \mathcal{L}_{\text{scal}}^{\text{sem}}$$

包括：
- 交叉熵损失 $\mathcal{L}_{\text{ce}}$

## 7. 局限性分析

### 7.1 数据集局限

1. **规模限制**
   - 42个标注序列相对较小
   - 21,600帧总帧数有限
   - 可能不足以训练超大规模模型

2. **场景覆盖**
   - 6种场景类型，但可能未覆盖所有极端情况
   - 天气条件（雨、雪、雾）未明确提及
   - 动态对象（行人、车辆）处理未详细说明

3. **传感器限制**
   - 体素分辨率0.4m可能对精细结构不够
   - 垂直范围[-2.4, 4.0]m可能限制高层建筑感知
   - 偏振相机分辨率(1224×1024)相对较低

### 7.2 方法局限

1. **计算复杂度**
   - 多模态编码需要多个主干网络
   - BEV特征融合增加内存消耗
   - 实时性可能受限（未报告FPS）

2. **模态依赖**
   - LiDAR几何信息是性能关键
   - 相机-only性能很差（8.94% mIoU）
   - 传感器故障时鲁棒性未知

3. **泛化能力**
   - 仅在四足平台上验证
   - 其他腿部机器人（人形、双足）未测试
   - 不同步态模式的适应性未评估

### 7.3 技术局限

1. **VJC模块**
   - 仅处理垂直抖动，未考虑水平位移
   - 假设全局垂直偏移，可能不适用于复杂地形
   - 对快速运动的适应性未验证

2. **MIPF模块**
   - 语义提示可能丢失空间细节
   - 提示数量固定（3个），扩展性受限
   - 不同模态的权重固定，未自适应调整

3. **占据预测**
   - 12个语义类别可能不够细粒度
   - 未知空间处理未详细讨论
   - 时序信息未利用（单帧预测）

### 7.4 实验局限

1. **对比基线**
   - 多数基线为自动驾驶方法，非全景或四足优化
   - 未与最新的全景3D理解方法对比
   - 端到端学习方法未比较

2. **评估指标**
   - 仅使用mIoU，未考虑其他指标（IoU、Precision、Recall）
   - 实时性能（FPS）未报告
   - 内存和计算开销未详细分析

3. **消融实验**
   - 仅在整体数据集上消融，未分场景分析
   - 不同模态组合的详细消融缺失
   - 超参数搜索范围有限

### 8.1 研究价值评估

#### 8.1.1 重要性

#### 8.1.2 创新程度
- **渐进式创新**：VJC和MIPF模块是对现有技术的改进，非颠覆性突破
- **工程贡献**：数据集构建和系统集成是主要贡献
- **方法组合**：将现有技术（BEV、注意力、多模态融合）应用到新场景

### 8.2 技术深度分析

#### 8.2.1 VJC模块的思考
**优点**：
- 轻量级设计，参数少
- 直接解决四足机器人的核心挑战
- 可插拔式设计，易于集成

**潜在改进**：
- 考虑6自由度姿态变化（当前仅垂直）
- 结合IMU数据进行物理约束
- 学习不同步态模式的自适应补偿

**批判性观点**：
- 全局垂直偏移假设可能过于简化
- 在斜坡或不平坦地形的性能未知
- 与SLAM系统的集成未讨论

#### 8.2.2 MIPF模块的思考
**优点**：
- 几何主导原则符合直觉
- 提示机制降低计算成本
- 残差调制保持结构稳定性

**潜在改进**：
- 动态提示权重调整
- 空间变化的提示（而非全局提示）
- 层次化提示（粗到细）

**批判性观点**：
- 提示可能丢失局部细节信息
- 固定3个提示限制了扩展性
- 与其他融合策略（如门控、注意力）的对比不足

#### 8.2.3 数据集的思考
**优点**：
- 真实世界数据，包含真实挑战
- 多模态同步采集，质量高
- 多样化场景，覆盖面广

**潜在改进**：
- 扩大规模（更多序列、帧数）
- 增加天气和季节变化
- 包含更多动态对象和交互场景

**批判性观点**：
- 42个序列相对较小，可能限制深度学习潜力
- 未提及隐私保护措施（人脸、车牌模糊）
- 标注一致性验证未详细说明

### 8.3 Spatial AGI视角

#### 8.3.1 对Spatial AGI的贡献
**积极方面**：
- 提供全景感知能力，支持全方位环境理解
- 多模态融合模拟生物感知系统
- 具身平台验证算法在真实世界的可行性

**不足之处**：
- 静态场景为主，动态交互有限
- 单帧预测，未利用时序信息
- 缺乏高层语义推理（如场景理解、意图预测）

#### 8.3.2 与生物系统的对比
**相似性**：
- 多模态感知（视觉、热感、偏振类似动物感官）

**差异性**：
- 生物系统更节能高效
- 动物有更强的泛化和推理能力
- 生物感知与行动紧密耦合，当前方法解耦

#### 8.3.3 未来发展方向
1. **时序建模**

## 12. 附录

### 12.1 术语表
- **全景图像 (Panoramic Image)**：360°全方位视野的图像
- **占据预测 (Occupancy Prediction)**：预测3D空间中每个体素的占据状态和语义类别
- **BEV (Bird's-Eye-View)**：鸟瞰图，从顶部俯视的2D表示
- **Voxel (体素)**：3D空间中的立方体单元，类似于2D图像中的像素
- **全景环形镜头 (PAL)**：使用环形反射镜实现全景成像的光学系统
- **Stokes向量**：描述光的偏振状态的数学表示
- **DoLP (Degree of Linear Polarization)**：线性偏振度
- **AoLP (Angle of Linear Polarization)**：线性偏振角

### 12.2 数学符号
- $\mathcal{I}^{pal}, \mathcal{I}^{th}, \mathcal{I}^{pol}$：全景、热成像、偏振图像
- $\mathcal{P}$：LiDAR点云
- $\mathbf{O}$：占据预测结果
- $\Phi$：多模态融合网络
- $\mathbf{F}$：特征图
- $\mathbf{F}_{v}$：垂直特征
- $\Delta h$：垂直偏移
- $\mathcal{G}$：采样网格
- $\mathbf{p}_{m}$：模态语义提示
- $\mathbf{P}$：提示集合
- $\mathbf{M}$：调制掩码
