## 摘要精读

### 核心问题

Token修剪对于提升视觉-语言模型(VLMs)的计算效率至关重要，特别是在视频任务中，时序冗余(time redundancy)非常普遍。

### 现有方法的局限性

论文指出现有方法存在两种主要范式：

1. **仅ViT内修剪**: 
   - 在视觉transformer (ViT)内部进行token修剪
   - 主要针对单模态感知任务（如动作识别、物体分割）
   - **问题**: 未适应下游视觉-语言任务

2. **仅LLM内修剪**:
   - 仅在大型语言模型(LLM)内部修剪，保持ViT输出不变
   - **问题**: 通常需要复杂的文本条件token选择机制(text-conditioned token selection)

### STTS的创新点

论文提出**Spatio-Temporal Token Scoring (STTS)**，这是一个简单且轻量级的模块：

#### 核心特性

1. **统一修剪**: 在ViT和LLM中都进行视觉token修剪
2. **无条件化**: 不需要文本条件或token合并
3. **端到端兼容**: 完全兼容端到端训练

#### 技术机制

1. **时序评分学习**: 通过辅助损失(auxiliary loss)学习时序评分
2. **空间评分学习**: 通过LLM下游梯度学习空间评分
3. **高效打包算法**: 辅助token修剪的高效算法

### 实验结果

- **修剪率**: 50%的视觉token
- **效率提升**: 62%（训练和推理阶段）
- **性能损失**: 仅0.7%（13个短视频和长视频QA任务平均）
- **扩展性**: 效率提升随着每视频采样帧数增加而增加
- **测试时缩放**: 长视频QA可额外提升0.5-1%性能

## 一、研究背景与动机

### 1.1 视频VLM的挑战

视频视觉-语言模型(Video VLMs)面临独特的挑战：

#### 1.1.1 计算复杂度

- **时空维度爆炸**: 视频包含T个时间帧，每帧H×W个空间token
- **总token数**: T × H × W，随着帧数线性增长
- **注意力复杂度**: O((T×H×W)²)，二次方增长

#### 1.1.2 时序冗余

视频中的时序冗余体现在：

1. **静态场景**: 连续帧中大量背景或静态物体重复
2. **缓慢运动**: 物体运动平滑，相邻帧高度相似
3. **重复模式**: 周期性动作或场景变化

### 1.2 现有Token修剪方法

#### 1.2.1 ViT内部修剪

**代表方法**:
- DynamicViT (Rao et al., 2021)
- EViT (Liang et al., 2022)
- A-ViT (Yin et al., 2022)

**特点**:
- 基于注意力分数或MLP预测进行token选择
- 主要优化单模态视觉任务
- 未考虑跨模态交互需求

**局限性**:
```
问题: 早期修剪可能丢失对语言理解重要的视觉细节
例如: "视频中第3秒出现的红色杯子" - 需要保留特定时间帧的详细token
```

#### 1.2.2 LLM内部修剪

**代表方法**:
- ToMe (Bolya et al., 2023)
- FastV (Chen et al., 2024)

**特点**:
- 在LLM层间修剪视觉token
- 常使用文本条件选择相关token

**局限性**:
```
问题1: 需要额外的文本-视觉对齐机制
问题2: ViT输出未被压缩，前向传播仍有计算开销
问题3: 复杂的条件化逻辑增加实现难度
```

### 1.3 STTS的动机

STTS旨在解决上述问题：

1. **统一修剪**: 在整个架构中统一处理token
2. **简化设计**: 无需复杂的条件化机制
3. **可训练性**: 支持端到端优化，学习任务相关的token重要性

## 二、核心算法原理

### 2.1 STTS框架概述

STTS是一个轻量级模块，插入到ViT和LLM的层间，动态评分和修剪视觉token。

#### 2.1.1 架构设计

```
输入视频: V ∈ ℝ^(T×H×W×C)
     ↓
ViT编码器 (带STTS模块)
     ↓
视觉token: {v_t^i} for t∈[1,T], i∈[1,N]
     ↓
STTS评分 → 修剪 → 打包
     ↓
压缩视觉token: {v'_k} for k∈[1,K], K << T×N
     ↓
LLM解码器 (带STTS模块)
     ↓
输出回答
```

### 2.2 时序评分 (Temporal Scoring)

#### 2.2.1 时序重要性建模

**目标**: 识别哪些时间帧对任务更重要

**方法**: 学习每个时间帧的重要性分数

```python
# 伪代码
class TemporalScorer(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.score_net = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim // 4),
            nn.ReLU(),
            nn.Linear(hidden_dim // 4, 1),
            nn.Sigmoid()
        )
    
    def forward(self, frame_tokens):
        # frame_tokens: [T, N, D]
        # 池化每帧的token
        frame_repr = frame_tokens.mean(dim=1)  # [T, D]
        # 计算时序分数
        temporal_scores = self.score_net(frame_repr)  # [T, 1]
        return temporal_scores
```

#### 2.2.2 辅助损失函数

**设计思想**: 
- 不依赖下游任务标签
- 自监督学习时序动态

**可能的辅助损失**:

1. **帧间一致性损失**:
```
L_temporal = Σ_t ||f(v_t) - f(v_{t+1})||² / (T-1)
```
- 鼓励相邻帧的相似性
- 高变化帧获得更高分数

2. **运动显著性损失**:
```
L_motion = -Σ_t |score(v_t) - score(v_{t-1})|
```
- 强调运动变化显著的帧

3. **信息熵损失**:
```
L_entropy = -Σ_t score(v_t) log(score(v_t))
```
- 避免所有帧获得相同分数

### 2.3 空间评分 (Spatial Scoring)

#### 2.3.1 空间重要性建模

**目标**: 在每个时间帧内，识别哪些空间token更重要

**方法**: 利用LLM下游任务的梯度信息

```python
# 伪代码
class SpatialScorer(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.attention_pool = nn.MultiheadAttention(
            embed_dim=hidden_dim,
            num_heads=8
        )
        self.score_proj = nn.Linear(hidden_dim, 1)
    
    def forward(self, frame_tokens, llm_hidden_state):
        # frame_tokens: [T, N, D]
        # llm_hidden_state: [L, D] (LLM的隐藏状态)
        
        # 使用LLM状态作为query
        context, _ = self.attention_pool(
            query=llm_hidden_state,
            key=frame_tokens,
            value=frame_tokens
        )
        
        # 计算空间相关性分数
        spatial_scores = self.score_proj(context)  # [T, N, 1]
        return torch.sigmoid(spatial_scores)
```

#### 2.3.2 基于梯度的学习

**原理**: 
- LLM对视觉token的梯度反映了其重要性
- 高梯度 = 对输出影响大 = 应该保留

**实现**:
```python
# 训练时的梯度流
def compute_importance_from_gradients(visual_tokens, llm_loss):
    # 计算梯度
    grads = torch.autograd.grad(
        llm_loss, 
        visual_tokens, 
        retain_graph=True
    )[0]
    
    # 梯度幅度作为重要性
    importance = grads.abs().mean(dim=-1)  # [T, N]
    return importance
```

### 2.4 统一评分与修剪

#### 2.4.1 联合时空分数

将时序和空间分数结合：

```
final_score(v_t^i) = α * temporal_score(t) + β * spatial_score(t, i)
```

其中α和β是可学习权重。

#### 2.4.2 修剪策略

**Top-K选择**:
```python
def prune_tokens(tokens, scores, keep_ratio=0.5):
    """
    tokens: [T×N, D]
    scores: [T×N]
    keep_ratio: 保留比例
    """
    num_keep = int(len(tokens) * keep_ratio)
    # 选择分数最高的token
    _, indices = torch.topk(scores, num_keep)
    pruned_tokens = tokens[indices]
    return pruned_tokens, indices
```

### 2.5 高效打包算法

#### 2.5.1 问题背景

修剪后token数量变化，需要高效打包以便批量处理。

#### 2.5.2 算法设计

**挑战**:
1. 不同样本保留的token数不同
2. 需要保持位置编码信息
3. 最大化GPU利用率

**解决方案**:

```python
def efficient_packing(batch_tokens, batch_scores, max_length):
    """
    batch_tokens: [B, T×N, D]
    batch_scores: [B, T×N]
    max_length: 打包后的最大序列长度
    """
    packed_tokens = []
    attention_masks = []
    position_ids = []
    
    for tokens, scores in zip(batch_tokens, batch_scores):
        # 修剪
        pruned, indices = prune_tokens(tokens, scores, keep_ratio=0.5)
        
        # 记录位置信息
        pos_ids = torch.arange(len(pruned))
        
        # 创建attention mask
        attn_mask = torch.ones(len(pruned))
        
        # Pad到max_length
        if len(pruned) < max_length:
            pad_length = max_length - len(pruned)
            pruned = F.pad(pruned, (0, 0, 0, pad_length))
            pos_ids = F.pad(pos_ids, (0, pad_length))
            attn_mask = F.pad(attn_mask, (0, pad_length))
        
        packed_tokens.append(pruned)
        position_ids.append(pos_ids)
        attention_masks.append(attn_mask)
    
    return (
        torch.stack(packed_tokens),
        torch.stack(attention_masks),
        torch.stack(position_ids)
    )
```

#### 2.5.3 优化策略

1. **动态批处理**: 根据实际token数调整batch size
2. **内存复用**: 预分配内存池，减少碎片
3. **并行计算**: 在GPU上并行处理多个样本

## 四、与Spatial AGI的关系

### 4.1 时空token对视频理解的影响

#### 4.1.1 空间理解

**传统方法的问题**:
- 均匀处理所有空间token
- 忽略物体和背景的重要性差异

**STTS的优势**:
1. **物体聚焦**: 保留物体区域的token，修剪背景
2. **语义对齐**: 根据文本任务调整空间注意力
3. **动态调整**: 不同任务关注不同区域

**示例**:
```
任务: "描述视频中人物的动作"
- STTS会保留人物区域的token
- 修剪静态背景（墙壁、天空等）
- 结果: 更高效且准确的动作理解
```

#### 4.1.2 时间理解

**时序建模的挑战**:
- 视频中的冗余帧
- 关键事件可能只占少数帧

**STTS的时序评分**:
1. **关键帧检测**: 自动识别重要时刻
2. **动态压缩**: 根据运动和变化调整采样
3. **长视频处理**: 高效处理长时间序列

**对Spatial AGI的启发**:
```
Spatial AGI需要:
1. 理解3D场景的时间演化
2. 跟踪物体在时空中的运动
3. 推理因果关系和时序依赖

STTS的时序token优化可以:
✓ 聚焦关键时空事件
✓ 压缩冗余的静态时段
✓ 为复杂推理保留必要信息
```

### 4.2 效率与性能的权衡

#### 4.2.1 为什么这个权衡重要？

**Spatial AGI的需求**:
1. **实时性**: 机器人需要实时感知和决策
2. **资源受限**: 嵌入式设备算力有限
3. **长时推理**: 需要处理长时间跨度的事件

**STTS的解决方案**:

| 需求 | 传统方法 | STTS |
|------|----------|------|
| 实时感知 | 延迟高(500ms) | 延迟低(190ms) |
| 资源受限 | 显存40GB | 显存15GB |
| 长时推理 | 受限于计算 | 可扩展到64+帧 |

#### 4.2.2 权衡的艺术

**0.7%的性能损失是否可接受？**

从Spatial AGI角度分析：

1. **实时系统**:
```
传统方法: 500ms延迟，61.8%准确率
         → 每秒只能处理2帧
         → 可能错过快速事件

STTS: 190ms延迟，61.4%准确率
     → 每秒可处理5帧
     → 更高时间分辨率
     → 整体系统性能可能更好
```

2. **长视频理解**:
```
传统方法: 受限于计算，只能用16帧
         → 覆盖时间短
         → 可能错过关键事件

STTS: 可用64帧，性能60.2%
     → 4倍时间覆盖
     → 更完整的时序建模
```

**结论**: 在实际应用中，效率提升带来的系统级收益远大于0.7%的性能损失

### 4.3 对视频场景理解的启发

#### 4.3.1 时空注意力的重新思考

**传统观念**:
- 所有时空位置同等重要
- 均匀采样和处理

**STTS的启发**:
1. **非均匀重要性**: 时空token的重要性分布高度不均匀
2. **任务依赖**: 重要性随任务变化
3. **动态适应**: 需要根据内容动态调整

**对Spatial AGI的应用**:

```python
# 传统的均匀时空采样
def uniform_sampling(video, num_frames):
    indices = np.linspace(0, len(video), num_frames)
    return [video[i] for i in indices]

# STTS启发的自适应采样
def adaptive_sampling(video, task, num_frames):
    # 计算时序重要性
    temporal_scores = compute_temporal_importance(video, task)
    
    # 根据重要性采样
    indices = importance_based_sampling(temporal_scores, num_frames)
    
    # 对每个选中的帧，计算空间重要性
    frames = []
    for idx in indices:
        frame = video[idx]
        spatial_scores = compute_spatial_importance(frame, task)
        important_regions = extract_important_regions(frame, spatial_scores)
        frames.append(important_regions)
    
    return frames
```

#### 4.3.2 多尺度时空建模

**启发**:
- STTS的统一修剪暗示了多尺度处理的重要性
- 不同任务需要不同时空分辨率

**Spatial AGI的层次化理解**:

```
Level 1: 快速感知 (高效率，低精度)
         - 使用高修剪率(75%)
         - 检测场景和主要物体
         - 延迟: <50ms

Level 2: 详细理解 (中等效率，中等精度)
         - 使用中等修剪率(50%)
         - 物体识别和关系推理
         - 延迟: <200ms
```

#### 5.2.1 高效打包算法

```python
class EfficientPacker:
    def __init__(self, max_tokens, padding_strategy='dynamic'):
        self.max_tokens = max_tokens
        self.padding_strategy = padding_strategy
        self.memory_pool = self.allocate_memory_pool()
    
    def pack_batch(self, batch_tokens, batch_scores):
        # 第一遍: 确定每个样本保留的token数
        keep_counts = []
        for tokens, scores in zip(batch_tokens, batch_scores):
            keep_count = int(len(tokens) * self.keep_ratio)
            keep_counts.append(keep_count)
        
        # 根据策略调整batch size
        if self.padding_strategy == 'dynamic':
            batch_size = self.compute_optimal_batch_size(keep_counts)
        
        # 第二遍: 打包和padding
        packed = []
        for i in range(min(batch_size, len(batch_tokens))):
            tokens, scores = batch_tokens[i], batch_scores[i]
            keep_count = keep_counts[i]
            
            # 修剪
            pruned = self.prune_top_k(tokens, scores, keep_count)
            
            # 从内存池分配
            packed_tensor = self.memory_pool.allocate(self.max_tokens)
            packed_tensor[:keep_count] = pruned
            packed_tensor[keep_count:] = self.pad_token
            
            packed.append(packed_tensor)
        
        return torch.stack(packed)
```

```python
def approximate_importance(visual_tokens, llm_loss):
    # 使用一阶泰勒展开近似
    # 而非精确梯度
    with torch.no_grad():
        perturbation = torch.randn_like(visual_tokens) * 0.01
        loss_perturbed = compute_loss(visual_tokens + perturbation)
        importance = (llm_loss - loss_perturbed) / 0.01
    return importance.abs()

# 优化3: 稀疏梯度更新
def sparse_gradient_update(importance, top_k_ratio=0.5):
    # 只更新top-k重要的token
    threshold = torch.quantile(importance, 1 - top_k_ratio)
    mask = importance > threshold
    return mask
```

```python
# 伪代码
def train_stts(model, dataloader, config):
    optimizer = AdamW([
        {'params': model.vit.parameters(), 'lr': config.lr_vit},
        {'params': model.llm.parameters(), 'lr': config.lr_llm},
        {'params': model.stts.parameters(), 'lr': config.lr_stts},
    ])
    
    for epoch in range(config.epochs):
        for batch in dataloader:
            videos, questions, answers = batch
            
            # 前向传播
            outputs = model(videos, questions)
            
            # 主损失 (QA任务)
            main_loss = cross_entropy(outputs, answers)
            
            # 辅助损失 (时序学习)
            temporal_loss = compute_temporal_aux_loss(
                model.stts.temporal_scores,
                videos
            )
            
            # 总损失
            total_loss = (main_loss + 
                         config.aux_weight * temporal_loss)
            
            # 反向传播
            optimizer.zero_grad()
            total_loss.backward()
            
            # STTS从LLM梯度学习空间重要性
            # (自动通过计算图)
            
            optimizer.step()
```

#### 11.2.2 从被动到主动

STTS是被动修剪，能否主动采样？

**思路**:
```python
# 主动采样
def active_sampling(scene, task, budget):
    # 根据不确定性选择视角
    viewpoints = generate_candidate_viewpoints(scene)
    uncertainties = estimate_uncertainty(viewpoints, task)
    
    # 贪婪选择
    selected = []
    for _ in range(budget):
        best_view = argmax(uncertainties)
        selected.append(best_view)
        uncertainties = update(uncertainties, best_view)
    
    return selected
```

#### 11.2.3 从单任务到多任务

STTS针对单一任务，如何处理多任务？

**挑战**:
- 不同任务需要不同token
- 任务冲突和权衡

**思路**:
```python
# 多任务STTS
class MultiTaskSTTS(nn.Module):
    def forward(self, tokens, tasks):
        # 为每个任务计算分数
        task_scores = [self.scorers[task](tokens) for task in tasks]
        
        # 聚合 (例如: max, weighted sum)
        final_scores = aggregate(task_scores, strategy='max')
        
        return prune(tokens, final_scores)
```

```python
def compute_importance(tokens, loss):
    grads = torch.autograd.grad(loss, tokens, retain_graph=True)[0]
    return grads.abs().mean(dim=-1)
```

2. **时序辅助损失**:
```python
def temporal_aux_loss(frame_scores, frames):
    # 相邻帧一致性
    consistency = F.mse_loss(frame_scores[1:], frame_scores[:-1])
    # 运动显著性
    motion = torch.abs(frame_scores[1:] - frame_scores[:-1]).mean()
    return consistency - 0.1 * motion
```

3. **高效打包**:
```python
def pack_tokens(batch_tokens, batch_scores, max_len):
    packed = []
    masks = []
    for tokens, scores in zip(batch_tokens, batch_scores):
        k = int(len(tokens) * 0.5)
        indices = torch.topk(scores, k).indices
        pruned = tokens[indices]
        
        # Pad
        pad_len = max_len - len(pruned)
        padded = F.pad(pruned, (0, 0, 0, pad_len))
        mask = torch.cat([torch.ones(k), torch.zeros(pad_len)])
        
        packed.append(padded)
        masks.append(mask)
    
    return torch.stack(packed), torch.stack(masks)
```
