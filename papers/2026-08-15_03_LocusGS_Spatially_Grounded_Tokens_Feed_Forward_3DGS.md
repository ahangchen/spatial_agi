**发表日期**: 2026-08-13  
**arXiv链接**: https://arxiv.org/abs/2608.12825

## 论文概览

LocusGS 解决 query-based 前馈 3DGS 中一个被忽视的结构性缺陷：**纯潜空间表示的 Gaussian query 缺乏空间责任感**——同一个 query 解码出的高斯散落在场景中相距遥远的区域，与场景结构对齐差。解法是给每个 query 配备显式 3D 锚点状态（中心 + 支撑半径），贯穿解码全程：引导跨视图特征聚合（anchor-to-ray 几何偏置）、query 间自注意力（锚点位置编码）、以及高斯生成（锚点中心化解码）。

### 一句话总结

> 把 DETR 的动态锚点思想从 2D 检测搬到 3D 重建：每个 Gaussian query 获得显式 (中心 μ, 半径 r) 锚点状态，逐层精化并直接参与注意力计算与高斯解码——让 query"知道自己在哪、管多大地方"。

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

**分析**:

1. **核心思想和动机**

   **Query-based 前馈 3DGS 的范式与缺陷**：
   - 前馈 3DGS 两大家族：稠密像素对齐（pixelSplat/MVSplat/DepthSplat——从图像网格特征直接回归高斯）与 query-based（TokenGS——固定数量可学习 query 聚合多视图证据解码高斯组）
   - Query-based 的优势：高斯预算与图像分辨率/视图数解耦（固定预算）
   - **但代价是空间责任感丢失**：稠密方法的 query（像素）天然锚定在图像位置（进而通过深度锚定 3D），而可学习 query 是纯潜空间嵌入——没有任何机制告诉它"你负责场景的哪块区域"

   **观察到的失败模式**（Figure 1）：TokenGS 中单个 query 解码的 64 个高斯散布整个场景，token 级空间一致性弱、与场景结构对齐差。这意味着：
   - 多视图证据聚合没有空间过滤（query 聚合了与自己"辖区"无关的证据）
   - 高斯生成没有空间约束（解码出的高斯可以出现在任何地方）
   - 冗余与冲突：不同 query 的高斯可能重叠覆盖同一区域

   **核心洞察**：这个失败源于 query 的表示方式——纯潜特征不指定 3D 位置与覆盖范围。解法不是换架构，而是**给 query 加显式空间状态**。

2. **主要技术方法**

   **(1) 显式 3D 锚点状态**：
   - 第 i 个 query 在解码器第 l 层的锚点：a_i^l = (μ_i^l, r_i^l)
   - μ ∈ R³ 是锚点中心（当前 3D 参考位置），r ∈ R⁺ 是支撑半径（管辖范围）
   - 半径参数化：r = softplus(ρ) + ε（保证正值，ρ 无约束）
   - 初始锚点参数 {μ_i^0, ρ_i^0} 可学习、跨场景共享，中心在归一化 3D 场景空间随机初始化
   - 分工：token 特征 q 编码外观/重建线索，锚点状态提供显式空间描述子

   **(2) 锚点引导的解码器**（三个注入点）：

   **注入点A——锚点感知自注意力**：
   - 从锚点中心导出位置嵌入：p_i^l = MLP(PE(μ_i^l))，PE 为正弦位置编码
   - 自注意力前注入：q̃ = q + p
   - 效果：query 之间的交互依赖当前 3D 锚点位置（相邻 query 更多交流），而非仅潜特征相似

   **注入点B——anchor-to-ray 几何偏置（核心创新）**：
   - 目标：让 query 优先聚合与其 3D 支撑区一致的多视图证据
   - 度量：锚点中心 μ 与图像 token 相机光线 ℓ_j 的最短欧氏距离 D(μ, ℓ_j)
   - 偏置：b_ij = -½·(D(μ_i, ℓ_j)/(σ₀·r_i))²，σ₀ 固定带宽
   - 注入交叉注意力 logits：α_ij = softmax_j(q̄·k_j/√d + γ·b_ij)，γ = softplus(γ̃) ≥ 0 可学习缩放
   - 效果：光线穿过锚点附近的图像 token 得分更高；半径控制偏好范围（大半径 = 宽松聚合）；内容相似性与几何一致性联合决定注意力

   **注入点C——动态锚点精化**：
   - 每层解码后，更新后的 token 特征预测残差：Δμ = f_μ(q^{l+1}), Δρ = f_ρ(q^{l+1})
   - 锚点随层深逐层适应输入场景——从"共享通用初始化"演化为"场景特定空间布局"

   **(3) 锚点中心化高斯解码**：
   - 最终高斯中心预测为精化锚点的**半径缩放局部偏移**（radius-scaled offset），而非自由回归
   - 强制每个 query 的高斯组落在锚点支撑球内——从生成端保证空间紧凑性
   - 消融显示这是最强组件：自由高斯中心 → PSNR 从 24.284 崩到 22.079（-2.2）

3. **算法流程和关键步骤**

   ```
   输入: 多视图图像 I = {I_v} + 相机位姿 P
   
   Step 1: 图像编码
   - 图像 → 多视图图像 token（记忆库）
   - 相机参数 → patch 级 Plücker 光线表示
   
   Step 2: Query 初始化（跨场景共享可学习参数）
   - N 个 query: 潜特征 q_i^0 + 锚点 (μ_i^0, r_i^0=softplus(ρ_i^0)+ε)
   - 锚点中心在归一化 3D 空间随机分布
   
   Step 3: L 层解码器循环（每层）
   a. 锚点位置嵌入注入 → 自注意力（空间感知的 query 交互）
   b. anchor-to-ray 偏置注入 → 交叉注意力（几何过滤的证据聚合）
      - 计算 D(μ_i, ℓ_j)（点到光线最短距离）
      - b_ij = -½(D/(σ₀r_i))², logits += γ·b_ij
   c. 特征更新后预测锚点残差 Δμ, Δρ → 锚点精化
   
   Step 4: 高斯解码（锚点中心化）
   - 每个 query 解码 K 个高斯: 中心 = 锚点 + 半径缩放偏移
   - 加上尺度 s、旋转 R、颜色 c、不透明度 α
   
   输出: N×K 个高斯基元（预算固定，与输入分辨率/视图数无关）
   ```

4. **输入输出**

   - **输入**: 带位姿的多视图图像（RE10K/DL3DV 设定，2-6 视图）
   - **输出**: 固定预算的 3D 高斯集合（单次前向），可实时渲染新视角
   - **监督**: 中间层锚点监督集合 S={6,12}（Table 20 表明 {6,12} 优于 {12} 单层与 {3,6,9,12} 全层——中间监督但不过密）

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

1. **如何理解和表示空间**

   LocusGS 的空间表示创新在于**查询锚定的显式空间划分**：
   - 场景空间由 N 个锚点球（中心+半径）划分管辖——这是**软性空间划分**（soft spatial partitioning），类似 Voronoi 但可重叠、可学习
   - 锚点布局是场景结构的"粗支架"（coarse spatial scaffold）——论文展示学到的锚点形成连贯空间布局，天然构成场景的抽象表示
   - 这与 Spatial AGI 的"空间分而治之"原则直接呼应：复杂 3D 场景的理解可以分解为局部区域的理解（锚点辖区）+ 区域间关系（锚点拓扑）

   **层次表示视角**：锚点层（N 个球，场景骨架）→ 高斯层（N×K 个基元，局部细节）。这种"锚点-高斯"两层结构与 Scaffold-GS 的锚点组织一脉相承，但 LocusGS 的锚点是从多视图特征前馈精化的 query 状态，而非场景特定优化产物。

2. **如何处理空间关系**

   - **query-证据关系**（anchor-to-ray）：空间关系显式编码为"锚点到光线的距离"——3D 查询点与 2D 观测射线的几何关联。这是极简且正确的空间先验：与辖区无关的观测证据被系统性抑制
   - **query-query 关系**（锚点自注意力）：相邻锚点的 query 更多交互——空间邻近性成为信息流的组织原则
   - **query-输出关系**（锚点中心化解码）：输出（高斯）被约束在输入（锚点）的支撑域内——空间责任感从输入到输出端到端贯通

3. **对Spatial AGI的启发**

   - **启发1: 潜空间表示需要显式空间锚定**。LocusGS 证明：纯潜特征的空间任务是欠约束的，加一个显式 (位置, 范围) 状态就能大幅改善。这对所有 Spatial AGI 的 token 设计成立——VLM 的视觉 token、世界模型的记忆 token、VLA 的场景 token 都可能受益于显式空间状态附加
   - **启发2: 几何偏置是免费的归纳偏置**。anchor-to-ray 偏置只用初等几何（点到线距离），零参数（除缩放 γ），却带来 +1.3~1.6 PSNR。Spatial AGI 系统中"几何正确的注意力先验"远比堆参数高效
   - **启发3: 锚点=可学习的空间分治**。N 个锚点自动学习场景的空间划分，这与 K-means/Voronoi 的区别在于端到端可微且服务下游任务——为 Spatial AGI 的场景抽象提供了新工具（锚点布局本身就是场景的低维摘要）
   - **启发4: DETR 锚点思想的 3D 迁移路线图**。DAB-DETR 的动态锚点框 → LocusGS 的动态锚点球——2D 检测的成熟设计向 3D 重建迁移的又一成功案例。后续可以预期：3D 场景图生成的锚点化、空间推理 VLM 的锚点 token

4. **可以应用的Spatial AGI场景**

   - **实时场景重建**：机器人/AR 的快速环境建模（单次前向，预算可控）
   - **场景抽象与记忆**：锚点布局作为场景的空间摘要，存入 Spatial AGI 记忆系统（与点缓存/场景图互补——锚点是"骨架"，高斯是"血肉"）
   - **VLA 的场景 token 化**：锚点化的场景 token 天然具备空间局部性，适合作为 VLA 的场景输入（替代无结构的视觉 token）
   - **主动重建**：锚点支撑半径暴露"管辖范围"，未覆盖区域提示 Next-Best-View 规划（与 DA-NBV 类方法结合）
   - **3D 场景编辑**：锚点级操作（移动/删除一个锚点球 = 编辑一个局部区域）比高斯级操作更符合语义

### Q3: 创新点和局限性

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**分析**:

1. **主要创新点**

   - **创新1: 发现并量化 query-based 3DGS 的空间涣散问题**。首次系统指出 TokenGS 类方法的 query 缺乏空间专化（Figure 1 的 token 级高斯可视化是有力证据）
   - **创新2: 锚点状态贯穿全流程**。不是简单加位置编码，而是三个注入点（自注意力/交叉注意力/解码）+ 逐层精化的完整设计
   - **创新3: anchor-to-ray 几何偏置**。点到光线距离的高斯核偏置，把多视图几何（对极/光线结构）编码进注意力——内容与几何双通道证据聚合
   - **创新4: 锚点中心化的半径缩放偏移解码**。最强消融组件（-2.2 PSNR if 移除）——输出空间约束比输入过滤更重要
   - **创新5: 效率优势**。1024 token 以 66K 高斯（GS-LRM 的一半）超过 GS-LRM 的 PSNR/SSIM——空间结构化带来表示效率

2. **主要局限性**

   - **局限1: 固定预算的刚性**。N 个 query 均匀预算无法适应场景复杂度分布——大空旷区域与小物体密集区域获得同等锚点数。真实场景需要自适应预算（密集区多锚点）
   - **局限2: 依赖位姿输入**。Plücker 光线表示需要已知相机位姿；无位姿设定（FlexSplat 等方向）未覆盖
   - **局限3: 锚点重叠/冗余未处理**。支撑球可重叠，不同 query 辖区冲突无显式消解机制（依赖训练隐式协调）
   - **局限4: 评估限于室内/地产场景**。RE10K/DL3DV 以室内场景为主；大尺度室外（街景、航拍）、动态场景、无边界场景未验证
   - **局限5: 锚点监督的细节依赖**。中间层监督集合 S 的选择（{6,12}）是超参数，不同层深的模型可能需要重新调优
   - **局限6: 无语义**。锚点布局是纯几何支架，不携带语义标签——对 Spatial AGI 的语义-几何联合理解需要外挂分割/检测

3. **与其他相关工作的对比**

   | 维度 | LocusGS | TokenGS | MVSplat/DepthSplat | GS-LRM | Scaffold-GS |
   |------|---------|---------|-------------------|--------|-------------|
   | 范式 | 锚点 query | 纯潜 query | 稠密像素对齐 | 稠密+LRM | 逐场景优化 |
   | 高斯预算 | 固定(N×K) | 固定 | 随视图数缩放 | 固定 | 场景自适应 |
   | 空间结构 | 显式锚点球 | 无 | 像素对齐隐式 | 像素对齐隐式 | 显式锚点(优化) |
   | 前馈速度 | ✅ 单次前向 | ✅ | ✅ | ✅ | ❌ 逐场景 |
   | PSNR (RE10K) | 28.89 | 28.41 | 26.39 | 28.10 | (不同设定) |
   
   **与 DAB-DETR 的关系**: 概念上最直接的先例——DAB-DETR 的动态锚点框（2D 检测）→ LocusGS 的动态锚点球（3D 重建）。差异：DAB-DETR 锚点是 4D 框参数作为 query 内容，LocusGS 锚点是独立状态 + 派生偏置/解码
   **与 Scaffold-GS 的关系**: 锚点组织高斯的思想同源，但 Scaffold-GS 锚点是场景特定优化的产物（测试时逐场景），LocusGS 是前馈网络的输出（跨场景泛化）

## 核心技术发现

- **发现1**: 纯潜 query 的空间任务是欠定的——TokenGS 的 token 级高斯散布全场景，与场景结构错位。显式 (中心, 半径) 状态是恢复空间责任感的充分条件
- **发现2**: 输出端空间约束（锚点中心化解码，-2.2 PSNR if 移除）比输入端过滤（anchor-to-ray 偏置，-1.5 if 移除）贡献更大——"强制高斯落在辖区内"比"优先聚合辖区证据"更关键
- **发现3**: 纯内容交叉注意力（去掉几何偏置）灾难性下降到 22.751（-1.53）——几何偏置不是锦上添花而是必需品，内容相似性单独不足以做多视图证据的正确聚合
- **发现4**: 半径状态独立贡献 0.64 PSNR（去掉半径仅留中心：23.640 vs 24.284）——管辖"范围"与管辖"位置"同等重要
- **发现5**: 中间监督 {6,12} 层最优，全层监督 {3,6,9,12} 反而略差——锚点精化需要"自由演化空间"，过密监督干扰
- **发现6**: 空间结构化提升表示效率：一半高斯数超过 GS-LRM——结构化组织的 66K 高斯 > 无组织的 131K

## 与Spatial AGI的关系

### 直接贡献

1. 提供"显式空间锚定 query"的完整参考设计：锚点状态设计（中心+半径+softplus）、三个注意力注入点、锚点中心化解码——可整体或部分移植
2. anchor-to-ray 偏置是"几何正确的注意力先验"模板：任何 3D query ↔ 2D 观测的注意力都可注入此类零参数几何偏置
3. 锚点布局作为场景空间摘要（N 球骨架）——为 Spatial AGI 记忆系统提供轻量场景抽象原语

### 技术启发

- VLM 空间 token 设计：视觉 patch token 无空间状态是 VLM 空间推理弱的结构性原因之一（呼应 G²VLM/SpatialStack 的几何 token 注入路线）——LocusGS 证明锚点状态 + 几何偏置的完整方案在重建任务上的收益
- 世界模型记忆组织：AlayaWorld 的点缓存是稠密几何记忆，LocusGS 锚点是稀疏结构记忆——两者可组合（锚点索引点缓存，区域级存取）
- 效率启示：空间结构化是比增加基元数量更高效的表示路径

### 应用场景

- 机器人实时环境重建与记忆构建
- AR/VR 快速场景数字化
- VLA 场景 token 化前端
- 主动重建的 NBV 规划（锚点覆盖缺口）
- 3D 场景语义编辑的锚点级接口

## 个人思考

### 最令人兴奋的发现

**"输出约束 > 输入过滤"的消融结论**。直觉上会以为"让 query 看对地方"（几何偏置过滤证据）是主要收益来源，但消融显示"让 query 生成对地方"（锚点中心化解码）才是最大贡献（-2.2 vs -1.5）。这暗示空间涣散的根源在**解码端的无约束自由度**——潜特征到高斯的映射没有空间约束时，网络会走"最平滑"的捷径（每个 query 学到场景的全局平均模式而非局部专化）。对 Spatial AGI 的普遍启示：**给输出加空间约束比给输入加空间过滤更能诱导空间专化**。

其次是**锚点布局作为免费场景摘要**。N 个锚点球自动形成的空间布局本身是有价值的表示——它是场景的低维骨架。项目页的交互查看器展示了锚点布局如何"骨架化"场景结构。这启发 Spatial AGI 记忆设计：与其存稠密点云/高斯，不如存"锚点骨架 + 按需局部细化"。

### 潜在局限

最深的局限是**均匀预算与场景复杂度的错配**。真实世界场景的空间复杂度高度非均匀（桌面小物体区 vs 空旷墙面），固定 N 个锚点意味着复杂区域欠表示、简单区域浪费预算。Scaffold-GS 的逐场景优化可以自适应，但前馈范式如何获得自适应预算是开放问题——可能的路径：级联锚点（粗锚点发现复杂区→分配子锚点）、密度感知的 token 生成（非均匀采样 query）。

另一个观察：**锚点球是各向同性的**。半径 r 是标量，支撑域是球。真实场景结构（墙面、桌面）是各向异性薄片——椭球锚点（3 轴半径）或平面锚点可能更匹配。Scaffold-GS 的高斯锚点其实是各向异性的，LocusGS 为简化选择了球，这里存在明确的改进空间。

## 方法细节补充

### Anchor-to-Ray 偏置的几何含义

D(μ, ℓ) 是 3D 锚点到相机光线的最短距离。偏置 b = -½(D/(σ₀r))² 是标准高斯核：
- D=0（光线正穿锚点）：b=0，无惩罚——该观测与辖区完全一致
- D=σ₀r（距离达带宽×半径）：b=-½，温和惩罚
- D→∞：b→-∞，强烈惩罚——观测与辖区无关

半径 r 的作用是**自适应带宽**：大锚点（宽辖区）惩罚更宽松，小锚点（窄辖区）惩罚更严格。这让简单区域（墙面一个大锚点）与复杂区域（物体群多个小锚点）的证据聚合粒度自动适配。

### 与 DETR 家族的技术对照

| 组件 | DAB-DETR (2D检测) | LocusGS (3D重建) |
|------|-------------------|------------------|
| 锚点状态 | 4D 框 (cx,cy,w,h) | 5D 球 (x,y,z,r,ρ) |
| 锚点注入 | 作为 query 内容拼接 | 位置嵌入 + 注意力偏置 + 解码参考 |
| 逐层精化 | ✅ | ✅ |
| 输出解码 | 框回归 | 半径缩放偏移高斯解码 |
| 观测几何 | 无（2D 特征直接匹配） | anchor-to-ray 光线几何偏置 |

LocusGS 的增量贡献在于：3D 设定下锚点与 2D 观测（光线）的几何关联可以显式计算（点到线距离），而 2D 检测中 query 与图像特征无此几何桥梁——3D 反而提供了更丰富的几何先验注入点。

## 总结

### 核心发现总结

LocusGS 识别并解决了 query-based 前馈 3DGS 的空间涣散问题：纯潜 query 无空间责任感导致 token 级高斯散布全场景。解法是显式 3D 锚点状态（中心+支撑半径）贯穿解码全程——锚点位置嵌入（自注意力）、anchor-to-ray 几何偏置（交叉注意力）、半径缩放偏移解码（生成端）+ 逐层精化。在 RE10K/DL3DV 上以相同预算全面超越 TokenGS（+0.5~1.6 PSNR），1024-token 版本以一半高斯数超过 GS-LRM。消融揭示输出端锚点约束（-2.2 if 移除）与几何偏置（-1.5 if 移除）是两大支柱。

### 对Spatial AGI的意义

1. **确立"显式空间锚定 token"设计范式**：潜特征 + 显式空间状态（位置/范围）的 query 设计可推广到 VLM 视觉 token、世界模型记忆 token、VLA 场景 token
2. **几何偏置作为零参数空间先验**：点到光线距离的注意力偏置是 3D-2D 注意力的正确几何先验模板
3. **锚点骨架作为轻量场景摘要**：N 球布局是场景的低维结构表示，可与点缓存（稠密）/场景图（语义）组合成层次化 Spatial AGI 记忆
4. **输出空间约束 > 输入空间过滤**的消融结论，为空间专化的诱导机制设计提供优先级指导

## 深度讨论：空间接地作为通用架构原则

### 从 LocusGS 看“接地”的三层含义

Spatial AGI 领域的 grounding（接地/落地）有三层递进含义，LocusGS 在第三层提供了新证据：

**第一层：语义接地**（语言↔视觉）——词与像素的对应，如 CLIP/SAM/GroundingDINO 做的事

**第二层：几何接地**（语言/特征↔3D）——语义与 3D 位置的对应，如 G²VLM 统一重建与推理、Chain of Spatial Thoughts 模态无关接地

**第三层：结构接地**（计算↔空间责任）——这是 LocusGS 开启的层面：不是“语义落在哪”，而是“每个计算单元（token/query）在空间上负责哪”。空间责任感是分布式表示的隐式结构属性，需要显式状态来诱导。

三层接地的组合才构成完整 Spatial AGI：语义接地（什么）、几何接地（哪里）、结构接地（谁负责）。LocusGS 证明了第三层的缺失是深层架构问题，且修复成本极低（5 维状态 + 零参数偏置）。

### 为什么纯潜表示必然空间涣散？——优化视角的推演

从优化角度可以论证空间涣散的必然性：

1. 初始化时 N 个 query 潜特征随机，与场景任何区域无关联偏好
2. 训练初期，每个 query 从所有图像 token 均匀聚合证据（注意力均匀）
3. 梯度下降寻找最低阻尼路径：让每个 query 学习“全局有用”的模式（如全局颜色分布）比“局部专化”更平滑
4. 一旦早期训练形成全局模式，后续训练的梯度不足以打破（局部极小）
5. 结果：所有 query 趋同于全局模式，解码的高斯无空间差异→散布

LocusGS 的锚点干预发生在第 1 步：初始化时锚点随机分布即提供了“潜在分工”的种子（锚点 A 管左上、锚点 B 管右下），几何偏置把证据聚合引导到辖区，解码约束把输出锁定在辖区——分工被强制维持并逐层精化。

这与 VLM 空间推理失败的结构性解释异曲同工：ViT patch token 无显式空间状态，空间关系只能从注意力模式中“涌现”——而涌现失败时（大部分情况）就是空间盲。G²VLM/SpatialStack 的几何 token 注入与 LocusGS 的锚点状态是同一原则在不同任务族的实例化。

### 锚点机制的潜在推广路线

**推广1：VLM 空间 token 锚点化**。多视图 VLM（如 RoboDual-VLA 类系统）的视觉 token 附加 (μ,r) 锚点，锚点来自深度估计——空间推理在锚点坐标系中进行（“锚点 A 内的杯子 vs 锚点 B 内的桌子”），替代隐式的全局注意力。

**推广2：世界模型记忆锚点化**。AlayaWorld 点缓存增加锚点索引层：N 个锚点球覆盖点缓存，记忆检索先定位锚点再取局部点——检索复杂度从 O(点数) 降到 O(锚点数+局部点)。

**推广3：多 Agent 空间分工**。多机器人系统的任务分配用锚点表达：“机器人 A 负责锚点 1-5 区域”——锚点成为空间责任的可通信、可交接协议单元。

**推广4：4D 锚点（时空管辖）**。锚点增加时间半径：“这个锚点管这块区域过去 2 秒”——动态场景中时空局部性接管（与 4D-WAM 轨迹场思想结合）。

### 批判性反思：锚点是否是最优的空间责任表示？

锚点球是简单但非唯一的选择，其他候选各有优劣：

| 表示 | 优势 | 劣势 |
|------|------|------|
| 锚点球 (LocusGS) | 简单、可微、直观 | 各向同性、预算刚性 |
| 锚点椭球 | 匹配薄片结构 | 参数多、优化难 |
| Voronoi 胞 | 无重叠、完全划分 | 不可微边界、无范围参数 |
| 密度场 (occupancy) | 连续、自适应 | 无离散结构、难检索 |
| 八叉树层级 | 多尺度、自适应 | 离散决策不可微 |

LocusGS 选择球是工程折衷。真实系统可能需要层级混合：粗球锚点 + 细椭球子锚点 + 密度场微调。这个设计空间刚刚打开。

## 附录E: 逐公式解读速查

**式(1) 半径参数化**: r = softplus(ρ) + ε
- 保证正值（半径物理意义）+ ε 数值稳定；softplus 平滑可微优于 ReLU/_exp

**式(2) 锚点位置嵌入**: q̃ = q + MLP(PE(μ))
- 3D 连续坐标 → 正弦编码（多频率）→ MLP 投影到特征维；类比 NeRF 位置编码，但服务于注意力偏置而非辐射场

**式(3) 几何偏置**: b = -½(D/(σ₀r))²
- 高斯核形式；D=点到光线最短距离；σ₀ 固定带宽、r 自适应带宽——双带宽设计让大小锚点各得其所

**式(4) 偏置注入**: α = softmax(qk/√d + γb)
- γ=softplus(γ̃)≥0 可学习门控——网络自己决定几何 vs 内容的权重（初始化若 γ≈0 则几乎无偏置，训练中逐渐打开）

**式(5) 证据聚合**: q̂ = Σαv
- 标准注意力值聚合，但 α 已被几何修正

**锚点精化**: Δμ=f_μ(q), Δρ=f_ρ(q)
- 残差更新（非直接回归）保持稳定；锚点轨迹逐层演化类似迭代的坐标回归

**高斯解码**: x = μ + r·δ
- 高斯中心 = 锚点 + 半径缩放偏移——输出空间被约束在锚点球内，这是消融中最强组件（-2.21）
