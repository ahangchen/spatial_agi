**发表日期**: 2026-10-15
**arXiv链接**: https://arxiv.org/abs/2610.21882

## 一句话总结

Anvil 提出通过"知识再循环"（knowledge recirculation）扩展具身空间智能的统一框架：Anvil-Gen 数据飞轮以 Ground-Relation-Act 三族 11 种原生输出形式生成、交叉验证并按失败反馈修复场景对齐监督（5.8M 条源接地记录、160K 图像）；Anvil-Ben 提供训练集与 held-out 场景链式评测；Anvil-MOPD 用 9B 学生模型经"语义首发错误路由 + 阶段归一化"的多教师蒸馏整合专家知识，七个公开基准平均 74.27%，超 Qwen3.5-9B 9.29 个百分点，验证后的学生再回流参与数据验证，形成数据↔模型闭环。

## 核心问题

### Q1: 这篇文章的核心算法原理是什么？

#### 1. 核心思想和动机

- **问题定义**：具身空间智能 > 视觉识别——模型必须定位实体、推理关系、并以动作相关形式表达知识（认出咖啡机 ≠ 知道杯子能放在它旁边哪）。
- **核心痛点：监督碎片化**。不同能力阶段的监督散落在互不兼容的几何/语义输出格式中（检测框、深度序、可供性、动作计划……），联合训练会把不同阶段需要的知识**混淆（conflate）**。
- **研究问题**：异构空间专家知识如何变成可靠监督，并整合进一个还能反哺数据验证的模型？
- **答案：知识再循环**——数据生产与模型学习耦合为闭环：数据飞轮生成监督 → 专家学习 → 蒸馏成通才 → 通才回流协助数据验证（但证据核验保留最终接受权）→ 更好的数据 → 更好的模型。

#### 2. 主要技术方法

**(a) Anvil-Gen：异构数据飞轮**

**三族 11 种原生输出形式（Ground–Relation–Act 接口）**：
- Ground（4 种）：box、detection、mask、point
- Relation（4 种）：depth order（深度序）、metric comparison（度量比较）、direction（方向）、relation graph（关系图）
- Act（3 种）：affordance（可供性）、gripper configuration（夹爪配置）、action plan（动作计划）

每个 contract d 规定目标空间 Y_d、必需字段、坐标系与语义评估器；任务图 G=(S, ε) 显式表达输出间依赖。

**三大机制**：
1. **Form-specific generation（形式特定生成）**：几何感知 CoT 结构约束生成，源标注与专家输出通过共享场景/实体引用对齐。
2. **Cross-stage consistency verification（跨阶段一致性验证）**：输出间依赖转为显式验证约束——例如 Ground 的框错了，Relation 的深度序就可疑；跨形式裁决（cross-form adjudication）。
3. **Failure-driven recollection（失败驱动召回）**：失败反馈引导跨源跨形式的目标性数据再生成与采集。

**(b) Anvil-Ben：场景对齐基准**

- Anvil-Train：学习用；Anvil-Eval：580K held-out 空间记录。
- 两类评测：原生输出任务（测单项能力）+ 场景链式任务（测阶段能力 vs 错误传播的区分）。
- 受控上游替换（把上游 Ground 换掉看 Relation 变化）测错误传播。

**(c) Anvil-MOPD：多教师蒸馏（9B 学生）**

两个关键机制：
1. **Semantic-first-fault routing（语义首发错误路由）**：在学生 rollout 上，同时选择"哪个专家教师"与"修正哪个响应区间"——瞄准学生**最早的决定性错误**（语义引用能暴露结构检查漏掉的"格式正确但几何错误"）。
2. **Stage normalization（阶段归一化）**：不同原生输出的长度差异巨大（一个框 4 个数 vs 一份动作计划几百 token），归一化损失尺度以平衡异构输出的监督。

**知识再循环闭环**：验证通过的记录可刷新专家；蒸馏出的通才在证据核验的授权下协助后续验证。

#### 3. 算法流程

```
源数据（网页图像/重建场景/仿真环境, RGB-D, 几何）
  → Anvil-Gen: 形式特定生成(11种contract) 
      → 跨阶段一致性验证(几何规则CPU检查 + 跨形式裁决)
      → 失败定位 → 命名反馈修复(模型调用)
  → Anvil-Ben: Anvil-Train(5.22M) + Anvil-Eval(580K held-out)
  → 各形式专家训练 → 多教师蒸馏(语义首发错误路由+阶段归一化)
  → Anvil-MOPD 通才(9B)
  → 通才回流: 协助数据验证(证据核验保留接受权)
  → 循环
```

#### 4. 输入输出

- **Anvil-Gen 输入**：RGB 图像/RGB-D 帧 + 实体清单 E + 指令 x；输出：11 种原生形式的接地记录（源溯源 source-grounded）。
- **Anvil-MOPD 输入**：图像 + 指令；输出：11 种形式的空间判断（定位、关系、可供性、动作计划）。
- **规模**：5.8M 记录 / 160K 图像；580K 评测 + 5.22M 训练。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

- **空间知识的原子分类学**：Ground（实体在哪）→ Relation（实体间几何/语义关系）→ Act（能对实体做什么）三族分解——这是对"空间理解"的工程化拆解，每个能力都有原生输出格式与评估器。
- **场景对齐（scene-aligned）作为空间表示的组织原则**：同一场景的所有标注通过共享实体引用与显式依赖链接——空间知识不是孤立的 QA 对，而是场景内相互勾稽的记录网。
- **源接地（source-grounded）**：每条记录可溯源到源证据（深度、实例几何），空间判断不接受无出处的断言。

#### 2. 如何处理空间关系

- **跨阶段依赖显式化**：Relation 依赖 Ground 的框，Act 依赖 Relation 的判断——错误沿任务图传播。Anvil 用链式任务与受控上游替换量化这种传播（上游 box 换掉 → Relation 专家掉 10.64 点）。
- **空间组合能力**：单独学会的 Ground 和 Relation 不会自动组合（atomic mixture 只有 44.68% 严格成功，修复语法后仍远低于链式监督的 69.86%）——空间组合必须显式训练依赖。
- **状态条件计划验证**：动作计划的有效性判断依赖场景状态（Observation 8：动作规则支持 state-conditioned plan verification）——空间关系最终服务于"什么计划在当前场景可行"。

#### 3. 对 Spatial AGI 的启发

1. **空间智能 = 数据工程问题**：Anvil 的核心贡献不在模型（9B 常规蒸馏），而在"异构专家知识 → 可靠监督 → 通才"的数据流水线。这与 Holi-World 的 Foundry、W0 的 Xp-Data 共同宣告：Spatial AGI 的主战场是监督工程。
2. **统一接口是整合异构知识的前提**：Ground-Relation-Act 共享实体与显式依赖，类似 W0 的统一运动学接口——接口先行，能力随后。
3. **链式监督对抗错误传播**：独立正确的阶段输出不会自动组合成功（44.68% vs 69.86%）——Spatial AGI 训练必须包含"下游消费上游输出"的链式样本。
4. **蒸馏的选择性**：教师监督只该落在学生最早的决定性错误上（语义首发错误路由 +2.13 点），flat distillation 既浪费又引入教师错误——"选择性纠错 > 全面灌输"。
5. **命名反馈的修复杠杆**：失败类别命名使修复产出 ×10.09——错误信息的粒度决定修复效率，空间数据引擎的验证器应当输出结构化失败类型。
6. **数据↔模型双向闭环**：通才回流验证、证据核验保留仲裁权——模型参与数据生产但不拥有最终决定权，这是防止模型自我强化的制度设计。

#### 4. 可以应用的 Spatial AGI 场景

- **机器人操作前置推理**：可供性 + 夹爪配置 + 动作计划验证，直接服务操作规划。
- **空间数据引擎**：Anvil-Gen 的 11-contract 飞轮可为任何空间 VLM 生产训练数据。
- **能力诊断**：Anvil-Ben 的链式任务能区分"能力缺失"与"错误传播"——模型改进的精确指南针。
- **专家 → 通才的空间知识整合范式**：可推广到深度估计、导航、操作等专家群。

### Q3: 基于前面的分析，这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

1. **知识再循环框架**：首次把空间数据生产、专家训练、多教师蒸馏、通才回流验证串成显式闭环，并给出受控实验证据。
2. **Ground-Relation-Act 11-contract 统一接口**：异构空间输出形式的系统化组织，共享实体 + 显式依赖。
3. **语义首发错误路由**：多教师蒸馏中同时路由"教师选择"与"修正区间"，瞄准学生最早决定性错误（+2.13 点严格成功率）。
4. **阶段归一化**：解决异构输出长度导致的损失尺度失衡——多形式蒸馏的技术必需品。
5. **命名反馈修复**：失败类别命名 → 修复产出 ×10.09（39.38 vs 3.98 条正确记录/GPU 时）。
6. **错误传播的受控测量**：链式任务 + 语法修复对照（69.86% vs 44.68%）+ 上游替换（-10.64 点）——空间组合失败被分解为"语法缺失"与"内容依赖"两部分。
7. **CPU 优先的验证经济学**：598,891 条记录重检 13.26 秒（纯 CPU 规则检查），模型调用只留给未解决的语义错误——按证据可得性分配算力。

#### 2. 主要局限性

1. **RefSpatial 回归**：7 基准中有一个退化——异构监督的覆盖不完全无代价，能力间存在干扰。
2. **Grounding 修复难**：命名反馈的修复收益集中在深度序（Relation），Grounding 仍难修复——最底层感知错误的纠错机制缺位。
3. **模拟器/重建域偏差**：5.8M 记录的源构成（网页/重建/仿真）比例与域覆盖未详述，开放世界泛化存疑（论文附录 G 自己承认"from predefined interfaces to open-world spatial supervision"是未来工作）。
4. **预设接口的天花板**：11 种 contract 覆盖不了全部空间能力（如自由文本空间推理、长时程空间记忆），新能力需新 contract + 新专家。
5. **9B 通才的组成性上限**：专家整合 ≠ 组合式空间能力涌现（论文附录 G 承认"from specialist consolidation to compositional spatial competence"待解）。
6. **交互缺失**：再循环目前限于数据验证回路，未含"通过与环境交互学习"（附录 G 第三条 future work）。

#### 3. 与其他相关工作的对比

| 方向 | 代表 | Anvil 差异 |
|------|------|-----------|
| 空间监督合成 | SpatialVLM/空间数据引擎类 | 11 形式统一接口 + 跨阶段交叉验证 + 失败驱动修复 |
| 具身基础模型 | RT 系/Octo/空间专注模型 | 专家→通才蒸馏整合，非单模型端到端 |
| 知识蒸馏 | GKD/on-policy/多教师 | 语义首发错误路由（教师+span 双路由）+ 阶段归一化 |
| 迭代自举 | STaR 类 | 再循环有证据核验仲裁权，防自我强化 |
| 数据飞轮 | Holi-World Foundry | Foundry 感知流水线（几何为主），Anvil 语义多形式（含 Act）；CPU 规则 + 模型修复的分工类似 |

- **优势**：目前最完整的"空间数据↔模型"闭环系统化；受控实验把每个机制的贡献单独量化。
- **劣势**：接口预设性、Grounding 修复短板、组成性能力未解决——作者在附录 G 的三条 future work 诚实标出了边界。

## 核心技术发现

- **发现 1**：7 公开基准平均 74.27%，超 Qwen3.5-9B 9.29 点、RynnBrain-8B 11.03 点；VABench-Point 80.67%。排除 VABench-Point 后对基座仍 +4.45 点。
- **发现 2**：指向能力的增益不是靠多次猜测——只取第一点评分，286 题公共子集上仍领先基座 34.62 点。
- **发现 3**：混合训练使 Where2Place 比 replay 高 30.25 点（两种子），但 replay 更好保住 pointing/depth——补短板须与防遗忘配对。
- **发现 3b**：语义 uniform 路由超 flat 蒸馏 2.13 点；教师监督仅达 63.00% 采样响应，但通用 VQA 保持 99.83%——选择性纠错几乎零遗忘代价。
- **发现 4**：命名反馈修复的源正确记录是 generic retry 的 10.09×（归一化 GPU 时后 9.90×：39.38 vs 3.98 条/时）；修复集中在深度序，grounding 难修。
- **发现 5**：9,608 帧 RGB-D → 8 个 CPU worker 325 秒构建 2,463 条链式记录（无生成式标注）；598,891 条存储记录重检 13.26 秒——源几何让监督构建与结构检查近乎免费。
- **发现 6**：链式监督 69.86% vs 原子混合 44.68%（修复语法后）——空间组合能力必须显式训练依赖，语法修复只能追回部分差距。
- **发现 7**：空白图像使 grounding 从 57.35% 崩到 7.66%、BLINK-depth 接近随机；上游 box 替换使 Relation 专家掉 10.64 点——预测真正依赖图像与上游几何，不是语言先验。
- **发现 8**：动作规则支持状态条件计划验证——包含相同动作但顺序不同的计划可被区分。

## 与Spatial AGI的关系

### 直接贡献
- 提供空间智能的"数据操作系统"：11-contract 接口 + 飞轮 + 基准 + 蒸馏配方，全部组件可复用。
- 用受控实验为空间数据工程的每个决策（补什么数据、教师往哪打、怎么修复失败）提供了量化依据。

### 技术启发
- Spatial AGI 的能力栈应显式分层（Ground/Relation/Act）并训练层间依赖——组合能力不会免费涌现。
- 验证算力分配原则：证据充分的用规则（CPU），语义未决的用模型（GPU）——这个分工模式可推广到一切数据引擎。
- 通才回流 + 证据仲裁的双权结构是"模型参与数据生产"的安全设计模板。

### 应用场景
- 机器人操作规划前置（可供性/夹爪/计划验证）、空间 VLM 训练数据生产、模型能力诊断、多专家知识整合。

## 个人思考

### 最令人兴奋的发现
- **44.68% vs 69.86% 这个对照**。它精确回答了一个长期悬而未决的问题：为什么单独训练各阶段再拼接不work？答案是双重的——25 个点是语法（可修），25 个点是内容依赖（必须链式训练）。这个分解法值得写进所有多阶段 AI 系统的调试手册。
- **10.09× 修复杠杆**同样点破了一个行业惯性：验证器输出"拒绝"是不够的，输出"失败类别名"就能放大一个数量级的修复效率。错误信息的结构化是数据引擎最便宜的升级。
- 知识再循环的制度设计（通才可参与验证、但证据核验握有仲裁权）是对"模型自我强化污染数据"风险的成熟工程回应。

### 潜在局限
- 11 种 contract 是对空间能力的先验切片，切片外的能力（空间记忆、多房间推理、动态场景）无处安放——接口的封闭性与空间智能的开放性存在根本张力（作者自己列为 future work）。
- Grounding 难修复是隐忧：底层感知错误如果无法高效修复，飞轮对最关键能力的自我改进会卡壳。
- RefSpatial 回归提示"异构监督的干扰"未被完全驯服——阶段归一化平衡了损失尺度，但没平衡能力间的梯度冲突。

### 与今日研究的关联
- **与 Holi-World（今日 02）**：两个数据飞轮的分工——Foundry 从几何/感知侧自动建世界记录（无语义 Act），Anvil 从语义/动作侧生成 11 形式监督（无 4D 轨迹）。合并版 = "几何接地 + 语义多形式 + 动作接地"的完整空间数据引擎。
- **与 SpatialScout（今日 03）**：SpatialScout 证明 VLM 精确空间构建极弱（IoU 3.25%@0.9），Anvil 展示了通过源接地监督可以训练出强的 pointing（VABench-Point 80.67%）——空间构建能力的数据路线存在，但 Anvil 的 grounding 是 2D 检测/框级别，3D 公制级（SpatialScout 评测的那种）仍是空白。
- **与 Ropedia W0（今日 01）**：W0 用世界模型生成 rollout 作监督来源，Anvil 用多专家蒸馏整合监督——"世界模型当老师"与"专家当老师"是空间智能监督的两种未来，可能融合（世界模型 rollout + Anvil 式交叉验证）。
- **与 Fréchet Forcing（今日 04）**：Anvil 的"语义首发错误路由"与 FF 的"失败模式诊断"共享同一哲学：先精确定位失败，再施加针对性梯度/修复——诊断驱动的训练正在成为方法论共识。

## 关键数据

- **数据规模**：5.8M 源接地记录、160K 图像；580K held-out 评测 + 5.22M 训练；11 种输出形式（4 Ground + 4 Relation + 3 Act）。
- **模型**：Anvil-MOPD 9B 学生；多教师（各形式专家）；修复模型 Qwen3.6-27B。
- **主结果**：7 公开基准平均 74.27%（+9.29 vs Qwen3.5-9B；+11.03 vs RynnBrain-8B）；VABench-Point 80.67%；Embspatial 超 Qwen3-VL-8B 3.47 点。
- **机制消融**：
  - Where2Place：混合训练 +30.25 点 vs replay。
  - 语义路由：+2.13 点严格 G-R 成功；教师监督覆盖率 63.00%；VQA 保持 99.83%。
  - 修复：命名反馈 10.09×（39.38 vs 3.98 正确记录/GPU 时）；885 候选各一次调用。
  - 效率：2,463 链式记录 325 秒（8 CPU workers）；598,891 记录重检 13.26 秒。
  - 链式 vs 原子：69.86% vs 44.68%（语法修复后）；上游替换 -10.64 点；空白图像 grounding 57.35%→7.66%。

## 总结

### 核心发现总结
Anvil 用 Ground-Relation-Act 统一接口把异构空间专家知识组织成场景对齐的可验证监督，经语义首发错误路由的多教师蒸馏整合进 9B 通才，并以知识再循环让通才回流数据验证——受控实验逐一证明了目标覆盖、选择性纠错、命名反馈修复、链式监督四个机制的独立贡献，最终在七个公开空间基准上取得平均 74.27% 的领先。

### 对Spatial AGI的意义
- 它确立了 Spatial AGI 的"数据操作系统"形态：接口标准化 → 飞轮生产 → 交叉验证 → 选择性蒸馏 → 回流闭环，每个环节有量化设计依据。
- "组合能力必须链式训练"（44.68 vs 69.86）与"错误信息粒度决定修复效率"（10.09×）两条发现对所有多阶段空间系统普适。
- 开放世界监督、组合式能力涌现、交互式学习三条 future work 恰好是 Spatial AGI 下一阶段的路线图。

## 附录 A：11-Contract 接口精读

### A.1 三族能力的依赖结构

```
Ground（实体在哪）          Relation（实体间关系）       Act（能做什么）
├─ box                     ├─ depth order              ├─ affordance
├─ detection               ├─ metric comparison        ├─ gripper configuration
├─ mask                    ├─ direction                └─ action plan
└─ point                   └─ relation graph

依赖方向: Ground → Relation → Act
（框错了深度序可疑；关系错了可供性/计划不可信）
```

每个 contract 规定：目标空间 Y_d、必需字段、坐标系、语义评估器。任务图 G=(S, ε) 把输出间依赖写成显式边——这是"交叉验证"与"链式训练"的共同基础。

### A.2 为什么"原生形式"重要

- 每种能力有其自然的输出形态（检测框就 4 个数，动作计划是结构化序列），强行统一成自由文本会丢失可验证性，强行统一成单一 token 化会丢失语义评估器。
- Anvil 保留 11 种原生形式 + 共享实体引用对齐——"形异神同"（不同的形，共享实体/场景/依赖）。
- 阶段归一化解决异构长度在损失端的失衡——这是原生形式路线的必要配套。

## 附录 C：蒸馏机制的深度解析

### C.1 语义首发错误路由（Semantic-first-fault routing）

**双路由决策**：
1. **选哪个教师**：按学生 rollout 的首发错误所属阶段/语义类别，匹配对应专家。
2. **修哪个 span**：不是整条响应重写，而是定位到最早的"决定性"错误区间——后续内容在这个错误条件下生成，修它们价值低。

**为什么"语义"优先于"结构"**：
- 结构检查（JSON 合法、坐标在界内）抓不住"格式正确但几何荒谬"的错误；
- 语义引用（实体、关系描述）能暴露这类错误——实验中 semantic-uniform 路由 +2.13 点严格 G-R 成功。

**预算含义**：教师监督只覆盖 63.00% 的采样响应——近 4 成响应根本不需要教师（学生已对），省下的预算集中在刀刃上；副产品是 VQA 通用能力保持 99.83%（没有全面重写导致的能力侵蚀）。

### C.2 阶段归一化（Stage normalization）

- 问题：box 输出 ~10 token，action plan 可达数百 token——朴素求和让长形式主导梯度。
- 解法：按阶段归一化损失尺度，使每种形式对总梯度的贡献与其重要性（而非长度）成比例。
- 这是多形式输出训练的通用必备件（类比多任务学习的不确定性加权，但这里是确定性归一）。

### C.3 与 STaR 类自举的本质区别

| | STaR 类自举 | Anvil 再循环 |
|---|------------|--------------|
| 数据来源 | 模型自己答对的题 | 多源（源几何+专家+生成）+ 交叉验证 |
| 验证 | 答案对错自检 | 跨形式勾稽 + 证据核验仲裁 |
| 风险 | 自我强化（错误共识） | 通才仅"协助"，仲裁权在证据 |
| 回流物 | 新训练样本 | 验证信号 + 修复目标 |

## 附录 D：数据飞轮的成本经济学精读

**三级算力分配策略**：

```
Tier 1  源证据直接构建（CPU, 免费级）
        RGB-D 已配准 → 深度序/度量比较/框 直接导出
        9,608 帧 → 2,463 链式记录 / 325 CPU 秒（8 workers）

Tier 2  结构规则重检（CPU, 近免费）
        解析/哈希/规则评估, 598,891 条 / 13.26 秒

Tier 3  模型修复/裁决（GPU, 昂贵, 仅限未决语义错误）
        命名反馈修复: 39.38 正确记录/GPU时
        generic retry:      3.98 正确记录/GPU时
```

**原则：算力跟着证据走**——证据充分的记录用规则构建与检查；语义未决的才请模型。这与 Holi-World Foundry 的"VLM 只当审查员"、Fréchet Forcing 的"统计锚只打分布"同属一个元原则：**把生成式模型的调用限制在其不可替代的环节**。

## 附录 O：Anvil-Ben 评测设计的展开

### O.1 两类评测任务的分工

**原生输出任务（native-output tasks）**
- 测什么：单一能力项（如 depth order 单独测）。
- 回答的问题：该阶段本身是否 competent？
- 形式：与训练 contract 一致的原生输出 + 语义评估器打分。

**场景链式任务（linked assessments）**
- 测什么：Ground→Relation 严格联合成功（框对且关系对才算对）。
- 回答的问题：阶段能力能否组合成可用的空间判断？
- 关键对照：对失败响应做"闭合 stage 标签"的语法修复（JSON 不变）——分离"格式失败"与"内容失败"。

**受控上游替换**
- 保持图像与 depth 目标不变，只替换上游 box → Relation 专家 -10.64 点。
- 回答的问题：下游是否真的消费上游？（若是，上游错误必然传播——链式训练的必要性论证）

### O.2 状态条件计划验证（Observation 8 展开）

- 构造 1,012 个计划有效性判断：包含相同动作集合、但顺序/前置条件不同的计划对。
- 动作规则（action rules）允许在不执行的情况下判定"该计划在当前场景状态是否可行"。
- 这是 Act 族从"输出动作"到"验证动作"的能力闭环——机器人在执行前自查计划的可行性，是安全性的关键前置。

## 附录 P：修复机制的细节展开

### P.1 命名反馈的信息内容

修复提示包含：**失败类别名**（如"depth order violation"）——但不包含参考坐标或排序（避免把答案喂给修复模型、保持任务真实性）。

这构成一个精妙的信息量控制：
- generic retry（零信息）：修复模型只能盲改 → 3.98 条正确/ GPU 时
- named feedback（类别级信息）：定位到失败维度 → 39.38 条正确/ GPU 时
- （隐含上限）完整 GT：信息泄露，不可用于训练数据生产

**类别级信息是"有效且不作弊"的最优信息量**——这个设计判断可推广到一切数据修复系统。

### P.2 修复收益的分布

- 修复集中在 **depth ordering**（Relation 族）——因为失败类别可清晰命名（A 在 B 前/后错了）。
- **grounding 仍难修**——定位错误缺乏同粒度的可命名类型学（"框偏了"有无数种偏法）。
- 推论：**失败类型学密度决定修复收益率**。想修什么能力，先给它建失败分类学。

## 附录 Q：Anvil 的训练配置速记（附录 C 摘要）

- 检查点角色分离：study checkpoints 仅用于对照实验，最终 checkpoint 才报告主表。

- 链接 SFT 与路由：修复数据与路由配置联动。

这套实验卫生规范（匹配预算、种子、bootstrap、角色分离）与 SpatialScout 的协议意识、FF 的 bootstrap 检验形成呼应——2026 年顶级的空间智能实验正在普遍采纳"受控实验 + 统计检验"的硬标准。
