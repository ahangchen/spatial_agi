# SplatTok: Data-Driven Compression of 3D Gaussian Splats with Scene-Level Tokens

**发表日期**: 2026-11-24
**arXiv链接**: https://arxiv.org/abs/2611.32202

---

## 一句话总结

SplatTok 提出"场景再合成编码器-解码器"范式：把整个 3D splat 编码为少量 3D 锚定潜在 token，冻结解码器从 token 合成一套全新标准高斯（不保留与输入的对应关系）；压缩 = 在解码器潜空间做短程量化感知搜索，无需训练图像即可达到逐场景优化级压缩率（比 HAC++ 小 13–60% 且 PSNR 更高，比 FCGS 小 4–6.5 倍，压缩 75–110 倍）。

## 核心问题

### Q1: 核心算法原理

#### 1. 核心思想和动机

- **问题背景**：3DGS 已成为拍摄/共享照片级 3D 场景的标准方式，但一个典型场景数百 MB 到 1 GB+——难以流式传输到头显/手机、难以按千计存储、难以像图像/视频一样分发。
- **理想压缩的四个条件**：(1) 比 original 小 1–2 个数量级且渲染几乎无损；(2) 生成快速；(3) 不需要原始训练图像（splat 常以独立文件流通，训练图像早已丢弃）；(4) 解码回标准 splat，任何 3DGS 渲染器都能显示。
- **现有方法的取舍困境**：
  - 逐场景结构化方法（Scaffold-GS/HAC/HAC++/ContextGS 等 anchor+熵模型）：压缩率最高（~100×），但需训练图像、每场景数十分钟优化、每个目标码率重训、输出非标准 splat（渲染要自带网络）；
  - 后处理方法（LightGaussian/MesonGS/KISS-GS 等）：保标准格式，但压缩率温和、常需微调；
  - 前馈编码 FCGS（+/LocoMoco）：秒级、无需图像、输出标准 splat，但逐图元编码给定高斯，压缩率限于 10–30×。
- **核心洞察（关键转变）**：一个 splat 只是场景的"一种实现"——不同图元排布可产生几乎相同的渲染。与其学习"如何编码给定图元"（FCGS）或"每场景建新表示"（HAC++），不如**学习整个场景族的分布模型**，在其中压缩：存一个"能重新合成出好场景"的紧凑描述。

#### 2. 主要技术方法

**（a）场景再合成编解码器**
- **编码器**：Transformer 跨全场景注意，把输入 splat 编码为一组紧凑的**3D 锚定潜在 token**（每个 token 汇总其区域，并带全场景上下文）。
- **解码器**：从不看输入高斯，从 token 在锚点周围**合成全新的标准高斯集合**（位置、协方差、外观等），不保留与输入图元的对应。
- **训练**：跨数千真实场景（DL3DV），**仅用渲染监督**（不监督图元重建）——训练目标就是"渲染得像"，允许解码器自由选择最优图元排布。

**（b）压缩 = 潜空间搜索（latent search）**
- 编码器输出已是较好的潜码；冻结网络、量化在环（quantization-aware），只对 token 做短程搜索即可逼近解码器可达的最优码。
- 搜索目标只需"输入 splat 从其相机渲染出的图"——无需训练图像；有训练图像时可改用其为目标。
- 这是学习图像压缩中 encode-time refinement 思想首次应用于整个 3D 场景。
- **理论分析**：搜索只改动代码 4–10%，却使对输入 splat 的保真提升约 8 dB——说明编码器残余误差主要是**摊销差距（amortization gap）**而非解码器能力极限，搜索闭合了固定解码器与容许码空间内至少 84% 的初始最优性差距。

**（c）码率控制**
- 码率由 token 精度（量化步长）与锚点密度决定——**单一训练模型服务多个目标码率**，无需按码率重训。

#### 3. 算法流程和关键步骤

```
压缩：
1. 输入标准 splat（无需训练图像）
2. 编码器 → 3D 锚定 token（紧凑）
3. 量化 + 熵编码 → 比特流
4. （可选）量化感知潜空间搜索：冻结解码器，以输入 splat 渲染图为目标精调 token
解压：
5. 解码器从 token 合成全新标准高斯 → 任意 3DGS 渲染器可渲染
```

#### 4. 输入输出

- 输入：任意标准 3DGS splat（+ 其渲染图；训练图像可选）。
- 输出：紧凑 token 比特流（75–110× 压缩）→ 解码回标准 splat。
- 泛化：DL3DV 训练的单一模型零重训压缩 35 万到数百万高斯的场景；实验覆盖 DL3DV、Mip-NeRF 360、Tanks and Temples、Deep Blending。

### Q2: 与 Spatial AGI 的关系

#### 1. 如何理解和表示空间

- 论文的哲学立场对 Spatial AGI 极有启发：**空间表示不是唯一实现，而是一个等价类**。"场景"的本质是其可渲染的视觉-几何内容，而非具体图元集合。存储/传输的应是场景的"语义坐标"（潜码），渲染器+生成模型负责实例化。
- 这与生成式 3D（ArgsWorld 等自回归 3DGS 生成）与"程序化场景表示"的思潮一致：空间从"数据"变为"代码 + 生成先验"。
- 潜在 token 锚定在 3D 位置上——空间结构保留在码本中，外观/图元细节交给解码器先验，形成"显式几何 + 生成外观"的分层表示。

#### 2. 如何处理空间关系

- 编码器跨全场景注意力使每个 token 携带其区域在全局上下文中的关系信息——空间关系被压缩进 token 间的组合结构。
- 摊销差距的分析揭示：跨场景先验能承担大部分空间细节，特定场景只需存储"偏离先验的部分"——这正是空间智能"共性先验 + 个性编码"的信息论表达。

#### 3. 对 Spatial AGI 的启发

- **空间资产分发的基础设施**：头显/手机流式加载、千级资产库、云-端协同都依赖 75–110× 压缩；SplatTok 让 3DGS 空间记忆像视频一样可分发，是 Spatial AGI"空间互联网"的编解码层。
- **"生成式解码"作为空间表示的通用范式**：世界模型生成 rollout、生成式压缩再合成场景、自回归 3D 生成——同一趋势：空间内容=潜码×强解码先验。Spatial AGI 的空间记忆可存为 token，用世界模型解码。
- 单模型多码率 + 无需图像 + 标准输出三个工程性质，使其可嵌入现有 3DGS 生态，成为空间数据管线的即插即用组件。
- 与 AnyPrune/GOLD-SLAM 组合：SLAM 在线建图（GOLD-SLAM）→ 快剪（AnyPrune）→ 深压缩分发（SplatTok）= 完整空间数据生命周期。

#### 4. 可以应用的 Spatial AGI 场景

- VR/AR 头显的 3DGS 场景流式传输。
- 大规模空间资产库（数字孪生城市、地图服务）存储降本。
- 机器人集群间的空间地图共享（带宽受限）。
- 3DGS 生成模型的输出压缩与标准化分发。

### Q3: 创新点和局限性

#### 1. 主要创新点

- **范式创新**：首个"场景再合成"编码器-解码器压缩——学场景族分布而非编码给定图元，解码合成全新标准高斯。
- **压缩=潜空间搜索**：冻结解码器 + 量化感知 token 搜索，达到逐场景优化级质量，却无需训练图像、无逐场景表示训练、单模型多码率——同时满足四个此前不可兼得的条件。
- **摊销差距分析**：证明编码器残余误差 84%+ 可被搜索闭合，为"前馈编码 + 搜索精调"范式给出机理解释。
- **实证强**：默认锚密度下 PSNR 超 HAC++ 且文件小 13–41%；粗锚下小 53–60%；无训练图像时以 4–6.5× 更小文件匹敌 FCGS；35 万→数百万高斯跨数据集泛化。

#### 2. 主要局限性

- **丢失图元对应**：解码 splat 与输入无逐图元对应，对需要编辑/跟踪特定图元的下游应用（物体级操作、语义绑定）不友好。
- **搜索耗时**：潜空间搜索虽只动 token，仍需以渲染为目标的迭代优化，比 FCGS 纯前馈慢。
- **域依赖**：解码先验来自 DL3DV 训练分布，风格差异大的场景（如工业、水下）泛化未知。
- **质量上限**：7–11 MB 场景 28 dB 左右，仍低于逐场景方法的最佳点；极端低码率下结构保真有限。

#### 3. 与相关工作的对比

- vs **HAC++/KISS-GS**（逐场景）：同尺寸 PSNR 更高、无需训练图像、秒-分钟级 vs 数十分钟、单模型 vs 每码率重训、标准输出 vs 专用渲染器。
- vs **FCGS/LocoMoco**（前馈逐图元）：压缩率 4–6.5× 更高（75–110× vs 10–30×），代价是搜索与图元对应丢失。
- vs **LightGaussian/KISS-GS**（后处理）：互补——SplatTok 可进一步压缩它们已压缩的 splat。
- **优势**：四条件兼得的首个方法。**劣势**：无对应性、依赖解码先验分布、搜索有成本。

## 核心技术发现

1. 场景等价类是真实存在的压缩空间：放弃图元对应、以渲染为监督，压缩率从 10–30× 跃升至 75–110×。
2. 编码器的主要误差是摊销差距而非解码极限：短程潜码搜索（改动 4–10%）带来约 8 dB 提升，闭合 84%+ 最优性差距。
3. 单模型多码率可行：码率由 token 精度与锚点密度连续控制。
4. 跨数量级泛化：35 万高斯训练分布可压缩数百万高斯场景。

## 个人思考

### 最令人兴奋的发现

- "渲染监督而非图元监督"这一训练选择是全文的胜负手：它把压缩问题从信号编码问题转化为生成模型问题，打开了数量级的空间。这也预示 3DGS 的"存储格式"终局可能是"少量 token + 强大的场景生成先验"。
- 摊销差距分析给了一个可复用的科学结论：前馈大模型的单次推理误差，很多不是能力边界而是摊销取舍——轻量测试时优化即可收回。这对 Spatial AGI 的"fast weights / slow inference"设计有普遍意义。

### 潜在局限

- 图元对应丢失在语义编辑、物体级空间推理（Spatial AGI 的高层任务）场景是硬伤——压缩后的场景不再是"可操作的对象集合"。未来需要"分层 token：场景级 + 物体级"的编解码。
- 解码先验的分布局限性在长尾真实场景会暴露；世界模型化的解码器（可吸收更广分布）是自然的下一步。

### 与昨日研究的关联

- 与今日 AnyPrune 形成"快剪 vs 深压"互补级联；与 ArgsWorld（昨日，自回归 3DGS 生成）共享"生成先验承载空间内容"的内核——SplatTok 的解码器本质是一个条件场景生成模型。
- 与 GOLD-SLAM 组合成完整空间数据管线：在线建图 → 剪枝 → 深压缩 → 分发 → 端侧解码渲染。
- 与 Lost on Campus 的大规模孪生环境呼应：当空间孪生以千计规模存储时，75–110× 压缩是可行性前提。

## 总结

### 核心发现总结
SplatTok 用"场景再合成 + 潜空间搜索"把 3DGS 压缩从图元编码升级为场景级生成建模，首次同时满足高压缩率、无需训练图像、免逐场景训练、标准格式输出四个条件。

### 对 Spatial AGI 的意义
它为空间记忆提供了可分发、可规模化的编码层，并示范了"生成先验承载空间内容"的表示范式——这是 Spatial AGI 空间数据基础设施的关键一环。
