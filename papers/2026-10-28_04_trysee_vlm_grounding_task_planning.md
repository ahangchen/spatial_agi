## 论文基本信息

- **任务**: 专用领域（specialized domains）的 VLM 闭环机器人任务规划
- **核心问题**: VLM 在训练数据欠代表性的领域（工业/科学场景）图像理解与 grounding 失效
- **方案**: 模块化闭环管线——VLM 推理 + 可替换领域视觉预处理模块 + 既有机器人执行栈
- **关键机制**: 规划/验证双模式循环 + 动态预处理选择（VLM 主动请求所需视觉信息）
- **评测**: 5个领域（PC组装/农业/服务/航空驾驶舱/电子废料拆解），含真实机器人 brownfield 现场测试

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

#### 1. 核心思想和动机

**问题背景**:
- VLM 在日常环境（办公室/家庭）的机器人推理与规划上表现出色，但在专用领域（工业、科学应用）挣扎——这些领域的物体、部件、组件在通用训练数据中欠代表性。
- 这些领域的数据收集与标注恰恰特别昂贵和耗时（鸡生蛋问题）。
- 即使 VLM 认出物体，其图像级输出也无法提供足够可靠的几何目标供机器人执行。

**Grounding 的三步需求**: VLM 生成有效任务计划需要：①物体与环境特征 → 任务语义的链接（语义接地）；②任务语义 → 具体运动与位姿的链接（动作接地）。通用 VLM 常在第一步就对生僻物体失败。

**核心思想**: 不微调 VLM、不替换既有机器人软件栈，而是通过"可替换的领域感知模块 + 既有运动规划组件"补偿 VLM 的物体识别与位姿生成短板。**把泛化要求从 VLM 转移到可以用小数据训练的专用视觉模型上**。

#### 2. 主要技术方法

**两大组件**:

**（一）VLM 双模式（planning mode / verification mode）**

- **规划模式输入**: 任务描述、动作工具箱（Table I：open_gripper/close_gripper/move_to(location label)/move_next_to(label & direction)/move_towards(direction)/任务特定动作如 mill()）、环境当前图像、可交互物体与兴趣点列表
- **规划模式输出**: Thought（下一步的自然语言理由）+ 工具箱动作序列 + 该序列的目标（自然语言）
- 步长划分由 VLM 自主决定，被指示每次只生成一个主要环境交互（如抓取一个物体）
- **验证模式**: 对比执行前后的图像与规划目标，先描述图像（聚焦差异），再输出 Observation（目标是否达成）
- 过去 Observations 集合构成 VLM 的记忆，附加到后续规划输入中
- **关键设计选择**: 规划与验证显式分离，各自用约束目标的独立 prompt——避免单个调用同时承担两个复杂任务
- VLM 视为黑盒：不微调、不适配任务。领域适应与推理模型选择解耦，新 VLM 可无缝接入

**（二）Vision Preprocessing Module（三函数接口）**

模块名字叫"预处理"，但实际同时是 VLM 的视觉预处理接口和机器人执行层的动作接地接口：

1. **find_objects**: 识别任务相关可交互物体，返回表达性自然语言标签 → 建立 VLM 与视觉模块的**共享词汇表**，VLM 用这些标签推理并参数化动作
2. **mask_objects**: 在输入图像上叠加指定物体的分割掩码（颜色编码），连同物体标签一起给 VLM → 视觉语义接地（VLM 可以推理物体间空间关系）
3. **generate_pose**: 给定物体标签生成机器人目标位姿 → 动作接地，让机器人真正能与环境交互

**闭环管线（ReAct 框架）**:

```
每轮迭代:
1. 拍摄工作区当前图像 → find_objects + mask_objects 预处理
2. 预处理图像 + 标签 → VLM规划模式 → Thought + 动作序列 + 目标
3. 动作序列解析为行为树（BT），叶节点调用动作工具箱
4. 执行时用新鲜图像通过 generate_pose 映射物体标签→位姿
   （降低 VLM 推理延迟期间场景变化的敏感性）
5. 执行完毕 → 新图像 + 预处理
6. 验证模式：执行前图像 + 执行后图像 + 目标 → Observation
7. Observation 追加到记忆，进入下一轮迭代
```

**动态预处理选择（Dynamic Preprocessing Selection, S）**——针对物体密集场景：

- 问题：密集环境中同时提供所有掩码会让 VLM 被海量视觉注释淹没，关注错误掩码而忽略关键信息
- 方案：初始只给未预处理图像+物体标签列表；VLM **迭代请求**它需要的预处理图像，直到有足够信息作答
- 效果：限制同时呈现的视觉注释数量，帮助验证器聚焦任务相关变化。实践中 VLM 通常只请求一张恰好包含目标提及物体的预处理图像
- BT 作为 VLM 计划与底层控制框架之间**可检查的接口**

**真实机器人实现（任务E：热计量表拆解）**:
- 硬件: UR10e + Weiss CRG 200-085 夹爪（自定义手指）+ 2×StereoLabs ZED 2i 立体相机
- 软件: ROS 2 + MoveIt 2 + ros2_ros_bt_py（BT执行）
- find_objects: YOLOv9，仅 181 个标注实例微调
- mask_objects: SAM 2 用 YOLOv9 的 bounding box 作 region proposal（分割不训练）
- generate_pose: 标定相机模型把检测特征投影到3D
- mill 动作: VLM 选择要铣掉的部件 → 视觉模块生成自定义铣削轨迹 → 机械臂夹持热计量表沿轨迹移动

#### 3. 算法流程总结

```
初始化: find_objects → 标签列表
循环 {
  规划: 图像+掩码+标签+任务+记忆+工具箱 → VLM → Thought+动作+目标
  执行: 动作→BT；执行时用新鲜图像 generate_pose 映射标签→位姿
  验证: 执行前图+执行后图 → [动态预处理选择] → VLM → Observation
  记忆更新: Observation 追加
} 直到任务完成
```

#### 4. 输入输出

- **输入**: 自然语言任务指令 + 相机图像流
- **输出**: 行为树形式的动作序列（经既有运动规划栈执行）+ 验证 Observations
- **适配成本**: 换领域只需替换感知模块（少量数据训练）+ 任务特定 BT 节点，零 VLM 微调

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

- **空间理解的分层外包**: TrySee 承认通用模型的空间理解有限，把"哪里有物体"（find_objects）、"物体在图像哪里"（mask_objects）、"物体在3D哪里"（generate_pose）分层外包给专用感知模块。Spatial AGI 不必是一个全能模型，可以是一个**能力编排系统**——这对理解 Spatial AGI 的系统形态很重要。
- **空间关系的语言-视觉双语表示**: 共享词汇表（自然语言标签）+ 颜色编码掩码的组合，让空间关系同时存在于语义空间（标签可被语言推理）和视觉空间（掩码可被视觉定位）。空间关系的表示必须同时对接语言推理和几何执行两个下游。
- **时间维度的空间更新**: "执行时用新鲜图像生成位姿"体现了一个朴素但关键的空间事实——环境在动作之间变化，空间表示必须即时刷新。TrySee 的空间理解是**逐动作刷新的在线空间**，而非一次性构建的离线地图。

#### 2. 如何处理空间关系

- **验证即空间关系核对**: 验证模式本质是"执行前后的空间状态是否发生了目标要求的变化"。空间任务规划的闭环以空间关系变化为验收标准。
- **密集场景的注意力管理**: 动态预处理选择解决的问题本质是**空间注意力的分配**——物体多的场景中，同时标注一切反而让模型迷失；按需请求相关物体的空间信息，模拟了人类视觉的聚焦机制。这对空间智能的接口设计有普遍意义：**给模型的空间信息要按需供给，而非一次灌满**。
- **动作接地的即时性**: move_to(case) 中 "case" 标签在动作开始执行那一刻才映射为位姿——空间引用的解引用（dereference）发生在动作时刻而非计划时刻，避免陈旧空间引用。

#### 3. 对Spatial AGI的启发

1. **Grounding 是空间智能的系统接口问题**: 论文把 grounding 从"模型能力"重新定义为"接口设计"（共享词汇表+掩码+位姿生成三函数）。Spatial AGI 的感知-推理-行动衔接可以用同样的显式接口模式，让各层独立演进。
2. **泛化要求的重新分配**: 把领域泛化从 VLM（大数据训练）转移到专用视觉模型（181个样本微调）——空间智能系统在数据稀缺领域的落地路径。**哪里需要泛化，就把泛化能力放在哪里**；不需要泛化的地方用专用小模型。
3. **失败模式的转变**: grounding 修复后，剩余失败转移到指令跟随与逻辑一致性（如抓取前忘开夹爪）。这提示空间智能的失败来源是分层的，修复一层就暴露下一层——系统改进应按层递进。
4. **验证分离设计**: 规划与验证用不同 prompt 分开调用，各自约束目标。与论文1的"策略+验证器分离"遥相呼应——**生成与验证的分离是空间智能系统的通用架构原则**（第三次在本日研究中出现）。
5. **零微调的部署哲学**: VLM 黑盒化使系统能够"搭便车"于 VLM 的持续进步（换新模型不改接口）。Spatial AGI 基础设施应该把快速演进的大模型层与稳定的感知/执行层解耦。

#### 4. 可以应用的Spatial AGI场景

- **工业拆解/回收**: 电子废料拆解（论文的原型场景）——brownfield 环境的机器人自动化
- **精密装配**: PC组装类任务的推广（工业装配线）
- **农业机器人**: 细粒度物种识别+按指令处理（收获/浇水/施肥）
- **航空/航天操作**: 大量交互对象的驾驶舱/航天器检查与操作
- **服务机器人**: 需要人脸识别等专用感知的服务场景
- **Spatial AGI 的"接口规范"**: find_objects/mask_objects/generate_pose 三函数可以成为空间感知-规划接口的候选标准

### Q3: 这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

1. **在线 grounding 而非外部 grounding**: 相关工作（SAYCAN、INNERMONOLOGUE、REFLECT 等）依赖外部机制执行计划；TrySee 把 grounding 内建到规划循环的视觉模块本身，且随执行持续更新。
2. **动态预处理选择（S）**: VLM 主动请求所需视觉信息的选择性感知机制，解决了密集场景"掩码过多反而有害"的问题（任务D验证准确率 +19.5pt）。这是 VLM 视觉输入的"主动视觉"设计。
3. **零 VLM 微调的领域适配**: 只需 181 个标注实例微调 YOLOv9 + SAM2 零训练分割 + 既有 ROS/MoveIt 栈。brownfield 工业环境的真实部署验证了实用性。
4. **规划/验证双模式的显式分离**: 各自独立 prompt、约束输出格式，避免任务混淆。
5. **BT 作为可检查接口**: VLM 计划解析为行为树执行，兼顾 LLM 灵活性与传统控制框架的可审查性。
6. **跨模型验证**: 用 Gemma 3 复测证明 grounding 接口的收益不依赖于特定 VLM。

#### 2. 主要局限性

1. **动作间变化假设**: 论文自述"best suited to ... environment changes primarily between actions"——动作执行过程中的环境变化（被推倒的物体、移动的人）无法处理。
2. **感知错误的敏感性未测量**: 受控研究用手动准备的感知输出隔离 grounding 效果，未测感知错误向下游传播的影响；真实部署中 YOLOv9 的检测错误率未知。
3. **规划失败的残留**: grounding 修复后 Overall Accuracy 67.3%，剩余失败是指令跟随（跳步骤）与逻辑一致性（顺序错误）——grounding 接口无法补偿推理缺陷。
4. **短视界计划的局限**: 每次 VLM 只生成一个主要交互，长任务的累积记忆管理（线性增长的 Observation 列表）可能成为瓶颈。
5. **验证的图像对比局限**: 依赖执行前后图像的可见差异，被遮挡区域的变化或相机视角变化引起的差异可能误判。
6. **任务集规模小**: 每任务11个序列，统计功效有限。

#### 3. 与其他相关工作的对比

| 系统 | 闭环 | Grounding方式 | 领域适配 | VLM微调 |
|------|------|--------------|---------|---------|
| SAYCAN | 开环 | 供性函数评分 | 需训练 | × |
| INNERMONOLOGUE | 半闭环 | VQA/人工反馈注入 | — | × |
| REFLECT | 闭环（事后反思） | 检测+CLIP场景表示 | — | × |
| BETR-XP-LLM / REPLAN | 闭环 | VLM验证批判 | — | × |
| MOKA | 开环 | mark视觉提示+点供性 | — | × |
| VLA模型 | 端到端 | 隐式 | 大规模遥操作数据 | 内建 |
| **TrySee** | **闭环（逐步规划-执行-验证）** | **在线视觉模块（标签+掩码+位姿）** | **小数据感知模块替换** | **×** |

**定位差异**: TrySee 是部署导向哲学——最大化复用既有机器人栈、最小化训练需求，以模块化换取适应性。与追求端到端能力的 VLA 路线形成鲜明对照，两者是空间智能落地光谱的两端。

**优势**: 数据效率极高（181样本）；即插即用新VLM；与既有栈兼容。
**劣势**: 推理层级高（动作原语粒度），精细操作依赖底层控制器；多模态推理延迟影响实时性；上限受 VLM 推理能力制约。

## 核心技术发现

- **发现1**: 视觉预处理模块使规划准确率从 3.6% 跃升至 83.6%（五任务平均）——**语义 grounding 是专用领域 VLM 规划的首要瓶颈**，修复它之后失败模式才转移到推理层。
- **发现2**: 自然语言描述（D）只有微弱增益（3.6→20.0%），远不及视觉掩码（V 的 83.6%）——**"文字描述生僻物体"无法替代"在图像上指出它"**。空间引用本质是视觉的、指示性的（deictic），语言描述在小细节上（如区分金发与黑发的客户）传递效率低。
- **发现3**: 密集场景（驾驶舱任务D）中同时标注所有控件反而拖累 VLM；动态选择（S）让验证准确率提升 19.5pt，且 VLM 通常一次只请求一张图——**选择性注意力可以用"按需请求"的接口机制实现**。
- **发现4**: grounding 修复后，剩余规划错误全部是高层推理问题（指令跟随、逻辑顺序），无一例是语义 grounding——清晰定位了 VLM 规划系统的两级失败结构。
- **发现5**: 验证基线约50%（二元判断的随机水平），视觉模块将其提升到 81-97%——VLM 在无辅助时对"目标是否达成"的判断接近瞎猜。
- **发现6**: 跨模型（LLaVA-OneVision → Gemma 3）趋势一致，grounding 接口收益模型无关。

### 直接贡献
提供了专用领域 VLM 空间规划的系统接口模板（find_objects / mask_objects / generate_pose）与闭环规划-验证架构，是 Spatial AGI 从"模型中心"走向"系统中心"的实例。

### 技术启发
- 空间引用的视觉指示性（掩码>文字描述）
- 按需供给的空间信息接口（动态预处理选择）
- 生成-验证分离 + 记忆式闭环
- 泛化要求的分层分配（VLM管推理泛化，小模型管感知适配）

### 应用场景
brownfield 工业自动化、专用领域机器人部署、Spatial AGI 感知-规划接口标准、失败分层诊断方法论。

## 个人思考

### 最令人兴奋的发现

**发现2（掩码远胜文字描述）**虽然直觉上不意外，但量化对比仍然震撼：文字描述 20% vs 视觉掩码 83.6%。这个结果对空间智能的接口设计有直接指导意义——** whenever 你想让模型理解"哪个是哪个"，在图上标注永远优于用文字形容**。空间引用的语言学本质是指示（deixis），"这个/那个"需要视觉锚点。

**动态预处理选择**也很精妙：它把"给模型什么信息"的决定权交还给模型本身。这与论文1的验证器（模型判断"够近没"）、论文3的智能体审查（模型决定"修不修"）共同呈现了一个模式——**让模型参与管理自己的信息流**，比设计者预设信息流更有效。

### 潜在局限

动作间变化假设是实用性的最大约束——真实环境中动作执行期间的干扰（人走动、物体倾倒）很常见。扩展方向是把感知循环加速到动作内频率（视觉伺服式），或者把 fast 底层反馈与 slow VLM 验证分层。

另一个隐忧是验证环节对"图像对可见差异"的依赖。若相机视角在执行中发生移动，前后图像的差异可能完全来自视角而非任务效果——论文未讨论视角配准。实践中可能需要固定相机或先做视角对齐。

### 与今日研究的关联

- **与论文1（PrecisionReach-GS）**: 同为电子废料拆解场景！论文1用VLA+3DGS数据生成解决"精确触及"，TrySee用VLM+模块感知解决"任务规划"——两者恰好是拆解系统的上下两层，可以组合：TrySee 规划"拆电池"，VLA 策略执行精确触及。论文1的 reach verifier 甚至可以作为 TrySee 验证模式中"触及目标"这类子目标的专用验证器。
- **与论文3（SceneAgent）**: SceneAgent 的仿真器渲染审查与 TrySee 的验证模式都是"生成-验证分离"，且都依赖视觉对比。TrySee 的动态预处理选择可以用于 SceneAgent 的 Reviewer（物体多时按需请求特写视图——论文3已经部分这么做了，8隔离视图）。

- **共享词汇表的设计**与论文3的技能库（skills）都是"语义对齐"工程：让不同模块用同一套词汇谈论空间，是空间智能系统集成的隐形基础工程。

## 总结

### 核心发现总结

TrySee 用一个三函数视觉预处理接口（找物体/标掩码/生位姿）+ 规划-验证双模式闭环 + 动态预处理选择，在不微调 VLM 的前提下把专用领域任务规划的 Overall Accuracy 从 0% 提升到 67.3%（规划 3.6%→83.6%，验证 50.2%→91.2%），并在真实 brownfield 电子废料拆解环境完成部署验证。核心洞见有三：专用领域的瓶颈是语义 grounding 而非推理能力；空间引用的视觉指示性远优于语言描述；密集场景的空间信息应按需供给。

### 对Spatial AGI的意义

TrySee 代表 Spatial AGI 的"系统集成派"路线：承认通用模型的空间理解局限，用模块化接口把专用感知、通用推理、成熟执行栈拼成一个大于部分之和的系统。它的三函数接口是感知-规划解耦的候选标准，它的失败分层诊断（grounding→推理）提供了空间智能系统迭代改进的方法论。在大模型能力快速演进的当下，这种"接口稳定、模型可换"的架构哲学对任何长期空间智能项目都有借鉴价值。

## 扩展分析：系统设计的深层逻辑

### A. 为什么"规划-验证分离"优于"一体化推理"？

单个 VLM 调用同时做规划与验证的问题：
1. **注意力竞争**: 规划要求前瞻（下一步做什么），验证要求后视（刚才发生了什么），两种认知模式在同一上下文中互相干扰。
2. **输出格式冲突**: 规划输出结构化动作序列，验证输出二元判断+描述，混合格式增加解析错误。
3. **错误级联**: 一体化调用中规划错误会直接污染验证判断（确认偏误的模型版）。

分离后的收益在数据中可见：验证准确率（91.2%）显著高于规划准确率（83.6%），说明验证任务在约束 prompt 下更容易做好。这与论文1的 VLA+验证器分离、论文3的生成-审查分离构成本日研究的第三个"分离架构"实例——**分离是空间智能系统对付复杂性的第一工具**。

### B. 共享词汇表作为系统集成的隐形基础工程

find_objects 返回"表达性自然语言标签"这个细节值得放大：整个系统的语义一致性建立在这些标签上——
- VLM 用标签参数化动作（move_to(case)）
- 感知模块用标签定位（generate_pose(case)）
- 验证用标签核对（"Battery removed?"）

如果 find_objects 返回的标签与任务指令中的词汇不一致（指令说"散热器"而感知返回" heatsink "），规划就会失败。论文通过让标签"表达性"（expressive）来缓解，但标签的领域适配（同义词、任务术语对齐）是隐含的工程工作量。**空间智能系统的语义接口标准化**是一个被低估的研究方向。

### C. 行为树作为 LLM 计划的可检查接口

选择 BT 而非直接执行 VLM 输出：
1. **可审查性**: BT 是显式控制流结构，人类工程师可以检查、修改、验证。
2. **可执行性**: ros2_ros_bt_py 直接在既有控制框架中执行。
3. **反应性**: BT 天然支持条件与循环，失败时可局部重试。
4. **边界清晰**: VLM 负责 BT 的内容（动作序列），框架负责 BT 的语义（执行/监视/恢复）。

这个模式（LLM 生成结构化中间表示 → 传统框架执行）是 LLM 与传统系统工程结合的标准姿势，比"LLM 直接发控制指令"可靠得多。

### D. 动态预处理选择的主动感知本质

形式上这是一个"信息请求循环"，认知科学上是**主动感知（active perception）**：
- 模型先看原始场景形成假设
- 请求特定视角/标注以检验假设
- 迭代直到确信

与任务D的数据对照：全量掩码 61.0% → 按需掩码 80.5%。**信息过载对 VLM 是真实的伤害**，不是"多多益善"。这给所有多模态系统一个警示：上下文里塞满视觉标注可能适得其反，信息的选择机制比信息的数量更重要。

### E. 181 个样本的领域适配经济学

YOLOv9 用 181 个标注实例微调即可支撑真实拆解任务，这个数据效率数字极具实践价值：
- 对比：VLA 模型需要数千到数万条遥操作演示
- 对比：微调 VLM 需要领域图像-文本对的大规模标注
- TrySee 路线：只需检测框标注（比演示便宜一个数量级）+ SAM2 免训练分割 + 位姿标定

**结论**: 空间智能在垂直领域的落地成本由"泛化需求的分布"决定。TrySee 把泛化需求压缩到一个小检测模型上，其他一切复用既有资产。这条经济学曲线值得每个空间智能项目在立项时算一遍。

### G. 任务C的启示：语言无法承载的视觉细节

自然语言描述让任务C规划准确率提升 36.4pt（如"blonde vs brunette"的描述），但仍远逊于视觉模块的100%。**发色、面部特征这类视觉细节用语言传递时信息损失严重**——描述者要枚举特征，理解者要重建特征，两次有损转换。视觉掩码是零损耗的直接指示。这再次确认：空间智能的接地接口应该尽量保留视觉通道，语言只做高层语义协调。

### H. 验证基线 50% 的含义

无辅助 VLM 的验证准确率约等于抛硬币。这不是 VLM "不会验证"，而是它面对"目标是否达成"这类对比判断缺乏可依赖的视觉锚点——生僻物体认不出、图像差异看不清。视觉掩码把锚点显式给出后，验证准确率跳到 81-94%。**判断能力的瓶颈往往是信息获取而非判断逻辑**——这一原则广泛适用于空间智能的评估环节设计。

## 扩展思考

### I. TrySee 与 VLA 路线的和解

论文把 VLA 列为对照路线，强调 VLA 需要大数据和特定 embodiment。但本日论文1（PrecisionReach-GS）显示 VLA 数据成本可以被 3DGS 合成大幅压缩。两条路线未来可能和解：
- **上层 TrySee 式规划**: 语言理解、任务分解、异常处理——利用 VLM 的零样本推理
- **下层 VLA 式执行**: 精确触及、精细操作——用合成数据训练的策略+验证器
- **接口**: TrySee 的 move_to(label) 在执行层展开为 VLA 的 rollout，reach verifier 作为子目标验证

分层混合可能是专用领域机器人系统的最终形态。

### J. 感知置信度接口的设想

论文 Discussion 中自己提到：自然扩展是把感知置信度暴露给同一模块接口，让不确定的检测触发额外观察或受控恢复。这会把"感知不确定性"提升为一等公民——VLM 规划时知道"这个物体识别置信度低"，可以请求更多视角或采取保守动作。空间智能系统中不确定性的端到端传播（感知置信→规划保守度→验证阈值）是可靠的具身系统的必要特征。

### K. 从"brownfield 部署"看空间智能的产业落地

论文的部署场景是 brownfield（既有工业环境改造）而非 greenfield（新建自动化环境）。这个定位很务实：绝大多数真实需求是改造存量环境。brownfield 的约束——不能重排环境、设备老旧、停机成本高——恰好检验 TrySee 的优势：零微调、复用既有栈、小数据适配。**空间智能的产业化主战场在存量改造，技术选型应以此为锚**。

## 复现要点清单

1. **规划 prompt**: 任务描述 + 动作工具箱 + 当前图像 + 物体标签列表 + 记忆（历史Observations）；指示一次只做一个主要交互
2. **验证 prompt**: 执行前后图像 + 规划目标；先描述差异再输出 Observation
3. **动态选择**: 初始只给原始图+标签；VLM 迭代请求 mask_objects 结果

5. **执行**: BT 解析 + MoveIt 2；位姿在动作开始时用新鲜图像映射
6. **评测协议**: 三级准确率（规划/验证/Overall）、每任务11序列、手动判定

## 术语表

- **Grounding**: 将语言语义链接到感知内容与动作能力的系统过程；本文分语义接地（find/mask）与动作接地（generate_pose）
- **Deixis（指示）**: 语言中依赖语境指向具体对象的用法；空间引用的视觉掩码是典型的视觉指示
- **ReAct**: Reasoning + Acting 的 LLM agent 框架，交替进行推理与行动

- **Brownfield**: 存在既有设施与约束的改造环境（工业场景常用语）
- **Short-horizon plan**: 短视界计划，只规划近期少量动作，依靠闭环逐步推进

## 扩展分析：五配置消融的完整解读

### L. 配置间关系的逻辑结构

五个配置构成一个递进的消融阶梯：
- **Baseline**: VLM 裸奔——只有图像与任务文本
- **D（Descriptions）**: 加入领域物体的文字描述
- **V（Vision）**: 加入视觉预处理（标签+掩码+位姿）
- **D+V**: 文字描述+视觉预处理
- **D+V+S**: 再加动态预处理选择

关键对比与结论：
1. **D vs V（20.0% vs 83.6%）**: 视觉指示远胜语言描述——空间接地必须走视觉通道。
2. **V vs D+V（83.6% vs 81.8%）**: 视觉模块到位后，文字描述不再有边际价值（甚至轻微干扰）。好的视觉 grounding 使语言描述冗余。
3. **D+V vs D+V+S（验证 82.0% vs 91.2%）**: 密集场景中按需请求的增量收益集中在验证环节。
4. **V 单独 vs D+V 的任务差异**: 任务B农业中 D+V（规划81.8%）低于 V（90.9%）——文字描述在已有视觉 grounding 时可能引入额外推理分支干扰。

### M. Overall Accuracy 的复合衰减

规划 83.6%、验证 91.2%，但 Overall 只有 67.3%——多步任务的复合衰减：一个任务序列包含多次规划+多次验证，任一环节出错即 Overall 失败。这提示：
- **系统级准确率随任务长度指数衰减**是闭环规划系统的通病
- 改进优先级应放在"失败恢复"而非单纯提升单步准确率：局部失败若能被检测并恢复，Overall 不会再受限于单步错误率
- TrySee 的验证机制其实已经具备恢复能力的基础（检测失败→重规划），但论文未报告恢复成功率——这是评估设计的缺口

### N. 跨模型一致性（Gemma 3）的深层含义

Gemma 3 上同样的配置阶梯趋势（Baseline 0% → V 45.5% → D+V+S 63.6%）表明：
- grounding 接口的收益不依赖特定 VLM 的内部机制
- 接口是"模型无关的能力注入层"
- 实践含义：空间智能系统可以放心地把感知-规划接口设计为稳定资产，底层 VLM 的更新换代不会破坏系统

同时也观察到 Gemma 3 的基线规划准确率（18.2%）高于 LLaVA-OneVision（0.0%）——不同 VLM 的"裸奔"能力差异大，但经过 grounding 后收敛到相近水平。**grounding 接口还是能力均衡器**：它压缩了不同模型间的差距，使系统性能更多由接口质量而非模型选择决定。

## 扩展思考：专用领域空间智能的设计准则

综合本文证据，可以提炼出专用领域空间智能系统的五条设计准则：

1. **准则一：视觉优先原则** — 空间引用与状态判断优先使用视觉指示（掩码/标注），语言描述只做高层语义协调。
2. **准则二：按需供给原则** — 视觉信息按模型需求供给，密集场景禁止一次性全量标注。
3. **准则三：生成-验证分离原则** — 规划与验证使用独立调用与约束输出，防止确认偏误。
4. **准则四：泛化再分配原则** — 把领域泛化需求从大模型转移到小数据可训练的专用感知模块。
5. **准则五：接口稳定原则** — 感知-规划-执行接口设计为长期稳定资产，底层模型可替换。

这五条准则与论文1（验证分离）、论文3（接口化技能+审查）互相印证，构成本日研究的"系统设计共识"。

## 附录：相关工作定位速查

**LLM/VLM 任务规划（开环）**: SAYCAN（技能库+供性函数）、PROGPROMPT（Python语法计划）、SAYPLAN（3D场景图遍历）——动态环境易失败。
**反应式规划**: INNERMONOLOGUE（VQA反馈注入）、ROSLLM（ROS集成）、REFLECT（分层记忆+失败反思）、BETR-XP-LLM/REPLAN（VLM验证批判）、AHA（微调失败检测）、行为树路线。
**显式视觉接地**: ConceptGraphs（3D场景图）、LISA（语言推理→分割掩码）、SoM（标记提示）、MOKA（mark+点供性）。
**VLA路线**: 直接视觉→动作，需大规模遥操作数据，绑定 embodiment。

TrySee 的差异化定位：grounding 在线由视觉模块完成（非外部机制）、闭环逐步规划-验证、领域适配靠小数据模块替换、复用既有执行栈。

## 附录：评测指标定义

- **Planning Accuracy**: 生成计划被判定正确的序列比例（独立于验证输出）
- **Verification Accuracy**: 验证决策与已知执行结果匹配的比例（仅对正确计划的序列评测）
- **Overall Accuracy**: 规划正确且所有相关验证决策都正确的序列比例

三个指标分别对应"会不会规划""会不会判断""端到端可靠"，构成完整的诊断三元组——这个指标体系本身就可以被其他空间规划系统借用。
