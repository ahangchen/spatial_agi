## 摘要要点

- 背景：LLM/LMM 让 GIS 从专家驱动的工具型分析，转向能理解意图、构建空间工作流、执行地理空间任务的半自主系统
- 现有 agentic GIS 的问题：推理、执行、评估三者的整合碎片化
- 提出 ANASSA（Autonomous Neural Agents for Spatial Systems Architecture）：
  - **11 个组件（C1-C11）× 4 层**的统一架构
  - **六步地理空间 AI 认知循环**（Geospatial AI Cognitive Loop）
  - 跨组件契约与治理机制
  - 覆盖：结构化空间推理、多智能体编排、执行反馈、权威空间验证、来源追溯（provenance）、不确定性处理、人类决策权威
- 目标：让 agentic 地理空间工作流**可追溯、可复现、可问责**
- 诚实声明：不单独声称多智能体编排/HITL/反馈环/权威数据验证是新的——贡献是"空间接地"的整合

## 核心问题

### Q1: 核心算法原理是什么？

**问题**: 这篇文章的核心算法原理是什么？（注：本文是架构规范而非算法论文，此处分析其架构设计原理）

**分析**:

#### 1. 核心思想和动机

- **现实痛点**：地理空间数据散落在互不联通的系统中（GIS 平台、卫星流、IoT 传感器、现场设备、云数据库、遗留基础设施），人类分析师被迫手工抽取、转换、路由、对账——协调开销挤占了真正做空间推理与决策支持的认知带宽。
- **文献综合诊断**：作者系统综合了 agentic GIS 框架（GeoAgentic-RAG、GeoAgent 等）、基准（GeoBenchX、GeoAgentBench）与综述，识别出五大局限：
  1. 空间推理不完整——定量分析与模糊空间谓词上输出"语法正确但语境错误"
  2. 执行鲁棒性不足——异构数据、坐标变换、拓扑约束难以全自主管理
  3. 强依赖数据质量与元数据——数据不完整环境泛化差
  4. 多模态长时程推理、记忆管理、跨模态整合受限
  5. 评估框架静态/简化，缺多模态、时序动态、长链推理的标准化协议
- **核心研究缺口**：三个维度的整合碎片化——(1) 空间接地的推理 (2) 执行感知的工作流编排 (3) 面向真实多模态场景的评估就绪
- **设计哲学**：推理、执行、评估应**协同设计**而非独立优化；从"半自主分析 agent"走向"完全接地的地理空间智能系统"
- **学术定位的诚实**：ANASSA 自认是 GeoBlockchain 协调模型从区块链协调到 AI agent 编排的演进；贡献在"空间接地的整合"而非单项技术

#### 2. 主要架构方法

**四层十一组件架构**：

- **治理与输出层（Governance and Output）**：
  - C7：治理机制——验证框架输出、治理 agent 与工作流行为
  - C10：验证输出组件
- **操作层（Operational）**：
  - C1：参与者（participants）
  - C2：行业部门（industry sectors）
  - C3：部署路径（deployment paths）
  - C4：ANASSA Orchestrator——技术性 system-of-systems 骨干
  - C6：多模态空间数据
- **认知引擎层（Cognitive Engine）**：
  - C5：六步地理空间 AI 认知循环（系统心脏）
- **基础层（Foundation）**：
  - C8：权威数据与知识基础（authoritative data and knowledge foundation）
  - C9、C11：基础关联的过程组件，作为垂直跨层流程运行（来源追溯 provenance、学习等）

**Orchestrator（C4）的内部结构**（"Layer 0" 内部基础设施层，非第五层）：

- L1：多模型语言网关（multi-model language gateway）
- L2：专业化地理空间 agent——分析、制图、遥感、工作流编排
- L3：GIS 平台与协议集成
- L4：计算、检索与模型托管基础设施

**C4 的职责**：把参与者意图分解为 agent 任务图（task graph）、排序执行、施加执行控制、监控中间状态、合成验证后的输出。

**学习机制**：每个循环后，Learning Agent 可以更新参与者偏好模型、行业参数、agent 能力、Orchestrator 协调规则——但受策略与来源控制；C7 治理规则的变更由 Learning Agent 提议但**必须人工授权**。

#### 3. 六步地理空间 AI 认知循环（C5）

| 步骤 | 名称 | 负责方 | 功能 | 人工门（HITL） |
|---|---|---|---|---|
| S1 | Sensing（感知） | 感知 agent | 接收 C6 准备的多模态空间数据 | 否 |
| S2 | Reasoning（推理） | 推理 agent | 由 C4 AI 栈驱动的结构化空间推理 | 否 |
| S3 | Planning（规划） | 规划 agent | 从 C1/C2 取上下文，构建工作流计划 | **是** |
| S4 | Decision & Hallucination Validation（决策与幻觉验证） | 验证 agent | 对 C8 权威数据验证决策；幻觉验证是更广空间验证功能的一部分（还评估空间参照、拓扑……） | **是** |
| S5 | Execution（执行） | 执行 agent | 经 C3 基础设施部署执行 | 否 |
| S6 | Learning（学习） | 学习 agent | 更新偏好/参数/能力/协调规则（受治理） | 变更需授权 |

- 每步由专属地理空间 agent 承担，由 Orchestrator 协调， grounding 在 C8 权威数据上
- 关键设计：**幻觉验证被并入 S4 的更大空间验证功能**——不只查"编造事实"，还验证空间参照正确性、拓扑一致性等空间专属的正确性维度
- 人工检查点放在 S3（计划批准）与 S4（决策批准）——即"做什么"与"是否可信"两个人类最该把关的关口

**与传统/LLM 增强工作流的对照**（Figure 1）：

- 传统 GIS：用户 → 手工查询 → 工具执行 → 结果
- LLM/LMM 增强 GIS：用户 → 提示 → LLM/LMM → 脚本 → 执行 → 结果
- Agentic GIS（ANASSA）：用户 → 意图 → 工作流 → 多智能体执行 → 反馈 → 验证后输出

#### 4. 输入输出（作为系统架构）

- **输入**：参与者自然语言意图 + 多模态空间数据（遥感影像、LiDAR、矢量、IoT 流）
- **中间产物**：agent 任务图、结构化工作流、中间验证状态、来源记录
- **输出**：经过权威验证、带来源追溯与不确定性标注的空间分析结果
- **治理属性**：全过程可追溯（traceable）、可复现（reproducible）、可问责（accountable）

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

- **空间语义 vs 文本相似度**：论文明确指出传统 RAG 靠文本相似度、无法表达拓扑、邻近性、空间依赖——空间语义是一等公民，不能被降维成文本。这是 Spatial AGI 的一个基础立场。
- **空间的权威性维度**：地理空间领域天然有"权威数据源"（official geodata）概念。ANASSA 把空间理解锚定在 C8 权威数据上——空间知识的正确性有外部基准，而非模型自证。
- **空间验证的多维性**：幻觉验证不只查事实编造，还要查空间参照（坐标系/位置）、拓扑一致性等空间专属错误类型——空间幻觉有自己的形态学。

#### 2. 如何处理空间关系

- **结构化中间表示**：引用 GeoFlow 图、概念转换等结构化工作流表示来约束推理——自然语言意图必须经过显式的空间操作图才能落到执行。
- **执行感知的编排**：工具排序、参数配置、运行时反馈适配是空间关系处理能否落地的关键（GeoAgentBench 显示性能取决于此）。
- **不确定性处理**：空间数据天然带不确定性（定位误差、比例尺、时效性），架构级的不确定性处理组件是空间关系可信推理的前提。

#### 3. 对 Spatial AGI 的启发

- **从模型到系统的视角转换**：Spatial AGI 的瓶颈可能不在单一模型能力，而在推理-执行-评估的系统整合。ANASSA 提供了最完整的架构级蓝图。
- **治理与问责是空间智能的硬需求**：空间决策影响真实世界（城市规划、应急响应、国防），可追溯/可复现/可问责不是可选项。这对更广义的 Spatial AGI 是重要提醒——能力之外还有责任架构。
- **人类权威的结构化嵌入**：HITL 不是附加品，而是放在 S3/S4 的架构级检查点。"人类决策权威"（human decision authority）被写进架构——Spatial AGI 的价值观设计样本。
- **认知循环的普适性**：S1-S6 循环（感知→推理→规划→决策验证→执行→学习）本质上是一个通用的空间智能体认知架构，GIS 只是实例化领域。
- **空间幻觉的分类学起点**：S4 把空间参照/拓扑验证与幻觉验证并列，暗示空间幻觉需要专门的理论与检测器——这是新的研究议程。

#### 4. 可以应用的 Spatial AGI 场景

1. **直接应用域**：政府空间决策支持、应急管理、国防情报、城市规划——所有需要权威数据与问责的高风险空间场景
2. **架构移植**：六步认知循环 + HITL 检查点可移植到机器人任务规划、自动驾驶决策系统
3. **空间幻觉检测**：S4 的空间验证功能可作为具身智能体输出的通用验证层
4. **多智能体空间系统设计参考**：本文的组件契约思想可用于组织导航/操作/通信多 agent 系统
5. **评估协议设计**：其"评估就绪"的架构变量定义为空间智能基准设计提供了清单

### Q3: 这个方法的主要创新点和局限性是什么？

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**分析**:

#### 1. 主要创新点

- **整合性架构规范**：首次把空间推理、执行编排、权威验证、来源追溯、不确定性、治理、人类权威放進一个有明确组件契约的统一架构。作者诚实声明单项皆非首创，首创在"空间接地的整合"——这种自我定位在同类论文中罕见地清醒。
- **六步认知循环作为可复用模式**：特别是 S4 把"决策与幻觉验证"合并为一个空间验证关卡——空间幻觉的架构级处理是新的。
- **治理作为架构支柱**：C7 与 C10 独立成层，Learning Agent 的权限被严格限定（提议治理变更但需人工授权）——学习自由与治理刚性的平衡设计。
- **评估就绪的变量定义**：为后续实现定义了必须报告的可测量架构变量，把"规范"与"实证"的衔接准备好。
- **文献综合的系统化**：对 agentic GIS 领域的框架、基准、局限做了当前最完整的梳理，本身即是参考价值。

#### 2. 主要局限性

- **无实证**：论文自己承认"Empirical performance evaluation is reserved for implementation and deployment studies"。架构未经实现检验，其组件契约是否可落地、开销多大，全部未知。
- **规范与实现的鸿沟**：十一组件、四层、六步的粒度是设计者的先验划分，实际系统中哪些组件该合并/拆分，没有实现证据支撑。
- **LLM 中心假设**：架构假定 LLM/LMM 是推理基底（"neural"的由来），对非 LLM 的空间智能路径（如本文同日的 JEPA 类模型）没有接口设计。
- **权威数据的静态性假设**：C8 权威数据本身可能过时/有误/有偏，架构把权威性当作外生给定，缺少对权威数据源的批判机制。
- **实时性未讨论**：GIS 场景中很多任务有强实时要求（应急响应），十一组件+双 HITL 检查点的延迟代价未评估。
- **泛化性存疑**：为地理空间量身定制（坐标系、权威数据、制图 agent），向室内/机器人空间智能移植时哪些组件有意义需要重新论证。

#### 3. 与其他相关工作的对比

- **vs GeoAgentic-RAG / GeoAgent**：那些是可运行的系统（85%+ 执行成功率），ANASSA 是更上位的架构规范——吸收其经验（工具排序、反馈适配的重要性）但未实现。
- **vs Spatial-Agent / GeoFlow**：结构化工作流表示的思路被吸收进 S3 规划步骤；ANASSA 的差异是加上了治理、验证、学习与评估的完整闭环。
- **vs 通用 agent 框架（AutoGen、LangGraph 等）**：通用框架提供编排机制但不理解空间；ANASSA 的组件契约是空间语义化了的（权威空间证据、拓扑验证、空间来源）。
- **vs GIScience 传统**：传统 GIS 的权威数据、元数据标准（ISO 19115 等）、空间数据基础设施（SDI）被继承为 C8；agentic 层是新增。
- **劣势总结**：对比所有上述工作，ANASSA 的独特性是"最全"，但"最全"与"最有用"之间隔着实现——它是蓝图而非建筑。

## 核心技术发现

- 发现1：agentic GIS 的瓶颈是推理-执行-评估的整合碎片化，而非单项能力不足（GeoBenchX/GeoAgentBench 的长链性能骤降佐证）
- 发现2：空间幻觉需要专门的验证形态——空间参照、拓扑一致性等维度与事实幻觉并列
- 发现3：六步认知循环中 HITL 最该放的位置是规划（做什么）与决策验证（是否可信）
- 发现4：学习能力的治理设计：Learning Agent 可以更新偏好/参数/能力/协调规则，但治理规则变更必须人工授权

## 个人思考

### 最令人兴奋的发现

S4 的设计："Decision and Hallucination Validation" 作为一个架构组件存在，且幻觉验证被泛化为空间验证——承认 LLM 空间输出需要专门的正确性关卡。这与我近期观察一致：VLM 空间推理的错误往往不是"不知道"而是"自信地错"，架构级的验证层比继续堆模型参数更对症。

另外，HITL 检查点放在 S3/S4 而非每一步，是对"人类注意力稀缺"的尊重——只在意图转译与可信性判断这两个语义鸿沟最大的地方介入。

### 潜在局限

- 没有实现的架构规范，价值高度依赖后续落地；文献中这类"蓝图论文"的引用率高但转化率低。
- 十一组件的划分有明显的设计者先验色彩（如 C1 参与者与 C2 行业部门作为组件而非属性），实现者很可能合并简化。
- 对延迟/成本只字未提，而双 HITL + 多 agent 编排的开销在真实场景中可能是决定性的。

### 与昨日研究的关联

- 昨日精读的 GeoAgent 相关基准（GeoAgentBench 思路）正是本文综合的实证来源之一——本文是对本周 "VLM 空间推理系统化" 线索的架构层回应。
- 昨日的 sensVLA 强调空间接地的动作生成；ANASSA 强调空间接地的推理编排——两者分别覆盖动作层与认知层。
- 本周连续读到空间基准（VABench、SceneBench）都在诊断 VLM 空间幻觉——ANASSA 的 S4 给出了系统级而非模型级的应对方案。

## 关键数据

- 架构规模：11 组件（C1-C11）× 4 层
- 认知循环：6 步（S1 感知 → S2 推理 → S3 规划 → S4 决策与幻觉验证 → S5 执行 → S6 学习）
- HITL 检查点：2 个（S3、S4）
- Orchestrator 内部 AI 栈：4 层（L1 语言网关 / L2 专业 agent / L3 GIS 集成 / L4 计算基础设施）
- 实证结果：无（架构规范论文）
- 引用的实证锚点：GeoAgentic-RAG 执行成功率 >85%；GeoBenchX/GeoAgentBench 显示长链任务性能显著波动

## 总结

### 核心发现总结

ANASSA 是第一份把 agentic GIS 的推理、执行、验证、治理、来源、不确定性、人类权威装进同一个组件化架构的规范。六步认知循环（感知-推理-规划-决策验证-执行-学习）配双 HITL 检查点是其核心模式；空间幻觉被架构级地并入决策验证。它诚实定位为整合性贡献，实证留白。

### 对Spatial AGI的意义

- **系统观**：Spatial AGI 不只是更强的空间模型，而是推理-执行-评估协同设计的系统——本文给出了第一张完整图纸。
- **价值观**：可追溯/可复现/可问责 + 人类决策权威，为空间智能的能力扩张划出治理边界。
- **研究议程**：空间幻觉的形态学、空间验证器的设计、认知循环的延迟-可信权衡都是被本文点名的开放问题。
- **保持的距离**：蓝图 ≠ 建筑；在其组件被实现、开销被测量之前，对它的正确态度是"参考架构"而非"解决方案"。

## 深度延伸分析

### A. 逐组件批判性审视

#### A.1 十一组件的必要性问题

逐一审视哪些组件是"架构级"的、哪些其实是"配置级"的：

| 组件 | 层 | 架构级判断 |
|---|---|---|
| C7 治理 | 治理层 | ✅ 真·架构级：横切所有组件 |
| C10 验证输出 | 治理层 | ✅ 架构级：输出把关 |
| C1 参与者 | 操作层 | ⚠️ 更像用户模型/配置 |
| C2 行业部门 | 操作层 | ⚠️ 更像领域配置/模板 |
| C3 部署路径 | 操作层 | ⚠️ 运维概念 |
| C4 Orchestrator | 操作层 | ✅ 真·架构级核心 |
| C6 多模态数据 | 操作层 | ⚠️ 数据层抽象 |
| C5 认知循环 | 认知层 | ✅ 架构级心脏 |
| C8 权威数据 | 基础层 | ✅ 架构级：外部正确性锚点 |
| C9 provenance | 基础层（跨层流） | ✅ 架构级：可追溯性支柱 |
| C11 学习流程 | 基础层（跨层流） | ✅ 架构级：进化能力 |

推测：C1/C2/C3 的组件化源自 GIS 领域的组织现实（多部门、多行业、多部署形态），在通用 Spatial AGI 中可降为配置。

#### A.2 S4 的验证形态学推演

空间幻觉至少可枚举以下类型，S4 需要对应的检测器：

1. **位置幻觉**：编造不存在的地点/错误坐标
2. **拓扑幻觉**：违反邻接/包含/连通关系（"A 河流经 B 城市但实际不经过"）
3. **度量幻觉**：距离/面积/高程的量级错误
4. **时序空间幻觉**：过时空间状态（"现在的建成区"用旧数据）
5. **投影幻觉**：坐标系混用导致的形变错误
6. **语义幻觉**：空间术语误用（"流域"与"行政区分水岭"混淆）

每类都需要不同的验证策略：权威数据比对、拓扑一致性检查、量纲分析、时效性审计等。这是一个完整的未来研究纲领。

#### A.3 认知循环的延迟预算分析

假设一个应急响应场景：卫星过境 → 分析师意图 → 输出决策支持。各步延迟量级估计：

- S1 感知（数据准备）：分钟级（受数据管线限制）
- S2 推理：秒-分钟级（LLM 推理 + 检索）
- S3 规划 + HITL：**人工延迟主导**（分钟-小时级）
- S4 验证 + HITL：**人工延迟主导**
- S5 执行：任务相关（分钟-小时）
- S6 学习：后台

结论：双 HITL 使 ANASSA 天然适合"决策支持"而非"实时控制"场景。对实时具身场景需要降级版循环（自动验证 + 事后人工审计）。

#### A.4 与具身智能认知架构的对照

| 维度 | ANASSA（GIS） | 典型具身架构（如导航 agent） |
|---|---|---|
| 循环周期 | 分钟-小时 | 毫秒-秒 |
| HITL | 架构级检查点 | 通常无（安全层替代） |
| 验证锚点 | 权威数据 | 物理反馈/仿真 |
| 空间表示 | 图层/矢量/栅格 | 占据栅格/3DGS/点云 |
| 治理需求 | 法律问责 | 安全标准 |

对照揭示：ANASSA 循环的结构普适，但检查点机制、验证锚点必须按领域重设计。

#### A.5 学习治理的设计细节

ANASSA 对学习权限的四级划分值得抄录：

1. 参与者偏好模型——可自动更新（个性化）
2. 行业参数——可自动更新（领域适配）
3. agent 能力——可自动更新（工具/技能扩展）
4. Orchestrator 协调规则——可自动更新（编排优化）
5. **治理规则（C7）——只能提议，人工授权后生效**

第 5 条是整个设计的价值锚点：系统可以学习怎么做事，但不能学习"规则是什么"。这直接回应了自主系统的对齐问题。

### B. 与空间智能文献的逐点对照

#### B.1 与本周 agentic 空间论文的对照

本周候选清单中：SpatialClaw（动作接口）、S-Agent（空间工具使用）、DriveMCP（驾驶 agent 框架）都是 ANASSA 所综合的"半自主系统"实例。ANASSA 的价值是给这些点状工作一个统一坐标系——每个系统都能在 11 组件中找到自己的位置与缺的组件。

#### B.2 与空间幻觉文献的对照

CRISP、"The Art of Interrogation"、"Consistent Yet Wrong" 等工作在模型层诊断空间幻觉；ANASSA 在架构层设置验证关卡。两者互补：模型层减轻幻觉发生率，架构层拦截残余幻觉。

#### B.3 与人机交互规范的对照

ANASSA 的 HITL 设计与高可靠性领域（航空、医疗）的 human-on-the-loop / human-in-command 光谱相容。它选择了较强的人工权威（决策批准权），这与 GIS 应用的公共性匹配；机器人领域可能选择较弱形式（监督+否决权）。

#### B.4 与空间数据基础设施（SDI）传统的对照

ANASSA 的 C8/C9 本质上是 SDI（权威数据+元数据+来源）的 agent 化重述。从 SDI 到 agentic GIS 的演进里，真正的新东西是 C4/C5——推理与编排。理解这一点可以避免把旧酒当新瓶。

### C. 批判性解读

#### C.1 强项

- 问题诊断有实证支撑（综合了 benchmark 证据而非纯思辨）
- 组件契约与评估变量的定义为后续实现提供了可操作接口
- 治理设计的严肃性在 agentic 论文中罕见

#### C.2 需要警惕的点

- 零实现零实验——所有架构声明都是未检验的设计假设
- 期刊风格（ACM 格式）+ 综合型写作，创新密度相对低，更像立场/规范论文
- "11 组件"的整齐划分有 over-engineering 嫌疑，可能反映分类学偏好而非工程必然
- LLM/LMM 基底假设使其与推理成本、幻觉率等现实约束脱钩讨论

#### C.3 实现可行性的初步评估

若要在 GIS 之外（如室内机器人任务规划）实现一个 ANASSA 精简版：

- 保留：C4 编排、C5 循环、S4 空间验证、C9 来源
- 合并：C1/C2/C3 → 配置层；C7/C10 → 治理服务
- 替换：C8 权威数据 → 实时建图（如 VGGT-GS SLAM 输出）
- 简化：双 HITL → 单 HITL（仅 S4）或事后审计

估算工程量：一个 3-5 人团队 6-12 个月可产出 MVP。

### D. 开放问题

1. S4 空间验证器的误报/漏报权衡如何量化？权威数据本身滞后时怎么办？
2. HITL 检查点在紧急场景如何降级而不破坏问责链？
3. 多个 ANASSA 实例（不同机构）之间如何互操作？治理规则冲突如何仲裁？
4. 学习代理更新 agent 能力时，如何防止能力漂移侵蚀验证器的假设？
5. 架构如何接纳非 LLM 推理基底（JEPA 类、神经符号类）？

### E. 对今日研究组合的位置

今日五篇中，ANASSA 是唯一的系统/架构层工作，恰好补全今日组合的完整栈：

- VGGT-GS SLAM：感知层（空间状态从哪来）
- JEPA-Anything：模型层（状态如何预测）
- WorldContact：数据层（经验如何生成）
- XPACE：学习层（世界与动作如何联合建模）
- **ANASSA：系统层（这一切如何被编排、验证、治理）**

## 结论性评述

ANASSA 的贡献不是新算法而是新坐标：它把 agentic 空间智能的碎片化进展钉到一个统一的架构坐标系上，并把治理、验证、人类权威确立为架构支柱而非事后补丁。六步认知循环与 S4 空间验证是两个可跨领域复用的设计模式。它最大的弱点——零实现——同时也是对读者的诚实提示：这是思考空间智能系统时的脚手架，而非可直接部署的产品。

### F. 深度思考：架构论文在领域发展中的角色

ANASSA 代表一类特殊的论文：不产新知识，而是给已有知识建立坐标系。这类论文的价值周期通常是：

1. **短期**（0-1年）：引用多、转化少——大家都需要"引用一个完整框架"来定位自己的工作
2. **中期**（1-3年）：实现者开始检验，部分组件被验证/抛弃，架构精化
3. **长期**（3年+）：少数设计模式存活（如本文的 S4 验证关卡可能存活），整体架构大概率被重新设计

给读者的预期管理：把它当"空间智能系统设计的 checklist 与词汇表"，而不是"标准答案"。

### G. S4 验证关卡的实现草案（假设我们要实现它）

```
输入：待验证的空间决策/输出 + 置信度元数据
  │
  ├─► 类型路由：位置/拓扑/度量/时序/投影/语义
  │
  ├─► 各类型验证器：
  │    位置：地理编码器反向查询权威库
  │    拓扑：空间关系代数（九交模型）一致性检查
  │    度量：量纲分析 + 数量级 sanity check
  │    时序：数据版本时间戳审计
  │    投影：坐标系元数据交叉验证
  │    语义：术语-本体一致性检查
  │
  ├─► 汇总：验证得分 + 不确定度标注 + 来源链接
  │
  └─► 分流：通过 → 输出 / 存疑 → HITL / 失败 → 返回重推理
```

其中拓扑九交模型检查与量纲分析是纯几何/逻辑工具，不依赖 LLM——验证器应该是 "确定性优先、模型辅助" 的混合体，这比全用 LLM 自查可靠得多。

### H. 对今日思考主线的贡献预设

1. "Spatial AGI 需要验证层而非只堆模型能力"的论点——与本周空间幻觉基准的诊断线呼应
2. 认知循环作为空间智能体的通用认知架构候选——为具身 agent 设计提供模板
3. 治理作为空间智能差异化需求（相比普通 AI 任务）的论据
