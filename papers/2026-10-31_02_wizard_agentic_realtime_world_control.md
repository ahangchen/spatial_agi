## 0. 一句话总结

Wizard 是一个 agentic 游戏世界模型：用显式的世界智能体维护场景几何（2.5D 深度代理）、角色骨架动画（动作库检索+重定向）和战斗规则状态，把它们编码成统一的结构化视觉代理（structured proxy）去条件化视频生成器，从而在 24 FPS 实时下实现玩家自由定制世界、零样本泛化到新场景/新角色/新动作的细粒度操控。

## 核心问题

### Q1: 核心算法原理是什么？

#### 1. 核心思想和动机

视频世界模型（键盘鼠标→画面）给交互式游戏打开了大门，但三条既有路线各有硬伤：

1. **动作条件模型**（ReactiveGWM、SCOPE 等）：玩家被限制在预定义动作集合内。
2. **提示条件模型**：只能执行训练中见过的动作/技能模式，无法跟随新指令。
3. **Agentic 框架**（WorldMind、Marionette、GameDirector、Code World Model）：把世界状态和游戏逻辑从视觉生成中解耦，用深度图/语义图/blockout/3D 包围盒等结构化代理引导视频生成——这是正确方向，但已有工作只支持简单设定（车辆驾驶、角色移动），不支持**关节化角色动作**（articulated actions），且泛化差、非实时。
4. **引擎式方法**：结构控制好，但依赖预定义场景，延迟高。

Wizard 的核心主张：**世界模型的状态管理（agent 负责）与视觉渲染（video model 负责）之间，需要一套"统一结构化视觉代理"作为接口语言**。场景用几何代理（深度+高度），角色用关节骨架，二者联合渲染成一个几何编码视频，任何用户提供的场景图和角色图都能被转成这种代理，从而获得零样本泛化。

#### 2. 主要技术方法

**（一）数据层：50.3 小时对齐 proxy-video 数据，750 场景 / 178 角色**

四个互补来源：
- **真实游戏录像**（8.8h，Elden Ring）：AAA 观感、6 个 boss 的关节化战斗（攻击、受击、特效）、11 区域探索、20+ 服装；直接从游戏进程读相机、深度、骨架，逐帧对齐。
- **程序化合成**（11.6h）：Sketchfab/Quaternius/KayKit 的 133 boss + 29 玩家资产，842 个 Poly Haven 场景资产，随机摆放 15-30 个道具、随机化颜色；专门设计 4 个鲁棒性场景：新角色入场、多角色共存、相机导致消失重现、跟拍下快速转身——迫使模型把角色绑定到"骨架+参考图"而非固定外观或屏幕位置。
- **Unreal Engine 仿真**（3.3h）：重建角色武器、脚本对手、bot 玩家，仿真状态直接出 RGB+代理，对齐精确。
- **公开数据集**（26.6h，WildWorld）：补充生物形态与运动模式多样性。

**（二）统一代理编码（unified proxy encoding）**

每帧把角色骨架与场景几何联合渲染成一个几何编码视频（沿用 Marionette 的通道编码思想）：
- R 通道 = 高度（角色 [0,0.2]，场景 [0.5,1]，天然区分）
- B 通道 = 相机前向深度（越亮越近）
- G 通道 = 角色 slot + 朝向编码（场景为 0）；同角色所有部位同值；slot 每场景动态分配并与参考图挂钩——**把外观从代码里解耦出来**，让生成器从参考图取外观，从而泛化到没见过的角色。
- 渲染时保留每像素最近表面，保持角色/场景遮挡关系。

**（三）Agentic 框架**

初始化（<5 分钟）：单目几何估计从任意用户图片构建可通行 2.5D 场景；角色参考图转 3D mesh 并自动绑骨架；通过动作库检索+重定向构建该角色的动作集。

运行时四个子代理：
1. **角色动画代理**：VLM 根据角色形态与意图动作风格，从动作库检索兼容骨架动画，重定向到目标骨架。
2. **场景操纵代理**：世界智能体编辑 3D 场景几何，OpenGL 渲染视觉代理。
3. **战斗状态代理**：显式维护血量、相对距离、朝向等状态，执行规则化战斗机制，boss 行为随战局自适应。
4. **渲染**：因果视频生成器以代理+参考图+文本为条件实时出帧。

**（四）角色感知的自适应掩码（adaptive masking）**

训练与推理时都用代理提供的角色位置构建注意力掩码：参考图 token 的注意力被限制到对应角色的图像区域。作用有二：强化参考图外观与生成区域的对齐；防止多角色时身份串扰（identity bleeding）。这是数据代理与模型注意力机制的漂亮联动——代理不只是控制信号，还提供注意力先验。

**（五）实时化**

因果适配（causal adaptation）+ 少步蒸馏，24 FPS 实时交互。

#### 3. 算法流程和关键步骤

初始化：
1. 用户给场景图+角色参考图（或语言描述）
2. 单目几何 → 可通行 2.5D 场景；角色图 → mesh → 自动 rig 骨架
3. VLM 检索动作库 → 重定向 → 该角色动作集就绪

每一交互步：
1. 玩家输入（键盘/鼠标/自由配置指令）
2. 动画代理更新骨架姿态；场景代理按相机更新几何渲染；战斗代理更新状态并决策 boss 行为
3. 联合渲染统一视觉代理（R/B/G 几何编码 + slot 编码）
4. 视频生成器以代理+参考图（自适应掩码注意力）+结构化 caption 生成下一帧，24 FPS
5. 状态回到代理层，闭环

#### 4. 输入输出

- 输入：任意场景图片 + 角色参考图/语言描述 + 玩家实时操作
- 输出：24 FPS 流式游戏画面，支持探索、召唤角色、角色变身、场景操纵、规则一致的战斗
- 副产物：显式世界状态（几何、骨架、战斗数值），天然可被其他程序消费

### Q2: 与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

Wizard 的空间观是**分层混合表示**：
- 场景层：2.5D 深度/高度代理——不追求完整 3D 重建，只保留"可通行 + 可渲染"的最小几何
- 实体层：关节骨架——空间中的活动物体以运动学结构表示
- 关系层：显式状态（距离、朝向、血量）——空间关系的语义化、可编程化

这与 Spatial AGI 追求的"单一 3D 神经场"形成有趣对照：Wizard 证明**异构分层代理比单一表示更可控**，每种表示服务一种控制需求。

#### 2. 如何处理空间关系

- 骨架投影+场景深度联合渲染，**遮挡关系在代理层面就确定了**，生成器只需"着色"不需"思考空间"
- slot 编码解决"空间中的实体身份"问题：同一空间多个角色各自锚定，参考图按 slot 检索
- 朝向编码进 G 通道：正面/背面骨架歧义被消除——空间关系的细节（谁面向谁）直接影响生成正确性

#### 3. 对 Spatial AGI 的启发

1. **"Agent 维护状态 + 生成器负责渲染"是世界模型的可编程架构**。Spatial AGI 若要有" mechanically consistent"的行为（物理规则、游戏规则），纯像素级学习不够，必须有符号化/数值化状态层。这与 Code World Model、Programmable World Model 一脉相承，Wizard 把它推到关节化动作粒度。
2. **结构化代理是控制与泛化的桥梁**。零样本泛化的来源不是生成器多强，而是代理表示足够通用（任何场景→深度代理，任何角色→骨架）。Spatial AGI 的空间表示应该优先追求"转换的普适性"而非"单一表示的表达力"。
3. **代理即注意力先验**：结构化信号不仅条件化输入，还能组织注意力（自适应掩码）。空间智能系统中，空间布局知识应该渗透到模型计算的组织方式，而不只是输入特征。
4. **动作库检索+重定向 = 空间动作的组合泛化**。新角色的动作不是端到端学的，而是"形态匹配→检索→重定向"的组合系统。这对机器人技能泛化（从动捕库到任意具身形态）是直接可借的路线。

#### 4. 可以应用的 Spatial AGI 场景

- **可定制具身仿真环境**：VLA 训练环境即时生成——扔进一张厨房照片+一只新机械手的图，得到可操控关节级交互的仿真
- **世界模型作为规划器**：agent 在 Wizard 式世界里 rollout 动作，代理层状态（距离、朝向）可直接做奖励
- **游戏/NPC 生成工业管线**：玩家驱动内容创作
- **具身多智能体模拟**：多角色共存训练场景原生支持
- **空间智能评测**：代理层提供 ground truth 状态，可精确评测生成/预测的空间一致性

### Q3: 主要创新点和局限性是什么？

#### 1. 主要创新点

1. **关节化角色动作首次进入 agentic 世界模型**：骨架代理 + 动作库检索重定向，把可控性从"移动/驾驶"推进到"任意关节动作"。
2. **统一视觉代理编码**：R/B/G 通道同时编码高度、深度、slot+朝向，一套编码统一场景与多角色，且 slot 动态绑定参考图实现外观解耦。
3. **自适应注意力掩码**：用代理中的角色位置约束参考图注意力，训练与推理一致，解决多角色身份保持——代理与注意力机制的联动设计是新颖的。
4. **大规模多源对齐数据集**：50.3h、750 场景、178 角色，四源互补，并有意设计鲁棒性场景（消失重现、快速转身）——数据工程本身的匠心值得称道。
5. **零样本泛化的实证**：新场景/新角色/新动作无需微调即可玩。

#### 2. 主要局限性

1. **2.5D 场景假设**：单目几何构建的"可通行 2.5D 环境"不支持真正的 3D 拓扑（多层建筑、悬挑、水下）；场景操纵被限制在几何编辑层面。
2. **动作依赖动作库**：所谓"新动作"仍是库内检索+重定向，真正从未见过的动作模式（全新交互类型）需要扩库；动作重定向到形态差异极大的角色（蛇形、多足）可能失真。
3. **战斗规则手工编码**：combat 状态与规则是显式程序化的，每类玩法需要人工设计代理逻辑——"mechanics consistency"的代价是可编程性而非可学习性。
4. **外观依赖参考图**：角色只在参考图视角/光照下的外观得到保证，极端视角与光照变化下的身份漂移未充分验证。
5. **域残留**：训练数据以第三人称战斗探索为主（Elden Ring 权重大），第一人称、其他玩法风格的外推未知。

#### 3. 与相关工作的对比

| 维度 | ReactiveGWM/SCOPE | Marionette/WorldMind | GameDirector | Code/Programmable WM | **Wizard** |
|---|---|---|---|---|---|
| 控制粒度 | 预定义动作 | 移动级 | 实体级状态 | 程序化状态 | **关节级动作** |
| 零样本泛化 | 弱 | 弱 | 中 | 中 | **强（场景+角色+动作）** |
| 状态一致性 | 弱 | 中 | 强 | 强 | **强** |
| 实时 | 部分 | ✗ | ✗ | ✗ | **✓ 24 FPS** |
| 数据规模 | 游戏限定 | 小 | 小 | 小 | **50.3h/750场景** |

## 核心技术发现

1. **结构化代理的质量决定世界模型可控性的上限**：深度+骨架+slot 编码的统一渲染，使生成器从"预测世界"退化为"渲染世界"，可控性接近引擎而观感接近生成模型。
2. **slot 动态绑定参考图是零样本角色泛化的关键**：代码只编"这是 2 号角色、面向北"，外观全部来自参考图——身份与编码彻底解耦。
3. **代理信号可以组织注意力**：自适应掩码把"哪里是哪个角色"的空间知识注入 cross-attention 结构，是结构化条件使用的进阶形态。
4. **数据中的"对照场景"设计**（消失重现、快速转身）是让模型学到正确绑定关系的隐式课程——数据设计即训练目标设计。

## 个人思考

### 最令人兴奋的发现

Wizard 与 L3G-World 同日出现，两者代表世界模型的两个工程方向：L3G 解决"记忆怎么不爆炸"，Wizard 解决"状态怎么可编程"。合起来看，下一代世界模型的骨架已经清晰：**符号状态层（agent/程序）+ 结构化空间代理（骨架/几何/语义）+ 神经渲染器（视频 DiT）+ 显式空间记忆（高斯场）**。Wizard 的 slot 编码与 L3G 的潜特征直通，本质上都在做同一件事——把"空间实体的身份/状态"编码成生成器可消费的最小充分信号。

### 潜在局限

最根本的局限是**代理层的人工性**：场景代理、动作库、战斗规则都是人工/程序构建的。Spatial AGI 的终极问题是这个代理层能否自我构建——从视频中自动归纳"什么实体、什么状态、什么规则"。Wizard 的数据管线（VLM 过滤、自动 rig、结构化 caption）已经展示了很多自动化要素，但玩法逻辑仍需人写。谁先把"规则归纳"自动化，谁就打开下一级台阶。

### 与昨日研究的关联

昨日精读的 WorldSimProbe 在诊断世界模型仿真器的保真度（faithfulness），Wizard 提供的显式状态层恰好是保真度可控的工程手段：规则在代理层保证正确，生成器只欠"渲染保真"一个债。昨日 SceneAgent 的 agentic real-to-sim 管线也在做"从真实构建可仿真代理"，与 Wizard 的初始化阶段（图片→几何+骨架）同构，只是方向相反（真实→仿真 vs 生成→仿真）。

## 总结

### 核心发现总结

Wizard 用"统一结构化视觉代理 + 显式世界状态 agent"把可控游戏世界模型推到关节级动作粒度和零样本泛化，24 FPS 实时。它证明世界模型的可控性来自表示设计而非模型规模：深度/骨架/slot 的代理编码让生成器只需要渲染，不需要理解。

### 对 Spatial AGI 的意义

Wizard 给出 Spatial AGI 系统的一个参考架构：符号状态层管"世界是什么、规则是什么"，结构化代理管"空间如何呈给模型"，生成器管"世界看起来如何"。三层解耦使每一层独立演进——这正是 Spatial AGI 从端到端黑箱走向可工程化系统的路径图。

## 附录 A：统一代理编码的通道设计详解

| 通道 | 语义 | 取值 | 设计动机 |
|---|---|---|---|
| R | 高度 | 角色 [0,0.2] / 场景 [0.5,1] | 单通道内按值域切分实体与背景，免分割 |
| B | 相机前向深度 | 越亮越近 | 保留每像素最近表面 → 遮挡正确 |
| G | slot + 朝向 | 角色同值；场景=0 | 身份锚定 + 消除正背面骨架歧义 |

三个通道合起来回答了空间智能的三个基本问题：**它在哪里（高度/深度）、它前面是什么（遮挡）、它是谁、朝向哪（身份/朝向）**。这个最小充分编码的设计思路可以推广为"空间条件信号的信息预算"问题：通道数是硬约束，每个通道必须承担最大辨识度。

## 附录 B：数据工程的四个鲁棒性场景（课程设计视角）

1. **新角色入场**：训练"参考图→新实体"绑定，防止模型把角色固化到训练集外观
2. **多角色共存**：训练 slot 区分，防身份串扰
3. **相机导致消失重现**：训练"实体持久性"——角色出画后再入画，身份不变。这是空间持久性（object permanence）的视觉课程！
4. **跟拍快速转身**：训练朝向-骨架一致性，防止转身后角色突变

第 3 条尤其值得 Spatial AGI 研究者注意：**物体恒存性可以通过数据场景设计直接教给视频模型**，不需要认知架构层面的假设。

## 附录 C：Agentic 框架的职责矩阵

| 子代理 | 输入 | 职责 | 输出 |
|---|---|---|---|
| 动画代理 | 角色形态、意图动作 | 检索+重定向 | 骨架姿态序列 |
| 场景代理 | 相机输入、玩家编辑 | 更新3D几何 | 场景几何 → 代理渲染 |
| 战斗代理 | 战斗状态 | 规则执行、boss决策 | 状态更新、动作指令 |
| 渲染器 | 统一代理+参考图+caption | 神经渲染 | 24 FPS 游戏画面 |

## 附录 F：深度问答

### F.1 为什么 slot 编码要每场景动态分配而不是全局角色 ID 表？

全局 ID 表要求生成器记住"ID 7 = 某个具体外观"，这直接封死零样本泛化。动态 slot（"本局 1P/2P"）+ 参考图注入，使生成器学到的是"slot n 的区域外观遵循参考图 n"这一**关系规则**而非外观查表。泛化能力来自规则的普适性——这是把生成器从"记忆"变成"执行"的关键一跳。

### F.2 2.5D 场景代理够用吗？

对第三人称地面探索+战斗，高度场+深度代理覆盖了绝大多数像素信息需求。失效场景：角色飞到高处俯视（高度场无法表达多层）、真实室内多层结构、镜面/透明物。Spatial AGI 若要用于机器人仿真（抓取、开门），2.5D 不够，需升级到 L3G 类完整 3D 记忆。2.5D 是"游戏世界"的最优解，不是"物理世界"的。

### F.3 自适应掩码的机制细节与意义

推理时代理已知每个角色的像素区域（骨架投影），把参考图 token 的 cross-attention 限制到对应区域，等价于给注意力一个硬性的空间绑定偏置。训练时同样构造，训练推理一致。意义在于：结构化条件的价值不止是输入分布，还可以是**计算图的组织先验**。这与 ViT 的 window attention、目标条件策略的 attention masking 同源——空间知识指导注意力分配是空间智能模型的通用模式。

### F.4 动作检索+重定向 vs 端到端动作生成

端到端（prompt→motion）泛化受限于训练分布；检索+重定向把问题分解为"语义匹配（库内，可靠）+ 形态迁移（几何问题，成熟）"，组合泛化能力更强且可控可审计。代价是动作空间被库的覆盖限制。混合路线：端到端生成候选动作再经重定向约束校正，可能是方向。

### F.5 训练目标里代理与视频如何对齐？

每个样本 = (代理视频, RGB clip, 参考图, 结构化 caption)。生成器学的是代理→视频的翻译，代理的精确性使对齐误差极小。Qwen3-VL 生成的结构化 caption 描述条件信号/玩家/boss/背景，文本与代理互补。数据管线的核心资产是**四源统一到同一代理格式**——表示统一是数据规模化的前提。
