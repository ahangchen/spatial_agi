# SpatialScout-V2: Can VLM Agents Actively Explore Real-World 3D Scenes and Localize Objects?

**发表日期**: 2026-11-19
**arXiv链接**: https://arxiv.org/abs/2611.26177
**PDF链接**: https://arxiv.org/pdf/2611.26177
**HTML版本**: https://arxiv.org/html/2611.26177v1
**作者**: Zhaoxi Zhang, Hao Liang, Linxuan Wu, Yiming Xu, Yifu Yuan, Kun Liang, Chenming Tang, Meiyi Qiang, Wentao Zhang, Weikang Li, Yunfang Wu
**机构**: 北京大学、天津大学（与如视 Realsee 合作数据）

---

## 一句话总结

SpatialScout-V2 把"主动探索构建物体中心地图"的评测从仿真搬进 100 个真实住宅场景（3,171 个目标物体、29 类），用标定全景 + 三角化工具让 VLM Agent 自主选视角、观测、提交/修订 3D 物体中心；结果是七个前沿 VLM 中六个 all-target mean IoU 低于 20%，最强的 Claude Opus 5.5 也只有 22.52%——证明真实场景下的主动空间建构仍是 VLM Agent 的重大短板。

## 核心问题

### Q1: 核心算法原理是什么？

**问题**: 这篇文章的核心方法/系统设计是什么？

**分析**:

#### 1. 核心思想和动机

空间智能的本质要求 Agent 具备一种"获取证据—整合证据—修正表示"的闭环能力：

- **部分可观测性**：真实场景中 Agent 每次只能看到一个视角，必须决定下一步看哪里；
- **跨视角关联**：同一物体在不同视角下外观不同，Agent 必须识别"这是同一个东西"；
- **表示的增量构建与修正**：局部位置估计要融合进一个共享的三维表示，并随证据积累不断修正。

现有评测手段各有缺口：
- **空间问答类**（VSI-Bench 等）测试的是对固定观测的判断，答对单个问题不等于能完成长时程空间交互任务；
- **主动问答类**（OpenEQA active、E3VS-Bench）允许 Agent 主动获取证据，但仍然以"回答问题"为目标，而非"构建空间表示"本身；
- **前作 SpatialScout（v1）** 在仿真中引入了"主动建图"任务，但存在三个失真：图像是仿真资产渲染的、未选中的候选物体在渲染时被隐藏、观测是静态非交互的。

因此本文的核心动机是：**在真实场景中检验 Agent 能否通过主动探索，构建准确且完整的物体中心地图（object-center map）**。

#### 2. 主要技术方法（基准构建）

SpatialScout-V2 相比 v1 的三大升级：

1. **真实视觉观测**：用真实激光雷达相机（Galois 3D LiDAR）采集的全景图替代仿真渲染，保留真实物体的外观、材质和光照；
2. **保留原始场景内容**：v1 在渲染时隐藏未选中物体，v2 保留完整场景——包括目标物体、非目标物体以及它们之间的遮挡关系，Agent 必须在自然语境中定位；
3. **录制视角的交互式探索**：把多位置全景采集组织成交互环境，Agent 在已有观测和当前地图的引导下，自主选择下一个观测位置并调整朝向。

数据构建（标注流水线）：
- **全景实例分割**：用 Realsee 的全景分割模型在等距柱状全景图上直接预测语义区域、实例掩码和置信度；滤除低置信度；镜面/玻璃表面（会导致激光测距错误）被抑制；跨接缝掩码与粘连掩码会先重分割再提升到 3D；
- **跨视角提升与关联**：用对齐的度量深度和 camera-to-world 位姿把每个掩码反投影成 3D 点，双向重投影一致性把多视角下的同一物体关联起来，点云融合后去外点，拟合重力对齐的包围盒，合并碎片并用主轴方向精修盒中心和朝向；
- **人工校验**：每个盒子至少从两个视角人工检查，剔除不准的标注。最终库存：100 个测试场景，3,171 个物体，29 个类别（源标注词表为 102 类室内物体）。

坐标系统：所有盒子端点、相机外参统一通过固定转换 A(x,y,z)ᵀ=(x,z,−y)ᵀ 处理，形成世界轴对齐包围盒（AABB）和目标中心 p_i；相机位置、三角化点、提交的中心都在同一度量坐标系下。

#### 3. 算法流程和关键步骤（评测协议）

交互接口（工具集）：
- `list_camera_positions`：列出所有可用的录制机位；
- `select_camera_position`：移动到某个录制位置（保持相对 yaw/pitch）；
- `rotate_camera`：调整观察方向（yaw 循环，pitch ∈ [−85°, 85°]）；
- `capture_image`：获取当前视角的 512×512 透视投影（水平/垂直 FOV 均 90°，双线性插值，接缝处水平环绕）；
- `triangulate_observations`：多视角三角化工具——Agent 在至少两张图像上标记对应点，工具最小化到对应视线束的平方距离和，返回 3D 估计；约束包括至少一对基线 ≥5cm 的相机、法方程条件数 ≤10⁶、解在所有相机前方；返回垂直射线残差和最大射线夹角等诊断信息；
- `submit_positions`：添加/修订物体中心（需已知目标 ID + 三个有限坐标），覆盖之前的估计。

回合规则：
- 每个场景最多 120 个模型回合（turn），实际评估中所有 episode 都不超过 100 turns；
- 初始视角是字典序第一个机位、零 yaw/pitch；
- Agent 无法访问深度图和参考标注；定位深度/位姿只通过工具接口间接获得；
- 只有最终执行了成功 `finish_mapping` 的 run 会被打分；不完整或空地图仍然参与打分（这本身就是性能的一部分）。

#### 4. 输入输出

**输入（Agent 可见）**：
- 固定的目标库存 ℰ = {(i, c_i)}：实例 ID + 类别（同类别构成匹配组）；
- 可用机位列表及其位姿/内参（通过工具查询）；
- 标定 RGB 透视观测（512×512 JPEG）；
- 三角化工具返回的 3D 估计及诊断。

**输出（Agent 须产出）**：
- 每个目标的 3D 中心 (x,y,z) 提交，可多次修订。

**评分（系统侧）**：
- 将该 ID 的参考 AABB（保持参考边长）平移到预测中心，与同类别参考盒计算 3D IoU；
- 预测与参考做一对一匹配：mean IoU 用最大化总 IoU 的分配；阈值命中（IoU > 0 / 0.5 / 0.9）各自独立最大化匹配数；
- **双轨指标**：all-target（含遗漏，遗漏记 0）区分定位质量与完整性；submitted-target 只看已提交目标。

**关键数据（七个 VLM Agent，xhigh 推理档）**：
- Claude Opus 5.5：all-target mean IoU 22.52%（最佳），IoU>0.5 仅 18.36%，IoU>0.9 仅 0.19%；submitted-target 22.58%；
- Claude Sonnet 5.5：18.14%；
- GPT-6 Astra：submitted 21.65% 但 all-target 仅 15.50%——说明遗漏目标显著拉低总分；
- GPT-6.1 Sol：15.04%；
- 其余模型（MiMo-V2.6-Pro、Qwen3.8-Max、DeepSeek-V4.1-Flash）all-target 均低于 20%。

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

这篇工作对"空间表示"给出了一个明确的操作性定义：**物体中心地图（object-center map）**——即一组带语义类别标签的 3D 中心点集合。这个表示比点云/网格轻量得多，但抓住了空间智能的核心语义层：什么东西在哪里。

值得注意的深层含义：
- 空间表示不必是稠密几何；以物体为中心的稀疏语义表示已经足以支撑导航、操作等下游任务；
- 表示的**完整性**（覆盖率）和**准确性**（定位精度）是两个独立的维度，必须分开度量——GPT-6 Astra submitted 21.65% vs all-target 15.50% 的差距证明，只看已提交目标会掩盖"不知道自己不知道什么"的元认知缺陷；
- 空间表示是**动态过程量**而非静态产物：它在交互中逐步建立、逐步修正。

#### 2. 如何处理空间关系

论文把空间能力的处理拆解为四个可评测的子能力：
1. **主动感知决策**：选择哪个机位、什么朝向能最大化信息增益；
2. **跨视角数据关联**：识别多视角中的同一物体（实例级对应）；
3. **几何估计**：从 2D 对应点推算 3D 位置（三角化工具提供了"计算器"，但 Agent 必须自己判断标记哪些对应点、以及表面点到盒中心的偏移）；
4. **证据整合与修订**：把新观测融入已有地图，判断何时需要推翻旧估计。

结果显示 VLM 在 2-4 上普遍薄弱：提交覆盖广但精度低，说明"广撒网"策略不能替代精确的几何推理；工具使用分析显示不同模型在"拍图 vs 三角化"上分配差异显著，还存在大量重复操作。

#### 3. 对 Spatial AGI 的启发

- **评测范式启发**：评估空间智能不能只测"答对多少问题"，要测"能否在预算内主动建构出合格的空间表示"。这是从"知识型评测"到"建构型评测"的转变，与人类测绘/侦察的认知模式同构；
- **失败模式诊断**：22.52% 的天花板说明当前 VLM 的空间能力主要来自 2D 先验 + 语言先验，缺乏真正的 3D 几何推理回路。即使给了三角化这种"几何外挂"，Agent 也未必会用对（对应点选择、中心偏移推断都是瓶颈）；
- **工具增强空间推理的边界**：给 Agent 几何工具不等于几何能力——工具的正确使用本身需要空间理解，这是一个递归难题；
- **元认知与完整性**：知道哪些目标还没找到、主动补测，是空间智能中被忽视的维度。

#### 4. 可以应用的 Spatial AGI 场景

- **家庭机器人**：入库建图、物品寻找（"帮我找遥控器"需要先有完整物体地图）；
- **房产/建筑数字化**：如视自身的业务场景——VR 看房、自动标注；
- **搜索救援/巡检**：在部分观测下构建目标清单的空间分布并保证覆盖率；
- **AR 助手**：增量建立用户环境的持久物体级空间记忆；
- **Agent 训练环境**：作为 RL/自改进的环境接口（视角选择 + 提交奖励信号天然构成可优化的决策问题）。

### Q3: 主要创新点和局限性是什么？

**分析**:

#### 1. 主要创新点

1. **仿真到真实的关键跨越**：首个在真实住宅全景采集上评测"主动建图"的基准，保留真实外观、光照、遮挡与非目标干扰；
2. **交互式录制视角探索机制**：把静态全景数据集变成可交互环境——Agent 选机位、调朝向、自主决定观测序列，每次新观测同时服务于地图更新和后续探索决策；
3. **双轨评测指标设计**：all-target vs submitted-target 分离"定位准确性"和"库存覆盖率"，能诊断出遗漏型失败；
4. **参考标注流水线**：自动多视角标注 + 双视角人工校验，在 100 个真实场景上拿到可信的 3D 物体参考；
5. **工具使用行为分析**：不仅看结果，还分析交互预算在拍图/三角化/重复操作上的分配，提供了过程级诊断。

#### 2. 主要局限性

1. **观测受限于录制机位**：Agent 不能自由移动到任意位置，探索空间是离散的录制点集合，与真实具身导航有差距；
2. **无深度/无自主 SLAM**：深度图被屏蔽，Agent 只能靠 RGB + 三角化工具，这测的是"几何推理"而不是完整建图栈；
3. **物体中心这一表示的局限**：3D IoU 对细长/大型物体非常敏感（中心稍偏 IoU 就暴跌），指标可能与语义直觉不完全一致；且不评价物体朝向、形状；
4. **规模有限**：100 个住宅场景、29 类物体，主要是室内家居域，泛化性未知；
5. **单一评分维度**：没有评价探索效率（如路径代价）、地图的时序一致性（重复访问时估计是否稳定）；
6. **静态世界**：场景无动态变化，不涉及动态物体。

#### 3. 与其他相关工作的对比

- **vs VSI-Bench**：VSI 测固定视频上的空间问答；SpatialScout-V2 测主动交互下的地图建构，任务更接近真实具身需求，且能暴露"回答问题 OK 但构建表示失败"的断层；
- **vs OpenEQA (active) / E3VS-Bench**：它们允许主动取证但仍以 QA 为终点；SpatialScout-V2 的产出物是显式 3D 表示，评测几何准确性（IoU），是更"硬核"的空间能力检验；
- **vs SpatialScout v1**：v1 是仿真、隐藏未选物体、静态；v2 真实、完整场景、交互探索——三重升级使结论首次适用于真实世界；
- **vs 3D 感知模型（如 3D 检测/分割）**：传统感知管线（多视图几何 + 检测器）在这类任务上可以做到很高的精度；基准暴露的是**通用 VLM Agent** 在没有专门 3D 管线时的能力天花板，这恰恰界定了"端到端空间智能"与"感知管线工程"之间的差距。

## 核心技术发现

- 发现1：**前沿 VLM 的主动空间建构能力严重不足**——7 个模型中 6 个 all-target mean IoU < 20%，最强 22.52%，IoU>0.5 命中率仅 18.36%；
- 发现2：**覆盖与精度解耦**——提交覆盖广 ≠ 定位准（Opus 5.5 两项几乎相同说明它"广且准一点"，而 GPT-6 Astra 的 6 个点差距全部来自遗漏）；
- 发现3：**工具使用行为分化**——不同模型在图像获取与三角化之间的预算分配差异明显，重复操作普遍，说明 Agent 缺乏高效的探索策略；
- 发现4：**IoU>0.9 几乎为零（0.19%）**——即使定位成功也停留在"大致位置"层面，度量级精确空间理解完全缺失。

## 与Spatial AGI的关系

### 直接贡献
提供了一个严格的真实场景主动空间建构评测，给出了当前 VLM Agent 空间智能的"体检基线"，为后续模型迭代提供可量化目标。

### 技术启发
- 空间智能评测应从 QA 转向"建构任务 + 几何指标"；
- 物体中心地图是介于稠密几何和纯语义之间的实用中间表示；
- 元认知（知道自己没测哪些目标）应成为空间 Agent 的显式能力。

### 应用场景
家庭服务机器人建图、房产数字化、AR 持久空间记忆、搜索救援、Agent 自改进训练环境。

## 个人思考

### 最令人兴奋的发现

最有趣的是 GPT-6 Astra 的 submitted/all-target 差距（21.65% vs 15.50%）。这个 6 个点的缺口不是几何误差，而是**元认知缺口**：模型不知道自己漏了什么。真正的空间智能体应该有一个"库存完成度"的自我监控机制——这暗示未来的空间 Agent 架构里应该有一个显式的"coverage tracker"模块，而这在当前的端到端 VLM 范式中是缺失的。

另外，给足三角化工具后 IoU>0.9 仍然近乎为零，说明瓶颈不在"能不能算"，而在"会不会用"——Agent 无法可靠地跨视角选择对应点、无法推断可见表面点到物体盒中心的偏移。这提示几何工具的接口设计本身需要更高层的抽象（例如直接提供"两个视角下框选同一物体 → 返回 3D 中心估计"的语义级工具），这可能是缩短 VLM 与几何能力差距的更务实路径。

### 潜在局限

22.52% 这个数字部分是指标严格性的产物：用参考边长的 AABB 平移计算 IoU，对大物体极其苛刻（IoU>0.5 需要中心误差小于物体尺寸的一半量级）。如果用归一化中心距离作为补充指标，结论可能更温和。但即便如此，"六模型低于 20%"的一致性表明真实场景主动建图确实是一个未解问题。

### 与昨日研究的关联

昨天精读的 CoVeR（Coverage-Based Token Pruning for Multi-View 3D Reasoning）研究的是"多视角 token 冗余剪枝"，是被动多视角推理的效率问题；今天的 SpatialScout-V2 则把"视角选择"本身交给 Agent 决策——两者恰好构成"多视角信息如何压缩"与"多视角信息如何主动获取"的对偶。结合昨天的 SplatWAM（世界动作模型的实时 3D 想象），可以设想：未来空间 Agent 的闭环是"主动选视角 → 实时 3D 想象/建图 → 覆盖度监控 → 下一步决策"，今天这篇给出了这个闭环的第一个系统性评测。

## 关键数据

- 场景规模：100 个真实住宅（Realsee3D 测试集），3,171 个目标物体，29 个类别
- 交互预算：每场景 ≤120 turns（实测 ≤100）
- 观测格式：512×512 透视投影，90° FOV
- 评测模型：Claude Opus 5.5 / Claude Sonnet 5.5 / GPT-6 Astra / GPT-6.1 Sol / MiMo-V2.6-Pro / Qwen3.8-Max / DeepSeek-V4.1-Flash（均 xhigh 推理档）
- 最佳成绩：Claude Opus 5.5，all-target mean IoU 22.52%，IoU>0.5 18.36%，IoU>0.9 0.19%
- 工具：list/select_camera_position、rotate_camera、capture_image、triangulate_observations、submit_positions

## 总结

### 核心发现总结
SpatialScout-V2 将主动空间建构评测推进到真实住宅场景，用机位选择 + 三角化 + 地图修订的交互协议，暴露出当前最强 VLM Agent 在物体级 3D 定位与覆盖完整性上的系统性短板（最佳 mean IoU 仅 22.52%）。空间智能的"主动获取证据"与"几何精确建构"两个环节都远未解决。

### 对Spatial AGI的意义
这篇基准把"空间智能"从静态问答拉回到"探索-表示-修正"的动态闭环，为 Spatial AGI 提供了清晰的阶段性靶子：物体中心地图的准确率与覆盖率。它同时提示：纯端到端 VLM 路线在几何精确性上遇到硬墙，语义级几何工具、覆盖度自监控、主动探索策略的显式建模，是通往空间智能的三条互补路径。
