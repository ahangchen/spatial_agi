## 论文基本信息

- **任务**: 将 3D/4D 视觉采集转换为可交互的机器人仿真环境（real-to-sim 的 agentic 化）
- **输入类型**: RGB图像序列、3DGS资产、摄影测量、LiDAR、AI生成3DGS场景、动态场景4D视频
- **核心机制**: 编码智能体编排重建/物理建模工具链 + 基于仿真器渲染的视觉检查与修复
- **输出**: Isaac Lab/MuJoCo/Unreal 的 OpenUSD 场景（分割物体+物理参数+部件分解+铰接+软体）
- **亮点数字**: GraspClutter6D 杂乱箱场景 F1@1cm 最高 60.75%（SimFoundry 仅 6.9%）；4DCodeBench 动态 IoU 把 Gemini 4 Argon 从 0.86% 提升到 99.09%

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

#### 1. 核心思想和动机

- **具身AI的数据与评估瓶颈**: 通用机器人策略（VLA）需要大规模遥操作数据（耗时数月/年），策略评估需要在真实环境反复试跑（耗时、难复现、贵）。仿真可以同时扩展数据收集和评估。
- **视觉重建 ≠ 可交互仿真**: 3DGS 提供逼真外观，但缺少交互所需的物体几何、物理参数、铰接结构。Real-to-sim 系统需要组合分割、网格生成、位姿对齐、物理建模。
- **核心痛点是"协调与纠错"**: 各组件单独都可行，但级联时一个错误掩码、错误尺度或错误变换就能让整个场景不可用。现有系统（如 SimFoundry）是固定管线，缺乏跨阶段的错误检查与修复。
- **核心思想**: 用编码智能体（coding agents）编排整个转换流程，**在目标仿真器中渲染中间结果并视觉检查，发现错误就修复**——把 real-to-sim 从固定管线变成自我纠错的智能体工作流。

#### 2. 主要技术方法

**三阶段总体架构**:
1. 智能体引导的重建与修复
2. 场景增强（digital sisters、混合场景）
3. 演示生成与策略学习

**阶段一：智能体编排与验证（Agent Orchestration and Verification）**

- **智能体分工**:
  - **Orchestrator agent**: 从输入状态规划完整转换与处理步骤
  - **Ingest agents**: 准备输入数据、构建3DGS
  - **Runner agent**: 执行处理工具，每步做 actor-critic 式视觉审查
  - **Reviewer agent**: 对每个转换物体检查配准叠加图、八个隔离视图（六轴对齐+两斜视）、组装后场景的两个视图；发现问题（对齐/铰接/分解）就提出修正并复审
  - **Packager**: 组装场景
  - **Inspector**: 在 Isaac Lab 中审查导出结果
- **对齐残差量化**: 修剪相似变换 ICP（SAM3D位姿初始化）对齐网格到场景，用归一化中位数/90分位距离、覆盖率、轮廓一致性四个阈值决定是否接受候选。
- **状态传递**: 智能体通过场景目录中的文件协作，按 manifest 执行每步，维护接受/拒绝输出的 ledger。
- **技能自进化**: 智能体被指示研究可改进转换的方法，提出候选改动后在静态3D、动态4D、视频转4D基准上评估，只有通过固定提升/回归阈值才保留。对外部用户，通过的改动成为 draft PR，经独立基准运行+维护者审核后合并。**这意味着技能库本身在被智能体持续改进**。

**阶段二：输入准备与场景表示**

- RGB序列 → COLMAP 位姿估计 → Nerfstudio splatfacto-big 训练 3DGS
- 3DGS表示: g_i = (μ_i, Σ_i, α_i, h_i)（中心、协方差、不透明度、球谐颜色）
- 输出场景: S = (G_bg, {o_k})，物体 o_k = (P_k 高斯集, M_k 网格, T_k 变换, θ_k 物理属性, J_k 关节)
- 也接受现成3DGS、摄影测量、LiDAR、AI生成场景（World Labs Marble、NVIDIA Lyra、Tencent HY-World）

**阶段三：物体重建与背景补全**

- **语义特征关联**（LangSplat思路）: SAM 每10帧产出物体掩码；OpenCLIP ViT-B-16 编码掩码区域（512维）；DINOv2 ViT-S/14 给物体视觉特征。两者供物理先验用，**不用于决定高斯归属**。
- **跨视图掩码分组**: 共享3D高斯的掩码归为一个物体——高斯质心距离 < min(0.10, 0.6e)（e为物体范围），且高斯集合包含度 ≥ 0.18 或 Jaccard ≥ 0.08。
- **高斯-掩码关联准则**: 高斯中心投影在掩码内且靠近前表面：z_c(μ_i) ≤ ẑ_c(b_i) + max(ε_a, ε_r·ẑ_c(b_i))，ε_a=0.08重建单位（厨房约7cm），ε_r=0.03。
- **SAM3D 生成物体几何**，修剪相似变换 ICP 对齐到高斯。
- **背景补全**: 移除前景高斯后，用检测平面补全暴露区域，颜色取自邻近平面表面，可选 LaMa 纹理修补。

**阶段四：物理属性、部件与铰接**

- **物理先验**: MLP，输入 DINOv2+OpenCLIP特征+16个几何量，输出材料类别（10类）/刚体类型（6类）/碰撞原语（8类）+9个数值属性。训练于 GSO/YCB/ABO 物体记录，**标签由VLM书写而非物理测量**。
- **加权投票融合**: y* = argmax_y Σ w_v 1[y_v = y]，来源包括物理先验、VLM、物体名称关键词先验；未知类别权重×0.4；后续VLM审计可推翻。
- **10类材料**: 塑料/金属/木材/织物/纸与纸板/橡胶与泡沫/玻璃与陶瓷/食物与有机物/液体与颗粒/未知
- **6类刚体**: 动态刚体/静态刚体/运动学/软体可变形/布料壳/流体与颗粒
- **8类碰撞原语**: box/sphere/cylinder/capsule/convex hull/triangle mesh/tetrahedral mesh/cloth mesh
- **软体判定**: 刚性分数 deformability ≥ 0.65 时转为软体
- **部件分解**: PartSAM 分解物体部件，VLM检查缺失几何（如笔帽下的笔尖），CubePart 生成缺失区域
- **铰接**: Articulate Anything 从图像/文本提出URDF关节与运动范围，智能体在仿真中审查

**阶段五：断裂仿真（差异化能力）**

- **纸张撕裂**: 正交各向异性薄板有限元（NVIDIA Warp）+内部边不可逆内聚断裂。羊皮纸撕裂示例中49个界面渐进失效，撕裂后薄板覆盖碗口95%。
- **陶瓷碎裂**: 表面三角网格分块+推断4.5mm内壁+NVIDIA Blast 应力超限不可逆断键；裂纹沿块边界扩展；碎片为原生PhysX刚体。材料参数为工程假设（抗拉6MPa、杨氏模量6GPa、断裂能14 J/m²、密度1850 kg/m³）。
- **西瓜/果冻**: Newton 中的内聚有限元。

**阶段六：3D→4D 扩展（动态场景）**

- 输入动态场景视频，估计未知内外参（如从容器边缘灭点+物体轮廓）
- 静态几何+按材料选择求解器: MPM（凝胶/弹塑性/液体与刚体交互）、FLIP（不可压液体）、断裂模型（脆性物体）
- **关键约束**: 粒子/顶点全程保留索引不删除不重播种 → 每条轨迹追踪同一块材料（持久轨迹 X^m ∈ R^{F×N×3}）
- **拟合方式**: 智能体调整初始状态与物理参数直到仿真渲染与视频匹配（早/中/晚帧并排+叠加对比）
- **可复现交付物**: 最终场景由单一 build script 生成，**不读取输入视频**，可从头再生并检查格式/帧数/分辨率

**阶段七：场景导出与编辑**

- OpenUSD 格式（Isaac Lab 实验，也验证 MuJoCo/Unreal）
- USD physics schema: 刚体/质量/碰撞形状/关节/摩擦/恢复系数/密度
- 限制: schema 不覆盖软体/断裂/流体，需各引擎扩展（PhysX/Warp/Newton/Blast）
- Three.js 交互查看器: 机器人放置、背景裁剪、资产插入、手动修正

**阶段八：Digital Twins & Sisters 与混合场景**

- **Digital twin**: 重建场景本体
- **Digital sisters（姐妹变体）**: 两种生成方式——
  1. 无模型扰动: 有界变形改网格形状（检查范围/体积变化与可抓取性）+程序化纹理（噪声/色相旋转/斑驳/斑点）烘焙到顶点色
  2. Meshy 生成: Gemini 2.5 Flash 分解功能组件并提案变体 → Gemini 3 Pro Image 逐组件编辑图像（要求真实合理、与场景匹配、其他组件不变）→ 检查后 Meshy image-to-3D 生成带纹理网格；仅外观变化用 Meshy-6 retexture（几何与UV不变）
- **混合场景**: 单个采集物体放入艺术家制作环境（如服务器机架组件接入现有机架场景），无需重采集整个工作区

**阶段九：演示生成与策略学习（policy autoresearch loop）**

- **闭环**:
  1. 当前策略在真实机器人/仿真 rollout
  2. 智能体审查录像找失败模式并标记发生段
  3. 每个失败模式：智能体推测原因、设计能复现它的 digital sisters（变化相关物体/摆放/光照）
  4. 在 sisters 中评估策略；失败处由编码模型（GPT-6 Astra / Gemini 4 Argon）编写或修订专家控制器
  5. 控制器在 sisters 中运行，只有通过任务成功检查的 episode 保留
  6. 合格仿真录像加入微调数据 → 重训策略（LoRA 微调 π0.5）→ 固定配对验证集对比 → 回到真实机器人进入下一轮
- **初始状态随机化**: 物体在任务区域内采样，仿真物理沉降后再执行
- **脚本专家**: approach→descend→grasp→lift→carry→lower→release→retreat，成功检查（物体进入目标容器）
- **观测渲染**: 网格前景（含机器人与操作物体）深度合成到高斯背景上

#### 3. 算法流程总结

```
输入（RGB/3DGS/LiDAR/AI生成/4D视频）
  → Orchestrator 规划
  → Ingest: COLMAP + splatfacto → 3DGS
  → SAM掩码 + 跨视图分组 + 高斯归属
  → SAM3D 物体网格 + ICP对齐
  → 背景平面补全
  → 物理先验MLP + VLM投票 → 材质/刚体类型/碰撞原语/数值属性
  → PartSAM部件分解 + CubePart补全 + Articulate Anything铰接
  → Packager组装 → Inspector在Isaac Lab审查
  → Reviewer逐物体视觉审查（8隔离视图+组装视图）→ 发现问题则修复重审
  → [可选] digital sisters / 混合场景 / 4D动态拟合
  → 导出OpenUSD
  → [可选] 演示生成 → LoRA微调VLA → autoresearch闭环
```

#### 4. 输入输出

- **输入**: 多种形式的视觉采集（最简：13张RGB视图）
- **输出**: OpenUSD 交互场景（分割物体+网格+物理属性+铰接/软体/断裂）+ 可选的 scripted 演示数据集 + 微调后的 VLA
- **中间产物**: 每物体8视图检查图、对齐残差报告、接受/拒绝ledger、技能改动PR

### Q2: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

- **空间的三重表示并存**: SceneAgent 的场景表示同时维护高斯（外观）、网格（交互几何）、物理属性（行为）三层。这承认了一个事实：**单一空间表示无法同时满足"看起来真"和"摸起来对"**。Spatial AGI 最终需要的空间世界模型大概率也是这种分层复合结构，而非单一统一表示。
- **空间作为"过程"而非"产物"**: 传统 real-to-sim 把重建视为确定性产物；SceneAgent 把它视为智能体驱动的迭代过程——空间理解的输出带有"审查-修复"的循环。这与空间智能作为主动认知过程的观点一致：空间不是被一次性感知的，而是被反复校验的。
- **4D拟合的可复现性要求**: 最终 build script 不读视频就能再生整个动态场景——这实际上要求把视频中的动态"编译"为程序化的物理世界描述。**空间理解的终点是可执行的世界程序**，这个哲学与程序化世界生成（如HY-World）一脉相承。

#### 2. 如何处理空间关系

- **跨视图空间一致性作为分组准则**: 掩码按共享3D高斯分组，几何准则（质心距离、包含度、Jaccard）显式编码"什么算同一个物体"的空间定义。物体身份本质上是3D空间连续性。
- **仿真器内验证的空间接地**: 智能体的"审查"是在目标仿真器中渲染后进行——空间正确性的最终标准是"在交互环境中看起来/表现是否正确"。这是具身接地（grounded verification）的实例。
- **物理参数的空间行为化**: 材料、摩擦、质量不是标签而是行为预测器。空间理解的深层是行为理解——知道"这个物体是玻璃的"意味着知道"推倒它会碎"。
- **失败模式驱动的空间增强**: autoresearch loop 把真实失败转化为针对性的空间变体（sisters），空间多样性不再是盲目随机化而是失败导向的定向扩展。

#### 3. 对Spatial AGI的启发

1. **Agentic 化是复杂空间管线的必然形态**: 当空间转换涉及十余个模型和工具时，固定管线的错误级联不可维护。智能体编排+视觉检查+修复循环是把空间工程系统化的可行路径。Spatial AGI 的构建过程本身可以是一个智能体系统。
2. **技能自进化**: 智能体可以研究、提案、基准评估并改进自己的技能库（带阈值门控与PR审核）。这是"空间智能系统自我改进"的具体机制，值得所有长期运行的空间管线借鉴。
3. **数字姐妹与定向增强**: 训练数据多样性可以由"失败模式分析→定向变体生成"驱动，比盲目 domain randomization 高效。Spatial AGI 的训练数据引擎应该闭环到策略的失败上。
4. **物理先验的务实定位**: 论文明确不解决逆物理问题（ ill-posed ），而是把VLM估计的物理参数定位为"domain randomization 的起点"。承认空间物理参数估计的根本不确定性，用随机化吸收它——这是诚实且实用的设计。
5. **4D世界的"编译"范式**: 从视频到可再生的世界程序，暗示空间理解的输出形态应该是可执行、可检查、可版本化的世界代码，而不是一次性资产。

#### 4. 可以应用的Spatial AGI场景

- **机器人仿真数据工厂**: 大规模把网络视频/采集数据转为交互仿真环境，训练通用操作策略
- **策略评估基准环境**: 从目标环境采集快速构建可复现的评估场景（替代昂贵的真机评估）
- **失败驱动的策略诊所**: 真机失败 → 仿真复现 → 定向数据 → 修复 → 部署的自动化闭环
- **动态世界理解基准**: 4DCodeBench 式的"视频→可执行世界程序"评测范式
- **数字孪生运维**: 工厂/实验室/数据中心的持续数字孪生，支持机器人部署前的压力测试
- **内容与具身交叉**: AI生成的3DGS场景（Marble/Lyra/HY-World）一键转为可交互环境，连接世界生成与具身智能

### Q3: 这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

1. **仿真器接地的智能体审查循环**: 区别于以往固定 real-to-sim 管线，智能体在目标仿真器中渲染并检查每个中间产物，错误在级联前被截断。
2. **输入类型的广覆盖**: 统一管线处理 3DGS/摄影测量/LiDAR/AI生成场景/4D视频，且 4D 扩展涵盖液体（MPM/FLIP）、可变形、断裂三类动态。
3. **技能自进化机制**: 智能体可以提案并基准验证技能改动，带回归阈值的门控使技能库可持续演进且不倒退。
4. **持久轨迹的4D拟合**: 粒子不删除不重播种，每条轨迹追踪同一材料块——使动态重建具有材料追踪语义。
5. **Policy autoresearch loop**: 真实失败→仿真复现→定向sisters→专家修订→数据回灌的完全自动化闭环。
6. **量化对比的严谨性**: 与基准数据集GT网格配准比较、匈牙利匹配、多种子采样平均、paired design（同一harness有/无skills各跑一次）——评测设计在系统类论文中罕见地扎实。

#### 2. 主要局限性

1. **物理参数的"工程估计"本质**: 断裂示例的材料参数是手动假设（6MPa等），"prediction from captures and validation against measured break forces remain future work"。VLM书写的物理标签更是近似中的近似。
2. **断裂/软体不进自动导出**: 这类行为是逐场景手工作品（own Isaac Lab scene），USD schema 不覆盖，跨引擎不可迁移。管线的主线仍是刚体+铰接。
3. **转换成本高**: 论文自己在 Limitations 承认 conversion cost 问题；4D拟合靠智能体反复试错调整参数，token 消耗大（4DCodeBench 对比图明确以 tokens/task 为轴）。
4. **真机迁移只是"初步"**: policy transfer 实验是 preliminary，real-world rollouts "still in progress"，核心闭环的最后一公里尚未验证。
5. **评测规模小**: GraspClutter6D 单场景20物体、厨房4物体、4D三个合成场景。大规模统计显著性未知。
6. **对编码智能体能力的依赖**: 不同 harness（Codex/Claude Code/GLM-5.3等）表现差异巨大（F1 40-60% vs 5%），说明系统上限受底层LLM能力制约，可复现性依赖特定模型版本。

## 核心技术发现

- **发现1**: 技能（skills）对各种编码智能体都有大幅增益——F1 提升普遍在 8-50 个百分点（如 Claude Code 5.58→60.46%），且让原本产出不可评分的 harness（Antigravity、Muse）变得可用。**好的工具编排比换更强的底层模型更有效**。
- **发现2**: 动态场景拟合的收益极端分化——Gemini 4 Argon 从 0.86% 到 99.09%（+98pt），而 Claude Opus 5.5 只从 52.16% 到 55.95%。说明 skills 的价值在于"教会不会的"，对已经会的增益有限。
- **发现3**: 高斯-掩码归属的几何准则（前表面深度约束 ε_a=0.08）是分割质量的关键细节——单纯投影在掩码内会导致把背景高斯误归物体。
- **发现4**: VLM 书写的物理标签 + 加权投票 + 审计推翻的三层结构，在无法获得真物理测量的现实约束下是可行的工程妥协。
- **发现5**: 单一 similarity transform 全局配准评分（不允许逐物体修正）的评测协议，诚实反映"装配级"质量而非"修图级"质量。

### 核心发现总结

## 扩展分析：系统架构深度拆解

### A. 智能体工作流的信息流设计

SceneAgent 的智能体协作有三条信息流：

1. **计划流**: Orchestrator 读取输入状态 → 产出转换 manifest（每步的操作清单）
2. **状态流**: 各智能体通过场景目录中的文件共享状态（ledger 记录每步接受/拒绝）
3. **审查流**: Reviewer 的视觉证据链——配准叠加图 → 8个隔离视图 → 组装后视图，粒度从物体级到场景级递进

**关键洞察**: 审查的粒度分层很重要。只看最终场景会漏掉"组装后互相遮挡的物体级缺陷"；只看物体级会漏掉"单个都对但拼起来错位"。物体→场景的双级审查是错误截断的完整覆盖。

### B. ICP 对齐验收的四指标阈值

修剪相似变换 ICP 之后，候选通过需要同时满足四个固定阈值：
- 归一化中位数点距
- 90分位点距
- 覆盖率（网格对高斯集合的空间覆盖）
- 轮廓一致性（silhouette agreement）

单指标容易作弊（如缩小网格降低点距但牺牲覆盖），四指标联合保证了"既贴合又完整"。这种**多维验收门控**适用于任何几何对齐任务。

### C. 高斯-掩码归属准则的细节价值

公式 z_c(μ_i) ≤ ẑ_c(b_i) + max(ε_a, ε_r·ẑ_c(b_i)) 的解读：
- ẑ_c(b_i) 是该粗图像格（约192像素格子）中投影高斯的最小深度——即"该格可见最前表面"
- 高斯深度不得超过前表面深度 + 容差（绝对 ε_a=0.08 或相对 3%，取大者）
- 效果：**只接受属于该表面及紧邻其后这一薄层的高斯**，把物体后方/内部的杂散高斯排除

这是 3DGS 语义分割的一个通用技巧：2D掩码是表面的投影，高斯归属必须做"表面附近性"检验，否则体积中的游离高斯会污染物体分割。昨天读的 PanoGraphGS 等全景分割+场景图工作中也有类似问题。

### D. 物理先验的标签来源问题

物理先验 MLP 的训练标签是 VLM 书写的（不是物理测量）：
- 好处：可规模化（GSO/YCB/ABO 全量物体自动标注）
- 坏处：学到的是"VLM对物体外观的物理常识"而非真实物理
- **三层缓冲设计**: MLP预测 → 与VLM/关键词加权投票 → VLM审计可推翻。任何单源错误都可被其他源纠正。
- 论文诚实地把数值属性定位为"domain randomization 的起点"——承认物理参数的根本不确定性，用随机分布吸收而非追求点估计。这与 sim-to-real 中 "learning to be robust rather than learning to be exact" 的思想一致。

### E. 4D 拟合为何要求持久轨迹？

粒子不删除不重播种的约束带来材料追踪语义：
- 每条轨迹 X^m_t 追踪同一块材料 → 可以回答"这块水后来去哪了"
- 若粒子重播种，轨迹中断，动态场景失去物质守恒的可解释性
- 这也是 4DCodeBench 的评测要求：交付物包含持久轨迹，动态 IoU 掩码才能跨帧对齐

**对空间智能的含义**: 对动态世界的理解不仅是"每帧长什么样"，而是"物质如何流动"。material identity 是动态空间理解的基本单位——与昨日 AW-0（世界动作模型）把动作作为世界基本单位形成有趣对照。

### F. Digital Sisters 的两级生成策略

1. **程序化扰动（无模型调用）**: 有界变形+程序化纹理。便宜、可控、可验证（检查范围/体积/可抓取性）。
2. **生成模型级联（Gemini 2.5 Flash分解 → Gemini 3 Pro Image 逐组件编辑 → 检查 → Meshy image-to-3D）**: 贵但多样。"逐组件编辑"约束（一次只改一个命名组件，其他保持不变）是对生成模型幻觉抑制的精心设计。

**成本分层思想**: 大量变体用便宜方法，少量需要真多样性的用贵方法。这是数据生成管线的通用经济学。

### G. Policy Autoresearch Loop 的流程可靠性分析

闭环的每个环节都有质量门：
- 失败模式标记：人工/智能体审查录像（证据来自真实 rollout）
- sisters 设计：针对失败模式定向（不是盲目随机）
- 专家控制器：由编码模型写，但必须通过任务成功检查才能贡献数据
- 策略更新：新旧 checkpoint 在固定配对验证集上对比（防退化）

**最重要的门是"成功检查才入数据集"**——保证微调数据只包含任务成功的演示。这避免了用失败演示污染策略的风险，但也意味着专家能力上限决定数据上限。若控制器写不出来，该失败模式无法修复——系统会"知道卡在哪"但无法自动突破，这时需要人类介入设计任务分解。

## 扩展分析：实验的方法论价值

### H. Paired Design 的说服力

同一 harness 有/无 skills 各跑一次的配对设计，比"我们的系统 vs 别人的系统"更干净：
- 消除了底层模型差异的混杂
- skills 的增益归因明确（同一模型、同一提示框架，只差技能集）
- 每个配置都成为 skills 有效性的独立证据

6个 harness 在 GraspClutter6D 全部提升（5.58-60.46% 不等），证据链非常强。

### I. Token 成本作为一轴的评估

4DCodeBench 对比图以"tokens per task"为横轴——承认 agentic 系统的实用性必须计入成本。SceneAgent 的技能让某些 harness 用更少 token 达到更高 IoU（Gemini 4 Argon 0.86%→99.09%）。**能力/成本比**应成为 agentic 空间系统的标准评估维度。

### J. "单变换全局配准"评分协议的诚实性

评分时只用一个共享相似变换对齐全局，不允许逐物体修正——反映的是"装配级交付质量"。如果允许逐物体对齐，会把修复工作转嫁给评测，虚高分数。这种协议设计上的克制值得系统类论文学习。

## 扩展思考

### K. Real-to-Sim 的"编排时代"与 Spatial AGI

SceneAgent 的出现标志着领域重心的转移：
- 2024-2025: 单点算法时代（更好的重建、更好的分割、更好的物理估计）
- 2026: 编排时代（把成熟的单点工具用智能体协调起来，重点是错误截断与流程可靠性）

对 Spatial AGI 的预测：
1. 未来的空间数据引擎会以 agentic 管线为默认形态
2. 技能库（skill library）会成为空间工程的核心资产，与模型权重同等重要
3. 评测从"模型指标"扩展到"管线指标"（F1@装配级、tokens/task、修复成功率）

### L. 从"数字孪生"到"数字家族"

Digital twin → sisters → cousins（SimFoundry）→ hybrid scenes 的谱系，实质是把"一个环境"扩展为"环境分布"。Spatial AGI 的训练需要的是环境分布而非单环境：
- twin 保证真实性锚点
- sisters 提供受控多样性
- hybrid 打破场景边界

这个"家族式"数据结构可能成为具身训练数据的标准组织方式。

### M. 4D 世界程序的愿景

SceneAgent 4D 管线的终极形态是：给一段视频，输出一个可再生的世界程序（build script + 物理参数 + 求解器配置）。这与 HY-World（程序化世界建模）、WorldCoder 类工作的愿景合流。**空间理解的终点是世界的可执行描述**——当这个闭环成熟，视频就不再是数据的终点而是世界的压缩编码。

### N. 与论文1、2的整合设想

把今天三篇论文拼成一个系统：
- SG-Splat（论文2）提供免标定前馈 3DGS ingest
- SceneAgent（论文3）转换为交互环境 + 失败驱动 sisters
- PrecisionReach-GS（论文1）在环境中生成触及数据 + 验证器把关
这就是一个完整的"视频进、VLA策略出"的空间数据工厂。三篇论文恰好是同一台机器的三个齿轮。

## 术语表

- **3DGS 原语**: g=(μ 中心, Σ 协方差, α 不透明度, h 球谐颜色系数)
- **Digital twin / sister**: 重建场景本体 / 其受控变体物体
- **MPM（Material Point Method）**: 物质点法，欧拉网格+拉格朗日粒子的混合欧拉-拉格朗日法，适合凝胶/弹塑性/颗粒
- **FLIP**: 混合欧拉-拉格朗日不可压液体求解器
- **NVIDIA Warp / Newton / Blast**: 分别为可微物理框架 / 内聚有限元求解器 / 破坏仿真系统
- **URDF**: 统一机器人描述格式，描述关节/连杆
- **OpenUSD**: Universal Scene Description，皮克斯开发、Omniverse 推广的场景描述标准
- **LangSplat**: 将语言特征（CLIP类）关联到3D高斯的方法
- **trimmed ICP**: 剔除最远点对后迭代的鲁棒点云配准
- **Hungarian matching**: 以 Chamfer 距离为代价的预测-真值物体最优匹配
- **DynIoU**: 动态物质掩码的跨帧 IoU（4DCodeBench 定义）
- **Harness**: 编码智能体的运行环境（如 Codex、Claude Code、Stirrup）
- **Skills**: 可复用的指令与工具集，指导智能体执行转换工作流

## 附录：关键公式备忘

- **高斯-掩码归属**: π_c(μ_i) ∈ m 且 z_c(μ_i) ≤ ẑ_c(b_i) + max(ε_a, ε_r·ẑ_c(b_i))，ε_a=0.08（重建单位，厨房约7cm），ε_r=0.03
- **掩码跨视图分组**: 高斯质心距 < min(0.10, 0.6e) 且（包含度 ≥ 0.18 或 Jaccard ≥ 0.08）
- **材料投票**: y* = argmax_y Σ_v w_v·1[y_v=y]，未知类权重×0.4
- **软体判定**: deformability ≥ 0.65
- **Chamfer**: d_CD = ½(均|x到Y最近| + 均|y到X最近|)
- **F1@τ**: 2PR/(P+R)，P/R 为采样点距参考 ≤τ 的比例
- **DynIoU**: 排除边界带的动态掩码 IoU 帧均值
- **撕裂覆盖**: 71×71 网格中低于碗缘12mm以内的点被撕裂薄板覆盖的比例（取撤手后最低值）
