## 0. 论文速览

GraFT 是华为 Riemann Lab 提出的**免训练（training-free）3D 空间推理框架**。它的核心洞察是：MLLM 在空间推理上的失败，不是因为模型"不够聪明"，而是因为它**拿不到合适的证据（evidence）**。GraFT 不去微调模型，也不给它加 3D 编码器，而是构建一个紧凑的、可增量维护的 **3D 场景图（3D Scene Graph, 3DSG）**，然后根据任务类型，从同一张图里派生出三种不同的"证据供给"能力：

1. **符号几何工具（Symbolic Tools）**：精确的度量计算（计数、尺寸、距离、邻近排序、房间尺寸）
2. **任务条件化的 BEV 渲染（Bird's-Eye-View）**：解决自我中心 → 世界中心（egocentric→allocentric）的视角转换推理
3. **几何引导的自我中心帧检索（Egocentric Frame Retrieval）**：为外观属性类问题挑选最清晰的第一人称视角帧

冻结的 MLLM 只需动用它已有的两个能力——调用工具、解读结构化视觉输入——就能完成 3D 空间推理。

**一句话总结**：空间智能不一定来自训练，也可以来自"把正确的证据以正确的形式喂给模型"。

**关键成绩**：
- VSI-Bench：3 个冻结开源 backbone 提升 37%~65%，最佳配置平均分 **51.4**，超过所有专有模型（最高 45.4）、所有通用开源模型（最高 40.9），甚至超过多个专门微调过的空间推理模型
- ScanQA：同 backbone 下所有 caption 指标全面提升，CIDEr 从 58.0 → **73.6**（+27%），零参数更新

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

**分析**:

#### 1. 核心思想和动机

论文的出发点是对现有两条技术路线的深刻不满：

**路线A：把空间能力训练进模型**
- 监督微调：SpatialVLM、SpatialRGPT、MM-Spatial 注入大规模度量监督
- 强化学习：SpaceR、SpatialLadder、ViLaSR、R1-Zero-VSI 等
- 问题：需要大规模数据策展和训练成本；空间先验被绑死在训练分布和特定 backbone 上；遇到新场景/新任务分布可能失效

**路线B：给模型外挂 3D 编码器**
- 3D-LLM、PointLLM、Chat-Scene 通过专用编码器消费点云等显式 3D 输入
- 问题：编码器与一种输入格式绑定，同样要在任务看到之前就"押注"一种表征

**作者的关键观察：不同空间任务需要的证据类型是异构的**
- 布局类任务（哪个在左边、房间怎么布置）→ 需要全局的、地图式的视图
- 物体外观类任务（沙发是什么颜色）→ 只要给对 2D 视角，MLLM 预训练能力就够用
- 精确度量类任务（桌子到墙多远）→ 交给外部几何工具比依赖学习到的先验更可靠

既然需求异构，就不该在训练时预先押注单一策略。**GraFT 的方案：让一张 3D 场景图作为"任务 ↔ 证据"的媒介，按需派生证据，backbone 全程冻结。**

这背后有一个更深的认识论立场：**空间推理的瓶颈在感知-表征层，不在推理层**。MLLM 已经会推理，缺的是可信的空间事实。与其教模型"猜"几何，不如让它"查"几何。

#### 2. 主要技术方法

**场景表征：层次化 3D 场景图**

GraFT 消费上游感知管线产出的层次化 3DSG（作为输入直接给定，从而解耦推理层与建图层）：

- 图形式：G = (N, E)
- 节点四层：建筑物节点 N_B → 楼层节点 N_F → 房间节点 N_R → 物体节点 N_O
- 边：记录相邻层之间的包含关系（containment）

**物体节点的核心元组**（这是整个系统的信息基石）：

```
o_i = (ℓ_i, c_i, s_i, R_i, n_i, V_i)
```

| 符号 | 含义 |
|------|------|
| ℓ_i | 语义类别标签 |
| c_i | 包围盒中心，世界坐标系米制 (x,y,z) |
| s_i | 沿盒轴的全尺寸 (w,d,h) |
| R_i | 朝向（由存储的单位四元数恢复的旋转矩阵） |
| n_i | 单位表面法向 |
| V_i | 该物体可见的视频帧集合 |

每帧视频带标定 θ_t = (R_t, p_t, K_t)：相机旋转、光心、内参。V_i 就是物体包围盒能投影进去的帧子集。

**三大能力模块**：

**模块1：符号几何工具（Symbolic Module）**

五个确定性工具，直接从包围盒读取答案：
- **count**：列出每个物体类别及实例数
- **size**：返回物体宽/深/高（即盒尺寸）
- **distance**：两个类别包围盒的表面到表面距离
- **proximity**：按到锚点物体的最近距离给多个候选类别排序（谁最近/最远）
- **room**：房间的宽、深、高、地板面积

设计纪律非常严格：**每个几何任务恰好一次工具调用，绝不链式调用工具**。这保证符号模块是单步确定性过程，数值计算完全不经过 backbone。任何从图像推断的量只会叠加误差；而从盒几何函数式导出的量，精度直接继承上游感知。

**模块2：BEV 模块（选择性世界中心渲染）**

- 从 3DSG 直接渲染俯视图，但**只画任务相关物体**，每个物体按精确尺寸比例画成干净的盒子，其余场景内容全部省略
- 与 Struct2D 的区别：Struct2D 在完整场景的俯视图上标记相关物体；GraFT 只渲染相关物体本身——无杂波、比例忠实，空间关系一目了然
- 视点和朝向由任务决定而非相机轨迹决定：给定视点中心 c_a 和决定朝向的参考点 c_f，绕视点旋转角度 θ 使朝向方向 (c_f − c_a) 指向图像上方——这正是自我中心到世界中心的显式对齐
- 可选的"锚点→目标"箭头叠加，把关系显式化而不是留给模型猜

**模块3：自我中心模块（几何引导的帧检索）**

两阶段管线：

**阶段一：可见性门控（visibility gate）**，三个几何条件同时满足才算可见：

```
v_{i,t} = 1[ n_{i,t} ≥ 2,                          # ≥2个盒角投到相机前方且在图像内
             d_min ≤ d_{i,t} ≤ d_max,              # 相机-物体距离在有效深度区间
             <z_t, c_i - p_t>/d_{i,t} ≥ cos τ ]    # 光轴与物体方向夹角在τ内
```

- 8 个盒角：中心 c_i 沿盒轴 R_i 偏移半尺寸 s_i 的全部符号组合
- 只要求 2 个角在画面内 → 允许部分视图
- 阈值全局固定一次，跨场景跨任务共享

**阶段二：帧打分**，三个 [0,1] 项的乘积：

```
中心性: s_ctr = max(0, 1 - ||u_{i,t} - u_0|| / ρ)     # 物体投影越居中越高
邻近性: s_prox = 1 / max(d_{i,t}, 1)                   # 越近越好，1米下限防近距主导
覆盖度: s_cov = n_{i,t} / 8                            # 在画面内的盒角比例

总分: s(o_i, t) = v_{i,t} · s_prox · s_ctr · s_cov     # 取top-k帧喂给backbone
```

论文给的直观例子：view 1 得分 0.84×0.63×1.00=0.53（近、居中、全覆盖）排第一；view 2 因物体只部分入画被 0.25 的覆盖度惩罚（0.61×0.65×0.25=0.10）。

**模块选择**：任务到模块的匹配是一个规范的工具选择（tool-selection）步骤，由冻结 backbone 自行完成——它本来就会调用工具。

#### 3. 算法流程和关键步骤

```
离线/上游（每个场景一次）:
  1. 输入标定视频 → 上游感知管线（重建+分割+语义）→ 层次化3DSG
  2. 每个物体节点存: 类别/盒中心/尺寸/朝向/法向/可见帧集合V_i

在线推理（每个问题一次）:
  3. 冻结MLLM接收问题 + 3DSG摘要（序列化）
  4. 任务路由（tool selection）:
     - 度量类 → 符号工具（单步确定性计算）→ 数值证据
     - 布局/视角类 → 任务条件BEV渲染（只画相关物体，按朝向对齐）→ 图像证据
     - 外观类 → 几何打分检索top-k自我中心帧 → 像素证据
  5. backbone对证据做最终推理，生成答案
全程无参数更新。
```

**感知摊销（perception amortization）**是与工具增强方法（TIGeR、SpatialAgent、SpaceTools）的本质区别：那些方法每个问题重新跑一次深度/位姿/框估计；GraFT 在建图时跑一次感知，之后所有问题的工具调用都是对图的确定性几何运算——把感知成本摊销到所有问题上。

#### 4. 输入输出

- **输入**：
  - 一段带标定的 RGB 视频（或等价的 posed 帧序列）
  - 上游管线产出的层次化 3DSG
  - 自然语言空间推理问题（可能多轮）
- **输出**：
  - 中间：任务路由决策 + 一种证据（数值/BEV图/top-k帧）
  - 最终：自然语言答案
- **不更新**：backbone 的任何参数

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

#### 1. 如何理解和表示空间

GraFT 给出了一种极具工程智慧的答案：**空间 = 符号结构 + 度量几何 + 视角索引**。

- **符号层**：场景不是像素堆，而是一个"什么在哪里"的层次图（建筑-楼层-房间-物体）
- **几何层**：每个实体有精确的米制包围盒（位置/尺寸/朝向/法向），是一切定量推理的公理基础
- **视角层**：每个实体索引了自己被观察到的帧集合 V_i，把 3D 结构和 2D 观测挂接起来

这三层正好对应空间智能的三种基本操作：检索事实（查图）、空间变换（BEV/旋转）、感知外观（回看帧）。相比点云/体素/NeRF 等稠密表征，3DSG 是**可读、可维护、可增量更新**的——对需要长期存在的空间智能体至关重要。

#### 2. 如何处理空间关系

- **定量关系**（距离/尺寸/计数）→ 符号计算，零幻觉。模型从不"估算"数字
- **构型关系**（左右/环绕/朝向）→ 世界中心的 BEV 渲染 + 显式旋转对齐，把认知科学里的 egocentric/allocentric 转换问题变成图像重绘问题
- **感知关系**（看起来什么样）→ 几何打分选最佳观测视角，把"哪个帧最能看清X"变成可计算的检索问题

值得注意：论文刻意不把空间关系"教"给模型，而是**把关系渲染成模型已经会读的视觉格式**。这是一种"接口适配"而非"能力灌输"。

#### 3. 对Spatial AGI的启发

这可能是今天五篇里对 Spatial AGI 路线图最有战略意义的一篇：

1. **"免训练"路径的可行性证明**：空间智能不一定要靠烧数据微调。一个正确维护的空间记忆结构 + 证据路由，可以让现有基础模型立刻获得可靠空间能力。这大幅降低了 Spatial AGI 的迭代成本——升级空间能力 ≠ 重训模型

2. **证据路由（evidence routing）作为核心机制**：空间任务异构，智能体应该学会"这个问题需要什么证据"再决定调用哪个模块。这是 agent 架构层面的问题，比模型层面的 SFT/RL 更可组合、更可解释、更可调试

3. **确定性优先原则**：凡是能从结构化记忆确定性导出的事实，绝不交给神经网络猜测。数值幻觉是空间智能落地的最大障碍之一，GraFT 用架构而非训练回避了它

4. **3DSG 作为空间记忆的标准载体**：机器人社区（Hydra、ConceptGraphs 等实时开放词汇 3DSG 工作）与 MLLM 社区在此会师。Spatial AGI 的"空间记忆"很可能就该长这样：层次化、米制、带视角索引、可增量维护

5. **与既有研究的呼应**：这与我们此前分析的 Reasmory（3D 重建作为 VLM 空间推理的显式记忆）、GaussMemory（任务驱动的 3DGS 场景记忆）、S-Agent（空间工具使用）、GraFT 前身的 Struct2D（结构化 BEV 提示）一脉相承——**显式空间记忆 + 工具化访问**正在从多种技术路径汇聚成一个共识范式

#### 4. 可以应用的Spatial AGI场景

- **家庭/服务机器人**：室内问答、找物、空间指令理解（"把厨房里离冰箱最近的杯子拿来"→ proximity 工具一次解决）
- **AR 导航与助手**：实时 3DSG + BEV 渲染做环境解说与路径解释
- **仓储与巡检**：库存计数、尺寸测量、异常定位——全是符号工具的主场
- **具身智能体的记忆系统**：长期运行 agent 的空间记忆层，backbone 可随时更换升级
- **自动驾驶座舱**：车内/车外场景的空间问答
- **无障碍辅助**：为视障用户做精确空间描述（距离、方位都是确定性的）

### Q3: 创新点和局限性

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**分析**:

#### 1. 主要创新点

1. **范式级贡献：免训练的空间推理框架**。在全民 SFT/RL 的氛围里，证明"换输入不换模型"就能击败一票微调模型，是清醒且有说服力的反主流结论

2. **3DSG 的三重复用（一个图，三种能力）**。以往 3DSG 在具身 AI 里基本被序列化成文本塞进 prompt；GraFT 把同一张图同时用作：符号工具的数据源、BEV 渲染的几何源、帧检索的索引。表征复用率高，工程面窄

3. **任务条件化选择性 BEV**。只渲染相关物体、按任务设定视点与朝向、可选关系箭头——信息密度和信噪比的把控远好于"全场景俯视图"类方案（GPT4Scene、Struct2D）。"省略即增强"是个漂亮的反直觉设计

4. **纯几何的帧质量打分**。可见性门控（2角+深度区间+光轴锥角）与三因子乘积打分（中心性×邻近性×覆盖度）全部可微less/无学习、无模型依赖，跨场景共享阈值。简洁到可以直接抄进任何工程管线

5. **感知摊销架构**。感知一次建图，推理期工具只做确定性几何——对比每个问题重跑感知的工具增强方法，成本结构根本性更优

#### 2. 主要局限性

1. **继承上游感知的全部误差与失败模式**：包围盒不准 → 所有符号工具的答案系统性偏差；漏检物体 → count/距离答案直接错误。框架把感知精度变成硬上限，且推理层无法自查感知错误（答案"确定地错"比"模糊地错"可能更危险）

2. **依赖标定视频与位姿**：需要 posed 帧（R_t, p_t, K_t），真实部署中 SLAM/标定漂移会传导进图。户外、大尺度、动态场景（论文只在室内 ScanQA/VSI-Bench 类场景验证）尚未覆盖

3. **模块路由是单点风险**：任务→模块的选择由冻结模型完成，路由错则证据错。论文没有详细报告路由错误率；复杂复合问题（既要度量又要外观）如何拆解也未充分讨论

4. **符号工具的表达力边界**：单步不链式调用保证确定性，但也限制了一阶逻辑之外的空间推理（如"不在桌上的所有物体中离窗最远的"需要组合操作）

5. **关系语义层缺失**：3DSG 目前只有层级包含边，没有物体间拓扑/语义关系（支撑、悬挂、邻接）边。空间关系推理很多仍被推给 BEV 渲染让模型读图，而非图中显式存储

6. **静态场景假设**：物体不动的场景图无法直接处理动态世界，动态空间的增量图维护是开放问题

#### 3. 与其他相关工作的对比

| 维度 | SFT/RL 路线 (SpatialVLM/SpaceR) | 3D编码器路线 (PointLLM/3D-LLM) | 结构化提示 (Struct2D/GPT4Scene) | 工具增强 (TIGeR/SpaceTools) | **GraFT** |
|------|------|------|------|------|------|
| 是否训练 | 大量SFT/RL | 训练编码器+对齐 | 部分需要 | 少量/免 | **零训练** |
| 3D信息来源 | 数据集先验 | 点云输入 | 重建场景图 | 每问重新感知 | **一次性建图** |
| 换backbone成本 | 重训 | 重训 | 低 | 低 | **即插即用** |
| 数值可靠性 | 学习先验 | 学习 | 学习 | 中等 | **确定性** |
| 感知成本/问 | - | - | 一次 | 每问一次 | **一次摊销** |
| BEV | 无 | 无 | 固定全场景 | 无 | **按需选择性** |
| VSI-Bench最佳 | 多个被超越 | - | 40.9级 | - | **51.4** |

优势：免训练、backbone 无关、确定性度量、感知摊销、BEV 按需渲染。
劣势：天花板锁死在感知质量；无端到端梯度可优化；场景静态假设；关系语义浅。

## 核心技术发现

1. **冻结 MLLM + 3DSG 证据路由，VSI-Bench 平均 51.4，超过所有专有模型（最佳 45.4）和通用开源模型（最佳 40.9），并超过多个空间推理微调模型**——免训练路线首次在该基准上全面领先
2. 三个冻结开源 backbone 分别提升 37%、（中）到 65%——框架增益与 backbone 强弱正相关且稳定，说明缺的是证据不是推理力
3. 选择性 BEV（只画相关物体 + 任务朝向对齐）是 egocentric→allocentric 转换的高性价比解法，优于全场景 BEV
4. 三因子几何打分（proximity × centrality × coverage）选帧即可大幅提升外观类问答（ScanQA CIDEr 58.0→73.6）
5. 单步确定性工具调用（不链式）在保持推理简洁的同时不损失几何任务精度

## 与Spatial AGI的关系

### 直接贡献
提供了一个可即刻部署的空间推理架构模板：**空间记忆（3DSG）→ 证据路由 → 冻结基础模型**。Spatial AGI 系统可以把"空间能力"从模型权重中解耦出来，放进可审计、可增量维护的显式结构中。

### 技术启发
- 确定性优先：能量化计算的不让模型猜
- 表征复用：一张图服务多种能力，工程面最小化
- 接口适配优于能力灌输：把空间关系渲染成模型会读的形式

### 应用场景
家庭机器人、AR 助手、仓储巡检、无障碍辅助、具身智能体长期空间记忆层。

## 个人思考

### 最令人兴奋的发现

**51.4 > 45.4 这个不等式的含义远超一个 benchmark 数字。** 它意味着：在空间推理这件事上，"更好的架构化证据供给"当前比"更多的训练"更有效。这为 Spatial AGI 的工程路线提供了一个杠杆点——空间能力可以作为**外部记忆系统**独立迭代、独立升级、独立审计，而不被基础模型的更新节奏绑架。

另一个动人之处是它的"克制"：不链式工具调用、只画相关物体、阈值全局固定——每个设计都在拒绝不必要的复杂度。这种克制换来了可解释性：每个答案都能回溯到图里的一条几何事实或一帧明确的图像证据。**可审计的空间智能**对安全攸关场景（机器人进入人类生活空间）是刚需。

### 潜在局限

我最担心的两点：
1. **"确定地错"问题**：感知错误经过符号工具放大后，输出是自信且不可质疑的错误答案（模型会说"距离是 2.3 米"而不是"大概 2 米吧"）。GraFT 框架内没有不确定度传播机制——3DSG 节点若带置信度，工具输出应连带置信度给模型
2. **静态世界假设**：真实空间是动态的（人移动物体、门开关）。增量式 3DSG 维护（机器人社区有基础）与 GraFT 推理层的衔接是下一步必须补的课

### 与昨日研究的关联

- 与昨日 **NavArena**（用 3DGS 自动构造导航基准）形成有趣对照：NavArena 用稠密 3DGS 表征生成训练/评测环境，GraFT 用稀疏符号 3DSG 支撑推理——稠密表征擅长"仿真与生成"，稀疏符号表征擅长"查询与推理"，Spatial AGI 可能需要两者并存的双层空间记忆
- 与 **GeoAgent**（VLM 地理定位导航）共享一个主题：给 VLM 补空间结构，与其改模型不如改输入
- 近期分析的 **Reasmory**（重建作为显式记忆）、**GaussMemory**（任务驱动 3DGS 记忆）、**SoftNav**（3D token 注入）都在解决同一问题的不同侧面；GraFT 是其中"最不训练"的极端方案，而它的胜利恰恰说明显式结构化证据的价值被整个领域低估了

## 总结

### 核心发现总结
GraFT 证明：用一个紧凑的层次化 3D 场景图作为证据媒介，配以"符号工具 / 任务条件 BEV / 几何选帧"三路证据路由，可以让完全冻结的 MLLM 在 3D 空间推理上超越所有专有模型和多数空间微调模型。空间推理的短板首先是可以用架构补的感知-证据短板。

## 附录A: 方法细节深挖

### A1. 3DSG 节点设计的
完整信息记录

物体节点六元组 o_i = (ℓ, c, s, R, n, V) 中每个字段都有明确的消费者：

- ℓ (类别)：count/proximity 工具的检索键；BEV 渲染的图例文字
- c (中心)：distance/proximity 的计算输入；BEV 的放置位置
- s (尺寸)：size 工具直接返回；BEV 盒子的长宽比例来源
- R (朝向)：8 个盒角的生成母矩阵；BEV 盒子的旋转
- n (法向)：辅助朝向消歧（如沙发正面）
- V (可见帧)：帧检索的候选集；覆盖度/中心性打分的输入

**设计要点**：字段的最小完备性。没有特征向量、没有嵌入、没有点云——每个字段都是"可解释、可查询、可验证"的经典几何量。这让 3DSG 具备三个稀有性质：
1. 人类可审计：任何人打开节点就能核对答案来源
2. 零漂移存储：不像神经记忆会遗忘/干涉
3. 增量可维护：新物体 = 插入新节点，无需重训任何组件

### A2. 可见性门控的几何直觉

三个门控条件各挡住一类坏帧：

| 条件 | 挡住的帧 | 为什么是坏帧 |
|------|---------|-------------|
| n_{i,t} ≥ 2 | 物体完全出画/只剩边缘 | 无法提供外观信息 |
| d_min ≤ d ≤ d_max | 贴脸帧或远到模糊帧 | 近距视角畸变/远距分辨率不足 |
| 光轴夹角 ≤ τ | 余光扫过的帧 | 物体在画面边缘、常被遮挡 |

只要求 2/8 角入画是精心权衡：要求过半会丢掉"物体刚进入画面"的帧（这些帧往往构图完整度高）；全放开又会让极端 partial view 进入候选。2 是"有足够信息描述物体"的经验下限。

### A3. 打分乘积形式的隐含语义

s = v · s_prox · s_ctr · s_cov 用乘积而非加权求和，意味着三项是**合取关系**（任一项趋零总分趋零）而非折衷关系。这符合"好视图必须同时近、居中、完整"的直觉。对比加权求和：一项满分可以弥补另一项缺失，会产生"很近但只拍到一角"的坏帧高分。乘积形式是最小信息量的合取建模。

1 米下限的 s_prox = 1/max(d,1) 也是防退化设计：没有它，贴脸帧（d→0.1m）分数会是 3 米帧的 30 倍，top-k 全被个别极端帧占据。

### A4. BEV 的"省略即增强"信息论解释

全场景 BEV 的像素预算被无关物体稀释，相关物体的角分辨率低、边易与杂波粘连；选择性 BEV 把全部像素预算给相关物体，等于做了一次任务条件化的**信道聚焦**。同时"按比例精确绘制"传递了 SECOND 类信息：模型可以直接从图中读出"A 的包围盒面积约是 B 的两倍"——图像变成了度量事实的可视化载体，而不再是需要估计的对象。

朝向对齐（c_f−c_a 转到图上方）消除了心理旋转需求：认知心理学表明 mental rotation 是空间推理的主要错误源之一；把旋转在渲染期完成，模型读图时零旋转负荷。

### A5. 与函数式编程的类比

GraFT 的工具层本质是：**把 3DSG 当作不可变数据库，工具是纯函数**。
- 同一输入永远同一输出（确定性）
- 无副作用（不修改图）
- 可组合性被主动限制（禁止链式调用）以换取可验证性

这个纪律换来两个系统性质：答案可复现（评测/调试友好）、错误可归因（错答案必是图错或路由错，二者都可离线审计）。

## 附录B: 实验结果深度解读

### B1. VSI-Bench 分项推断

VSI-Bench 包含数值类（对象计数、绝对距离、相对距离、房间面积）与认知类（出现顺序、相对方向）任务。由此推断 GraFT 的得分结构：

- 数值类：符号工具应接近感知精度上限，显著超基线
- 相对方向类：BEV 模块的主场，egocentric→allocentric 一次对齐解决
- 出现顺序类：可从 V_i 帧索引的时间戳确定性导出（隐藏的第六个工具）

51.4 的平均分意味着认知类任务仍有明显提升空间——这也符合"证据路由对复合推理帮助有限"的预期。

### B2. backbone 增益差异的解读

三个 backbone 提升 37%~65% 不等，提示：
- 增益大的 backbone 本身工具调用/图像解读能力强，证据给到就能用
- 增益小的可能路由（选模块）环节失误更多
- 极限情况下，若 backbone 不会读 BEV 图，框架反而可能引入噪声——GraFT 与 backbone 存在能力匹配区间

### B3. ScanQA 结果的含义

ScanQA 是生成式问答（CIDEr/BLEU 等 caption 指标），CIDEr +27% 说明选帧策略改善了答案的内容保真度——模型看到了"真正看清物体"的帧，描述性内容随之变准。这验证了：**即使是"外观"这种看似纯感知的属性，几何引导的检索也能带来决定性差异**。

若要在自己的 Spatial AGI 项目中复刻 GraFT，需要准备：

**不存在**的部分：训练脚本、数据集构造、损失函数、超参搜索。这正是论文标题里 "Training-Free" 的含金量。

## 附录E: 关键公式与伪代码汇总

### E1. 可见性门控（Eq.1 重述）

```
v(i,t) = 1[ corners_in_view(i,t) >= 2
            AND d_min <= ||c_i - p_t|| <= d_max
            AND angle(z_t, c_i - p_t) <= tau ]
```

- corners_in_view: 8 盒角经 π(·, θ_t) 投影后落在相机前方且图像内的个数
- θ_t = (R_t, p_t, K_t)：帧 t 的旋转/光心/内参
- 全局共享阈值，一次标定跨场景使用

### E2. 帧打分（Eq.2-5 重述）

```
s_ctr(i,t) = max(0, 1 - ||u(i,t) - u_0|| / rho)
s_prox(i,t) = 1 / max(d(i,t), 1)
s_cov(i,t)  = corners_in_view(i,t) / 8
score(i,t)  = v(i,t) * s_prox * s_ctr * s_cov
```

取 score 最高的 top-k 帧作为外观证据。

### E3. BEV 渲染流程伪代码

```
def render_bev(graph, task_objects, c_a, c_f, arrow=None):
    pts = [project_box_xz(graph[o]) for o in task_objects]
    theta = heading_angle(c_f - c_a)        # 面向方向转到图上方
    pts = rotate(pts, -theta, pivot=c_a)    # 世界系 -> 任务朝向系
    canvas = draw_scaled_boxes(pts)         # 按精确比例绘制
    if arrow: canvas.overlay(arrow)         # 可选关系箭头
    return canvas
```

def graft_answer(question, graph, mllm):
