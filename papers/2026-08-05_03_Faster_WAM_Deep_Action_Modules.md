## 论文摘要

World Action Models (WAMs) 将机器人动作预测与视频世界模型耦合。现有WAMs使用共享骨干或Mixture-of-Transformers设计，通常将动作模块的深度与视频骨干的深度绑定，导致大量计算开销和高推理延迟。

本文引入 **Dock of Transformer (DoT)** 设计原则，将预训练视频Transformer视为表示中枢，通过docking接口连接轻量级输出头。然后提出 **Faster-WAM**，在30层视频骨干上仅dock一个单层动作头。docking接口融合所有视频层的key/value并应用RoPE重对齐。无需额外embodied预训练，Faster-WAM在LIBERO和RoboTwin 2.0上取得有竞争力的性能，同时在LIBERO-Plus上展现强大的分布外泛化。Faster-WAM达到最低端到端延迟（66.5ms/推理），比Fast-WAM加速3.2倍。

## Q1: 核心算法原理

### 1. 核心思想和动机

**核心问题**: WAM的动作模块需要和视频骨干一样深吗？

**动机分析**:
- WAM = 视频骨干 + 动作模块
- 现有设计（FastWAM等）将动作模块深度 = 视频骨干深度（如30层对30层）
- 但视频生成（需要高质量像素预测）和动作预测（低维连续控制）难度不同
- 动作预测可能只需要浅层网络就能完成
- 深层动作模块 = 不必要的计算和延迟

**核心思路**: 视频骨干是"表示中枢"，动作模块只需轻量级"输出头"。关键问题是如何让浅层动作头访问深层视频特征。

### 2. 主要技术方法

#### (a) Dock of Transformer (DoT) 设计原则

**核心理念**: 
- 预训练视频Transformer = 表示中枢（hub）
- 任务特定模块 = 轻量级输出头（通过docking接口连接）
- docking接口提供从所有视频层直接访问的能力

**与现有方法的区别**:
- MoE/MoT: 不同模态在相同深度并行处理
- DoT: 不同模态可以有不同深度，通过接口连接

#### (b) Docking接口

**多层特征聚合**:
- 从视频骨干的所有层（30层）提取key和value
- 融合后提供给单层动作头
- RoPE重对齐: 解决视频和动作不同模态的位置编码不对齐问题

**数学描述**:
```
K_all = [K_1, K_2, ..., K_L]  // 所有视频层的key
V_all = [V_1, V_2, ..., V_L]  // 所有视频层的value
K_fused, V_fused = DockInterface(K_all, V_all)
ActionOutput = SingleLayerHead(Q_action, K_fused, V_fused)
```

#### (c) Faster-WAM实例化

- 视频骨干: 30层Transformer（预训练视频模型）
- 动作头: **1层**（vs FastWAM的30层）
- 总参数量大幅减少
- 推理延迟: 66.5ms（vs Fast-WAM的213ms）

### 3. 算法流程

```
输入: 当前RGB观测o_t, 语言指令ℓ_t, 本体感知q_t
↓
1. 视频骨干处理当前观测:
   - 所有30层生成中间表示 (K_l, V_l), l=1..30
↓
2. Docking接口:
   a. 从所有层提取 {K_l, V_l}
   b. 特征融合: K_fused = F_K({K_l}), V_fused = F_V({V_l})
   c. RoPE重对齐: 对齐视频和动作的位置编码
↓
3. 单层动作头:
   ActionOutput = Attention(Q_action, K_fused, V_fused) + FFN
↓
输出: 动作chunk a_t

训练: 使用flow-matching损失
推理: 仅需视频骨干前向 + 单层动作头
```

### 4. 输入输出

**输入**: 多视角RGB观测 + 语言指令 + 本体感知  
**输出**: 连续动作chunk  
**推理延迟**: 66.5ms（3.2x faster than Fast-WAM）

## Q2: 与Spatial AGI的关系

### 1. 如何理解和表示空间

- **多层视频特征**: 从30层视频骨干的所有层提取表示，不同层可能编码不同空间抽象
- **浅层**: 空间几何（边缘、深度线索）
- **深层**: 语义理解（物体识别、场景理解）
- **Docking接口**: 让动作头同时访问所有空间抽象层次

### 2. 如何处理空间关系

- **隐式空间表示**: 通过预训练视频骨干的空间理解能力
- **RoPE重对齐**: 处理不同模态的空间位置编码差异
- **动作到空间的映射**: 轻量级动作头将空间表示映射到动作空间

### 3. 对Spatial AGI的启发

1. **深度不对称性**: 不同任务（视频生成vs动作预测）需要不同深度——Spatial AGI系统设计中应考虑任务复杂度
2. **表示中枢范式**: 一个强大的视觉表示骨干可以服务多个轻量级任务头
3. **多层特征访问**: 不同层次的空间理解（几何→语义）都应该可访问
4. **效率优先**: 66.5ms延迟适合实时embodied AI部署

### 4. 可以应用的Spatial AGI场景

- **实时机器人控制**: 低延迟动作预测
- **多任务Spatial AGI**: 一个骨干 + 多个任务头（导航、操作、规划）
- **边缘部署**: 轻量级动作头适合资源受限设备

## Q3: 创新点和局限性

### 1. 主要创新点

1. **DoT设计原则**: 将视频Transformer作为表示中枢，任务模块作为轻量级输出头——通用架构设计原则
2. **单层动作头**: 首次证明1层动作头 + 多层特征docking就够了
3. **RoPE重对齐**: 解决跨模态位置编码对齐问题
4. **3.2x加速**: 66.5ms vs 213ms，实用性强
5. **强OOD泛化**: LIBERO-Plus上的分布外表现优秀

### 2. 主要局限性

1. **视频骨干仍然是完整深度**: 虽然动作头减到1层，但视频骨干仍需完整前向
2. **特征融合设计**: Docking接口的融合策略（如何最优地从30层中提取信息）可能需要进一步优化
3. **仅评估操作任务**: 未在导航、驾驶等任务上验证
4. **与FastWAM对比**: 虽然更快，但精度上仍是"competitive"而非"SOTA"
5. **无未来视频预测**: 仅评估动作预测，未探索视频生成质量

### 3. 与相关工作的对比

| 方法 | 动作模块深度 | 视频骨干深度 | 推理延迟 | LIBERO性能 |
|------|-------------|-------------|----------|-----------|
| UWM | ~30 | ~30 | 高 | 好 |
| FastWAM | ~30 | ~30 | 213ms | 好 |
| **Faster-WAM** | **1** | **30** | **66.5ms** | **Competitive** |

## 核心技术发现

1. **动作预测不需要深层**: 1层动作头通过docking接口就能达到competitive性能——颠覆了"深层=好"的直觉
2. **多层信息互补**: 不同视频层的key/value包含互补的空间信息
3. **RoPE重对齐**: 跨模态位置编码对齐是关键技术挑战
4. **OOD泛化强**: 浅层动作头 + 多层特征融合可能比深动作头泛化更好

---

## 与Spatial AGI的关系

### 直接贡献
- 为Spatial AGI系统提供了高效的架构设计原则（DoT）
- 66.5ms延迟使实时空间推理成为可能
- 多层特征访问确保多层次空间理解

### 技术启发
- **不对称深度**: 视觉理解需要深层，动作预测可以很浅——Spatial AGI系统应利用这种不对称性
- **表示复用**: 一个强大的视觉骨干可以服务多个空间任务
- **效率与泛化的正向关系**: 更浅的动作头反而泛化更好

---

## 总结

Faster-WAM回答了一个重要问题：WAM的动作模块不需要深层。通过DoT设计原则和docking接口，单层动作头就能利用30层视频骨干的全部表示能力，达到3.2x加速和更强的OOD泛化。这对Spatial AGI的启示是：系统设计应考虑任务复杂度的不对称性，用强大的视觉骨干 + 轻量级任务头实现高效的空间智能。
