# UNITAS: A 3D-Native World Action Model for Embodied Manipulation

**发表日期**: 2026-10-09
**arXiv链接**: https://arxiv.org/abs/2610.12099
**PDF链接**: https://arxiv.org/pdf/2610.12099
**HTML版本**: https://arxiv.org/html/2610.12099v1
**作者**: Ruixiang Wang, Wenlve Zhou, Bo Yue, Hengyan Liu, Dekun Lu, ..., Kui Jia (港中深 + DexForce 具力科技 + 佛山大学 + 中山大学 + 华南理工)
**代码**: https://github.com/DexForce/UNITAS

## 论文速览

- 问题: 世界动作模型 (WAM) 大多基于视频生成器，用图像/视觉潜变量表示世界演化；但机器人交互发生在度量3D空间，图像只是视角依赖的投影，像素距离≠物理距离
- 方案: Unitas — 首个 3D-native 世界动作模型，在共享度量3D坐标系内统一观测、动作与场景动力学
- 核心表示: action flow (手/夹爪的3D点轨迹) + scene flow (条件化的场景点位移)
- 关键组件: world-aligned 3D位置嵌入 (有/无深度均可)、物理时间轨迹 tokenizer (一条轨迹一个token)
- 规模与结果: 仅 1.7B 参数；RoboTwin 场景预测比 PointWorld 位移误差低 49%；LIBERO 99.8%；真机平均 85%

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？

**分析**:

1. **核心思想和动机**

   - WAM 要回答一个耦合的物理问题: 给定任务指令，机器人该执行什么运动，以及这个运动将如何改变周围世界
   - 视频类 WAM 的根本缺陷:
     - 同一机器人动作在不同视角产生不同像素变化；相同像素位移不对应相同物理距离
     - 相机内参/外参差异使映射跨具身不一致
     - 视频WAM评估显示对视角和机器人状态变化敏感；照片级逼真的预测仍可能错误表示位移、使刚性几何形变、让静态区域漂移
   - 结论: 视觉表示把度量运动和接触关系留给空间推理隐式处理——正确的做法是把观测、动作、场景变化放进同一个度量3D坐标系
   - 先驱 PointWorld 只在给定外部机器人运动时预测度量点流，不能从指令生成动作; Unitas 要同时支持行为生成与后果预测

2. **主要技术方法**

   - **3D-native 因式分解**:
     p(A, u, S | C, q0) = p(A|C) · p(u|C, q0) · p(S|A, C)
     - A: action flow (交互本体的点轨迹)
     - u: 可执行末端动作块 (action chunk)
     - S: scene flow (场景点位移)
     - 策略模式只评估 p(u|C,q0)；模拟器模式在给定/生成 A 的条件下预测 S
   - **World-Aligned 3D 位置嵌入**:
     - 每个预测窗口内固定一个度量坐标系 F_W
     - 有深度: 像素反投影 K^-1、T_W 变换到世界坐标，Fourier 编码后加到视觉 token 上
     - 无深度: 沿标定相机射线均匀采样 M=64 个候选深度 (0.1~2.0m)，用 patch 特征对候选位置做注意力加权 (softmax score)，得到位置的软估计——一种"射线上的隐式深度定位"
   - **Action Flow 统一具身表示**:
     - 人手和机器人夹爪形态/接口不同，但都可以表示为共享坐标系中对应3D点的轨迹
     - 跨具身(人手演示、不同机器人)用同一接口
   - **物理时间轨迹 Tokenizer**:
     - 不同数据源帧率/时长不一，逐时间步编码会让 backbone 容量分配失衡
     - 把整条点轨迹按物理时间对齐后编码为单个 token，锚定在其当前3D位置
   - **层耦合 Mixture-of-Transformers**:
     - 点动力学专家: 同时建模 action flow 和 scene flow
     - 动作专家: 生成末端动作块
     - 因果注意力掩码支持去噪步间 KV cache，加速推理
   - **Scene Flow 条件解码**: 训练时以干净演示 action flow 为条件；推理时用生成的或外部给定的 action flow

3. **算法流程和关键步骤**

   - 输入: 指令 ℓ、多视图观测、相机标定 (K_i, T_W)、历史动作流、末端状态 q0
   - Step 1: 视觉编码器提取 token，加 world-aligned 3D 位置嵌入 (有深度反投影 / 无深度射线加权)
   - Step 2: MoT 点动力学专家 + 动作专家并行处理: 生成 action flow 和可执行动作块
   - Step 3a (策略模式): 直接执行动作块
   - Step 3b (模拟器模式): 以 action flow 为条件解码 scene flow，预测场景变化
   - Step 4: 去噪迭代，因果掩码 + KV cache 复用共享上下文

4. **输入输出**

   - 输入: 多视图 RGB(±深度)、相机标定、指令、末端状态、历史动作流
   - 输出 (策略模式): 可执行末端动作块
   - 输出 (模拟器模式): action-conditioned 场景点位移轨迹 (scene flow)
   - 参数量: 1.7B

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

**分析**:

1. **如何理解和表示空间**

   - 空间被表示为唯一的度量坐标系 F_W: 观测、动作、场景演化全部锚定其中
   - 点轨迹是"最小公共分母"式的空间交互表示——既能代表人手、夹爪，也能代表场景
   - 物理时间作为一维坐标与3D空间并列: 空间智能 = 度量空间 × 物理时间中的轨迹推理

2. **如何处理空间关系**

   - 空间关系通过"固定空间锚点上的特征"来建模: 动作和场景 token 都锚在当前3D位置，网络在锚点上累积运动特征
   - 接触、遮挡、支撑等物理关系在共享坐标系中天然可计算——不需要从2D投影中隐式恢复
   - 场景对动作的响应 (p(S|A)) 显式建模了因果: 这是"世界模型"区别于"视频生成器"的关键

3. **对Spatial AGI的启发**

   - **3D-native 是世界模型的正道**: 论文用数据证明，1.7B 的3D原生模型在场景预测和操作成功率上打败更大的视频类 WAM——空间智能的容量应花在度量结构上，而不是照片逼真度上
   - **统一的物理接口**: action flow 是跨具身(人/机器人)、跨任务的通用动作语言，这正是 Spatial AGI 需要的具身无关层
   - **策略与模拟器一体**: 同一模型既能"做"也能"想象后果"，这是 Spatial AGI 系统的核心双能力 (行动 + 预演)
   - **无深度的空间接地**: 射线候选加权让纯 RGB 系统也能获得度量接地，降低3D原生的部署门槛

4. **可以应用的Spatial AGI场景**

   - 人视频→机器人技能迁移: 人手 action flow 直接作为演示接口
   - 模拟器模式用于策略预演/评估/数据生成 (model-based RL)
   - 跨具身基础模型的动作接口层
   - 与 VLM 规划器组合: VLM 出指令，Unitas 出动作+后果预测

### Q3: 创新点和局限性

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

**分析**:

1. **主要创新点**

   - 首个把观测、动作、场景动力学统一进共享度量3D坐标系的 WAM
   - action flow 作为跨具身统一动作表示 + scene flow 作为条件化场景响应，二者共享一个物理时间轨迹 tokenizer
   - 无深度时的 world-aligned 位置嵌入 (射线候选注意力加权) 兼顾了接地精度与部署灵活性
   - 小模型 (1.7B) 大性能: 证明3D原生表示的样本效率优势

2. **主要局限性**

   - 每个预测窗口内坐标系固定，跨窗口的全局一致性(长时程地图级一致性)未见讨论
   - 点轨迹表示对拓扑变化(如倒水、切菜等流体/变形)的表达能力有限
   - 无深度模式的位置接地本质是软估计，精度依赖训练分布
   - 多视图相机标定仍是硬前提，自由移动相机场景需要额外处理
   - MoT 双专家架构比单一 transformer 复杂，工程成本高

3. **与其他相关工作的对比**

   - vs 视频类 WAM (Fast-WAM, 及基于视频生成先验的系列): Unitas 度量接地、跨视角稳定；视频类逼真但度量不忠
   - vs PointWorld: PointWorld 只在给定外部动作时预测点流 (纯模拟器)；Unitas 同时从指令生成动作 (策略+模拟器双模式)
   - vs 3D策略 (RVT, PerAct 类): 那些只用3D做感知输入; Unitas 把3D作为动作与世界演化的共享接口
   - vs LaMP/GeomVLA: 它们用轨迹去噪的中间特征条件化动作; Unitas 直接联合建模动作流与场景流

## 核心技术发现

- 发现1: 视频WAM的"逼真但不忠实"问题是系统性的——位移失真、刚性形变、静态漂移
- 发现2: 点轨迹 (action flow + scene flow) 可以作为人手/机器人/场景的统一物理语言
- 发现3: 物理时间对齐的轨迹级 token 化解决异构数据源的容量分配问题
- 发现4: 无深度时射线候选注意力加权是廉价而有效的空间接地方案
- 发现5: 1.7B 3D-native < 更大视频模型的误差，但 > 其任务成功率——度量结构 > 表观逼真

## 关键数据

- 参数量: 1.7B
- 模拟器模式 (RoboTwin): Moving ADE ↓35%, Moving FDE ↓21%, Static ADE ↓49% (vs PointWorld)
- 策略模式: LIBERO 99.8% 成功率; LIBERO-Plus 89.1% (对相机/机器人状态变化鲁棒); VLABench 领先
- 真机: Organize Books 90%, Pack the Ball 65%, 平均 85%
- 深度缺失模式: 射线采样 M=64, 深度范围 0.1~2.0m

## 与Spatial AGI的关系

### 直接贡献

- 为 Spatial AGI 提供了"策略+模拟器"双模式3D原生基座，交互的最小单位从像素变成了度量点轨迹

### 技术启发

- 空间锚定 token: 让 transformer 的容量围绕物理空间组织，而非图像网格
- 统一物理时间接口: 异构具身数据可在同一表示下联合训练

### 应用场景

- 跨具身操作基础模型
- 基于世界模型的策略预演与评估
- 人示范视频驱动的技能学习

## 个人思考

### 最令人兴奋的发现

- "照片级逼真的预测仍可能错报位移、形变刚性几何"——这句话应该刻在所有做视频世界模型的团队墙上。Unitas 用 1.7B 参数打赢更大模型的事实说明: Spatial AGI 的算力应该花在正确的归纳偏置(度量坐标系)上，而不是无差别地堆生成容量。3D-native + 物理时间接口可能就是具身世界模型的正确抽象层级。

### 潜在局限

- 点轨迹是对交互的"骨架级"抽象，对接触力学、形变、流体的表达仍然粗糙; 长时程跨窗口一致性也未解决。要成为通用 Spatial AGI 基座，还需要与语义层(VLM)和持久空间记忆(如 Slot3R 这类)结合。

### 与昨日研究的关联

- 与昨日 Long-WAM (扩展世界动作模型上下文) 互补: Long-WAM 扩展时间上下文，Unitas 解决空间表示的度量忠实性——WAM 的两大短板(上下文长度、空间接地)正被分别攻坚。
- 与 SearchWorld 的价值接地想象、EvoMem 的状态记忆共同勾勒出 WAM 演化全景: 上下文、空间、价值、记忆四个轴。

## 总结

### 核心发现总结

- Unitas 是首个 3D-native WAM: 观测、动作、场景演化共享度量坐标系，action flow/scene flow 统一具身表示
- 1.7B 参数取得 SOTA 级场景预测与操作成功率，验证度量结构先验的效率优势

### 对Spatial AGI的意义

- 具身空间智能的正确起点是度量3D中的轨迹推理，而非视频生成
- "既能行动也能想象后果"的统一模型是 Spatial AGI agent 的合理架构雏形
