## 论文概览

OneCanvas提出了一种极其简洁的方法来解决3D场景理解问题：将多视角的patch特征重投影到一个单一的全景画布上，让预训练VLM像处理普通图像一样理解3D场景。该方法不需要任何新的架构组件、辅助损失项或专用3D编码器——3D理解完全从输入的表示方式中涌现。

### 一句话总结

> **通过全景特征重投影将3D场景理解简化为标准VLM输入处理问题，用最少的架构修改实现SOTA性能，同时训练计算量比最强竞品少一个数量级。**

### 核心数据

| 指标 | 数值 | 对比 |
|------|------|------|
| SQA3D EM@1 | **65.3** | +2.3 over previous best |
| VSI-Bench average | **70.1** | SOTA |
| SPBench zero-shot | **72.1** | +4.8 over next best |

## 核心问题

### Q1: 核心算法原理

**问题**: 这篇文章的核心算法原理是什么？请详细描述核心思想、技术方法、算法流程和输入输出。

#### 1. 核心思想和动机

OneCanvas的出发点极其简洁且具有深刻的洞察力。作者观察到了当前3D VLM领域的两条主要技术路线及其各自的问题：

**路线A：架构扩展派**
- 通过添加点云tokenizer、深度编码器、3D融合模块等专用几何组件来增强VLM
- 代表方法：LL3DA, 3D-LLM, Video-3D LLM, VLM-3R, SpaceMind, HiSpatial
- **问题**：需要联合训练新模块与语言主干，训练成本高，且几何编码器与语言模型的对接困难

**路线B：数据扩展派**
- 通过收集大规模空间QA数据来"暴力"教会VLM空间推理
- 代表方法：SenseNova-SI, Cambrian-S
- **问题**：需要整理和标注数百万高质量空间问答对，且模型可能学习统计捷径而非真正的空间推理

**更关键的问题是**：Ma et al. (2026)的审计研究发现，在SQA3D等基准上，纯文本基线的性能竟然接近或匹配最先进的几何感知模型！这说明现有方法实际上并没有真正利用几何输入，而是退化为利用问题和场景类别的统计规律性。

OneCanvas的核心insight是：**问题的根源不在于缺少架构或数据，而在于输入表示方式不对**。如果能让VLM"看到"统一的、包含完整3D信息的输入表示，预训练VLM中潜在的空间推理能力就可以被唤醒。

#### 2. 主要技术方法

##### 2.1 全景特征重投影（Panoramic Feature Reprojection）

这是OneCanvas的核心创新。具体过程：

**输入**：K张带位姿的RGB图像 + 深度图 + 相机内参

**Step 1: 特征提取**
- 使用Qwen3-VL的冻结视觉编码器从每个视角提取patch级特征图 F_k ∈ ℝ^(H_f × W_f × D)
- 每个patch (u, v) 有对应的深度值 z = D_k(u, v)

**Step 2: 3D反投影（Lifting）**
- 每个patch使用深度值、相机内参和位姿反投影到3D世界坐标：

```
p_world = T_k · [(u - c_x) · z / f_x, (v - c_y) · z / f_y, z]^T
```

- 其中 T_k ∈ SE(3) 是相机到世界的变换
- 结果：得到一组提升后的patch集合 P = {(p_i, f_i, t_i)}，每个patch有世界坐标、特征向量和时间索引

**Step 3: 全景画布投影**
- 选择画布原点 c ∈ ℝ³ 和朝向 R ∈ SO(3)
- 计算每个patch在画布坐标系下的局部偏移：q_i = R^T(p_i - c) = (q_x, q_y, q_z)
- 转换为连续球面坐标：
  - 经度 θ_i = atan2(q_x, q_z) ∈ [-π, π]
  - 纬度 φ_i = arctan(-q_y / √(q_x² + q_z²)) ∈ [-π/2, π/2]

**关键设计选择：连续位置而非像素网格**
- 不进行光栅化或聚合！每个patch保持为独立token
- 共置的patch保持区分（通过3D位置嵌入消除歧义）
- 模型通过注意力机制而非预定义规则解决重叠

**Step 4: VLM消费**
- 将经度W = θ、纬度H = φ、时间T = 帧索引设置到Qwen3-VL的3D-RoPE位置编码中
- 所有值线性缩放到[0, 100]范围内（匹配预训练分布）
- VLM将画布作为普通单张图像处理

##### 2.2 3D位置嵌入（3D Position Embedding）

从3D到2D角度坐标的投影会丢失深度信息。为补偿这一损失，OneCanvas设计了丰富的3D位置嵌入：

**组成部分（共136维）**：
1. **逐轴正弦编码**（3轴 × 16频率 × 3 = 144维中的一部分）
   - 对 q_x, q_y, q_z 各使用16个对数间隔频率 ω_k ∈ [0.1, 100] rad/m
   - 每个频率生成 {sin(ω_k · q_a), cos(ω_k · q_a), q_a}
   
2. **径向原语编码**
   - 对 ‖q_i‖（到原点距离）和 r_xz = √(q_x² + q_z²)（水平径向距离）
   - 使用8个对数间隔频率 ν_k ∈ [0.1, 10] rad/m
   - 直接暴露与成对距离、地板面积等相关的量

3. **单位方向向量**（原始值直通）
   - q_i / ‖q_i‖ 作为方向信息

**融合方式**：
- 136维编码通过2层MLP投影
- 通过学习的标量门控加到patch特征上
- 在特征空间注入度量位置，而非作为额外的RoPE维度
- 保持了3D-RoPE的预训练角度和时间语义不变

**设计理由**：
> "Injecting metric position in feature space rather than as additional RoPE dimensions keeps 3D-RoPE's pretrained angular and temporal semantics intact, and lets the VLM attend to metric position through the same content-attention pathway it uses for any other feature."

##### 2.3 空间预训练课程（Spatial Pretraining Curriculum）

这是OneCanvas的第二个核心创新，利用全景画布表示的独特优势生成空间推理训练数据。

**核心insight**：空间推理难以从下游QA中学习，因为：
- 监督是间接的
- 目标任务分布狭窄
- 场景外观线索在几何信号形成之前就主导了梯度
- 模型在学会读取几何输入之前就已经拟合了答案的边缘分布

**课程对象（Curriculum Objects）的设计**：
- 在画布上放置一个盒子区域，填充从真实场景采样的单个patch特征
- 在提示文本中通过内联副本引用该物体（保持文本token的MRoPE位置）
- 模型通过视觉匹配路径解析引用
- **外观与尺寸和位置解耦**：几何信息成为解决问题的主要信号

**物体特征来源**：
- 预计算的激活池，来自ScanNet、ScanNet++、ARKitScenes的held-out场景
- 视觉编码器将其视为普通视觉内容

**任务类型（6大家族）**：

| 任务家族 | 具体内容 | 能力训练 |
|----------|----------|----------|
| 度量测量 | 表面间距、相对距离比较、地板面积读数 | 度量推理 |
| 自我中心方向 | 左/右/前/后查询、时钟方向变体、相机视角变体 | 视角推理 |
| 多轮导航 | 1-4轮路径查询 | 路径规划 |
| 可观测性 | 帧序列中的首次出现、从给定姿态的可见性 | 视点推理 |
| 计数 | 可分性条件、位置条件 | 组合推理 |
| 多目标边界框 | 2-4个物体的3D边界框有序读出 | 空间定位 |

**答案分布控制**：
- 抑制数据集统计捷径
- 确保模型真正学习空间推理而非记忆答案分布
- 直接回应了Ma et al. (2026)审计中发现的问题

##### 2.4 答案分布控制（Answer Distribution Control）

这是防止VLM学习统计捷径的关键技术。在课程数据生成过程中，作者主动控制了答案的分布，使得：
- 答案不能从问题模板或物体类别中直接推断
- 几何信息是得出正确答案的唯一可靠路径
- 答案分布均匀，避免模型利用先验偏见

#### 3. 算法流程和关键步骤

**完整训练流程**：

```
┌─────────────────────────────────────────────────────┐
│                Stage 1: 空间预训练                   │
│                                                      │
│  输入: 程序化生成的全景画布（空画布+放置的物体）     │
│  训练: LoRA r=256, α=512, dropout=0.05              │
│  优化: Adam, lr=2e-5, cosine schedule, 3% warmup    │
│  批量: effective batch 16                            │
│  数据: 6大家族任务, 物体patch≤200/样本              │
│  目标: 学习几何读取能力, 抑制场景先验捷径            │
│                                                      │
│  ↓ LoRA权重合并回基础模型 ↓                          │
├─────────────────────────────────────────────────────┤
│                Stage 2: 目标适配                     │
│                                                      │
│  输入: 真实场景的下游QA数据                          │
│  训练: LoRA r=64, α=128, dropout=0.05（新适配器）   │
│  优化: 同Stage 1, 10k steps, effective batch 32     │
│  数据: VLM-3R-VSIBench(70%) + SQA3D(15%) + ViCA(15%)│
│  目标: 格式适配, 保持Stage 1的几何读取能力           │
│                                                      │
│  关键: 低秩适配器限制drift, 锚定Stage 1能力          │
└─────────────────────────────────────────────────────┘
```

**推理流程**：
```
多视角RGB-D → 冻结视觉编码器 → patch特征 → 3D反投影 → 全景画布聚合(+3D位置嵌入) → VLM → 答案
```

#### 4. 输入输出

**输入**：
- K=32帧 posed RGB图像（均匀采样）
- 度量深度图（GT或前馈重建）
- 相机内参 C_k = (f_x, f_y, c_x, c_y)
- 相机位姿 T_k ∈ SE(3)

**输出**：
- 场景问答文本回答
- 空间推理结果（距离、方向、计数等）

**画布配置**：
- 训练分辨率：320×240
- SQA3D评估：320×240
- VSI-Bench/SPBench评估：640×480
- 画布原点：SQA3D用agent位姿，SPBench单图用查询位姿，其他用相机质心

### Q2: 与Spatial AGI的关系

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？

#### 1. 如何理解和表示空间

OneCanvas提供了一种独特的空间表示方法，其核心思想可以概括为"**通过坐标变换实现维度降维**"：

**表示层次**：
```
3D世界坐标 (p_x, p_y, p_z)
    ↓ 画布坐标变换
画布坐标系 (q_x, q_y, q_z)
    ↓ 球面投影
2D角度坐标 (θ, φ) → 填入VLM的3D-RoPE空间轴
    ↓ + 136维位置编码
特征空间增强 → 保留度量深度信息
```

**关键设计哲学**：

1. **统一坐标系**：所有patch共享同一空间坐标系，自然编码物体间的空间关系
   - 消除了多视角输入中的坐标系切换问题
   - VLM的自注意力可以直接"看到"全场景的几何关系

2. **连续而非离散**：patch在画布上的位置是连续的浮点数，不是整数网格
   - 避免了光栅化导致的信息丢失
   - 共置patch保持为独立token，由注意力解决重叠

3. **视角灵活性**：canvas origin可自由选择
   - 场景中心：全局场景理解
   - Agent位姿：situated reasoning（具身推理）
   - 任意位置：灵活的空间查询

4. **度量保留**：通过3D位置嵌入保留深度信息
   - 角度坐标丢失深度 → 位置编码补偿
   - 在特征空间而非位置编码空间注入 → 保持RoPE语义

#### 2. 如何处理空间关系

**显式机制**：
- 所有patch共享同一画布坐标系 → 物体间空间关系编码在它们的相对角度位置中
- 3D位置嵌入直接暴露径向距离信息 → VLM可以进行度量推理
- 时间轴保留源帧索引 → 时序推理仍可用

**隐式机制**：
- VLM的自注意力机制在画布上全局工作 → 可以捕获远距离空间关系
- 预训练VLM的2D空间先验与画布的角度坐标对齐 → 利用已有能力
- 注意力而非预定义规则解决重叠 → 模型学习最优的融合策略

**空间关系处理的优势**：
1. 全景360°视野避免信息丢失
2. 统一画布避免多视角切换的认知负荷
3. 连续坐标避免网格离散化误差
4. 3D位置嵌入支持度量级精度

#### 3. 对Spatial AGI的启发

OneCanvas为Spatial AGI提供了多个层次的深刻启发：

**启发A：表示优先于架构（Representation > Architecture）**
- 最优雅的解决方案可能是改变输入表示方式而非添加复杂模块
- 预训练VLM中可能已经存在潜在的空间推理能力，只是需要正确的"接口"来唤醒
- 这质疑了当前3D VLM领域"更多模块=更好性能"的趋势

**启发B：数据生成 > 数据收集**
- 程序化生成空间推理数据具有独特优势：
  - 可控制答案分布，避免统计捷径
  - 可生成无限量训练数据
  - 可精确控制难度和覆盖范围
  - 几何信号是唯一的解题路径
- 这为Spatial AGI的数据工程提供了新范式

**启发C：视角中心推理是关键能力**
- canvas origin的选择使VLM可以进行"从某个位置看"的推理
- 这是embodied AI的核心需求：agent需要在自己的位置上理解和推理场景
- SQA3D上的实验证实了agent-pose centering的重要性

**启发D：效率是实用化的关键**
- 计算量比最强竞品少一个数量级
- 不需要专用3D编码器或复杂架构修改
- 这为低门槛部署Spatial AGI提供了可行路径

**启发E：解决根本问题而非症状**
- 论文直接回应了Ma et al. (2026)的审计发现——现有3D VLM没有真正使用几何信息
- 通过答案分布控制从根源上解决了统计捷径问题
- 这种"找到根本问题并直接解决"的思路对Spatial AGI研究非常重要

#### 4. 可以应用的Spatial AGI场景

| 场景 | 应用方式 | 优势 |
|------|----------|------|
| 机器人场景理解 | 输入多视角RGB-D → 全景画布 → 场景QA | 统一表示，自然支持situated reasoning |
| 导航与路径规划 | canvas origin设为robot pose | 视角中心推理，路径规划性能最强 |
| 自动驾驶多视角融合 | 多摄像头 → 全景画布 | 360°统一视野，避免BEV限制 |
| AR/VR空间推理 | 深度传感器+位姿 → 画布 | 实时性强，不需要重建 |
| 具身AI指令理解 | 自然语言+场景画布 | VLM原生理解，无需中间转换 |
| 空间关系问答 | 任意空间查询 | 支持度量级和方向性查询 |
| 场景重建辅助 | 画布作为中间表示 | 可与重建方法互补 |

### Q3: 创新点和局限性

**问题**: 基于前面的分析，这个方法的主要创新点和局限性是什么？

#### 1. 主要创新点

**创新点1：极简设计哲学（Radical Simplicity）**
- **零架构修改**：不添加任何新组件到VLM
- **零辅助损失**：不需要额外的训练目标
- **零专用编码器**：不需要点云tokenizer或深度编码器
- 3D理解完全从输入表示方式中涌现
- 这是3D VLM领域罕见的"做减法"的创新

**创新点2：全景画布表示（Panoramic Canvas Representation）**
- 将多视角3D信息统一到VLM原生输入格式
- 连续角度坐标而非离散网格
- 保留所有patch为独立token，由注意力解决重叠
- 支持任意canvas origin的灵活视角选择

**创新点3：3D位置嵌入设计**
- 136维多尺度编码
- 逐轴正弦 + 径向原语 + 方向直通
- 在特征空间而非位置编码空间注入度量信息
- 保持了RoPE预训练语义的完整性

**创新点4：空间预训练课程（Spatial Pretraining Curriculum）**
- 利用画布表示的独特优势生成无限空间推理训练数据
- 程序化放置物体patch到任意3D位置
- 外观与几何解耦：物体特征来自真实场景但尺寸和位置随机化
- 6大家族任务覆盖度量、方向、导航、可观测性、计数、定位
- 答案分布控制直接解决Ma et al. (2026)审计发现的统计捷径问题
- 这是一种全新的数据增强范式——在表示空间而非像素空间进行增强

**创新点5：两阶段训练策略的精巧设计**
- Stage 1（r=256 LoRA）学习几何读取 → 合并回基础模型
- Stage 2（r=64 LoRA）仅做格式适配，低秩限制drift
- "合并-冻结-小适配器"的策略锚定了Stage 1的几何能力
- 这种训练范式可推广到其他"能力注入"场景

**创新点6：SOTA性能 + 极致效率**
- SQA3D: 65.3 EM@1（+2.3 over previous best）
- VSI-Bench: 70.1 average
- SPBench: 72.1 zero-shot（+4.8 over next best）
- 训练计算比最强竞品少一个数量级
- 证明了简洁方法可以超越复杂方法

#### 2. 主要局限性

**局限1：依赖深度和相机位姿的质量**
- OneCanvas需要度量深度图和相机位姿作为输入
- 纯RGB方法不需要这些，适用范围更广
- 虽然前馈重建模型（如DUSt3R、VGGT、Depth Anything 3）正在缩小这一差距
- 但位姿估计失败仍会降低画布质量
- 对于没有深度传感器的场景（如普通视频），需要额外的估计步骤

**局限2：全景画布的分辨率限制**
- 训练时使用320×240分辨率
- 评估时最高使用640×480分辨率
- 等距柱面投影的像素密度不均匀（极点区域过密，赤道区域相对稀疏）
- 对于需要精细物体识别的任务，画布分辨率可能不够
- 这也解释了为什么"object counting"任务上base VLM保持小幅领先——重投影不准确可能导致实例分裂或合并

**局限3：等距柱面投影的固有畸变**
- 虽然OneCanvas在特征空间投影而非像素空间（PanoEnv指出的问题得到缓解）
- 但在高纬度区域仍有几何畸变
- 3D位置嵌入部分缓解了深度信息丢失
- 但角度坐标在极点附近的数值精度问题仍然存在

**局限4：程序化预训练数据的覆盖范围**
- 课程任务是手工设计的（6大家族）
- 添加新的空间技能需要编写新的任务生成器
- 不能像数据收集方法那样通过"投喂更多数据"来扩展
- 预训练数据可能无法覆盖所有真实世界的空间推理场景
- 室外大尺度场景未测试

**局限5：对VLM主干架构的依赖**
- 需要主干VLM支持至少2D位置编码（如Qwen3-VL的3D-RoPE）
- 对于仅支持1D位置编码的模型不适用
- 所有实验仅在Qwen3-VL-8B上进行
- 在其他VLM主干上的泛化能力未验证

**局限6：全局全景的固有权衡**
- 单一全局全景画布用紧凑性换取了精度
- 对非常大场景或室外场景，一个画布可能无法提供足够的空间分辨率
- 没有层次化或自适应分辨率的机制
- 与BEV方法类似，存在远距离区域表示精度不足的问题

**局限7：物体引用机制的限制**
- 内联副本的匹配机制可能对相似外观的物体产生混淆
- 当画布上有多个相似patch时，模型需要精确的视觉匹配
- 虽然在实验中工作良好，但在极端情况下的鲁棒性未验证

**核心差异分析**：

1. **vs HiSpatial/SenseNova-SI**: 不需要海量QA数据或复杂几何编码器。HiSpatial需要点图作为辅助输入和分层训练课程，OneCanvas通过简单的画布表示就超越了其性能。

2. **vs VLM-3R/SpaceMind**: 不需要额外的3D编码器模块。VLM-3R融合隐式3D token，SpaceMind添加相机引导的模态融合模块——两者都增加了架构复杂性，而OneCanvas证明这些都不必要。

3. **vs Ross3D**: 不需要重建目标。Ross3D通过重建视觉指令调优提供3D感知监督，而OneCanvas通过更直接的表示方式实现空间理解。

4. **vs BEV方法**: 不限于俯视图。BEV是OneCanvas思路的特例——将3D投影到2D——但BEV固定了视角（俯视），而OneCanvas支持任意canvas origin，包括agent-pose centering。

5. **vs PanoGrounder/PanoEnv**: PanoGrounder需要预重建网格或3DGS场景，PanoEnv研究VLM在ERP图像上的空间智能（发现畸变是挑战）。OneCanvas直接投影特征而非像素，避免了VLM需要处理ERP畸变的问题。

## 核心技术发现

### 发现1：表示设计比架构设计更重要
OneCanvas的核心贡献不是一个新的架构或损失函数，而是一种输入表示方式。通过简单地将多视角patch重投影到全景画布，标准VLM就能实现SOTA 3D推理。这质疑了领域内日益复杂的架构趋势。

### 发现2：连续位置 > 离散网格
作者明确选择不在画布上光栅化patch，而是保留每个patch为独立token，位于连续的(φ, θ)坐标上。这个设计避免了：
- 光栅化导致的信息丢失
- 预定义的聚合规则（如平均、深度选择）
- 重叠表面的混淆

让VLM的注意力机制自行决定如何融合共置的patch。

### 发现3：度量信息需要在特征空间注入
3D位置嵌入设计在特征空间（加到patch特征上）而非位置编码空间（额外RoPE维度），因为：
- 保持3D-RoPE的预训练角度/时间语义
- 让VLM通过内容注意力路径（而非位置编码）访问度量信息
- 避免了修改位置编码可能导致的预训练知识遗忘

### 发现4：答案分布控制是防止统计捷径的关键
Ma et al. (2026)的审计发现，现有3D VLM模型可以被纯文本基线匹配，说明它们没有真正利用几何信息。OneCanvas通过程序化生成数据时主动控制答案分布，从根源上解决了这个问题。

### 发现5：两阶段训练的有效性
Stage 1（空间预训练）→ 合并 → Stage 2（目标适配）的策略有效，因为：
- Stage 1的几何读取能力被"固化"到基础权重
- Stage 2的低秩适配器限制了drift，锚定了几何能力
- 这证明了"能力注入后适配"范式的有效性

### 发现6：视角中心推理的实证验证
Canvas origin消融实验（Table 5）显示：
- 使用agent位姿作为原点显著提升"Which"类问题（最依赖视角的类型）
- "Is"和"How"类问题对视角不敏感（符合预期）
- 从场景外部设原点一致降低性能
- 这证实了situated reasoning的重要性

## 与Spatial AGI的关系

### 直接贡献

OneCanvas为Spatial AGI提供了一条可行的"低门槛路径"：

1. **不需要从头训练3D原生模型**：通过精心设计的输入表示，现有预训练VLM可以直接用于3D推理
2. **不需要海量3D标注数据**：程序化预训练课程可以生成无限训练数据
3. **不需要专用硬件/架构**：在标准GPU上用LoRA即可训练
4. **自然支持embodied AI的关键能力**：situated reasoning、多视角融合、空间问答

### 技术启发

**启发1：维度转换的智慧**
OneCanvas展示了一种通用的问题解决策略：将高维问题（3D理解）转化为低维问题（2D VLM输入），但保留关键的高维信息（通过位置嵌入）。这种思路可推广到其他Spatial AGI问题。

**启发2：预训练能力的唤醒**
论文证明，预训练VLM中已经存在潜在的空间推理能力，只是标准的多视角输入格式没有正确激活这些能力。这暗示了：
- 未来Spatial AGI可能不需要从头训练，而是找到正确的"激活方式"
- 输入工程可能比架构工程更重要

**启发3：合成数据的新范式**
程序化生成空间推理数据——在表示空间而非像素空间增强——是一种可推广的合成数据范式：
- 可精确控制几何属性
- 可穷举覆盖空间关系类型
- 可控制答案分布避免偏差

### 应用场景

**短期应用（已验证）**：
- 3D场景问答（SQA3D）
- 空间推理基准（VSI-Bench）
- 通用空间推理（SPBench）

**中期应用（自然延伸）**：
- 机器人导航中的situated reasoning
- AR/VR中的空间交互
- 多摄像头监控场景分析
- 自动驾驶多视角融合

**长期应用（需要扩展）**：
- 大规模室外场景理解（需要解决画布分辨率限制）
- 动态场景理解（当前主要在静态场景验证）
- 多模态空间推理（结合语言、声音等）
- 交互式场景探索（结合主动感知）

## 个人思考

### 最令人兴奋的发现

**1. Occam's Razor的胜利**
OneCanvas的设计哲学让人深刻感受到"如无必要，勿增实体"的力量。在3D VLM领域纷纷添加点云编码器、深度编码器、融合模块的趋势中，这篇论文用最简单的方法（改变输入表示）取得了最好的结果。这提醒我们：**在添加复杂性之前，先穷尽简单方案**。

**2. 预训练VLM的隐藏能力**
论文证明预训练VLM中存在"沉睡的"空间推理能力，只需正确的输入格式就能唤醒。这引发了一个更深层的问题：VLM还在哪些方面有未被发现的隐藏能力？我们是否需要重新审视"需要专门架构才能解决特定任务"的假设？

**3. 统一坐标系的力量**
将所有视角的patch统一到一个画布坐标系中——这个看似简单的操作解决了多视角3D理解的多个核心问题：视角切换、信息丢失、关系编码。这让我想到，许多AI难题的瓶颈可能不在于算法，而在于表示。

**4. 合成数据的哲学**
OneCanvas的程序化预训练课程展示了一种高级的合成数据策略——不是在像素空间生成假图像，而是在特征空间直接构造几何关系。这种方法可以精确控制训练信号，避免了真实数据中的偏差和噪声。

### 潜在局限与开放问题

**1. 全景画布的"信息瓶颈"**
一个画布要承载整个场景的信息，对于复杂场景可能成为瓶颈。是否可以设计多分辨率画布或层次化画布？类似人类视觉的foveated rendering——在当前关注区域分配更多patch。

**2. 动态场景的挑战**
当前方法主要在静态室内场景验证。对于动态场景（移动的人、车、物体），画布需要随时间演化。是否可以扩展到时序全景画布？

**3. 深度估计的误差传播**
当使用估计的深度（而非GT深度）时，误差会直接影响patch在画布上的位置。这可能累积导致空间推理错误。需要研究对深度误差的鲁棒性。

**4. 可扩展性**
当前在室内场景（几十平米）验证。对于城市尺度（平方公里）的场景，一个画布显然不够。需要多画布或层次化表示。

**5. 与LLM推理能力的结合**
OneCanvas目前专注于感知层面的空间理解。如果将其与LLM的推理能力（如chain-of-thought、tree-of-thought）结合，是否能实现更高级的空间规划？

### 与近期研究的关联

**1. 与Occ-VLM（昨天研究）的对比**
昨天的Occ-VLM使用占据栅格(occupancy)作为3D场景表示。OneCanvas提供了一种替代方案——全景画布。
- Occ-VLM：显式几何，需要重建占据栅格
- OneCanvas：隐式特征重投影，不需要重建
- 两者代表了不同的空间表示哲学：显式几何 vs 隐式特征重投影
- 结合两者优势可能是有价值的方向：用占据栅格提供粗粒度几何结构，用全景画布提供细粒度语义

**2. 与PanoEnv的关联**
PanoEnv研究VLM在ERP图像上的空间智能，发现几何畸变是挑战。OneCanvas通过投影特征而非像素，巧妙绕过了这个问题——这是一个重要的技术差异。

**3. 与BEV方法的呼应**
自动驾驶中的Lift-Splat-Shoot等方法使用了类似的"lift-then-project"思路。OneCanvas将这一原则从BEV推广到全景画布，从自动驾驶推广到通用场景理解。

**4. 与程序化数据增强的关联**
空间预训练课程让人联想到最近在2D视觉中使用合成数据的趋势（如CutPaste、CopyPaste）。OneCanvas将其推广到3D空间——在表示空间而非像素空间进行"copy-paste"。

## 技术细节补充

### 3D位置嵌入的完整设计

```
输入: q = (q_x, q_y, q_z) — 画布坐标系下的偏移

Part 1: 逐轴正弦编码 (3 × 16 × 3 = 144维)
  for a in {x, y, z}:
    for k in 1..16:
      ω_k = log_space(0.1, 100, 16)[k]
      output += [sin(ω_k · q_a), cos(ω_k · q_a), q_a]

Part 2: 径向原语编码 (2 × 8 × 3 = 48维)
  r_full = ||q||           (到原点距离)
  r_xz = sqrt(q_x² + q_z²) (水平径向距离)
  for r in {r_full, r_xz}:
    for k in 1..8:
      ν_k = log_space(0.1, 10, 8)[k]
      output += [sin(ν_k · r), cos(ν_k · r), r]

Part 3: 方向直通 (3维)
  output += q / ||q||

Total: 144 + 48 + 3 ≈ 136维 (实际可能因实现略有不同)

后处理: 2层MLP投影 + 标量门控 → 加到patch特征上
```

### 训练配置详解

**Stage 1 空间预训练**:
- 基础模型: Qwen3-VL-8B
- LoRA: r=256, α=512, dropout=0.05
- 目标: attention和MLP的投影层
- 优化器: Adam, lr=2e-5, cosine schedule, 3% warmup
- 批量: effective batch 16
- 数据: 程序化生成的6大家族任务
- 物体patch限制: ≤200/样本, 每盒≥8 patch
- 硬件: 8× A6000 GPU

**Stage 2 目标适配**:
- 合并Stage 1 LoRA回基础模型
- 新LoRA: r=64, α=128, dropout=0.05
- 步数: 10k steps
- 批量: effective batch 32
- 数据混合: VLM-3R-VSIBench(70%) + SQA3D(15%) + ViCA(15%)
- 学习率: 2e-5, cosine, 3% warmup

**推理配置**:
- 帧数: K=32 (均匀采样)
- 输入分辨率: 320×240 (SQA3D) 或 640×480 (VSI-Bench, SPBench)
- ScanNet预处理: 裁剪3%边缘（避免伪影）
- 画布原点: SQA3D→agent pose, SPBench单图→查询位姿, 其他→相机质心

## 总结

### 核心发现总结

OneCanvas通过一个极其简洁的核心思想——将多视角patch特征重投影到单一全景画布——重新定义了3D场景理解的方法论。其贡献可以归纳为三个层面：

1. **表示层面**：全景画布 + 3D位置嵌入 = VLM原生的3D输入格式
2. **数据层面**：空间预训练课程 + 答案分布控制 = 无限高质量的几何推理训练数据
3. **训练层面**：两阶段LoRA策略 = 高效的能力注入与适配

这三个层面的协同使OneCanvas在SQA3D、VSI-Bench、SPBench上同时达到SOTA，且训练计算量比最强竞品少一个数量级。

### 对Spatial AGI的意义

OneCanvas证明了一个具有深远意义的原理：**Spatial AGI不一定需要复杂的3D专用架构**。通过精心设计的输入表示，预训练VLM中已经存在的空间推理能力可以被有效利用。这为低门槛部署Spatial AGI提供了可行路径。

更重要的是，OneCanvas的"表示优先"哲学和"程序化数据生成"策略为整个Spatial AGI领域提供了方法论指引——在追求更强的架构和更多的数据之前，先思考是否可以通过更好的表示来解决问题。

这篇论文让我想到Alan Kay的名言："Simple things should be easy, and complex things should be possible." OneCanvas让3D场景理解变简单了，而其背后的设计哲学（表示 > 架构，生成 > 收集，控制 > 规模）为更广泛的AI研究提供了启示。
