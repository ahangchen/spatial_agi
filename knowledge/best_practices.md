# 最佳实践 - 2026-03-12

## 论文分析流程

### 基本要求

**文档质量**:
- 至少500行详细分析
- 包含完整的技术细节
- Spatial AGI视角的深度思考
- 个人评价和未来方向

**分析内容**:
1. 基本信息（arXiv、PDF、笔记本ID）
2. 核心发现（3个以上）
3. 技术细节（算法、架构、实验）
4. 与Spatial AGI的关系
5. 局限性和未来方向
6. 个人思考和评价

### 工具使用

**NotebookLM**:
- 创建笔记本并记录ID
- 添加arXiv页面和PDF
- 询问3个核心问题
- 生成演示文稿（3-5分钟）
- 生成音频概览（2-3分钟）

**GLM WebReader MCP**:
- NotebookLM失败时的备选方案
- 直接基于arXiv HTML页面分析
- 不依赖NotebookLM索引
- 快速获取论文内容

**切换标准**:
- NotebookLM连接超时 > 90秒
- PDF添加失败3次以上
- ask返回空答案3次以上
- ask返回错误笔记本的答案2次以上

**不要切换**:
- 为了节省时间
- 响应慢但能工作
- 个人偏好

### Subagent管理

**任务分配**:
- 每篇论文独立Subagent
- timeout: 1800秒（30分钟）
- mode: run（一次性任务）
- runtime: subagent

**错误处理**:
- 网络错误：立即重试
- 连续失败：切换到GLM WebReader
- 记录失败原因和时间

**监控**:
- 使用subagents list查看状态
- 等待自动完成通知
- 不主动poll（避免浪费资源）

## Spatial AGI研究方法

### 模块化思维

**设计原则**:
1. 每个模块独立且可测试
2. 定义清晰的模块接口
3. 模块间通信协议标准化
4. 支持选择性执行

**模块分类**:
- 感知模块（看）
- 理解模块（懂）
- 规划模块（做）
- 评估模块（评）

### 跨粒度推理

**层次结构**:
- 场景 → 对象 → 部件 → 几何
- 语义 → 实例 → 像素

**推理方向**:
- Top-down（从粗到细）优于并行
- 渐进式课程学习更高效

**C2FMAE启示**:
- 级联解码器 > 并行解码器
- Cross-attention至关重要
- 任务顺序应与掩码策略对齐

### 度量级思维

**从模糊到精确**:
- 现有基准（VQA、GQA）无法评估度量级理解
- 需要厘米级精度的评估体系
- 度量锚点作为训练信号

**CourtSI启示**:
- 利用固定几何作为世界坐标系
- 人在回路引擎平衡自动化和精度
- 细粒度表示支持更精确的推理

## API限流处理最佳实践 (2026-03-13)

### 1. 错误类型识别
- **429 Too Many Requests**: 限流，需要长时间等待
- **其他网络错误**: 短暂故障，标准重试即可

### 2. 等待策略
- **限流错误**: 递增等待（20s/40s/60s），给服务器恢复时间
- **普通错误**: 标准等待（5s/10s/15s），避免过度延迟
- **连续失败**: 检测全局限流，额外延长等待时间

### 3. 动态调整
- 根据失败模式动态调整请求间隔
- 连续失败时降速，成功后恢复正常速度
- 记录失败状态，避免重复触发限流

### 4. 实现要点
```python
# 检测限流
is_rate_limit = '429' in error_msg or 'Too Many Requests' in error_msg

# 差异化等待
if is_rate_limit:
    wait_time = (attempt + 1) * 20  # 限流：20s/40s/60s
else:
    wait_time = (attempt + 1) * 5   # 普通：5s/10s/15s
```

### 5. 监控指标
- 请求成功率
- 连续失败次数
- 平均等待时间
- 限流触发频率

### 6. 适用场景
- arXiv API批量调用
- GitHub API大量请求
- 爬虫和批量下载
- LLM API调用
